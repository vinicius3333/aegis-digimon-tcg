# Replay object-storage options

Verified on 2026-10-08 against official provider pages and current pricing APIs. No account or bucket was created.

## Workload assumptions

The project's local sample was 40 gzip files from 20 bot matches, averaging 27,706.7 bytes each before two-hand exports were enabled; this is not a production average of the current format. With 3,000 accounts and 100 retained perspective files per account, 300,000 objects occupy approximately 8.31 GB at that average. A conservative 100,000-byte planning size produces 30 GB. Account count alone does not establish monthly traffic or writes. GB/GiB conventions differ between providers; prices below are approximate, before tax, exchange rates, app infrastructure, and existing account usage.

## Source conflicts and compatibility checks

- **Oracle:** the free-resource document explicitly distinguishes free-only versus paid/trial accounts. The broad “20 GB” marketing statement must not be applied to 20 GB of Standard storage after a paid upgrade. The live B91628/B91627 pricing API returned a 2026-10-01 update, a 10 GB Standard allowance, US$0.0255/GB-month thereafter, and US$0.0034/10,000 requests after 50,000. Oracle has São Paulo and Vinhedo regions and supports S3-compatible clients/presigned URLs. Existing tenancy type, home region, and already consumed quotas remain unverified. [Regions](https://docs.oracle.com/en-us/iaas/Content/General/Concepts/regions.htm), [presigned URLs](https://blogs.oracle.com/cloud-infrastructure/how-to-use-aws-s3-presigned-urls-with-oci-object-storage).
- **Scaleway:** older claims of 75 GB free _storage_ should not be reused: the current official price page offers 75 GB free _egress_, and the current storage trial is time-limited. [Current prices](https://www.scaleway.com/en/pricing/storage/), [trial terms](https://www.scaleway.com/en/docs/object-storage/faq/).
- **AWS:** older S3 FAQ text still describes 5 GB storage/12 months, while the current pricing page and dated free-tier announcement describe the July 2025 account-policy change. At this verification date, a pre-change account's initial 12-month period would already be over; do not advertise the old offer for new signups. [Current policy](https://aws.amazon.com/about-aws/whats-new/2025/07/aws-free-tier-credits-month-free-plan/), [current S3 pricing](https://aws.amazon.com/s3/pricing/).
- **Hetzner:** launch announcements show €4.99/US$5.99. The live product HTML calculator's `StartingPrice` and `Data.Price` now both return **EUR 6.49 / USD 7.99**; use current calculator values. Officially announced price adjustments took effect 2026-04-01. [Product](https://www.hetzner.com/storage/object-storage/), [price-adjustment statement](https://www.hetzner.com/pressroom/statement-price-adjustment/).
- **IDrive e2:** older mirrored official pages advertise US$4/TB; the canonical pricing page and current support FAQ agree on US$6/TB with a 1 TB minimum. The pricing page's 10 GB “Try” copy does not establish a permanent production entitlement, so it is excluded from the recurring-cost estimate. [Canonical prices](https://www.idrive.com/s3-storage-e2/pricing), [FAQ](https://support.idrive.com/s3-storage-e2/faq-pricing).

Among these providers, OCI is worth checking first if the project already operates an OCI tenancy with available quotas. Scaleway has a competitive low-volume pay-as-you-go rate but One Zone and European placement require an availability/latency decision. IDrive, Hetzner and Spaces have base bills disproportionate to a few gigabytes of replays. These are engineering judgments based on the cited limits, not claims of provider reliability.

Other screened options: [Wasabi](https://wasabi.com/pricing/faq) starts at US$7.99/TB-month with a 1 TB minimum bill and 90-day minimum retention for pay-as-you-go. [Storj Standard](https://storj.dev/dcs/pricing/simplified) lists US$7/TB-month storage, US$7/TB egress, a US$5 monthly minimum, 50 kB minimum object billing and 30-day minimum retention (documentation updated 2026-07-15; earlier announcements cited a different minimum). These minimums are unattractive for this small workload. [Bunny Storage's S3 support](https://bunny.net/blog/you-can-now-manage-bunny-storage-with-the-bunny-net-cli/) remains a public preview; it is not the primary production recommendation.

## Existing Oracle VPS: read-only SSH inspection

Inspected the existing `oracle-vps` SSH alias on 2026-10-08 at approximately 11:09–11:10 UTC. No production configuration, files, services or storage allocations were changed. Host addresses and credentials are deliberately omitted.

| Measurement                 | Observed value                                          |
| --------------------------- | ------------------------------------------------------- |
| Attached boot disk          | 200 GiB; no additional data disk appeared in `lsblk`    |
| Root filesystem capacity    | 196,318,593,024 bytes, approximately 196.3 GB           |
| Root filesystem used        | 128,438,550,528 bytes, approximately 128.4 GB; 66% used |
| Root filesystem available   | 67,880,042,496 bytes, approximately 67.9 GB / 63.2 GiB  |
| Root filesystem free inodes | 93,190,952; inode usage 3%                              |
| Aegis rollout logs          | Approximately 15.6 GB in `/opt/aegis-rollout/logs`      |

Evidence came from read-only `df`, `lsblk`, `findmnt`, `du` and Docker inspection over SSH. A separate `/var/oled` filesystem was excluded from the replay capacity estimate because it serves OS diagnostics. The running Aegis API mounts rollout routing read-only and logs writable; it currently has no persistent replay-data mount.

The available root disk can hold the estimated 8.31 GB inventory, or even the 30 GB conservative scenario, before filesystem overhead and future application growth. This is existing provisioned capacity, not an OCI Object Storage allowance. SSH disk inspection cannot establish whether the tenancy's disk allocation is free or paid.

A filesystem implementation could save the existing gzip bytes in a stable host directory such as `/opt/aegis-data/replays`, mounted into all API replicas and both deployment slots. Keep only ownership, match metadata and a storage key in the database. A new container or release must reuse this directory. This directory and mounts have **not** been created.

An initial **20 GB global replay quota**, combined with per-user limits and expiry, would leave approximately 48 GB of the currently available disk for other workloads. At 100 KB per replay, that global quota could become binding before every account reaches 100 files; do not promise 100 retained files unconditionally. Replays on this disk depend on the same host as the app, so a separate backup or managed object-storage destination provides recovery independent of the VPS.

Recommendation: the existing VPS is viable for a capped first version without provisioning more disk. B2 is the lowest-cost external shortlist option; R2 avoids download-volume charges and its request allowances suit many tiny files. The illustrative difference between B2 and R2 at 30 GB is about US$0.16/month, so operational simplicity and recovery matter more than that price difference. The research itself changed no storage backend. The later authorized implementation and VPS installation are recorded in [the account-replay design](../plans/2026-10-08-account-replays-vps-s3-design.md).
