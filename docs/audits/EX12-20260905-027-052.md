## Shared coordinator engine review

The coordinator diff was reviewed independently in `GameEngine.ts`,
`combat/controller.ts`, `effects/{EffectContext,builders,context,primitives}.ts`,
and `fortitudeOrdering.test.ts`. The current focused mechanism tests pass, including
the EX12-065 Q6866 ordering suite. The Fortitude change now captures eligibility before
movement, puts the keyword into the ordinary On Deletion trigger pool, and guards pending
effects whose deleted host has already been replayed or moved. The combat Scapegoat path
forwards the same snapshot fields through the GameEngine adapter.

No additional actionable correctness issue was reproducible in the reviewed diff. One
regression risk remains covered by the current tests: any future deletion path that moves
a Fortitude holder but fails to populate `fortitudeInstanceIds` will silently lose the
mandatory replay, so effect and combat deletion paths should continue to use the shared
snapshot payload. This is an implementation invariant rather than a current finding.
