# Card audits

One audit document per card collection. This directory is the only ledger; nothing else in the
repository claims to audit a set.

## Layout

```
docs/audits/
  README.md                 this file: rules, template, generated status index
  <SET>.md                  one per directory in apps/api/src/cards/ (except _a3)
  engine/                   cross-set engine audits, kebab-case file names
    dna-digivolve-into-filter.md
    intrinsic-evo-key-design.md
    vortex-timing.md
    engine-vs-dcgo-sequencing.md
```

## Rules

- Exactly one `docs/audits/<SET>.md` per directory under `apps/api/src/cards/`, excluding `_a3`
  (a test-only bucket). `apps/api/src/cards/audit-docs.test.ts` enforces this.
- `apps/api/src/cards/<SET>/AUDIT.md` does not exist. The card ledger lives in the docs file.
- Audits that cover engine seams rather than one set live in `docs/audits/engine/`.
- No logs, PNGs, or JSON in `docs/audits/`. Raw evidence stays in git history; the document records
  the commit SHA that produced it.
- Superseded reports are deleted, not archived. Each document's History section lists every removed
  file with the last commit that contained it.
- When reports disagree, the newest dated ledger wins and the document says so under Open items.
- `cards:` in the front matter is the number of `<SET>-*.ts` production modules in
  `apps/api/src/cards/<SET>/`, excluding tests.

## Per-set template

```markdown
---
set: BT20
cards: 102
status: verified | incomplete | blocked
verified_at: YYYY-MM-DD
catalog_commit: <sha or unknown>
evidence_commit: <sha of the last commit holding the raw evidence>
---

# BT20 audit

## Status

One paragraph. What is verified, what is not, and which source won when reports disagreed.

## Gates

Exact commands and results (collection suite, mechanism suites, catalog sync, typecheck, lint,
format, diff check) copied from the winning report, each with its source file.

## Card ledger

One `### <SET>-NNN — Name` section per card in ascending ID order. Keep contract, KB rulings,
implementation trace, proof test, clause scores, score, ambiguity, and commit when present.

## Mechanisms

Engine seams changed for this set, each as `### <name>` with an anchor tests can link to.

## Knowledge base index

Ruling IDs used by cards in this set.

## Open items

Cards below 10/10, ambiguities, deferred commands, and every contradiction between sources with the
file names and dates.

## History

One bullet per superseded file or directory: path, last commit SHA and date, one-line description.
Group per-card directories as one bullet with the file count.
```
