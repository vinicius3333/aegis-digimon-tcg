## Defect fixed

`digivolutionRequirement` compiled the printed `[ShineGreymon]` bracket as
`names: ["ShineGreymon"]`, the substring gate
(`matchingAlternateDigivolutionRequirement` in
`apps/api/src/engine/cards/cardData.ts` uses `name.includes(token)` for
`names`, `name === token` for `namesExact`). The catalog holds
"ShineGreymon: Ruin Mode" (EX4-074) and two other "ShineGreymon: Burst Mode"
prints, so the substring form wrongly opened the cost-4 route from those Lv7
bases. Changed to `namesExact: ["ShineGreymon"]`. This is the known set-wide
`[Name]` defect. **IR changed — `BT17-catalog-sync.test.ts` will be red until
the coordinator runs the set sync.**

## Engine seam closed

`it("gains only one Security Attack when a single yellow Tamer is available")`
— green; the assertion is unchanged.

- File: `apps/api/src/engine/effects/interpreter/costs.ts`, `canPayCost`,
  the `cost.kind === "suspend"` branch.
- Was: it returned `required > 0 && candidates.length >= required` and never
  read `cost.target.upTo`, unlike every neighbouring cost kind (`deleteOwn`,
  `trash`-from-security, `return`). With one legal yellow Tamer the "up to 2"
  cost was judged unpayable, so no decision was raised, nothing suspended and
  Security Attack stayed 0.
- Now: `if (cost.target?.upTo === true) return candidates.length > 0;` — the
  player chooses how many to suspend and `usePaidCount` scaling grants
  ＜Security Attack +1＞ for the one Tamer paid. Zero candidates stays
  unpayable (Comprehensive Rules 15-8-4-4-1, unperformable optional process),
  so "still attacks with no Security Attack bonus when no yellow Tamer can be
  suspended" still asserts no pending decision.
- Red-then-green: `Tests 1 failed | 11 passed (12)` before, `Tests 12 passed
  (12)` after. Full write-up:
  `docs/audits/BT17-reaudit/SUSPEND-UPTO-COST-MECHANISM.md`.

The IR was always correct; the gap was the engine's payability precheck.
