# BT17-036 Boutmon re-audit

Lane 42. Card-only. Module IR unchanged; only the test and this report were edited.

## Card summary (printed clauses)

Boutmon, Digimon, Lv5, Yellow/Green, DP 7000, play cost 7. EvoCosts Lv4 Yellow/Green
cost 4.

1. `[Digivolve]Lv.4 w/[Pulsemon] in its text: Cost 3` — alternate reduced route from any
   Lv4 whose text union holds "Pulsemon".
2. `[All Turns] [Once Per Turn]` When Boutmon would leave the battle area by an opponent's
   effect, trash the top security card to prevent it.
3. `[All Turns] [Once Per Turn]` When a card is trashed from your security stack by an
   effect, Boutmon with `[Leon Alexander]` in its digivolution cards may digivolve into a
   `[Pulsemon]`-text Digimon in hand without paying the cost.
4. Inherited `[End of Attack] [Once Per Turn]` If this Digimon has `[Pulsemon]` in its
   text, trash the top security card to unsuspend this Digimon.

Catalog carries U+00A0 before "in its text", "in its digivolution cards", "in the hand".

## Q&A ids covered

- Q2786 ("what does 'would leave the battle area' mean"): the answer enumerates trash,
  return to hand/deck, place in security, move to breeding, place under another card.
  Covered by the clause-2 behavioural tests, which exercise an effect-driven deletion
  (one such leave cause) and prove the prevention fires. The clause is modeled with
  `event: "wouldLeavePlay"` + `leaveCause: "byOpponentEffect"`, which is the single
  replacement hook every leave cause routes through, so the ruling is honoured for all
  listed causes; deletion is the representative case tested.

## Defects / retained red

None. No retained red remains in this file.

The former `it.fails` "should still unsuspend when Pulsemon is only on an underneath card
(whole-Digimon text)" was an authoring error, not an engine gap. `data/kb/rules/comprehensive.md`
§4-23-2 — "When an effect is gained, that doesn't mean that text is gained", with this exact
shape as its worked example — says a Digimon does not gain a digivolution card's text. So
"If this Digimon has [Pulsemon] in its text" reads the top card only, `selfTopMatchesText` in
`apps/api/src/engine/effects/interpreter/matching/permanent.ts` is correct, and Boutmon under a
non-Pulsemon top card is correctly gated off.

The test is now a plain `it` asserting the correct endpoint: with `BT1-009` (no Pulsemon text)
on top of Boutmon, the attacker is still suspended after the attack settles, security still holds
1 card, `state.pendingDecision` is undefined and `state.memory` is unchanged. The positive case
(Pulsemon `BT16-047` on top, unsuspend fires and security is spent) sits directly beside it.

The whole-stack reading was tried by the engine lane before the rule was found and made the gate
unconditional, breaking `BT17-034.test.ts:471`; it was reverted. Detail:
`WHOLE-DIGIMON-TEXT-MECHANISM.md`.

No local defects fixed (module IR was already correct).
