## Route-name (coordinator) decision — IR change

`[Digivolve][Koji Minamoto]: Cost 2` and `[Digivolve][Lobomon]: Cost 1` print no "in name", so
the module now declares `namesExact` (was `names`). **IR changed: yes.**

The requested near-name substring negative is **not constructible** from the real catalog:
- BT18-088 "Takuya Kanbara & Koji Minamoto" carries an exact `Koji Minamoto` alias
  (`STATIC_NAME_ALIASES_BY_CARD_ID`, and its `[Rule] Name: Also treated as [...]/[Koji Minamoto]`), so
  it legitimately takes the cost-2 route under both `names` and `namesExact` (it is the Q2762 base).
- Every "Lobomon"-containing card name equals `Lobomon`.

So the change is behaviourally inert on the current catalog but is the correct semantics.

Note: runtime legality (`digivolutionRequirementsFor` -> `effects.json`/overrides, in the read-only
`@aegis/shared` package) still uses the substring `names` gate; the proper runtime fix is an
`ALTERNATE_DIGIVOLUTION_OVERRIDES` entry (as done for BT18-101), which is out of this lane. Because
the distinction is inert here, no behaviour differs; the module declares the correct IR.
