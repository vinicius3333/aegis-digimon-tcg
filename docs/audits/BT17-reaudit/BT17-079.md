# BT17-079 Takuya Kanbara — re-audit

## Card

Tamer, Lv-, Red, play cost 3. Catalog `packages/shared/src/cards/data/cards.json`.

Printed clauses:

1. `[Security] Play this card without paying the cost.`
2. `[Start of Your Main Phase] If your opponent has a Digimon, gain 1 memory.`
3. Inherited `[Your Turn] This Digimon gets +2000 DP.`
4. Inherited `While this Digimon has 10000 DP or more, it gains ＜Piercing＞.`

Catalog note: the `[Security]` clause lives inside `effectText` for this card, while the
sibling BT17-080 carries it in a separate `securityEffectText` field. Reported, not edited.

## Q&A covered

- **Q2852** — <Piercing> keeps its second security check even if the checked card's
  `[Security]` effect drops the Digimon below 10000 DP after <Piercing> activated.
  Covered structurally only: the IR grants <Piercing> through an `Aura` whose `while`
  gate is `selfDpAtLeast: 10000`, which is the correct continuous spelling; the ruling is
  about the engine's <Piercing> activation window (a keyword already activated is not
  revoked mid-resolution), not about this card's IR. No card-level endpoint exists here,
  so no behavioural test was added for the ruling itself. The threshold either side of
  10000 is asserted behaviourally (see below).

## Defect fixed

`effects[1].actions[0].condition.filter` had no `zone`. An `opponentHas` counting filter
also counts the breeding area, so an opponent whose only Digimon was in breeding gave
memory. Comprehensive Rules §3-4-5-8 forbids referencing breeding-area card information.
Added `zone: "battleArea"`; the new breeding test is the witness.

**IR changed: yes.** `BT17-catalog-sync.test.ts` will be red until the coordinator runs
the set sync. `packages/shared/src/effects/effects.json` was not touched.
