## Q&A coverage

- **Q2806** ("up to 4" allows placing fewer): covered behaviourally — with only 2 Argomon in
  trash the effect places exactly 2 (stack length 2, DP 14000), proving `count:4, upTo:true`
  does not force 4. IR structural test also asserts `upTo:true`.
- **Q2807** (Lv.- Digimon cannot be chosen by the level budget): covered behaviourally — an
  opponent Lv.- Digimon (BT19-077 Calumon) survives while the eligible Lv.3 is deleted. Backed
  by the `hasLevel: true` filter on `DeleteLevelBudget`.
- **Q2808** (a source removed from trash before a triggered [On Deletion] resolves): documented
  as untestable in this lane. It requires a specific BT17-048 [On Deletion] → play-BT17-051 →
  BT17-051 [On Play] removing the [Argomon] from trash mid-chain, i.e. cross-card trigger
  ordering that this single-card fixture cannot stage without the coordinator range harness.
  The relevant guard (a card leaving trash before its [On Deletion] activates) is a general
  engine timing rule, not BT17-051 behaviour.

## Defects fixed locally

- **Route name gate was substring (`names`), must be exact (`namesExact`).** The printed route
  `[Digivolve]Lv.5 [Argomon]: Cost 4` uses a bracketed name with no "in name", so per the
  coordinator route-name decision it must be `namesExact`. Changed `names:["Argomon"]` →
  `namesExact:["Argomon"]` in `BT17-051.ts`. **This is an IR change.**
  - Note: the substring-vs-exact distinction is **unobservable in-game** here. No Lv.5 Digimon
    exists whose name contains "argomon" but is not exactly "Argomon" (all `*argomon*` cards are
    literally "Argomon"; the near-name "Gargomon" exists only at Lv.3/Lv.4). A near-name
    substring negative at Lv.5 is therefore impossible; the route negative instead uses a
    non-Argomon Lv.5 source (BT1-076 MegaKabuterimon) that falls back to the catalog cost-5
    route (memory 10→5 vs the 10→6 the cost-4 alternate would give).
