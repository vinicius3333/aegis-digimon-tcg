## Defects fixed locally (IR changed — yes)

1. **Name references were substring, not exact.** Both refs compiled as `match: "name"`, which
   is `includes()` (`engine/effects/interpreter/matching/definition.ts:349`). The printed text
   carries no "in name"/"in its name" wording, so per the coordinator's naming rule these are
   exact names. Under the old IR a Gargomon satisfied `[Argomon]` (`"gargomon".includes("argomon")`)
   and a yellow ClearAgumon satisfied `[Agumon]`, both wrongly granting ＜Draw 1＞. Now
   `match: "nameExact"`, with two near-name negatives in the test.
2. **The second condition branch was dead.** The IR expressed the printed OR as
   `filter.orFilters`, but `youHave` counts through `countMatching` →
   `permanentMatchesFilter` (`engine/effects/interpreter/matching/permanent.ts`), which never
   reads `filter.orFilters`. A yellow Agumon alone therefore never drew. Rewritten card-side as
   the `anyOf` condition combinator (`conditions.ts:759`), which is supported; no engine edit.
   This is an engine seam left in place and documented in the module comment: `youHave`/
   `opponentHas` silently ignore `filter.orFilters`.

## Remaining gaps

- The `you may` on clause 1 is asserted structurally (`optional: true`) but not behaviourally
  declined. `autoDeclineOptional` is a whole-run flag and would also decline the KoDokugumon
  `[On Play]` that produces the suspension, making the assertion vacuous; a per-decision
  decline would need a manual `respondDecision` sequence that the harness does not expose per
  effect key.
- `sourceFilter` is `kind: ["Digimon"]`, so an effect suspending an own *Tamer* correctly does
  not trigger — not covered by a dedicated test.

## Catalog discrepancies

The catalog effect text reads `a yellow Digimon with [Agumon]/[Greymon]` with no "in its name"
tail. digimoncard.io renders the same wording (`with [Agumon] or [Greymon]`), so the catalog is
consistent with the public listing; the slash-vs-"or" separator differs. Not edited.
