## Defect found and fixed (IR change)

**On Play name gate was substring, must be exact.** The module compiled
`[Marcus Damon]` as `nameOrTrait: [{ tokens: ["Marcus Damon"], match: "name" }]`
(substring). Comprehensive rule 2-3-1-2 (which uses `[Marcus Damon]` as its own
worked example) and 2-3-1-3 make a bracket-only `[X]` an **exact** name match and
reserve substring for "with `[X]` in its name". KB Q6101 confirms AD1-021
"Marcus Damon & Agumon" only carries `[Agumon]` as a substring and is not treated
specially. Under the old substring mode the On Play would wrongly select the
combined-name cards AD1-021 "Marcus Damon & Agumon" (not in the CardNames alias
table `packages/shared/src/cards/effectiveNames.ts`).

Fix: `match: "name"` -> `match: "nameExact"` on the On Play `SelectBind` filter only.
The `[Agumon]`/`[Greymon]` memory condition is genuinely "in its name" (2-3-1-3) and
correctly keeps `match: "name"` (substring), verified against `matchNameOrTrait`
(`apps/api/src/engine/effects/interpreter/matching/definition.ts`).

Result after fix (proven in `matchNameOrTrait` test): BT17-087 and ST24-13
("Marcus Damon & Thomas H. Norstein", aliased to "Marcus Damon" in the CardNames
table) both accepted; AD1-021 refused by `nameExact`, accepted by `name` — the
near-name negative required by the brief.

**IR changed: YES.** `effects.json` still holds the old `match: "name"`, so
`BT17-catalog-sync.test.ts` (coordinator-owned) goes red until the coordinator runs
the BT17 set sync. Not touched here per brief.
