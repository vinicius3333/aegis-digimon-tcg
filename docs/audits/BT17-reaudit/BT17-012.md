# BT17-012 BurningGreymon re-audit

## Card summary

Digimon, Lv4, Red/Purple, DP 6000, play cost 6, [Hybrid], type Dark Dragon.

Printed clauses:

1. `[Digivolve][Takuya Kanbara]: Cost 2` — alternate route from a Tamer base.
2. `[Digivolve][Agunimon]: Cost 1` — alternate route from a Lv4 Digimon base.
3. "You may digivolve this card from your hand onto one of your red Tamers as if
   that card is a level 3 red Digimon." — Tamer-onto generic path (level-3 cost).
4. `＜Raid＞` keyword.
5. `[When Attacking]` optional digivolve into a `[Hybrid]`-trait Digimon in hand,
   digivolution cost reduced by 1.
6. Inherited `[Your Turn] +2000 DP`.

## IR change

Yes. The two named digivolution routes were `names` (substring) and are now
`namesExact` (exact), per the coordinator route-name decision: printed
`[Digivolve][X]: Cost N` with no "in name" must be exact. A near-name substring
negative is included (Kokatorimon, a red Lv4 Digimon that is not Agunimon, is
refused on that route in the same fixture). This makes `BT17-catalog-sync.test.ts`
go red until the coordinator runs the set sync; effects.json was not touched.

## Defects fixed locally

The pre-existing test asserted only shallow `toMatchObject` shape and used a
non-red inherited-DP toggle by hand. Rewrote to behavioural endpoints: memory
deltas per route, stack identity, bonus draw, summoning sickness, requirement
negatives, and the inherited grant gated on turn. Corrected the two routes to
`namesExact`.
