# BT17-034 Bulkmon — re-audit (lane 10)

## Card

Digimon, Lv4, Yellow/Green, play cost 5, DP 5000, Vaccine, Dragonkin / Abadin
Electronics. EvoCosts: Yellow Lv3 cost 3, Green Lv3 cost 3.

Printed clauses:

1. `[Digivolve][Pulsemon]: Cost 2` — alternate digivolution route.
2. `[When Digivolving]` If you have 3 or more security cards, 1 of your
   opponent's Digimon gets -3000 DP for the turn.
3. `[When Digivolving]` If you have 3 or fewer security cards, suspend 1 of your
   opponent's Digimon.
4. `[All Turns] [Once Per Turn]` When a card is trashed from your security stack,
   if `[Leon Alexander]` is in this Digimon's digivolution cards,
   `＜Recovery +1 (Deck)＞`.
5. Inherited `[All Turns]` While this Digimon has `[Pulsemon]` in its text, it
   gets +1000 DP.

## Q&A covered

- **Q2784** — at exactly 3 security cards both the -3000 DP clause and the
  suspend clause activate. Covered by "fires both branches at exactly 3 security
  cards, per Q2784", plus the 4-security and 2-security single-branch tests that
  fence the boundary on both sides.

## Defects found and fixed locally

1. **Clause 1 was entirely unimplemented.** The module carried no
   `digivolutionRequirement`, and neither `ALTERNATE_DIGIVOLUTION_OVERRIDES` nor
   `generated-digivolve-overrides.json` names BT17-034, so
   `digivolutionRequirementsFor("BT17-034")` returned `undefined`: the printed
   `[Digivolve][Pulsemon]: Cost 2` route did not exist. Added
   `digivolutionRequirement: [{ names: ["Pulsemon"], cost: 2, isAlternate: true }]`.
2. **Set-wide `[Name]` defect.** `[Leon Alexander]` is a printed exact name
   reference but compiled as `match: "name"` (substring). Changed to
   `match: "nameExact"`, matching BT17-030's encoding of the same Tamer.
3. **Clauses 2 and 3 shared one action list.** With both clauses in a single
   `WhenDigivolving` effect, the suspend clause never fired when the DP clause's
   condition failed. Split into two independent `WhenDigivolving` effects — which
   is also the correct reading of two independent printed conditions (Q2784).
   Verified behaviourally: with 2 security cards the suspend now lands.
4. The suspend gate used `{ kind: "zoneCount", seat: "mine", zone: "security",
   op: "lte", value: 3 }`; replaced with the canonical mirror of the DP gate,
   `{ kind: "securityAtMost", value: 3 }`.

Fixture hygiene: the previous test put Digi-Egg `BT1-001` in security and deck.
All fixtures now use inert main-deck Digimon (`BT1-012`, `BT1-013`); no numeric
`security: <n>` form is used.

## Remaining gaps

- **Once-per-turn reset across a turn boundary is not covered.** Same-turn
  refusal is proven. The reset is not reachable through the current harness:
  `advance(engine).runTurn(seat)` (apps/api/src/engine/testkit/advance.ts,
  `runTurn` / `waitForMainPhase`) leaves the engine at `Phase.End` with
  `state.turnSeat` unchanged, and a second `runTurn` throws "Main phase did not
  become ready ... End". Setting `state.turnSeat` by hand does not clear
  `Phase.End`, so the start-of-turn subtrigger-ledger reset
  (`GameEngine.subTriggerTurnLedger` / `tracker.unregister`) is never reached
  from a test that has already acted inside the current turn. No card assertion
  was weakened; the gap is a testkit seam, not a card defect.
- Only the `deck` source of `＜Recovery +1 (Deck)＞` is asserted; no test proves a
  Recovery would be refused with an empty deck.
