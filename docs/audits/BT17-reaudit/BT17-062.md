## Defect found and fixed

The compiled IR used `match: "name"` (substring) for both printed exact
references, `[Kosuke Kisakata]` and `[Dorugoramon]`. This is the known set-wide
defect. Consequence for this card was real, not cosmetic: `Dorugoramon` as a
substring also matches **DexDorugoramon** (BT17-073, BT9-081), an illegal target
for a printed `[Dorugoramon]` reference. The previous behavioural test actually
digivolved into BT17-073 and passed, i.e. it asserted the wrong rule.

Fix: both tokens now compile as `match: "nameExact"`. The behavioural test uses a
real Dorugoramon (BT7-065) and a new negative proves DexDorugoramon is refused.

IR changed: **yes** — `BT17-catalog-sync.test.ts` will be red until the
coordinator runs the set sync. `effects.json` was not touched.
