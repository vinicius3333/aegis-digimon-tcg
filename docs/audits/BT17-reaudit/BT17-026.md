## Defects fixed locally (IR changed — see catalog-sync note)

1. **Missing combat-suspend block.** `effects[1]` Restrict had `restriction: "suspend"`
   without `blocksCombatSuspend: true`. The interpreter
   (`apps/api/src/engine/effects/interpreter/actions/restrictions.ts`) maps
   `"suspend"` -> `"beSuspended"` (can't be suspended by effects; combat self-suspend
   exempt) and only also records the combat `"suspend"` restriction when
   `blocksCombatSuspend` is set. The printed "can't suspend until the end of their
   turn" must also stop the Digimon from suspending to attack (KB comprehensive §4-23
   example + attack rule 11-2-1: attacking suspends the attacker). Added
   `blocksCombatSuspend: true`. Precedent: BT26-019, EX11-017 author identical
   "can't suspend until turn ends" wording with the flag.
   - Peer inconsistency (not my file): **EX7-022** prints the exact same sentence
     ("1 of your opponent's Digimon or Tamers can't suspend until the end of their
     turn") but is authored WITHOUT `blocksCombatSuspend` and its test asserts only
     the weaker `beSuspended` behaviour. EX7-022 carries the same latent
     under-authoring; coordinator should reconcile the two.

2. **Wrong host ref on the return cost.** The `[When Digivolving]` cost targeted
   `hostFilter: { sourceRef: "triggerSubject" }`. The printed text says "this
   Digimon's digivolution cards" — self-referential — so the host is the source, not
   the trigger subject. On this Main-effect-driven digivolve
   `ctx.trigger.subjectPermanentId` is unset, so `triggerSubject` resolved to
   `undefined`, `candidateLooseInstances` found no host, `canPayCost`
   (`costs.ts`, return/digivolutionCards branch) returned false, and `runAction.ts`
   silently skipped the optional and aborted the whole `[When Digivolving]` effect
   (no return, no restriction). Changed to `hostFilter: { isSelfRef: true }`, matching
   the many EX12/BT3-112 self-referential digivolution-card costs. `triggerSubject`
   is correct only when the subject is a different permanent (e.g. BT18-092
   "that Digimon's digivolution cards" on an attack trigger), which is why that peer
   works and BT17-026 did not.
