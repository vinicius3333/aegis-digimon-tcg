## Defects fixed locally

- Set-wide `nameExact` defect present. `[Infermon]` is a printed exact name
  reference but both `Digivolve.into.nameOrTrait` entries compiled as
  `match: "name"` (substring). Changed to `match: "nameExact"` in both
  sub-triggers. IR changed -> `BT17-catalog-sync.test.ts` will be red until the
  coordinator runs the set sync.

## Test gaps closed

- The digivolve half of clause 1 had only a structural assertion. Added a real
  behavioural case: opponent digivolves BT17-054 into BT17-056 (Lv5) on their
  turn; Keramon free-digivolves into Infermon, `Permanent.stack` is exactly
  `[Keramon]`, Infermon leaves hand, memory moves only by the opponent's own
  cost (5 -> 2), no pending decision.
- The [Unidentified] gate had no negative. Added a deletion case with a
  non-Unidentified top card (BT17-054, [Machine]) where no token appears.
- The existing token test now asserts the token's identity and that the board
  holds exactly the token.

## Remaining gaps

- Fixtures set `s.state.memory` directly rather than reaching the state through a
  full turn loop; acceptable per the harness style, but the "played" test still
  asserts a clamped memory value (10) rather than a delta.
- No case where Keramon's controller declines the optional digivolve
  (`autoAcceptOptional` is on in every behavioural fixture).
