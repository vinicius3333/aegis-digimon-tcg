# BT17-083 Koji Minamoto — re-audit

## Card summary

Blue Tamer, Lv-, play cost 4.

Printed clauses:

1. `[Security]` Play this card without paying the cost.
2. `[Start of Your Turn]` If you have 2 memory or less, set your memory to 3.
3. Inherited: `[Your Turn] [Once Per Turn]` When an effect adds cards to your hand,
   gain 1 memory. Then, this Digimon gains ＜Jamming＞ for the turn.

## Q&A covered

- **Q2861** — the inherited effect activates even when a single effect trashes the
  same number of cards it added (net-zero hand change). Covered by "fires for a
  Tamer effect whose net hand size is unchanged, once per turn only (Q2861)",
  which plays BT7-091 Koichi Kimura (`[On Play] ＜Draw 1＞. Then, trash 1 card in
  your hand.`) and asserts memory +1 and ＜Jamming＞ on the host.
- **Q2862** — the effect does **not** activate on the digivolution-bonus hand
  increase. Covered by the existing "does not trigger from the digivolution bonus
  hand addition" test: a real `digivolve` intent draws the bonus card, memory shows
  no watcher gain and the host has no ＜Jamming＞.

## Defect found and fixed: over-narrowed inherited watcher

`BT17-083.ts` carried

```ts
fireCondition: {
  kind: "triggerByYourDigimonEffect",
  raw: "one of your Digimon's effects adds cards to your hand",
},
```

The `raw` string is not this card's printed text. It is BT15-083's
("When **one of your Digimon's effects** adds cards to your hand"), and the gate
was copied with it. BT17-083 prints "When **an effect** adds cards to your hand",
the same wording as BT9-002, which compiles the same `whenEffectAddsToHand`
SubTrigger with **no** `fireCondition`. The engine agrees: the
`effectAddsToHandGate` comment in
`apps/api/src/engine/effects/interpreter/actions/subTrigger.ts:551` names
BT9-002 / BT15-083 / BT17-083 as the "an effect adds cards to YOUR hand" family and
notes the event already scopes the add to the watcher's own hand
(`effectAddedToHandSeat === source.ownerSeat`), so no extra gate is needed.

Effect of the bug: a Tamer's or Option's effect adding cards to your hand — the
Q2861 case among them, since the ruling says "an effect such as ＜Draw 1＞. Then,
trash 1" without restricting it to Digimon — silently failed to fire.

Fix: the `fireCondition` is removed and replaced with a comment naming the printed
wording and the BT15-002/BT15-083 contrast. **This changes the compiled IR**, so
`BT17-catalog-sync.test.ts` will be red until the coordinator runs the set sync.
`effects.json` was not touched.

Regression proof: the new test's first leg would not fire before the change
(verified — the watcher never granted ＜Jamming＞ with the gate in place).

## Clause → test → IR

| Clause | Test | IR |
| --- | --- | --- |
| 1 Security play without cost | "naturally plays itself from security without paying its cost" | `effects[0]` `trigger: "Security"`, `isSecurity: true`, `PlayWithoutCost` on self |
| 2 Start of Your Turn, memory ≤ 2 → set 3 | "sets memory to 3 at the natural start of your turn only from 2 or less" (both branches, through `advance().runTurn(0)`) | `effects[1]` `SetMemory value 3` with `condition memoryAtMost 2` |
| 3a inherited watcher fires on any effect hand-add | "naturally gains memory and grants its host Jamming when a Digimon effect draws"; "fires for a Tamer effect whose net hand size is unchanged, once per turn only (Q2861)"; "does not narrow the printed \"an effect\" wording to your Digimon's effects" | `effects[2]` `SubTrigger whenEffectAddsToHand`, no `fireCondition` |
| 3b gain 1 memory, then ＜Jamming＞ for the turn | same tests, asserting exact memory values and `hasKeyword(host, "Jamming")` | `GainMemory 1` + `GainKeyword Jamming duration "forTheTurn"` on `isSelfRef` |
| 3c `[Once Per Turn]` | "fires for a Tamer effect … once per turn only (Q2861)": second same-turn add grants no memory (7 → 4 on a 3-cost play), then the limit resets and the third play on the next own turn gains again | `effects[2].frequency: "OncePerTurn"` |
| 3d not the digivolution bonus | "does not trigger from the digivolution bonus hand addition" | Q2862; the bonus draw never routes through the `whenEffectAddsToHand` fire sites |

The once-per-turn reset runs through the real turn loop: opponent's turn via
`advance().runTurn(1)`, then this seat's own turn via `engine.runOneTurn()` +
`waitForMainPhase(0)` + `endMainPhaseIfOpen(0)`. No injected timing is used for
any behavioural claim. `observeStartTurn` wraps `fireTiming` but calls through to
the production implementation and only records memory — it observes, it does not
fire.
