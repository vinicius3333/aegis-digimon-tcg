## Q&A coverage (Q2778, Q2779, Q2780, Q2781, Q5453)

The last four all turn on one engine rule: the `whenOptionUsed` watcher gates on
`usedOptionCost`, which is the card-level use cost after card-level changes but
before payment-only reductions (`conditions.ts:858` `triggerOptionCostAtLeast`;
`primitives.ts:3035` `notifiedUseCost = projectedHandUseCost = effectiveLooseUseCost`).

- Q2778 (timing: activates after the used Option's [Main] effect) — covered
  behaviourally: the real-Option tests resolve BT1-102's [Main] (draw) first and
  the grant lands afterward through the production `useOptionFromHand` seam.
- Q2779 (Option effect activated by [Security]/<Delay> does not count as "use")
  — covered by architecture: `fireOptionUsed` is reached only from the
  option-use path (`primitives.ts:2939`, `actions/playCard.ts:163`), never from
  security or delay activation. Not re-tested per-card; a security-check-into-
  activation fixture is disproportionate and the seam is engine-owned.
- Q2780 (use cost itself reduced to <=1, e.g. BT2-099/BT8-097 -> does not
  trigger) and Q2781 (only the cost to pay reduced, use cost still 2+ ->
  triggers) — covered at the engine layer: distinguished by the same
  `effectiveLooseUseCost` snapshot that excludes payment-only reductions, with a
  dedicated engine test `actions/playCard.test.ts:317` ("reports the card-level
  adjusted use cost to whenOptionUsed", BT10-032 Q1956/Q1957). Re-testing per
  card would require the specific cost-modifier cards; not warranted.
- Q5453 (used without paying the cost, original use cost 2+ -> triggers) —
  covered at the engine layer: the 08-06 use-option-without-paying seam still
  fires `whenOptionUsed` carrying the original use cost (`primitives.ts:2939`).
