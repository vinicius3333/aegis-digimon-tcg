# EX12-001–026 audit revalidation (2026-09-05)

This report revalidates EX12-001 through EX12-026 against the committed card catalog,
the local rules knowledge base, the direct compiled IR modules, and the colocated
behavioral suites. The earlier EX12 ledger was treated as a claim to verify, not as
evidence.

## Evidence and method

- Catalog source: `packages/shared/src/cards/data/cards.json`, including colors, kinds,
  levels, costs, evolution requirements, traits, effect text, inherited text, and rules.
- Rules source: `node tools/kb/query.mjs card EX12-001` through `EX12-026`. Q&A IDs are
  recorded per row below where present; cards without a local entry were checked against
  the printed catalog text and the neighboring implementation patterns.
- Implementation source: [`apps/api/src/cards/EX12/EX12-001.ts`](../../apps/api/src/cards/EX12/EX12-001.ts)
  through [`EX12-026.ts`](../../apps/api/src/cards/EX12/EX12-026.ts). Every module uses one
  `registerIrCard` call, `coverage: "full"`, and an empty `residual` array; no legacy
  `registerCard` call or `RawUnparsed` node was found.
- Behavioral evidence: each focused suite was run in a separate process with one worker:
  `pnpm --filter @aegis/api exec vitest run src/cards/EX12/EX12-NNN.test.ts --maxWorkers 1`.
  All 26 suites passed, totaling 264 tests, including the EX12-019 immunity regression and
  a real friendly Digimon effect from BT16-042.
- Aggregate synchronization: the coordinator regenerated the committed
  `packages/shared/src/effects/effects.json` record for EX12-019, including
  `byOpponentEffectsOnly: true`; the catalog-sync suite passed against the synchronized
  record.

The five scores are contract/rules, IR trace, behavioral proof, peer/stack proof, and
delivery gates. A score below 10 identifies a current repository state that still needs
an integration step, even when the direct card module is correct.

## Follow-up

The only card-specific correction in this range is EX12-019: `byOpponentEffectsOnly: true`
was added to the Digimon-source `beAffected` restriction, and the focused suite now proves
that a real own Digimon-sourced DP effect applies while an opponent Digimon-sourced effect is
blocked and an Option effect remains applicable. Mutation testing shows that removing this
field does not change those observables because the shared permanent/source-kind gate already
permits own effects and limits the restriction to opponent Digimon sources; the field remains
the explicit IR representation of the printed opponent-only clause. The coordinator
synchronized the aggregate effects record, and the collection catalog-sync proof now covers
the same restriction shape.
