# BT23-034 Sakuyamon re-audit

Sources: committed catalog `BT23-034`; KB Q5282-Q5286 and Q5289-Q5292.

## Card summary

Yellow level 6 Digimon, play cost 11, DP 11000, Mega, Data, traits Shaman/Zaxon/CS.
Printed evolution: yellow Lv.5 for 3, plus the alternate `[Digivolve] Lv.5 w/[CS] trait: Cost 3`.

Printed clauses:

1. `When this card would be played, if you have a Tamer with the [Zaxon] trait, reduce the play cost by 5.`
2. `[On Play] [When Digivolving] [When Attacking] [Once Per Turn] Until your opponent's turn ends, 1 of their Digimon can't activate [When Digivolving] effects and gets -6000 DP.`
3. `[On Deletion] Place this card face up as the bottom security card.`

The catalog text matches the official card list. No discrepancy to report.

## Behavioral evidence

All behavioral tests drive public intents (`playCard`, `digivolve`, `attack`, `endPhase`, `surrender`)
through `startTurnLoop()`. No injected timing API is used anywhere in this file.

**Clause 1.** With BT23-086 Yuugo (Zaxon Tamer) on the board, playing Sakuyamon from memory 10
leaves memory 4 (cost 6). The exact hand instance leaves the hand and becomes a battle-area top
card, and the single opposing Digimon ends at 4000 DP with the restriction on. Without a Zaxon
Tamer the same play leaves memory -1 (cost 11).

**Clause 2, Q5282/Q5283/Q5286.** Seat 0 plays Sakuyamon and restricts the only opposing Digimon
(BT2-037 Angewomon, 10000 -> 4000). After a real turn pass, seat 1 digivolves that same permanent
into ST24-07 ShineGreymon, whose `[When Digivolving] [When Attacking] [Once Per Turn]` effect would
play a Tamer and apply -9000 DP. Nothing happens: the ST3-12 Tamer instance is still in seat 1's
hand and Sakuyamon is still at 11000 (Q5282). Seat 1 then attacks in the same turn; the same shared
effect activates on the `[When Attacking]` timing, moving that exact Tamer instance from hand to
battle area and dropping Sakuyamon to 2000 (Q5283 and Q5286 — the blocked timing did not consume
the once-per-turn use).

**Q5284.** Paired test against EX6-043 Diaboromon, whose `[All Turns] [Once Per Turn] When an
opponent's Digimon is played, you may activate 1 of this Digimon's [When Digivolving] effects`
would otherwise play a Diaboromon Token. With Sakuyamon's restriction on Diaboromon, two opponent
Digimon plays produce zero extra permanents in seat 1's battle area. The unrestricted control
produces at least one.

**Q5285.** Paired test against BT23-045 TigerVespamon's mandatory `[On Play] [When Digivolving] By
placing 1 [Royal Base] or [Zaxon] trait Digimon card ... face up as the bottom security card,
return 1 of your opponent's Digimon ...`. Restricted, the BT18-044 source stays in seat 1's hand,
seat 1's security stack is byte-identical to the pre-digivolve instance list, and seat 0's Digimon
stays on the board — the `by` cost is not processed at all. The control places that exact instance
face up at the bottom of security and returns seat 0's Digimon to hand.

**Q5289.** Sakuyamon attacks in seat 0's Main (which suspends it and weakens the future attacker
from 18000 to 12000), then seat 1 attacks the suspended Sakuyamon and wins the battle. Seat 0's
security stack becomes exactly `[existing face-down card, Sakuyamon]`, with the pre-existing card
still `faceUp: false`, the Sakuyamon instance last and `faceUp: true`, and Sakuyamon not in trash.

**Q5290.** With that same state as the fixture (BT23-034 face up as the only security card), a
3000-DP attacker attacks the player. The check runs normally: the face-up card fights as a
Security Digimon, the attacker's exact instance ends in seat 1's trash, the security stack is
empty, and the checked card's exact instance ends in seat 0's trash. Being trashed after a won
security battle is not a deletion, so the `[On Deletion]` clause does not re-place it.

**Q5291.** BT21-041 Calendamon (`[Security] At the end of the battle, play this card without paying
the cost`) sits face up as the only security card. A 3000-DP attack on the player checks it; the
`[Security]` effect still activates and that exact instance ends in seat 0's battle area.

**Q5292.** Seat 0's security holds two face-up cards and one face-down card. Playing EX3-029
Airdramon runs its `[On Play] ... Then, shuffle your security stack`. Afterwards every remaining
security card is `faceUp: false`.

**Duration.** The restriction and the -6000 are both observable through the whole opponent turn and
both gone at the start of seat 0's next Main (target back to 10000).

## Fixture notes

Two tests (Q5290, Q5291) seed a face-up security card directly. That is the exact state the Q5289
test proves BT23-034's `[On Deletion]` produces; no card in the pool places a Zaxon or Royal Base
Digimon carrying a triggered `[Security]` effect face up, so there is no shorter public route to a
face-up card with a `[Security]` effect. All security fixtures use real main-deck Digimon; no
Digi-Egg is placed in security or deck.
