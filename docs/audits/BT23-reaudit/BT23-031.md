- Play with own [LadyDevimon] (BT23-067) on the field: memory 10 -> 6 (cost 4), Angewomon on the battle area, no pending decision.
- Play with own [Mirei Mikagura] (BT22-089) Tamer: memory 10 -> 6.
- No qualifier: memory 10 -> 3 (full cost 7).
- Controls, all full cost: "LadyDevimon (X Antibody)" (EX7-058) on the field, a LadyDevimon in hand, a LadyDevimon in trash, and the opponent's LadyDevimon.
- Security clause at 4: the physical top instance (BT23-100, which carries a `[Security]` effect) moves to hand and is the only hand card; the deck's top instance becomes security index 0, face down; security back to 4; the moved card's `[Security]` effect does not fire (no extra permanent on the board, card not trashed).
- Security clause at 5: ends at 4, deck untouched, top instance in hand.
- Security clause at 0 (Q5276): hand stays empty, security becomes 1 with the deck's top card, face down.

## Defect found and fixed

`BT23-031.ts` gated the reduction with `match: "name"`, which is substring matching in
`matchNameOrTrait` (`apps/api/src/engine/effects/interpreter/matching/definition.ts`). The printed
reference is bracket-only, so comprehensive §2-3-1-2 requires an exact name. With the old IR,
"LadyDevimon (X Antibody)" (EX7-058) wrongly enabled the -3.

Fix: `match: "nameExact"` in `apps/api/src/cards/BT23/BT23-031.ts`. Confirmed as a real defect by
reverting the token and rerunning the near-name test, which then failed (memory 6 instead of 3).

## Remaining gap (engine, not fixed here)

The printed clause says "would be played **from the hand**". The IR carries no origin-zone
condition, and the pay-time path does not add one: `GameEngine.fireBeforePayCost`
(`apps/api/src/engine/GameEngine.ts:4096`) receives `originZone` but only forwards it to interactive
sub-trigger reductions — `wouldBePlayedSelfReducersFor` reductions are applied for any origin. The
`WouldBePlayedSelfReducer` shape (`engine/effects/interpreter/registration/reducers.ts:25`) has no
zone field, so this cannot be fixed inside the card module.

No retained red test is attached, because the gap is currently unreachable: every catalog effect that
plays a Digimon from the trash does so "without paying the cost", and the paid effect-play path
(`finalizeEffectPlayCost`) is only reached from hand for Digimon. The defect is latent, not live.
Recommended engine work: carry `originZone` into the self-reducer evaluation and add an
`originZone: "hand"` gate to reducers compiled from "would be played from the hand" text.
