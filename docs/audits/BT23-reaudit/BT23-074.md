# BT23-074 Eater Legion re-audit

## Card summary

Sources: committed catalog `BT23-074`; official BT23 card list (`logs/official-bt23.html`, entry BT23-074); KB Q5351, Q6703, Q6704, Q6705, Q6706, Q6707.

White Digimon, play cost 8, DP 8000, no printed EvoCost, form Eater, attribute `-`, types Hudie/CS. No lower text.

Printed clauses:

1. `[Digivolve] [Erika Mishima]: Cost 3` — the only digivolution route the card prints.
2. `＜Alliance＞`
3. `＜Reboot＞`
4. `[On Play] [When Digivolving] If you have [Mother Eater] in the breeding area, you may play up to 6 play cost's total worth of Digimon cards with the [Eater] trait from your hand without paying the costs.`

The catalog text matches the official list exactly. No discrepancy.

## Defect found and fixed

`BT23-074.ts` declared the route as `names: ["Erika Mishima"]`. `names` is the SUBSTRING gate
(`apps/api/src/engine/cards/cardData.ts`, "Name gate: base name must contain at least one token").
A bracketed `[Name]: Cost N` route is an EXACT identity, so the field must be `namesExact`.
The base is also a Tamer, not a Digimon (KB Q6703), which the requirement type expresses as
`baseIsTamer: true`. Both were added.

Honest limit on the proof: the fix is provable structurally, not behaviorally, because the
catalog holds exactly one card whose name contains "Erika Mishima" (`BT23-084`, a Tamer).
No near-name superstring and no non-Tamer card of that name exist, so substring and exact
matching pick the same single base today. The red-then-green check therefore fails only the
IR assertion (verified: reverting to `names` fails 1 of 11 tests, the record test). The fix
still matters — any future card named e.g. "Erika Mishima (X)" would wrongly satisfy `names`.

The module's `// @ts-nocheck` was removed; it typechecks without it.

## Additional behavioral endpoints

- Budget arithmetic: with three cost-3 Eater Bits offered, exactly two are played (3+3 = 6)
  and the third stays in hand. Memory moves 5 -> 2, proving the digivolve cost of 3 was the
  only payment and the plays were free.
- Budget floor: a lone cost-8 `BT22-082` Eater Adam is never played; it stays in hand and the
  board keeps a single permanent.
- Condition gate: with no `[Mother Eater]` in breeding, all three Eater Bits stay in hand.
- Refusal branch: with the auto-responder off, the `selectCards` request is inspected
  (`min: 0`, three candidates) and answered with an empty selection; nothing is played and
  memory is unchanged at 2.
- Illegal sources: `BT23-073` (Eater Digimon), `BT23-101` (Hudiemon), `BT23-083` are all
  refused with `invalid-evolution`, the card stays in hand, and memory is untouched. The card
  prints no EvoCost, so the Erika route is the only legal source.

Fixtures are legal: security holds real main-deck Digimon (`BT1-009`/`BT1-010`), the Digi-Egg
`BT22-007` sits in the breeding area, and Erika reaches the field either as a seeded permanent
or through the public `playCard` intent.
