### What the behavioral tests prove

- **Blocker + deletion chain.** The opponent attacks the player; `blockWindowOpened` lists Craniamon as the only eligible blocker; a public `declareBlock` keeps security at 3, kills the 5000 DP attacker, and the block suspension deletes the cost-2 Digimon while the cost-6 Digimon survives. Endpoints asserted: security length, surviving permanent ids, `isSuspended`, and exact trash card ids.
- **Lowest-play-cost set and zone.** Craniamon attacks the player. Both cost-3 opposing Digimon are deleted, the cost-6 and cost-13 survive, and the opponent's cost-2 breeding Digimon is untouched — which also proves the deletion pool is the battle area only, since a leak into the raising area would have made the breeder the sole lowest and spared the pair. Trash is checked by instance id, not card id, because the security check puts a card in trash too.
- **Once per turn.** Through `startTurnLoop()` and public `endPhase`: the first attack deletes the cost-2 Digimon; an explicit unsuspend and a second attack in the same turn delete nothing (the surviving battle-area set is asserted, not merely awaited); on the next own turn Craniamon is already unsuspended by the Active phase and the third attack deletes the now-lowest cost-3 Digimon.
- **Reboot.** Through the same public turn loop: Craniamon is re-suspended after the own Active phase, and the opponent's Active phase unsuspends it.
- **Leave-play replacement.** An opponent-seat effect deletion is prevented, Craniamon ends suspended, and that suspension chains into the lowest-cost deletion. Negative controls: an own-effect deletion is not prevented and Craniamon stays unsuspended; the declined branch (`autoDeclineOptional`) lets the ally die; an already-suspended Craniamon cannot pay the cost; two threatened allies yield exactly one survivor.
- **Digivolution.** The alternate `Lv.5 w/[CS]` route from off-color BT23-044 with `useAlternateCost: true` moves memory by exactly 3, keeps the base permanent id, puts the exact BT23-058 instance on top with the base instance beneath, and draws the exact top deck card. The printed Black level-5 route (BT2-060) is the control at the same cost. Negatives: BT1-039 (level 5, no CS) and BT22-031 (CS, level 4) both return `invalid-evolution` with memory and hand untouched.

### Mutation checks

To confirm the suite is not vacuous, the module was temporarily mutated and reverted:

| Mutation | Tests turned red |
|---|---|
| drop `leaveCause: "byOpponentEffect"` and flip `lowestPlayCost` -> `highestPlayCost` | 6 |
| drop `frequency: "OncePerTurn"` and set the replacement `count` to 2 | 2 |

The `count` change alone turned no behavioral test red: the engine's leave-prevention path saves one permanent per event regardless of that field, so the printed "1 of those" is proven by behavior but the IR `count` value itself is only proven by the shape test. This is an observation about the engine seam (`apps/api/src/engine/effects/leavePrevention.ts`), not a defect of this card — the observable result matches the printed text.
