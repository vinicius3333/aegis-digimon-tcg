## Rulings covered

`node tools/kb/query.mjs card BT23-091` lists one Q&A.

| Id | Question | How it is covered |
|---|---|---|
| Q5364 | What does "while you have (the specified card) on the field" mean? Answer: battle area or breeding area. | Covered, with an override. Comprehensive Rules §3-4-5-8 says information on breeding-area cards cannot be referenced unless the effect names the breeding area, and its worked example is this exact waiver shape ("even if you have a Digimon with the [Armor Form] trait in the breeding area, you can't ignore the color requirements"). So for C1 the [CS] check reads the battle area only. Test: "does not waive the color requirement for a [CS] Digimon in the breeding area (CR 3-4-5-8)", paired with the battle-area positive. |

Rules consulted: CR §4-21 (color requirements), §16-17 (＜Delay＞), the glossary line "You can't
activate this effect the turn this card enters play", §3-4-5-8 (breeding-area information),
§17-1-3-2-2 (an Option in the battle area is trashed unless an effect placed it).

## Defects found and fixed

1. **Illegal fixtures (the coordinator's flag).** The old test put `BT1-001` Yokomon and `BT1-002`
   Bebydomon — both Digi-Eggs — into security. Replaced. The whole file now uses main-deck cards
   only: `BT22-053` Keramon (the [CS] carrier), `BT1-049` Labramon, `BT1-034` Ikkakumon,
   `BT1-028` Elecmon, `BT1-030` Gomamon, `BT23-082` Makiko Date (the [CS] Tamer).

2. **Invalid `zone` literal in the module.** `BT23-091.ts` used `zone: "field"` on the C1 condition.
   `"field"` is not a member of `ZoneRef` (`packages/shared/src/effects/ir/filters/zones.ts`); it
   only compiled because the file carried `// @ts-nocheck`. At runtime `countMatching`
   (`apps/api/src/engine/effects/interpreter/scaling.ts`) treats an unrecognised zone as the default
   scan, so the observable result happened to be correct, but nothing held it there. Changed to
   `zone: "battleArea"`, which is both type-legal and the CR §3-4-5-8 semantics. Discriminator
   proof: setting the same field to `"breeding"` makes the breeding-area test fail (the waiver then
   fires from breeding); `"battleArea"` makes it pass.

3. **`// @ts-nocheck` removed** from `BT23-091.ts`. The module now typechecks with no errors, so a
   future bad `duration:` or `zone:` literal will surface instead of being silently accepted.

4. **Structural-only assertions replaced.** Three of the six old tests only read the compiled object
   (`effects.find(...).actions[0]` shape checks). Those earned no behavioral credit and are gone; the
   only remaining structural check is the catalog/coverage test.

5. **`placedByEffect` no longer hand-set.** The old tests seeded the Option as a battle-area
   permanent and wrote `permanent.placedByEffect = true` by hand. Every test now places it through
   its own printed [Main] or [Security] effect, so the placement path itself is under test.

No engine change was needed. No retained red, no skip.
