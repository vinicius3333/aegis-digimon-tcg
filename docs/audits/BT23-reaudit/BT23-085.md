## Defects found and fixed (local, in `BT23-085.ts`)

1. **Breeding-area leak on clause 1.** The `youHave` condition filter carried no `zone`, and
   `countMatching` (`apps/api/src/engine/effects/interpreter/scaling.ts:95-101`) scans the breeding
   area as well as the battle area when `zone` is unset. A lone [CS] Digimon in breeding therefore
   granted a memory. Added `zone: "battleArea"`.
   *Red-then-green proof:* with the fix reverted, `ignores a [CS] Digimon that is only in the
   breeding area` fails with `expected 1 to be +0`; with the fix, it passes.
2. **Missing zone scope on the clause 2 targets and the clause 3 source filter.** The three
   `[Hudie]` filters had no `zone`, so a breeding Digimon could match a watcher whose printed
   subject is a battle-area Digimon. Target enumeration already defaults to `battleArea`
   (`targeting/permanents.ts:110-117`), so this is a hardening change, not a behavior change — but
   it removes reliance on that default and matches the sibling card BT23-080.
3. **`// @ts-nocheck` removed.** The module typechecks without it, so duration/filter typos now
   surface (the brief's `toDuration` pitfall). `duration: "untilOpponentTurnEnd"` is a real
   `EffectDurationRef` value (`packages/shared/src/effects/ir/durations.ts`).

The prior test file was replaced. It was structural in the places that mattered: three of its five
cases asserted only IR shape, and the two "behavioral" ones injected `fireTiming(OnPlay, …)` and
`advance().fireSubTrigger("whenSuspended", …)` directly, which proves nothing about how the card
behaves under real play. Nothing in it pinned the memory paid, the security stack, the duration
boundary, or any refusal branch.

## Findings that are NOT defects

- `byOpponentEffectsOnly` is honored end to end: the opponent's -3000 DP effect is blocked while
  the controller's own `modifyDP` still lands. Both directions are pinned by tests.
- `UseOptionWithoutCost` has no printed cost cap on this card, and `optionUseCandidates`
  (`interpreter/actions/borrowed.ts:423-428`) applies no cap when the filter names none, despite
  the "historical default of 5" mentioned in the IR doc comment. A cost-5 Option (Comet Hammer) is
  usable, which the behavioral test proves.
- `sameTarget` on the two `GainKeyword` actions correctly reuses the Digimon the `Restrict` action
  chose (CAP-A9). The "exactly one of two [Hudie] copies" test pins it.

## Remaining gaps

- **Cost paid with no legal Option.** When the watcher fires and the hand holds no eligible
  Option, the engine still asks and, on accept, suspends Ryuji for nothing. No Q&A covers this and
  no ruling contradicts it, so the test asserts only that the ineligible Option stays in hand and
  never reaches the battle area, not whether Ryuji suspends. Worth a coordinator ruling check.
- **＜Reboot＞ is proved as a grant, not as an unsuspend.** The test asserts the keyword is live
  through the opponent's turn and gone afterwards; it does not walk the opponent's Unsuspend phase
  with the Digimon suspended. The grant expiry boundary makes that window narrow, and the keyword
  itself is engine-shared behavior, not card behavior.
- **The `[All Turns]` proof on the opponent's turn uses BT23-051 Golemon's printed ＜Blocker＞**
  rather than the ＜Blocker＞ Ryuji grants, so the two clauses stay independently proved.
