## Defect found and fixed

`digivolutionRequirement[0]` used `names: ["Phantomon"]`. Per `apps/api/src/engine/cards/cardData.ts:480-487`, `names` is a SUBSTRING gate and `namesExact` is equality. The printed route is a bracketed card name (`[Phantomon]: Cost 6`), which is exact, so the substring gate wrongly let BT20-073 **MetalPhantomon** (level 5, Purple/Black, also a `Ghost`) act as the base.

Proved red-then-green: with `names`, the run is `2 failed | 10 passed` — the IR-shape test and the MetalPhantomon negative, which got `{ ok: true }` instead of `{ ok: false, reason: "invalid-evolution" }`. With `namesExact`, 12 pass.

Also removed the file's `// @ts-nocheck`. `pnpm --filter @aegis/api typecheck` reports no error in `BT23-071.ts` or `BT23-071.test.ts` (pre-existing failures in `src/cards/BT23/BT23-068.test.ts` and `src/engine/combat/controller.ts` belong to other lanes).

## Remaining gaps

- `[On Deletion]` is opened with `advance().verb.deletePermanent(...)`. No public intent removes an established 14000 DP Digimon on demand, so the two On Deletion tests use the production deletion verb. The window itself and everything after it is real.
- No combat proof of `＜Piercing＞` excess damage, `＜Security A. +1＞` checking a second security card, or `＜Execute＞` in an attack. The keywords are asserted through the live continuous-effect seam only.
- No test that the `[On Deletion]` play is refused when the only trash Ghost is level 7, because BT23-071 itself is the only level-7 `Ghost` Digimon in the catalog; the level gate is covered indirectly by the non-Ghost control.
- The `controllerControls` gate is a battle-area check (`apps/api/src/engine/actions/digivolve.ts:572-592`). "While you have" is read as "in play"; not separately proven against a Violet Inboots in hand or trash.
