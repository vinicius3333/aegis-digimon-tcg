# BT23-043 CannonBeemon re-audit

## Card summary

Green/Black Lv.5 Ultimate Digimon. Play cost 8, DP 8000. Traits: Cyborg, X Antibody, Royal Base, CS, Insectoid. Printed evolution costs: Green Lv.4 for 4, Black Lv.4 for 4.

Printed clauses:

1. `[Digivolve] Lv.4 w/[Royal Base]/[CS] trait: Cost 3` — alternate evolution route.
2. `[Security] [Opponent's Turn] All of your Digimon with the [Royal Base] trait gain ＜Blocker＞`.
3. `[All Turns] [Once Per Turn] When this Digimon would leave the battle area other than by your effects, by flipping your top face-up security card face down, it doesn't leave.`
4. Inherited: `[All Turns] [Once Per Turn] When any of your [Royal Base] trait Digimon would leave the battle area other than by your effects, by flipping your top face-up security card face down, 1 of those Digimon doesn't leave.`

Catalog text matches the official card list. No discrepancy found; `cards.json` was not edited.

## Defects found and fixed

- `BT23-043.ts` opened with `// @ts-nocheck`, so the compiled IR was never type-checked. Removed. The module type-checks cleanly without it; no IR change was needed.
- The previous test suite had three material weaknesses, all replaced:
  - It relied on the turn seat to stand in for the resolving effect controller, so the own-effect exclusion was proved only indirectly.
  - It used `BT23-015` in security. Security fixtures now use real neutral main-deck Digimon (`BT1-009`..`BT1-012`).
  - The evolution test asserted only `{ ok: true }` — no cost, source stack, or draw. It also silently exercised the printed cost-4 route, not the printed cost-3 alternate route, because the intent did not declare `useAlternateCost` / `alternateRequirementIndex`.

## Behavioral findings worth the coordinator's attention

1. **The cost already flips the top FACE-UP card, not the top card.** `primitives.flipTopSecurity` scans from the top for the first face-up card. Proved with two face-down cards above two face-up ones: index 2 flipped, indices 0, 1 and 3 unchanged, stack order and instance identity preserved.

2. **Q5304 result, with one open interpretation question.** With All Delete-style simultaneous deletion of CannonBeemon, QueenBeemon (BT19-053) and TigerVespamon, and the controller ordering CannonBeemon's prevention first:
   - CannonBeemon's prevention pays (top face-up security flipped face down) and the deletion is prevented.
   - QueenBeemon's placement is **not** erased: it still runs afterward, and every Royal Base Digimon affected by the deletion effect reaches the bottom of security face up in battle-area order. Nothing reaches the trash.
   - Open question: the engine also sweeps CannonBeemon itself into security through QueenBeemon's placement, because CannonBeemon was affected by the deletion effect. Q5304's wording ("you can place all of your [Royal Base] trait Digimon that were affected by the deletion effect into your security stack") does not exclude the prevented Digimon, so this reads as correct — but it is not stated outright. The test asserts the current behavior and names it in a comment. If the coordinator reads the ruling as excluding the prevented Digimon, this becomes an engine defect in `apps/api/src/engine/effects/leavePrevention.ts` (`consultLeavePrevention` runs an `instead` replacement even after a `prevent` already succeeded for the same permanent: the `preventSucceeded` guard is checked only on the `prevent` branch, after the `instead` branch).

3. **Ordering must be driven, not defaulted.** When both CannonBeemon's prevention and QueenBeemon's placement are eligible for the same permanent, `GameEngine.orderReplacements` raises an `orderTriggers` decision. The harness's default `autoOrderTriggers` keeps the offered order, which puts QueenBeemon first and hides CannonBeemon's prevention entirely. The Q5304 test answers that decision explicitly. Sibling lanes touching this family should do the same.

## Remaining gaps

- No retained red tests. No `it.fails` / `it.skip` in this file.
- The Blocker aura is proved on a battle-area Royal Base Digimon while CannonBeemon sits face up in security. Blocking with a Digimon that gains the keyword *through* a different route in the same turn is not covered; it is not a printed clause of this card.
- The once-per-turn reset is proved by advancing a full production turn with `advance.runTurn` and asserting `turnCount` advanced, then re-running the prevention. It does not separately prove a reset across a *change of turn player*, because `runOneTurn` from a hand-laid mid-turn board does not reliably hand the turn over. The once-per-turn ledger is turn-start-scoped in `GameEngine` (`tracker` reset), so this is a fixture limit, not a behavior gap.
- Q5304 is the only indexed ruling for this card, and it is covered.
