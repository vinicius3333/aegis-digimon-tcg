### Modelling gap (Q5325 / Q5327 / Q5329) — engine lane, not this card

`immuneToOpponentDigimonEffects` compiles to a `beAffected` restriction qualified to
`fromSourceKind: ["Digimon"]` (`apps/api/src/engine/effects/interpreter/actions/grantStatic.ts:472`).
The target-resolution path then EXCLUDES the immune permanent from the candidate set
(`apps/api/src/engine/effects/interpreter/targeting/permanents.ts:102-130`). The rules say the
card is still chosen and simply not affected (Q5325). For a single-target "suspend / -DP"
effect the observable outcome is the same, which is why the behavioral test above is green;
it differs where a card counts what it chose, or resolves a second clause off the choice.
Q5327 and Q5329 need the same seam. No `it.fails` reproducer is retained here because
writing one would assert on engine internals rather than on this card's behavior; the gap is
handed to the engine lane.

Every behavioral test drives public intents only — `playCard`, `digivolve`, `attack`,

remains. The single exception is documented inline: placing an Option into the OPPONENT's
battle area uses the production `placeOptionAsPermanent` verb, because no public intent for
seat 0 can put a card there during seat 0's turn.

## Defects found and fixed

1. The previous test file proved the three trigger windows with injected timings
   (`engine.fireTiming(EffectTiming.OnPlay, …)` and `advance.fire`). Those earn no behavioral
   credit and never exercised the shared once-per-turn key, the `[All Turns]` rider under a
   real attack, or the digivolve costs. Replaced with public-intent runs.
2. The previous digivolve test asserted `{ ok: true }` alone, which proves nothing about the
   cost. Costs are now pinned by memory delta on all four legal routes.
3. The previous "unsuspends" assertion ran on a hand-armed `suspended: true` permanent, so it
   could not distinguish the rider firing from the fixture. It now runs off a real attack
   declaration.
4. No defect found in `BT23-059.ts`. The IR is correct on the points this set gets wrong
   repeatedly: the cost filter carries `zone: "battleArea"` and no `controller`, the delete
   target carries `kind: ["Digimon"]`, and the three windows share one `sharedUseKey`.
   `BT23-059.ts` is unchanged.

## Notes for the coordinator

- `useAlternateCost` is unobservable for this card. `apps/api/src/engine/actions/digivolve.ts:493-503`
  takes an alternate route without the flag whenever it is the only matching path, and no
  legal source for BT23-059 matches both a printed evoCost and an alternate requirement.
  The test pins the no-flag branch (BT10-067 still costs 1) rather than claiming a negative
  that does not exist.
- The `[All Turns]` clause fires from ANY Option leaving the battle area for the trash,
  including the one this card's own cost trashes. That self-chain is what the attack test
  observes.
