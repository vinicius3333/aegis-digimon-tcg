Every behavioral test drives public intents only (`playCard`, `digivolve`, `attack`, `endPhase`,
`respondDecision`) except the two decline-path On Play probes, which use `advance().fire(OnPlay)`;
the accepted On Play path is proved through a real `playCard` for 11 memory.

The duration test is a full four-turn boundary walk on the real turn loop: the restriction is
observable right after a public digivolve, the restricted Digimon still fails to unsuspend during
the opponent's unsuspend step, the restriction is gone once that turn ends, and the same Digimon
unsuspends normally on the opponent's following turn.

The once-per-turn test suspends the redirect target publicly (it attacks), proves the first opponent
attack is redirected (security stack untouched, 3000-DP attacker dead against the 6000-DP target),
proves the second attack of the same turn goes through to security, then returns through a full own
turn and proves the third attack — on the opponent's next turn — is redirected again.

## Defects found and fixed (all local to the test file)

1. "digivolves for 3 from an off-color level-5 CS card" used `BT23-044` Lilamon, which is **green**
   Lv.5. It exercised the printed evo cost, not the alternate route, and asserted only `{ok: true}` —
   no memory, no stack identity, no digivolution draw. Replaced by separate printed-route and
   alternate-route tests, each asserting cost 3, exact stack identity and the drawn card.
2. The evolution negative used `BT1-008` Frimon — a Digi-Egg seeded in the battle area, an illegal
   fixture. Replaced by `BT1-021` MetalGreymon (Red Lv.5, non-CS) for the colour/trait axis and
   `BT23-037` Tentomon (green Lv.3 `[CS]`) for the level axis.
3. "accepts the optional By condition" asserted the unsuspend restriction on the **same** opponent
   permanent it had suspended as the cost, so it could not tell the cost apart from the target. It
   also never covered Q5311's "either player" axis, and never proved the target is opponent-only.
   Replaced by two tests that pick cost and target explicitly and assert both candidate sets.
4. The redirect test had no security stack on either side, so "the attacker left the battle area"
   was equally consistent with a security trade. It also never asserted that the redirect target
   survived. Rewritten with a real security stack, exact security instance ids before and after,
   hand size and the target's DP.
5. Fortitude had only a keyword-seam assertion. Added a real battle: a stacked Rosemon is deleted by
   a 15000-DP attacker, the digivolution card goes to trash, and Rosemon returns to the battle area
   with an empty stack for zero memory (comprehensive §16-27).
6. No coverage existed for the once-per-turn cap or its reset, the `untilOpponentTurnEnd` duration,
   the When Digivolving half of clause 3, or the Q5312 candidate set. All four are now behavioral.

No change was needed in `BT23-046.ts`. The IR matches the printed text; the two-entry `nameOrTrait`
array is a union, not an intersection (`matching/definition.ts:163-168`), which is the printed "or".

Both key assertions were mutation-checked: forcing the first redirected attack to expect a security
loss, and adding the non-qualifying Digimon to the expected candidate set, each turn the suite red.

## Engine behaviour worth reusing (not defects)

- A `chooseTargets` target set with exactly one candidate resolves without prompting. Tests that
  want to inspect a candidate list must seed at least two candidates.
- `state.pendingDecision` does not carry `options`. The candidate list must be read from the
  recorded decision stream (`s.decisions`) by `decisionId`.
- On the real turn loop, a permanent seeded as `suspended` unsuspends during its controller's first
  unsuspend step. A loop test that needs a suspended own Digimon on the opponent's turn must suspend
  it during the controller's own turn — attacking with it is the public way.

## Remaining gaps

- The `[Plant]` token of the trait disjunction has no fixture: no Digimon in the catalog (all 4388
  entries checked) carries the `Plant` trait. `[Vegetation]`, `[Fairy]` and `[CS]` are each proved
  with a real card, and the token list itself is pinned in the IR-shape test.
- Fortitude's interaction with the Rosemon replay's own `[On Play]` clause is not asserted: the
  replay is a play, so clause 3 should offer itself again. The replay test runs with
  `autoAcceptOptional` and asserts only the Fortitude endpoint. This is a composition question the
  coordinator may want covered once, not a defect found here.
