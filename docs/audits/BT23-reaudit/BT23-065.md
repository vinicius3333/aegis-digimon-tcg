# BT23-065 Phantomon — re-audit

## Card summary

Catalog record (`packages/shared/src/cards/data/cards.json`): Purple Digimon, Lv.5 Ultimate, Virus,
play cost 7, DP 7000, types `Ghost` / `LIBERATOR`, evolution cost `Purple Lv.4: 3`.

Printed clauses:

- **C1** `[Hand] [Main]` If you have [Violet Inboots], by placing 1 [Bakemon] from your trash as any of
  your [Ghostmon]'s bottom digivolution card, it digivolves into this card for a digivolution cost of 3,
  ignoring digivolution requirements.
- **C2** `[On Deletion]` You may play 1 level 4 or lower Digimon card with the [Ghost] trait from your

## Defects found and fixed

1. **Bracketed names used substring matching.** `match: "name"` is a substring test
   (`apps/api/src/engine/effects/interpreter/matching/definition.ts:352`), while `nameExact` is
   equality (line 354). All three references on this card are printed in brackets
   ([Violet Inboots], [Bakemon], [Ghostmon]), so they are exact-name references. Changed all three to
   `nameExact`. No catalog card currently collides on these substrings, so the fix has no behavioral
   delta on today's catalog; the test proves it at the matcher level with synthetic near-name
   definitions ("Bakemon X", "DarkGhostmon", "Violet Inboots Ace"), which fail with `name` and pass
   with `nameExact`.
2. **Zone-less `youHave` also counted the breeding area.** `countMatching`
   (`apps/api/src/engine/effects/interpreter/scaling.ts:22`) scans battle area *and* breeding when the
   filter has no `zone`. Added `zone: "battleArea"`. Violet Inboots is a Tamer and cannot legally sit in
   breeding, so this is a correctness-of-intent fix with no reachable behavioral delta.
3. **`// @ts-nocheck` removed** from the module; it typechecks without the suppression.
4. **Test used an injected timing API.** The old On Deletion test called the private
   `engine.fireTiming(EffectTiming.OnDestroyedAnyone, ...)` through an `as any` cast, which proves
   nothing about how the trigger is reached in play. Replaced with real combat deletions. The old
   `mainEffectKey` helper also reached through `(s.engine as any).cardSourceOf`; it now uses the public
   `observe(engine).cardSource(...)` seam.
5. **Test fixture was wrong about its own negative.** The old deletion test used BT23-066 Matadormon as
   the "too high level" card, but Matadormon is Lv.5 *Undead/CS* — it fails the trait filter as well, so
   it could not isolate the level bound. Replaced with BT20-072 Phantomon (Lv.5, Ghost), which isolates
   `levelComparison lte 4`.

## Remaining gaps

- The `nameExact` fix has no behavioral delta on today's catalog: no printed card name contains
  "Bakemon", "Ghostmon" or "Violet Inboots" as a proper substring. The proof is therefore at the
  matcher level with synthetic definitions, not through a board fixture. It becomes load-bearing the
  moment a card such as a hypothetical "BlackGhostmon" is printed.
- The `zone: "battleArea"` fix likewise has no reachable behavioral delta, because Violet Inboots is a
  Tamer and the breeding area only holds Digimon. It is recorded as intent, not as proven behavior.
- Q5335 is proven through the engine's generic "another effect is resolving" gate, using this card's own
  effect as the resolving effect. A fixture that drives P-108 [Wisdom Training] itself (delay zone ->
  Delay activation -> pending digivolve decision) would be the literal ruling; it was not built because
  the Delay-zone activation route needs its own setup work outside this card's scope.
- The C1 route is only exercised with the Ghostmon host already on the battle area (seeded). A full
  breeding -> promote -> digivolve-to-Ghostmon lead-in is not built.
- No retained red tests and no `it.skip`. No engine seam was found on this card.

## Catalog discrepancy

None. The catalog text matches the official card text. The only quirk is a non-breaking space in
"[Ghost]\u00a0trait", which the catalog carries deliberately across the set; the test normalizes it
rather than proposing a catalog edit.
