## Defect found and fixed

`StartOfYourMainPhase` counted the breeding area. The `youHave` filter carried no `zone`, and `countMatching` (`apps/api/src/engine/effects/interpreter/scaling.ts:95-101`) adds the breeding permanent when the filter is zone-less. A [CS] Digimon sitting in breeding therefore granted the memory. Comprehensive rules 3-4-5-8 says information on cards in breeding areas cannot be referenced, so this was wrong. Fix: `zone: "battleArea"` on the condition filter, in `apps/api/src/cards/BT23/BT23-084.ts`.

Proof: with the fix removed, `does not count a [CS] Digimon in the breeding area, per comprehensive rules 3-4-5-8` and the structural pin both fail (2 failed / 16 passed); with the fix they pass (18 passed).

Also removed `// @ts-nocheck` from the module. It typechecks clean without it, so future `duration` or filter typos now surface.

## Catalog discrepancy (coordinator-owned, not edited)

BT23-084's `[Security]` clause sits inside `effectText` and the record has no `securityEffectText`. Every other Tamer with the same clause (BT21-081, BT23-078, BT23-082, BT23-083, BT23-085, BT23-086) puts it in `securityEffectText`. Engine behavior is unaffected — the security window is driven by the compiled `trigger: "Security"` effect — but `activeEffectText` for the security resolution reads `securityEffectText` and will be undefined here, and any consumer keying off the field sees BT23-084 as having no security effect. The same record uses a non-breaking space in "…[CS] trait, gain 1 memory." The test asserts over `effectText` plus `securityEffectText` with whitespace normalized, so it stays green after the catalog fix.
