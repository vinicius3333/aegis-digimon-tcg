## Ruling coverage

**Q5293.** BT1-070 Kuwagamon (Lv.4, 4000 DP, `[On Play] Suspend 1 of your opponent's Digimon`) is played onto the opponent's board after Dynasmon's player-wide -6000 DP is live. The test asserts Kuwagamon's exact instance is in the opponent trash, the opponent battle area is empty, and Dynasmon is still unsuspended — the observable proof that the pending `[On Play]` never activated because the rule check deleted the 0 DP Digimon first. The opponent cannot play a Digimon during the turn player's turn through an intent, so the play is driven through the effect-play verb; that is the production path Q5293 describes.

**Q5294.** ST22-08 Offensive Plug-In V sits on top of the audited player's security stack with Dynasmon in play. The opponent attacks the player. The `[Security]` effect deletes the attacker, and the test then asserts Dynasmon still gained ＜Security A. +1＞ and still performed Recovery, and that the attacker's `cardsMoved` event index is lower than the recovered card's. That is the ordering CR 15-16-10-2 requires: the `[Security]` effect activates immediately, the security-removal watcher runs after it.

**Q5295.** A real turn loop runs seat 0's turn, then seat 1's. On the opponent's turn the first removal grants ＜Security A. +1＞ with 4 security cards left, so Recovery does not qualify. A second removal in the same turn is refused: the keyword stays at 1 and the deck is asserted unchanged card for card even though the stack is now at 3 and would otherwise qualify. After the turn boundary, the test asserts the grant is still 1 (it expires at the end of the controller's own turn, not the opponent's), then a third removal takes the count to 2 and recovers the exact deck top.

**Q5296.** Retained red — see below.

## Defects found

**Fixed locally in `apps/api/src/cards/BT23/BT23-035.ts`:**

1. `// @ts-nocheck` removed. The module typechecks without it.
2. ＜Recovery +1 (Deck)＞ was compiled as `SecurityManipulation { op: "placeAsSecurity", from: ["deck"], source: { filter: { controllerDefault: "mine" }, count: 1 } }`. That target filter opened a `selectCards` decision over the whole deck, so the controller could recover **any** deck card instead of the top one, and the effect stalled whenever nothing answered the prompt. Recovery takes the deck's top card by rule (§16-6). The action now uses the same shape as EX1-027, which prints the identical clause: `{ op: "addTop", controller: "mine", source: "deck", amount: 1, condition: … }`. The behavioral test asserts the recovered card is the exact deck top, face down, with the second deck card untouched.

**Retained red (engine lane):**

`it.fails("checks an extra security card after Barrier trashes its own security")`.

Suspected seam: `CombatController` pays ＜Barrier＞ with `this.access.flipTopSecurityToTrash(perm.controllerSeat)` (`apps/api/src/engine/combat/controller.ts:1287` calling `apps/api/src/engine/state/access.ts:639`). `flipTopSecurityToTrash` is a bare zone move: it emits nothing and never publishes `whenSecurityRemoved` or `whenCardTrashedFromSecurity`, unlike `primitives.trashFromSecurity`.

Observed end state (Dynasmon attacks into a 13000 DP Security Digimon, Barrier accepted): event stream `attackDeclared, securityRevealed, barrierPrompt, barrierResolved, securityChecked`; Dynasmon survives and its own top security card is in trash; ＜Security A. +1＞ is 0; no Recovery happened (own security 0, deck untouched); the opponent's second security card is still in their stack. Expected per Q5296: the Barrier trash is a removal from the controller's own security stack, so the `[All Turns]` trigger gives ＜Security A. +1＞ and, at 0 security cards, Recovery, and the check loop — which re-reads Strike before each card — checks a second card.

Note this is only reachable at all because ＜Barrier＞ *is* offered during a Security Digimon battle; the prompt fires. The gap is the missing event publication, not the prompt.
