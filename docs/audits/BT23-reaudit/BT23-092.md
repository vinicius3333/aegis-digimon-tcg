## Defects found and fixed

1. **`zone: "field"` is not a `ZoneRef`** (`apps/api/src/cards/BT23/BT23-092.ts`). The waiver condition used a zone string the IR type does not define. It only reached the correct behaviour through `countMatching`'s unknown-zone fallback (`apps/api/src/engine/effects/interpreter/scaling.ts:95-101` scans the battle area **and** breeding for any zone it does not recognise) — one tightening of that fallback would have silently changed the card. Replaced with the type-valid `zone: ["battleArea", "breeding"]`, which routes to the same fallback branch deliberately. Behaviour is unchanged and pinned by both waiver tests (battle-area source and breeding-only source) plus the negative.
2. **`// @ts-nocheck` removed** from the module. It was masking defect 1. The module now typechecks clean.
3. **Illegal fixtures replaced.** The previous test seeded `BT1-001` / `BT1-002` (Digi-Eggs) in security. Replaced with main-deck Lv3 Digimon `BT1-009` / `BT1-010` / `BT1-011`.
4. **Structural-only assertions replaced.** Three of the four previous tests asserted the compiled IR shape only, and the two that ran the engine hand-seeded the Option into the battle area and set `placedByEffect` by hand — which skips the [Main] body, the colour gate and the placement itself. Every clause now runs through public intents (`playCard`, `attack`, `endPhase`) on a real turn loop.

## Notes on what is not proven

- **A Tamer's "can't suspend" is asserted at the ledger, not through a public action.** No public intent suspends an opponent's Tamer; Tamer suspension is an activation cost of that Tamer's own controller-chosen ability. The restriction on the Tamer is asserted with `observe(...).isRestricted(perm, "beSuspended")`. The Digimon side of the same restriction is proven publicly (the attack refusal), and both come from the same `Restrict` action, so the ledger read is the narrow part.
- **The choice of which opposing Digimon/Tamer is restricted** is steered with `preferInstanceIds` where the fixture has more than one candidate. The card does not say "of your opponent's choice", so the resolving player choosing is correct.
