# BT23-097 Seventh Penetration — re-audit

## Card summary

Purple Option, play cost 7, type [Seven Great Demon Lords]. Catalog record matches the official
text; no discrepancy found.

Printed clauses:

- **C1** `[Trash] [Your Turn] When any of your Digimon digivolve into [Belphemon (X Antibody)], by
  returning this card to the bottom of the deck, activate this card's [Main] effects.`
- **C2** `[Main] Delete 1 of your opponent's Digimon with a level as high or higher as the number of
  cards in your hand.`
- **C3** `[Security] Activate this card's [Main] effects.`

### Endpoints proven

- Cost: the card leaves the trash and lands at the **last** deck index (a three-card deck, not an
  empty one, so "bottom" is distinguishable from "top").
- Hand-size boundary: the Option is paid out of hand before the floor is read (5 in hand -> floor 4:
  the level 4 dies, the level 3 does not). The digivolution draw replaces the Belphemon card, so the
  C1 path resolves at the pre-intent hand size (3 -> the level 3 dies).
- Isolation from BT23-070's own `[When Digivolving]` "delete all with the highest level": every C1
  fixture gives the opponent a highest-level Digimon **plus** a lower one. Belphemon can only reach
  the former, so the latter's fate is attributable to BT23-097 alone. The declined run is the
  A/B control: the level 5 still dies, the level 3 lives.
- Controller boundaries: an opponent's digivolution does not trigger C1; C2 never offers the
  controller's own Digimon; from security, "your opponent" resolves to the attacking side and the
  floor is read from the **security player's** hand.
- Memory: 7 -> 0 on every play-from-hand run.
- No `actionRejected` / unsupported-effect event on any behavioral test (`assertNoLoudGap`).

## Defect found and fixed

`apps/api/src/cards/BT23/BT23-097.ts` used `match: "name"` for the bracketed card name
`[Belphemon (X Antibody)]`. `matchNameOrTrait` (`engine/effects/interpreter/matching/definition.ts`
~350) treats `"name"` as **substring** and `"nameExact"` as equality; a bracketed printed name is an
exact reference. Changed to `nameExact`.

Honest caveat: no released card's normalized name contains "belphemon x antibody" as a proper
substring (the catalog holds only `Belphemon: Sleep Mode`, `Belphemon: Rage Mode` and
`Belphemon (X Antibody)`), so this fix cannot be proven by a failing-then-passing test today. The
near-name control ("does not trigger on a digivolution into Belphemon: Rage Mode") passes under both
spellings; it is a regression guard, not proof. The green C1 tests do prove `nameExact` still fires
on the real card.

Also removed the module's `// @ts-nocheck`: the file typechecks without it, so future IR errors now
surface (per the brief's BT23-047 lesson).

## Remaining gaps

- The exact-name fix is unprovable behaviorally until a card named with `Belphemon (X Antibody)` as
  a prefix exists (see above).
- C1 is not once-per-turn and has no duration, so there is no reset or expiry boundary to prove.
- Not exercised: two copies of BT23-097 in the trash on one digivolution (the second copy's own
  ordering entry). The Q5570 test proves the ordering decision exists and is answerable; the
  multi-copy case is a resolver concern, not a card-module one.
- The prior test file asserted `deck[0]` for a deck-bottom return against an empty deck, and read
  both opponent deletions as this card's work when one of them was BT23-070's. Both were replaced.
