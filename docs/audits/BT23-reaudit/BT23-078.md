## Defects found and fixed

All three fixes are local to `BT23-078.ts`, and each was proved red before green.

1. **Trait gate matched exactly instead of by substring.** The five tokens used
   `match: "trait"` (exact trait equality, `engine/effects/interpreter/matching/definition.ts`
   ~356). The printed wording is "in any of their traits", which CR 2-3-2-4 defines as
   substring containment; the printed "(other than [Sea Animal])" exists only because
   `[Sea Animal]` contains "Animal". Under the old IR, every compound trait — `[Giant Bird]`,
   `[Holy Beast]`, `[Dark Animal]` — silently failed the gate. Changed to
   `match: "traitContains"`. Red proof: reverting the token to `match: "trait"` fails
   "reads [Giant Bird] as [Bird] per CR 2-3-2-4" and the IR shape test. Second red proof:
   with `traitContains` in place but the `excludeNameOrTrait` line deleted, Dolphmon wrongly
   fires the clause, so the carve-out is now load-bearing rather than decorative.
   The `[CS]` branch stays `match: "trait"`, which is CR 2-3-2-3's "with the [XX] trait".

2. **"1 of your Digimon" reached the breeding area.** `ModifyDP` and `Attack` used a zone-less
   `{ controller: "mine", kind: ["Digimon"] }` filter, so the breeding-area Digimon was a legal
   pick for the DP boost and the forced attack. Added `zone: "battleArea"` to both (CR 3-4-5-8).

3. **`// @ts-nocheck` hid the IR types.** Removed. The module now typechecks, which required
   typing the `whenPlayed`/`whenOneOfYoursDigivolves` map callback as
   `(event: SubTriggerEvent): Action`. This is the guard that catches silent `duration` and
   filter-key errors (the BT23-047 class of bug).

The old test suite used `advance().fireSubTrigger(...)` for every behavioral claim, so it proved
only that the watcher body runs, not that a real play or digivolve arms it. All behavioral tests
now go through public intents (`playCard`, `digivolve`, `attack`) and the real turn loop.

## Remaining gaps

- No behavioral proof that the breeding-area Digimon is excluded from the two "1 of your
  Digimon" picks. The fix is asserted structurally only, because the harness's decision
  automation picks from the candidate list the engine offers and a breeding Digimon that never
  appears there cannot be distinguished from one that is filtered later.
- The `[Sea Animal]` carve-out is compiled as a card-level exclusion. The printed text reads as a
  per-trait carve-out, so a Digimon printed with both `[Sea Animal]` and, say, `[Beast]` would
  differ between the two readings. No such card exists in the catalog today, so the difference is
  unobservable; the card-level spelling matches the whole BT15/BT23 family.
- No retained reds or skips. No engine seam blocked this card.
