# BT23-061 Ghostmon re-audit

## Card summary

Committed catalog `BT23-061`. Purple level 3 Rookie, Data, traits Ghost / LIBERATOR. Play cost 3, DP 1000, digivolve cost 0 from a level 2 Purple source. Rarity C.

Printed clauses:

1. `[On Play] [On Deletion] 1 of your Digimon with the [Ghost] trait gains ＜Blocker＞ until your opponent's turn ends.` — one clause body shared by two timing windows. Mandatory, exactly one recipient, own Digimon only, Ghost trait only.
2. Inherited: `[On Deletion] Gain 1 memory.`

Catalog text matches the official BT23 card list verbatim (`logs/official-bt23.html`, entry BT23-061). No discrepancy to report.

## Rulings

`node tools/kb/query.mjs card BT23-061` returns `(no knowledge-base entries)`. `KB-INDEX.md` agrees: 0 Q&A ids. So there is no Q&A or errata to cover, and every clause below is proven against the comprehensive rules plus the printed text.

One comprehensive-rules point drives a test: CR §3-4-5-3 — cards in the breeding area cannot be affected by effects unless the effect names the breeding area. The compiled filter has no `zone` field, so the breeding exclusion had to be proven, not assumed.

## Evidence detail

All acting is through public intents (`playCard`, `digivolve`, `attack`, `endPhase`, `surrender`) plus `startTurnLoop()`. The Advance Surface is used only for `waitForMainPhase` / `endMainPhaseIfOpen`, never to fire a timing directly. The prior test file fired `EffectTiming.OnPlay` through an injected cast and deleted permanents with `advance().verb.deletePermanent`; both are replaced by real play and real combat.

- **On Play, public.** Ghostmon is played from hand with memory 3. Endpoints asserted: memory 0, hand empty, the exact hand instance is now the permanent's top card, DP 1000, Blocker on itself, and `blockerHolders` for the seat equals exactly that one permanent id. `assertNoLoudGap` confirms no unsupported-effect rejection.
- **Target legality.** Fixture holds an own second Ghost (BT20-063), an own non-Ghost (BT1-009 Monodramon), an own Ghost in **breeding**, and an opponent Ghost. The recorded `chooseTargets`/`selectCards` candidate set is resolved to permanent ids and asserted to contain the two own battle-area Ghosts and to exclude the non-Ghost, the opponent Ghost, and the breeding Ghost. `preferInstanceIds` steers the pick to the second Ghost; the seat's Blocker holder list is exactly that permanent, and the opponent seat has none. The engine therefore already applies the CR §3-4-5-3 breeding exclusion without a `zone: "battleArea"` field in the IR, so no module change was needed there.
- **Duration.** Real turn loop. Ghostmon is played on seat 0's Main; one holder is recorded. After passing to seat 1's Main the holder list is asserted to still equal that same permanent id (the grant survives the whole opponent turn). After passing back to seat 0's Main the holder list is asserted empty. Both intermediate states are asserted explicitly. A neutral playable card is kept in each hand so Main does not auto-pass before the assertions.
- **On Deletion, public.** Ghostmon (1000 DP) attacks a suspended BT1-021 (larger DP) and loses the battle. After the attack settles, Ghostmon's exact instance is in trash and the surviving own Ghost is the sole Blocker holder; the non-Ghost has none.
- **On Deletion, no recipient.** Same battle with only a non-Ghost surviving. No Blocker is granted anywhere, no `actionRejected` event is emitted, and no loud gap fires. This proves the mandatory clause fizzles cleanly rather than erroring.
- **Inherited memory.** Ghostmon is publicly digivolved into BT4-080 Bakemon (level 4 Purple Ghost, no printed effects — chosen so the memory swing is unambiguous). Cost 2 is asserted (memory 2 -> 0), Ghostmon's exact instance is asserted as the single digivolution card, and the digivolve bonus draw is asserted by exact drawn instance in hand. Bakemon then loses a battle; both cards reach trash and memory is exactly 1. Ghostmon's own top-card clause is inactive as a digivolution card, so the whole +1 is the inherited clause.
- **Evolution.** Legal: BT10-006 Tokomon (level 2 Purple) in breeding digivolves into Ghostmon at memory 0 with memory unchanged (cost 0), Tokomon retained as the digivolution card, and the bonus draw landing as an exact instance in hand. Illegal negative: BT1-002 Bebydomon (level 2 **Red**) is refused; the intent returns `{ ok: false }`, the source's top card is unchanged, and memory is untouched.

## Defects found and fixed

- `apps/api/src/cards/BT23/BT23-061.ts` carried a `// @ts-nocheck` header. Removed. `pnpm --filter @aegis/api typecheck` reports no error in this module or its test, per the brief's instruction that a suppressed module hides duration-type errors like the BT23-047 one.

No IR defect was found. Checked specifically for the pitfalls listed in the worker brief: `controller: "mine"` is present, `kind: ["Digimon"]` is present, trait matching is `match: "trait"` (no name/substring risk — the card has no bracketed name condition), and `duration: "untilOpponentTurnEnd"` is a real member of `EffectDurationRef` (`packages/shared/src/effects/ir/durations.ts:8`), so `toDuration` does not silently downgrade it. The missing `zone: "battleArea"` is not a defect here: the breeding-exclusion test proves the engine already excludes breeding from this filter.
