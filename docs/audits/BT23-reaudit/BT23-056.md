## Evidence notes

Every behavioural test drives public intents (`playCard`, `digivolve`, `attack`, `declareBlock`,
`declineBlock`, `endPhase`, `surrender`) over the real turn loop (`startTurnLoop`). No test uses an
injected timing fire; the previous suite's `fireTiming(OnStartMainPhase)` and
`fireSubTrigger("whenAttackTargetSwitched")` shortcuts were replaced.

Endpoints asserted, not just the first mutation:

- Grant: subscription count on the chosen opponent permanent is 1 and on the granter's own Digimon
  is 0; the victim is unsuspended when the grant lands; at the victim's main-phase start it is
  suspended, one of its opponent's security cards is gone (3 -> 2), no attack is in flight and no
  decision is pending.
- Duration: the subscription is 0 on the next turn cycle and no further security card is checked.
- Digivolve: memory 3 -> 0, the source is the only digivolution card, exactly one card is drawn,
  and the illegal source leaves memory and the top card untouched.
- Inherited clause: the de-digivolve target is a Digimon that never enters a battle, so its stack
  change cannot be confused with a battle death. Cards removed from that stack are identified by
  instance id and located in the trash.

The two source cards used as fixtures are the printed routes: `BT23-041` (Lv.4 `[CS]`, Green/Yellow)
takes the alternate cost with `useAlternateCost: true`, `BT10-062` (Black Lv.4) takes the printed
colour route without it.

Fixture legality: security and deck contain only main-deck Digimon (`BT1-011`, `BT1-009`); no
Digi-Egg is placed outside breeding.

## Defects found

None. The hand-authored IR in `apps/api/src/cards/BT23/BT23-056.ts` is correct as written:
`[CS]` Tamer gate present, target restricted to the opponent's Digimon, granted trigger anchored on
the chosen permanent, `untilOpponentTurnEnd` expiry, inherited clause on the attack-target-switch
bus with `OncePerTurn`. The module was not changed.

## Interpretation risk (for the coordinator)

The inherited clause is modelled board-wide: the watcher fires on any attack-target switch, not
only on a switch involving its own host. That matches the printed English ("When attack targets
change", with no "this Digimon") and the interpreter's documented split at
`apps/api/src/engine/effects/interpreter/actions/subTrigger.ts:417-425`, where only an
`isSelfRef` source filter narrows the event to the host. If the intended reading is host-scoped,
the IR would need `sourceFilter: { isSelfRef: true }`. No Q&A on this card settles it, so I left
the current model and flagged it rather than changing the module.

## Remaining gaps

- No test drives the alternate route from a Lv.4 `[CS]` source of a fourth colour; one off-colour
  source (Green/Yellow) plus the printed Black route plus a rejection is the coverage.

  granted attack a second time; the firing path is already proven end to end on the `[On Play]`
  branch and both branches compile to the identical SubTrigger.
- The board-wide vs host-scoped reading of the inherited clause is unresolved (see above).
