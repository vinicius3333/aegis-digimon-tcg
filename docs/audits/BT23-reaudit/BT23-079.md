# BT23-079 Eri Karan

## Card summary

Catalog record (`packages/shared/src/cards/data/cards.json`): Blue Tamer, play cost 3, types
`App Driver` / `Appmon`, rarity R, max 4 per deck. The catalog text matches the official card
list. No discrepancy to report.

Printed clauses:

1. `[Start of Your Main Phase] If your opponent has a Digimon, gain 1 memory.`
2. `[Your Turn] When any of your Digimon get linked, by suspending this Tamer, those Digimon
   get +3000 DP until your opponent's turn ends.`
3. `Then, 1 of your Digimon may app fuse into a Digimon card in the hand.`
4. `[Security] Play this card without paying the cost.`

## Behavioral endpoints proved

- Clause 1 uses the real turn loop (`startTurnLoop` + `waitForMainPhase`). Memory at Main open
  is exactly one higher than the identical fixture with an empty opposing battle area, and the
  clause stays silent while seat 1 holds the turn.
- Clause 2 uses the public `linkCard` intent. Musclemon (1000 DP) linked with Perorimon
  (2000 link DP) reads 6000 DP with Eri suspended; the vanilla bystander is unchanged; memory
  moves 5 -> 4 for the link declaration only. The boost still reads 6000 during the opponent's
  Main phase and falls to 3000 once that turn ends, pinning the exact `untilOpponentTurnEnd`
  boundary.
- Controller boundary: an opponent linking their own Digimon on their own turn leaves Eri
  unsuspended and the host at link DP only. A `whenLinked` subject controlled by the opponent
  does nothing.
- Cost failure: an already-suspended Eri produces no boost, no fusion and no `digivolved`
  event, while the link itself still succeeds.
- Q5354: with the suspend declined, DP stays at 3000, Eri stays unsuspended, the host top card
  is unchanged, the hand still holds the fusion result, hand size drops by exactly the linked
  card, and no `digivolved` event is emitted (so no App Fusion procedure draw either).
- Clause 3: accepting the suspend and the fuse offer, then declining Dosukomon's own When
  Digivolving Link, moves the host top to the exact Dosukomon hand instance, leaves
  `stack = [old top, consumed link]`, empties `linked`, emits
  `digivolved / mechanic: appFusion / cardId: BT23-021`, charges no extra memory (memory 4)
  and draws exactly one card (`BT1-010`).
- Clause 4: a real opponent attack drives the security check. Eri lands in the battle area, is
  not trashed, security empties, and the memory line matches a control run whose revealed
  security card (BT1-009) has no security effect. The control run is the free-of-charge
  baseline, so the cost-3 Tamer demonstrably paid nothing.

No test uses `advance().fireSubTrigger` for a case a public intent can reach; the two
remaining injected-timing uses are the opponent-controlled `whenLinked` subject and the
opponent-turn `OnStartMainPhase` refire, neither of which has a public route.

## Defect found and fixed

`apps/api/src/cards/BT23/BT23-079.ts` opened with `// @ts-nocheck`, which suppressed type
checking for the whole IR module (the risk called out in the brief for `duration:` strings and
`EffectDurationRef`). The directive was removed. `pnpm --filter @aegis/api typecheck` compiles
the module cleanly, so `duration: "untilOpponentTurnEnd"` is a real `EffectDurationRef` and not
a silent fallback to end-of-each-turn — which the behavioral expiry test independently confirms.
