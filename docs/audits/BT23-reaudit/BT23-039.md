# BT23-039 Perorimon

## Catalog and rules

`packages/shared/src/cards/data/cards.json` records a Green level-3 Stnd./Appmon, play cost 3, 1000 DP, attribute `Entertainment`, type `Gourmet`, normal evolution from Green level 2 for 0.

Printed clauses:

1. `[Digivolve] Lv.2 w/[Appmon] trait: Cost 0` — alternate evolution route.
2. `[On Play] Reveal the top 3 cards of your deck. Add 1 card with the [Appmon] trait and 1 card with the [Game] or [Invincible (App Name)] trait among them to the hand. Return the rest to the bottom of the deck.`
3. `[Link] [Appmon] trait: Cost 1`, link DP 2000.
4. `[When Linking] You may suspend 1 of your opponent's Digimon.`

`node tools/kb/query.mjs card BT23-039` returns no entries. No Q&A ids are indexed for this card in `KB-INDEX.md`, so there is no ruling to cover or to contradict.

## Implementation trace

`apps/api/src/cards/BT23/BT23-039.ts` only calls `registerIrCard("BT23-039", compiled)`; behavior comes from the shared interpreter.

| Clause | IR | Test |
| --- | --- | --- |
| Alternate evolution | `digivolutionRequirement: [{ level: 2, traits: ["Appmon"], cost: 0, isAlternate: true }]` | hatched off-color level-2 Appmon route plus level-2 non-Appmon negative |
| On Play reveal | `RevealAdd` `revealCount: 3`, two `add` slots (`Appmon` trait; `Game`/`Invincible` trait), `rest: "deckBottom"` | four public play tests (two distinct adds, Invincible branch, single overlapping card, no match) |
| Link cost/DP | `linkRequirement: [{ cost: 1, traits: ["Appmon"] }]`, catalog `linkDp: 2000` | link test asserts memory 3 -> 2 and host DP +2000; non-Appmon host rejection |
| When Linking suspend | `AllTurns` + `isLinked`, `SubTrigger whenLinked` with `sourceFilter.isSelfRef`, optional `Suspend` on `controller: "opponent"` | suspend test (own Digimon untouched), refusal test, no-legal-target test, replacement test |

Distinct physical selection across the two add slots is enforced by `runRevealAdd` in `apps/api/src/engine/effects/interpreter/actions/reveal.ts`: each slot filters `!taken.has(...)`, so one card can satisfy only one slot. Trait comparison is exact-token in `matching/definition.ts` (`ref.match === "trait"` compares normalized whole traits), so `[Game]` and `[Invincible]` cannot substring-match unrelated traits.

## Behavioral proof

All entry points are public intents (`playCard`, `linkCard`, `hatchEgg`, `digivolve`). No injected timing API is used; the previous `advance.fire(EffectTiming.OnPlay, ...)` reveal test was replaced with a real play.

Reveal fixtures use real catalog traits: `BT21-009` Gatchmon (Appmon only), `BT23-016` Dokamon (Appmon + `Game` attribute), `BT23-024` Poseidomon (Appmon + `Invincible` type), `BT1-009` (neither). Every case asserts the physical instance ids in hand, the exact remaining deck order, the memory paid, and `assertNoLoudGap`.

The evolution case now uses the only legal source route: a level-2 Appmon is a Digi-Egg card, so the test hatches `BT23-001` Flickmon (Blue) from the egg deck with `hatchEgg`, then digivolves Perorimon in breeding for 0 and asserts the stack identity, cost 0 and the single evolution bonus draw. The negative hatches `BT21-003` Yokomon (Blue level-2 non-Appmon) and expects `invalid-evolution`, which isolates the alternate route from the Green normal route.

Defect fixed: the previous evolution test claimed an "off-color level-2 Appmon" but used `BT23-002` Yokomon — Green and non-Appmon — so it actually exercised the printed Green normal evolution and proved nothing about the Appmon alternate. It also seeded the level-2 card straight into the battle area, which no legal route produces.

## Remaining gaps

- The second add filter carries a dead token: `"Invincible (App Name)"` never matches, because trait normalization only strips spaces and hyphens, so the parenthesised form is not a real trait. The live token `"Invincible"` does the work and `BT23-024` proves it. No behavior is wrong, so the token was left in place as printed-text provenance.
- Slot order is fixed (Appmon first, then Game/Invincible). A player who spends the only overlapping card on the first slot loses the second add. That matches the printed sequence and is the player's choice, but it is not separately proven as a rules question because no ruling addresses it.
- No retained red tests and no engine seam suspected for this card.
- No catalog discrepancy found: the committed text matches the official wording of all four clauses.
