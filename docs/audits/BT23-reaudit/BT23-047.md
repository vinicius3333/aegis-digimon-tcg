# BT23-047 Examon re-audit

## Card

Green/Red/Blue level 7 Digimon, play cost 15, DP 15000, Mega, Data, traits Holy Warrior / Royal Knight / CS. Printed EvoCosts: green, red and blue Lv.6 for 5.

Printed clauses:

1. `[Digivolve] Lv.6 w/[CS] trait: Cost 5`
2. `[DNA Digivolve] Green Lv.6 + blue Lv.6: Cost 0`
3. `＜Piercing＞`
4. `＜Security A. +1＞`
5. `＜Partition (green Lv.5 & blue Lv.5)＞`
6. `[On Play] [When Digivolving]` suspend 5 opposing Digimon or Tamers; none of the opponent's Digimon can unsuspend in their next unsuspend phase; then this Digimon may attack.
7. `[Your Turn] [Once Per Turn]` when the opponent's security stack is removed from, trash 1 of their Option cards in the battle area, then delete 1 of their suspended Digimon or Tamers.

Rulings covered: Q5313, Q5314, Q5315.

## Defects found and fixed

Both fixes are local to `apps/api/src/cards/BT23/BT23-047.ts`.

1. **Missing evolution requirements.** The module carried no `digivolutionRequirement` and no
   `dnaDigivolveRequirement`, so the persisted IR had both null. The `[CS]` alternate was
   unreachable, and `dnaDigivolveCostFor` (`apps/api/src/engine/effects/primitives.ts:6234`)
   fell back to a per-material EvoCost match — which would have let a **single green Lv.6 plus
   any second material** DNA digivolve for 5. Added:
   - `dnaDigivolveRequirement: [{ cost: 0, materials: [{ color: "Green", level: 6 }, { color: "Blue", level: 6 }] }]`
   - `digivolutionRequirement: [{ level: 6, traits: ["CS"], cost: 5, isAlternate: true }]`
2. **Invalid duration marker.** The `Restrict` action used
   `duration: "untilTheirNextUnsuspendPhase"`, which is not a member of `EffectDurationRef`
   (`packages/shared/src/effects/ir/durations.ts:3`). `toDuration`
   (`apps/api/src/engine/effects/interpreter/duration.ts:10`) has no case for it and fell
   through to `default: EffectDuration.UntilEachTurnEnd` — the lock expired at the end of the
   controller's own turn, before the opponent's unsuspend phase, so clause 6 did nothing.
   Corrected to `"untilOpponentNextUnsuspendPhase"`, which maps to
   `EffectDuration.UntilNextUntap` and is swept at `ownerActivePhaseEnd`, after the unsuspend
   it must block. The bug was invisible because the module carried `// @ts-nocheck`; that
   directive was removed and the module now typechecks clean.

## Evidence notes

**Evolution.** Every route goes through a public intent. The printed route uses BT1-080 Titamon
(green Lv.6, no effect text): memory 5 to 0, the exact Titamon instance is the only card in the
stack, and the exact deck card lands in hand. The `[CS]` alternate uses BT23-058 Craniamon, which
is **black** — it can never satisfy a printed green/red/blue EvoCost, so a legal digivolution from
it can only be the alternate. The intent sets `useAlternateCost: true` and
`alternateRequirementIndex: 0`; an explicit index never silently falls back
(`apps/api/src/engine/actions/digivolve.ts:472`). The negative uses ST3-10 Magnadramon (yellow
Lv.6, no `[CS]`) and asserts `{ ok: false, reason: "invalid-evolution" }`, unchanged memory, and
the card still in hand on both the plain and the alternate-declared path.

**DNA.** There is a public `dnaDigivolve` intent
(`apps/api/src/engine/actions/dnaDigivolve.ts:42`), so the DNA proof needs no injected timing.
Both materials are built publicly in the same test: BT1-076 MegaKabuterimon digivolves into
BT1-080 Titamon for 2, BT1-038 Monzaemon into ST2-10 Plesiomon for 2, then the DNA digivolve pays
0. All three draws are asserted by exact instance id (two evolution bonuses plus the DNA
procedure's own draw, CR §8-2-3-3), the deck is empty, and the merged stack holds exactly the four
source instance ids. Two negatives pin the requirement: green Lv.6 + green Lv.6 (wrong colour) and
green Lv.6 + blue Lv.5 (wrong level) are both rejected with no memory paid and both materials still
on the board. Before the fix the wrong-colour pair would have been legal for 5 through the
per-material fallback.

**Keywords in combat.** `＜Security A. +1＞` is proved by a real attack on the player: security
drops from 4 to 2 in one attack, both cards reach trash, and Examon ends suspended. `＜Piercing＞`
is proved by a real Digimon battle against a suspended 3000 DP body: the victim's exact card
instance reaches trash and the pierced security check turns over **two** cards, because
`＜Security A. +1＞` modifies the number of cards checked in every security check this Digimon
performs (CR §16-4-1, quoted in the test).

**Partition.** The only public route that puts a green Lv.5 and a blue Lv.5 under one Examon is
the DNA merge, so the Partition tests reuse it. CR §16-29 excludes the holder's own effects, so
the deletion is driven from the opponent's seat (`s.state.turnSeat = 1`, then the effect-deletion
verb) — no player intent deletes an opposing Digimon by effect on this board, and the verb is the
production primitive. The accept branch asserts the battle area now holds exactly the
MegaKabuterimon and Monzaemon instance ids with empty stacks, and that the two Lv.6 cards and
Examon are the only cards in trash. The refuse branch answers the 0..1 selection with an empty
response (min 0 / max 1 asserted) and leaves all five cards in trash.

**On Play / When Digivolving.** The decline branch plays Examon publicly for 15 (memory 10 to
-5), asserts exactly five of six opposing bodies suspended and the unsuspend restriction on all
six, and that Examon is unsuspended with opposing security untouched. The accept branch attacks
the player and checks two security cards. The unsuspend lock is proved through
`startTurnLoop()`: Examon arrives by the `[CS]` alternate (cost 5, so memory stays positive and
the turn does not end on the spot), the restriction is observed armed, seat 1's Main phase is
reached with the Digimon **still suspended** and the restriction now expired, and after one full
round seat 1's next unsuspend phase stands it up.

**Q5313 / Q5314 / Q5315.** All three are covered by one public attack. The opponent's top security
card is P-035 Red Memory Boost!, whose `[Security]` effect places itself in the battle area — the
exact scenario in Q5315. Examon attacks the player, `＜Security A. +1＞` checks two cards, the
`[Security]` effect resolves first (Q5313), and the pending `[Your Turn]` effect then trashes that
exact P-035 instance and deletes the suspended opposing Digimon while the standing one survives.
Q5314 ("trashes an Option placed by an effect") is proved by the same assertion pair: the trashed
card is one `placedByEffect` marks (`apps/api/src/engine/effects/primitives.ts:1223`), set only by
the place-in-battle-area path. A second attack in the same turn removes another security card and
changes nothing else, proving the once-per-turn cap. A separate turn-loop test proves the reset:
two removals on turn 1 delete only one suspended Digimon, and after a full round the third removal
deletes the second one. The empty-board test shows the trigger resolves quietly with no pending
decision when the opponent has no Option and no suspended body. The own-security test shows a
removal from the controller's own stack does not fire it.

## Remaining gaps

- No public intent exists that deletes an opposing Digimon by effect on a bare board, so the
  Partition trigger is driven by the production effect-deletion verb rather than a card. A future
  peer test could substitute an opponent removal card.
- The `[CS]` alternate and the printed EvoCost both cost 5, so no fixture can distinguish which
  path was billed by memory alone. The off-colour base isolates the alternate instead.
- ＜Partition＞ on a battle death is untested because battle deletions never reach the primitive
  that implements it, matching CR §16-29's "other than by ... a battle" exclusion.
