## Duration audit

The module carries exactly two `duration:` strings, both `"permanent"`. `EffectDurationRef` (`packages/shared/src/effects/ir/durations.ts`) lists `"permanent"`, which maps to the never-clearing `EffectDuration.Permanent`. No unknown duration string is present, so neither keyword grant silently expires at turn end. The live keyword seam test confirms both grants are readable on the board.

## Once-per-turn evidence

- Same-turn refusal: `consumes its once-per-turn use even when no face-up Zaxon security card exists` attacks once with the lender face down (Q5330 still burns the use), flips the lender face up, then attacks again in the same turn; the opponent's Digimon survives. The second attack needs the attacker unsuspended, which this test does through `advance().verb.unsuspend`. That is an injected step, so the refusal proof is public in the attack and the lender state, but not in the unsuspend.
- Next-turn reset: `resets the once-per-turn borrow on the next own turn through the real turn loop` uses `startTurnLoop()`, `waitForMainPhase`, and public `endPhase` intents. It asserts the intermediate state explicitly — exactly one of two named victims deleted after the first attack, the attacker suspended, the attacker unsuspended after the real Unsuspend phase — then proves the second victim is deleted by the borrow on the next own turn.

## Mutation evidence for the borrow filter

Three temporary mutations of `BT23-060.ts` were run to check which assertions actually discriminate (the module was restored afterwards; the working tree carries the original filter).

| Mutation | Result |
| --- | --- |
| Drop `nameOrTrait` `Zaxon` | 2 failures: the IR trace test and `does not borrow from a face-up security Digimon without the Zaxon trait`. The trait restriction is behaviorally load-bearing. |
| Drop `faceUp: true` | 1 failure: the IR trace test only. |
| Drop `controller: "mine"` | 1 failure: the IR trace test only. |

Cause, not a card defect: `collectForeignCandidates` in `apps/api/src/engine/effects/interpreter/actions/borrowed.ts` (lines ~131-139) hardcodes both properties for `zone: "security"`. It reads the seat as `action.filter.controller === "opponent" ? opponent : mine`, and it pushes only `card.faceUp` security cards. So `faceUp: true` and `controller: "mine"` in this card's IR document the printed text but cannot change behavior. The two behavioral negatives still prove the printed rule holds; they just do not isolate those two IR fields. Flagged for the coordinator as an engine observation, not a card change.

## Defects found

None in the card module. Two notes:

- The `Delete` target uses `controllerDefault: "opponent"` rather than `controller: "opponent"`. `controllerDefault` is documented as seat-enumeration only, but `matching/permanent.ts:130` resolves the scope as `filter.controller ?? filter.controllerDefault`, so the opponent restriction is enforced. `plays for 12, de-digivolves first, then deletes only the opponent's resulting 4000-DP Digimon` proves it behaviorally: the controller's own 3000-DP Digimon is never chosen. Left as-is; changing the structural signature is a catalog-shaped decision, not a local card fix.
- `borrowedEffectOverrides` is deliberately narrowed to BT23-045's On Play. Q5331's answer states a general principle ("if the effect will activate, you must process the 'by' condition"), so a future Zaxon lender with a `by` cost will need the same treatment. Today BT23-045 is the only [Zaxon] Digimon whose On Play carries one, so the narrow scoping is correct and the control test proves other lenders are not force-processed.
