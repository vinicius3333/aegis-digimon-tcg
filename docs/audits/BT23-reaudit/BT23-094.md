## Defects found and fixed

1. **`// @ts-nocheck` hid a type error in the module.** Removing it surfaced three
   `TS2741: Property 'filter' is missing ... in type 'Target'` errors on the
   `DisableTimingEffect` targets. Fixed locally by giving each bound target the same
   `{ controllerDefault: "opponent", kind: ["Digimon"] }` filter its paired `GainKeyword`
   carries. The filter is inert at runtime — `resolvePermanentTargets`
   (`apps/api/src/engine/effects/interpreter/targeting/permanents.ts:29`) short-circuits on
   `fromSelectionRef` before any filter is read — so the change is type-only and the module
   now typechecks with no suppression. Future `duration:` typos will surface (the BT23-047
   lesson).

No rules defect was found. The IR already matched the printed text on every point checked:
`zone: ["battleArea", "breeding"]` for Q5368, exact `match: "trait"` for `[CS]`, one bound
target shared by both restrictions, `duration: "untilOpponentTurnEnd"` (a real
`EffectDurationRef` member), and `PlaceInBattleAreaSelf` on both [Main] and [Security].

## Remaining gaps

- The `[CS]` exact-trait match has no near-name negative: no printed trait in the catalog
  contains `CS` as a substring, so `match: "trait"` and `match: "traitContains"` cannot be
  told apart behaviorally. The clause-shape test pins the exact form instead.
- The [Main] and [Security] clauses use `controllerDefault: "opponent"` rather than
  `controller: "opponent"`, which is what the printed "1 of **their** Digimon" would suggest.
  This is the compiler convention across the whole BT23 Option cycle (BT23-092 is identical),
  and `seatsForController` (`interpreter/matching/permanent.ts:130`) narrows enumeration to
  the opponent's seat either way, so behavior is correct — the controller-boundary assertions
  in `applies both restrictions to one opposing Digimon ...` prove it. Left alone to stay
  consistent with the set; flagging it as a naming question for the coordinator, not a bug.
