# BT23-087 Violet Inboots re-audit

Sources: committed catalog `BT23-087`; KB Q5362, Q5569; comprehensive rules 3-4-5-3 and 3-4-5-8 (breeding area).

## Card summary

Violet Inboots is a Purple Tamer, play cost 3, trait LIBERATOR. Printed clauses:

1. `[Start of Your Main Phase] By returning this Tamer to the bottom of the deck, you may play 1 [Violet Inboots] from your hand without paying the cost.`
2. `Then, if you don't have a Digimon, you may play 1 [Ghostmon] from your trash without paying the cost.`
3. `[Your Turn] When any of your Digimon digivolve into a Digimon with the [Ghost] trait, by suspending this Tamer, that Digimon gains <Rush> for the turn.`
4. `[Security] Play this card without paying the cost.`

## Defects found and fixed (all local to `BT23-087.ts`)

1. **Breeding area leaked into "you don't have a Digimon".** The tail condition used a
   zone-less `youHaveNone` filter, and `countMatching` counts breeding-area permanents by
   default (`engine/effects/interpreter/scaling.ts:22`). Comprehensive rules 3-4-5-8 forbid
   referencing breeding-area information, so a Digimon in breeding wrongly blocked the
   Ghostmon play. Fixed with `zone: "battleArea"`. Red proof: with the fix reverted,
   `-t 'breeding area'` fails (`expected true to be false` — Ghostmon stayed in trash).
2. **Bracketed names matched by substring.** Both `[Violet Inboots]` and `[Ghostmon]` used
   `match: "name"`, which is substring matching
   (`engine/effects/interpreter/matching/definition.ts:352`). Changed to `nameExact`. No
   printed card currently has either name as a strict superset, so this is proved through
   `matchNameOrTrait` directly (`Violet Inboots ACE`, `SoulGhostmon`,
   `Ghostmon: X Antibody` all now fail to match).
3. **Invalid duration string.** The Rush grant used `duration: "untilTurnEnd"`, which is not
   an `EffectDurationRef`; `toDuration` silently maps unknown strings to end-of-each-turn.
   The printed wording is "for the turn", so the value is now `forTheTurn`. This surfaced
   only after removing the module's `// @ts-nocheck`.
4. **`// @ts-nocheck` removed.** The module typechecks without it, so future duration and
   filter errors will surface at build time.

Also added `zone: "battleArea"` to the sub-trigger `sourceFilter`. This one is
documentation, not a bug fix: the engine already does not raise
`whenOneOfYoursDigivolves` for a breeding-area digivolution, so the new
"inside the breeding area" test passes with and without the field. It is kept because
rules 3-4-5-3 make the battle-area scope the correct printed meaning.

## Remaining gaps

- No test distinguishes `forTheTurn` from the old silent fallback, because both clear at the
  same boundary for a grant made on the controller's own turn. The fix is a type-correctness
  fix, proved by `tsc`, not by behavior.
- The `nameExact` fix has no behavioral proof because the catalog contains no card whose
  name strictly contains "Ghostmon" or "Violet Inboots". Proof is at the matcher level.
- The sub-trigger `zone: "battleArea"` addition is unproven (green before and after).
- Both plays are "without paying the cost"; no test covers a cost-reduction or play-blocking
  interaction from another card.
