## Defects found

1. **Structural-only prior suite.** The previous `BT23-063.test.ts` proved C2 through `engine.fireTiming(EffectTiming.OnUseAttack, ...)` and proved C3 only by shape-matching the IR. It never declared an attack, never covered Q5332/Q5333, had no once-per-turn proof, no decline branch, no negative trait case and no controller-boundary case. Replaced.
2. **Prior alternate-route test was weak.** It asserted `{ ok: true }` for a plain `digivolve` intent without `useAlternateCost`, which the brief flags as proving nothing about the cost. The new tests pin the alternate branch explicitly (`useAlternateCost: true`, `alternateRequirementIndex: 0`) and assert memory reaching 0 from 2 plus the evolution bonus draw.
3. **`// @ts-nocheck` removed** from `BT23-063.ts`. The module typechecks without it (`pnpm --filter @aegis/api typecheck` reports no `BT23-063` diagnostic), so a future bad `duration:` or filter key will now surface.

No behavioral defect was found in the IR. The inherited target filter carries no `zone` key, which the brief warns can leak into the breeding area; the added breeding-area test shows the interpreter already excludes it (§3-4-5-3), so the module was left unchanged rather than edited without a red proof. The test asserts the filter as it actually is, with a comment naming the test that covers the risk.

## Remaining gaps

- The two `chooseOption` routes for the [CS] fixture both cost 3, so the test does not distinguish which digivolution route the engine picked. A fixture whose routes differ in cost would pin that, but it is BT23-067's behavior, not BT23-063's.
- C2 is not proved against a target that is legal for the printed effect but illegal as a digivolution (wrong level or colour). The engine filters the candidate list before the prompt, so such a case is indistinguishable from the "no legal target" test already present.
- The opponent-turn boundary is proved for C2 only; C3 on an opponent's attack is the same `WhenAttacking` window and the same controller check.
