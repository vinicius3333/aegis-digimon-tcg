## Rulings covered

`node tools/kb/query.mjs card BT23-077` returns "no knowledge-base entries", and
`docs/audits/BT23-reaudit/KB-INDEX.md` line 83 lists 0 Q&A ids for this card. There is
no card-specific Q&A to cover.

Mechanics were checked against the rules behaviour the engine already encodes:

- An attack declaration suspends by the rules and opens the `whenSuspended` window
  (`apps/api/src/engine/combat/controller.ts:1152-1168`). Blocking suspends the blocker
  through the same combat path, so the clause fires there too.
- A block requires ＜Blocker＞ (§16-5) — `apps/api/src/engine/combat/legality.ts:374`.
- De-Digivolve may target a Digimon with no digivolution cards; it then does nothing
  (`apps/api/src/engine/effects/interpreter/actions/digivolution.ts:16-48`).
- A "trait" is forms union attributes union types (`apps/api/src/engine/cards/cardData.ts:297-316`),
  so the catalog's `attributes: ["Data", "Virus"]` already answers a `[Virus]` trait
  condition. The whole Sistermon Ciel family (BT6-084, BT7-083, ST12-13) is encoded that
  way.

Note on the last row: renaming the keyword in the module does NOT stop the block. The
combat gate falls back to the printed keyword in the catalog effect text
(`hasBlocker` -> `hasPrintedKeyword`, `apps/api/src/engine/combat/legality.ts:89-97`),
so the behavioural block test proves the rule, while the ledger test is what pins the
module's IR. This is engine behaviour, not a defect in this card.

## Defects

### Fixed (local)

- Removed `// @ts-nocheck` from `apps/api/src/cards/BT23/BT23-077.ts`. The module
  typechecks without it, so `toDuration`-style silent type errors would now surface.
  `pnpm --filter @aegis/api typecheck` is clean with it removed.
- **Added the missing `(Rule)` effect** to `BT23-077.ts`: `trigger: "Rule"` with two
  `GrantStatic` actions (`grant: "name"`, `tokens: ["Sistermon Noir"]` and
  `grant: "trait"`, `tokens: ["Virus"]`). This is the exact shape BT6-084 Sistermon Ciel
  already uses in `effects.json`; BT23-077 had no `Rule` effect at all, so the alternate
  name did not exist on the board. Proved red (both new rule tests fail with the effect
  removed) then green.
- Replaced the injected-timing test file. The old tests called
  `engine.fireTiming(EffectTiming.OnPlay, ...)` and `advance().fireSubTrigger("whenSuspended", ...)`
  directly, so neither the On Play delete nor the suspend watcher was proved through a
  public path. Both now run through real play and real combat.

### Catalog gap for the coordinator (not edited)

The catalog `effectText` for BT23-077 omits the official `(Rule) Also has
Name:[Sistermon Noir] and Trait: [Virus].` line. The behaviour is now carried in the
card module, so play is correct, but any consumer reading `effectText` (card viewer,
text search, re-generation of the IR) will not see the rule. **Coordinator action:**
append the rule line to the BT23-077 catalog entry, matching the ST12-13 convention.

The empty `evoCosts` is **not** a gap: the official entry shows "Digivolve Cost 1" and
"Digivolve Cost 2" both as `-`, so this card has no evolution route. Nothing to fix,
and no evolution test is possible.

## Remaining gaps

- No once-per-turn clause on this card, so no same-turn refusal / next-turn reset case

- No duration on any effect, so no expiry-boundary case applies.

  asserted, because the printed effect leaves that choice to the controller.
