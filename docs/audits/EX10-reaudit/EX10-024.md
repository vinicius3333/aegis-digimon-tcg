# EX10-024 Kabemon — re-audit

## Card summary

Black Lv.3 Digimon, play cost 3, DP 1000, forms `Stnd.` / `Appmon`, attribute `System`,
type `Wallpaper`, link DP 2000.

Printed clauses:

1. `[Digivolve] Lv.2 w/[Appmon] trait: Cost 0` (alternate route; the printed `evoCosts`
   route is Black Lv.2 for 0).
2. `[Security] At the end of the battle, play this card without paying the cost.`
3. `[Link] [Appmon] trait: Cost 1` (link requirement).
4. Link effect: `[When Attacking] By trashing 1 of this Digimon's link cards,
   ＜De-Digivolve 1＞ 1 of your opponent's Digimon.`

## What changed

- `EX10-024.test.ts` rewritten. The committed version proved both Q&A ids only with
  `advance(engine).fire(EffectTiming.OnUseAttack, ...)` (injected timing, no behavioural
  credit) and set up the two-link board with
  `advance(engine).ledgers.continuous.addLinkMaxGrant(...)` (past the seam, in
  `engine.continuous`). Both are gone:
  - the link effect now fires from `applyIntent(0, { type: "attack", ... })`;
  - the second link card is legal board state because the host prints ＜Link +6＞
    (BT26-086 Kiwamimon), so no ledger poke is needed.
- Added the illegal-source digivolve negative, the declined-cost branch, catalog text
  assertions and post-settle endpoints (stack contents, trash membership, `pendingDecision`,
  `observe(engine).isAttacking()`).
- `EX10-024.ts`: comment only. The old comment claimed the cost used `sameHost` plus
  `hostFilter`; neither field exists in the IR. The real mechanism is `zone: "linked"` with
  `isSelfRef: true`, which `interpreter/costs.ts` resolves to the SOURCE's host permanent's
  link cards — exactly "this Digimon's link cards", this card included. No IR change, so no
  `effects.json` drift.

## Findings

- Implementation is faithful. No defect found in `EX10-024.ts`.
- Fixture trap worth recording for other lanes: `deDigivolve` in
  `apps/api/src/engine/effects/primitives.ts` has a `levelFloor` of 3, so a Lv.3 top card is
  never demoted. A ＜De-Digivolve＞ proof needs a Lv.4+ top (this test uses BT10-081 over
  BT10-074).
- A link card seeded past a host's link maximum is trashed by the rule sweep on the next
  attack, not at setup. `expect(host.linked).toHaveLength(2)` after `ready()` still passes,
  so a fixture that over-links silently loses the card mid-test. Using a host that prints
  ＜Link +6＞ avoids it without touching the ledger.

## Catalog discrepancy (reported, not edited)

`packages/shared/src/cards/data/cards.json` writes EX10-024's `effectText` and
`linkRequirement` with U+00A0 (no-break space) between `[Appmon]` and `trait`:
`"[Digivolve] Lv.2 w/[Appmon] trait: Cost 0 "` and `"[Link] [Appmon] trait: Cost 1"`.
Official text uses a normal space. Nothing in the engine reads these strings, so it is
cosmetic, but any test asserting the printed text must use ` `.

## Remaining gaps

- No test covers the link effect when the host has zero link cards, because Kabemon is
  itself a link card whenever the effect exists; the pool cannot be empty.
- The link intent is proved against one non-Appmon negative (BT1-009). A broader
  near-miss trait pool was not built; the requirement is a plain trait match.
