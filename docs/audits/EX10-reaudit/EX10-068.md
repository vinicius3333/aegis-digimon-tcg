# EX10-068 Digimon Emperor — re-audit

Tamer, White, play cost 5, DP 0, no evolution requirement, no inherited text.

## Printed clauses (catalog `packages/shared/src/cards/data/cards.json`)

1. `[Start of Your Main Phase]` For every 2 colors your opponent's Digimon and Tamers have,
   gain 1 memory.
2. `[On Play]` Delete 1 of your opponent's play cost 5 or lower Digimon.
3. `[On Play]` Then, by returning 1 Digimon card from your opponent's trash to the bottom of
   the deck, from your hand or trash and without paying the cost, you may play 1 level 4 or
   lower Digimon card with the same color as the card this effect returned.
4. `[Security]` Play this card without paying the cost.

Catalog text matches the official card. One cosmetic note only: `effectText` has a double
space between the two bracketed clauses. No edit made (catalog is coordinator-owned).

## How the proof is driven

Every behavioural case uses public intents only:

- `startTurnLoop()` + `waitForMainPhase(0)` for clause 1, ending each run with a real
  `surrender` intent so the loop resolves. Expected memory is asserted as a **delta against a
  control board** built by the same helper, so no turn-start bookkeeping is baked into the
  number.
- `playCard` for clauses 2 and 3.
- `attack` -> real security check for clause 4.

No `advance.fire*` / `fireSubTrigger` / `fireTiming` call appears in the file. The previous
test file drove **all five** of its behavioural cases through injected timing
(`fireForPermanent(OnPlay/OnStartMainPhase)`, `fireForInstance(SecuritySkill)`); that is the
main defect this re-audit fixes.

Fixtures are inert cards with no printed or inherited text (BT1-009, BT1-013, BT1-014,
BT1-027, BT1-038, BT1-065, BT10-022, BT10-055, BT8-041). `BT16-021` carries text but is only
ever placed in a trash or a deck, where it is inert. No Digi-Egg and no numeric `security: n`
form is used.

## Mutation check (the assertions bite)

With `sameColorAsReturned: true` removed and `playCostLte: 5` widened to `9` in the module,
4 of 14 tests fail: the structural contract, the cost-ceiling negative, the Q5182 colour
negative, and the security check (the attacker becomes a legal deletion target). Module
restored immediately; `git diff` for `EX10-068.ts` is empty.

Log: `logs/EX10-068-mutation.log`.

## Defects found and fixed

- **Test file rewritten** (`EX10-068.test.ts`). The previous file had no public-intent proof
  at all, no negative for the level ceiling, no optional-refusal case, no proof of the
  `trash` source zone, no controller-scope negative for the memory trigger, no
  inert-in-trash/hand negative, and asserted the security clause through injected timing.
- **No module change was needed.** The compiled IR already matched every printed clause, and
  the engine already carries the `sameColorAsReturned` capability with a transactional
  preflight. `packages/shared/src/effects/effects.json` therefore does not drift.

## Remaining gaps

- No peer module in the repository uses `sameColorAsReturned`; EX10-068 is the sole consumer,
  so there is no second card to cross-check the capability against.
- A Tamer has no digivolution stack and no evolution route, so the rubric's evolution-stack
  requirement is inapplicable. The applicable peer case is covered instead: a copy of
  EX10-068 sits under **opponent** control on the board at the same time as mine (proving the
  trigger and the colour count are both controller-scoped), and the security clause resolves
  against a live opposing attacker.
- Clause 1 is asserted as a delta rather than an absolute memory value, because the turn-loop
  entry sets the dial before the trigger runs. The delta is exact (0, +1, +2) and the control
  board differs only in the opponent's battle area.
