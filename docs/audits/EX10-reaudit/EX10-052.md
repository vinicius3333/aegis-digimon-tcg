## Defects fixed in this lane

1. **Declining the opponent's deletion suppressed ＜Recovery +1 (Deck)＞.** The `Delete`
   action on both triggers carried `abortOnDecline: true`, so a declined prompt aborted the
   whole clause and the following `ifThisEffectDidNotDelete` recovery never ran. Printed text
   says a decline is exactly the "didn't delete" case. Removed on both triggers. The peer with
   the same wording, `apps/api/src/cards/EX6/EX6-054.ts`, has never carried it.
   Evidence: `logs/EX10-052-run1.log` (red before), `logs/EX10-052-final.log` (green after).
2. **The leave replacement asked its controller for permission.** Without `optional: false`
   on the `Replacement` action, `preventCheck` in
   `apps/api/src/engine/effects/interpreter/actions/replacement.ts` prompts "Prevent leaving
   the battle area?" and a decline lets the removal through. EX10-052's printed "may" belongs
   to the opponent's deletion, not to the prevention, so the prevention is mandatory.
   Added `optional: false` to the `Replacement` (the prompt gate reads the replacement action,
   not the nested `Prevent`; the nested `optional: false` alone did not help — see
   `logs/EX10-052-run5.log`). Evidence: `logs/EX10-052-run5.log` (red), `run6` (green).

## Retained red

`it.fails("skips the whole clause when the hand cost cannot be paid")`.

- Seam: `apps/api/src/engine/effects/interpreter/actions/runAction.ts` (`Action.cost`) and
  `apps/api/src/engine/effects/interpreter/effect.ts` (`runEffect`). `Action.cost` gates only
  the action carrying it; a later action in the same `CardEffect` still resolves.
  `CardEffect` (`packages/shared/src/effects/ir/card.ts`) has `condition` but no whole-clause
  `cost`, so the IR cannot express "if the cost is unpayable, none of this happens".
- Expected with an empty hand: no deletion offer AND no ＜Recovery +1 (Deck)＞
  (comprehensive rules on activation costs — an unpayable cost stops the activation).
- Actual: the deletion offer is correctly skipped, but the card still recovers 1 card for free.
- The alternative IR shape (a leading mandatory `Trash` action, as `BT18/BT18-034.ts` compiles
  the identical wording) is strictly worse: it lets the opponent delete without any trash at
  all (`logs/EX10-052-run3.log`). The current shape is the closer of the two.
- A companion green test, `still skips the deletion offer when the hand cost cannot be paid`,
  pins the half of that behaviour that is already right.

## Structural-only test

`[Once Per Turn]: the second departure in the same turn is not prevented (structural)` uses
`advance().verb.deletePermanent`. Two departures of the SAME permanent inside one turn cannot
be produced by public intents here: the only public leave window this card can survive is one
where the opponent controls no Digimon or Tamer (otherwise they simply delete one and the
Lucemon leaves), which rules out any opponent attack, and a Digimon may attack only once per
turn. No behavioural credit is claimed for it. The per-turn RESET is proved publicly instead,
across a real turn loop, in `[All Turns] [Once Per Turn]: the per-turn use resets on the next
own turn`.
