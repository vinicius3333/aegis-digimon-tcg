## Defect fixed locally

The committed test proved every `[End of Your Turn]` case with
`advance(engine).fire(EffectTiming.OnEndTurn, permanent)`. That is injected timing and earns
no behavioural credit: it never shows that the clause opens in a real End phase, and it could
not have caught a wrong trigger (a clause bound to the opponent's turn end would have passed
identically). All five cases now run through the production turn loop
(`advance.runTurn(0)` or `startTurnLoop` + `endMainPhaseIfOpen`), and a new case proves the
clause stays silent through the opponent's End phase and then fires on the next own turn.

Also added, all previously missing:

- a behavioural ＜Blocker＞ proof (block window, redirected attack) instead of only
  `observe().hasKeyword`;
- an illegal-base negative for the `[Cupimon]` route;
- non-matching cards in the trash pool, proving the `textContains` filter excludes them;
- deck-bottom position for the returned main-deck cards (asserted behind the cards already
  in the deck), and a mixed egg/main-deck cost pool for Q5734 instead of an all-egg one.

No module change was needed. `EX10-013.ts` was left untouched, so `effects.json` does not
drift.

## Remaining gaps

1. **Egg-deck bottom position unproven.** A production Breeding phase parks when the Digi-Egg
   deck holds a card (`waitForMainPhase` stalls at `phase = Breeding` with no pending
   decision), so an end-of-turn scenario cannot start from a stocked egg deck. The test runs
   with an empty egg deck, which proves the returned Digi-Eggs arrive there but not that they
   go under an existing egg. Seam for the coordinator: `TurnStateMachine` Breeding phase /
   `testkit/advance.ts waitForMainPhase`.
2. **`textContains` ignores structured requirements (engine-wide, latent here).**
   `apps/api/src/engine/effects/interpreter/matching/definition.ts:216` builds the "in its
   text" blob from name, types, forms, attributes, `effectText` and `inheritedEffectText`
   only. Q5038 also counts digivolution, DNA, DigiXros, burst, App Fusion, Link and Assembly
   requirements. I checked every catalog card mentioning "Lucemon" (22 cards): all of them
   match through the printed text blob anyway, so EX10-013 has no witness and no behaviour
   changes. This is a note for the engine owner, not a defect of this card.
3. `[Once Per Turn]` is not printed on this card, so no once-per-turn gate applies.
