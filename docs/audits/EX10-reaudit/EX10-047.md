# EX10-047 Arukenimon — re-audit

## Card summary

Purple/Red Lv.5 Ultimate, [Dark Animal], Virus, 6000 DP, play cost 6.
Digivolve: Purple Lv.4 for 4, or Red Lv.4 for 4. No inherited text, no security text.

Printed clauses:

1. `[On Play]` By trashing 1 card in your hand, delete up to 6000 DP total worth of your
   opponent's Digimon.
2. `[On Deletion]` You may play 1 Tamer card with [Myotismon] in its text from your trash
   without paying the cost. This effect can't play cards with the same name as any of your
   Tamers.

## What the previous audit missed

The committed test file proved every behavioural clause through injected timing:
`advance(s.engine).fireForPermanent(EffectTiming.OnPlay, ...)` for `[On Play]` and
`advance(s.engine).verb.deletePermanent([...], "byEffect")` for `[On Deletion]`. Under this
run's rules that is structural proof only and earns 0 in the Behavior column, so the
previous 10/10 claim was not supported. It also had no negative for the text filter (only
the same-name exclusion), no "may" refusal on `[On Deletion]`, no memory assertion, and no
empty-board case.

Rewritten: `[On Play]` now runs through `applyIntent(0, { type: "playCard", ... })` with the
play cost taken from memory (11 -> 5), and `[On Deletion]` through a real losing attack. The
module (`EX10-047.ts`) needed no change — the IR was already correct.

## Defects found

- **Catalog (report only, not edited):** `packages/shared/src/cards/data/cards.json` stores
  `EX10-047.effectText` with a non-breaking space (U+00A0) after `[Myotismon]` in the
  `[On Deletion]` line. Harmless for matching (the compiled token is `"Myotismon"`), but it
  makes any exact-text comparison fail invisibly. The catalog test spells the codepoint out
  with a comment so the quirk is recorded rather than hidden.
- **Behaviour worth recording, not a defect:** using the `[On Play]` effect with no opposing
  Digimon at all still pays the hand card (`DeleteByDPBudget` returns early only after the
  cost has been paid). That is consistent with "up to" allowing a selection of zero, so the
  test asserts it rather than treating it as a bug. Same for the 7000 DP boundary case: the
  cost is a processing condition of a used effect and is paid even when the greedy budget
  pass selects nothing.

No test is retained red. No engine change was needed, so no seam is reported.

## Remaining gaps

- The Purple Lv.4 route is not exercised separately. Both printed routes cost 4 and differ
  only in the source colour, and the Red route is proved end to end, so the untested half is
  the catalog's colour field rather than any card-specific logic.
- The `[On Deletion]` proof uses combat deletion only. Deletion by an opponent effect, and
  deletion while a would-leave replacement is in play, are untested.
- `DeleteByDPBudget`'s budget bonuses (`dpDeleteBudgetBonus`, `deletionMaxDpBonus`) are read
  by the shared action but are not exercised from this card; they belong to the engine
  capability suite (`capabilities.test.ts` CAP-A1).
