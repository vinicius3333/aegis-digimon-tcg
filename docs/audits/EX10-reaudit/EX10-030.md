## Defects fixed in this lane

1. **Test seam breach (from the committed file).** The committed test called
   `advance(s.engine).ledgers.continuous.addLinkMaxGrant(...)` twice to fabricate a multi-link
   board. Replaced with BT21-101 Gaiamon, which prints `＜Link +1＞`, so the two-link board is
   real. (Committed copy kept at `logs/EX10-030.test.committed.ts`.)
2. **Broken fixture in the digivolve test.** It used EX10-029 Warpmon as the Lv.4 source. Warpmon's
   link effect is `[When Linking] By trashing 1 of this Digimon's link cards, …`, so accepting it
   immediately trashed the card the test had just linked; the assertion saw an empty link zone.
   Replaced with BT23-052 Consulmon, whose link effect only grants keywords.
3. **Wrong sort order** in the decline test (`[CARD_ID, "EX10-029"]` is not the sorted order).
4. **Leftover `console.log("DEBUG …")` statements** removed.
5. **Catalog assertion corrected** for the non-breaking space (below).
6. **Added** a Yellow Lv.4 digivolution route test, so both printed evo costs are exercised.
7. **Residency of the lower box corrected** (coordinator follow-up). The module recorded the
   would-leave replacement as `isInherited: true`, which also granted it while Cometmon sat in a
   host's *digivolution stack* — behaviour the printed card does not have. It is now
   `isLinked: true`, matching the corrected catalog and the 76 other link cards. The stale module
   comment defending the inherited reading was rewritten.

## Catalog discrepancies (reported, not edited)

1. `linkRequirement` is `"[Link] [Appmon] trait: Cost 3"` — a **non-breaking space (U+00A0)**
   between `[Appmon]` and `trait`, where every peer Appmon card uses a normal space. The test now
   asserts the literal ` ` so the mismatch is visible rather than silent. BT26-028 has the
   related defect of a trailing space. Worth a catalog cleanup pass.
2. **Fixed by the coordinator.** The lower box sat in **`inheritedEffectText`**, but the catalog has a dedicated `linkEffect`
   field and every other Appmon link card uses it (EX10-029, BT23-052, BT24-036, …). KB Q5086 and
   Q5089 both call this clause "this card's **link** effect". EX10-030 is the only card in the
   catalog with a `linkRequirement` and an `inheritedEffectText` but no `linkEffect`. This looks
   like a scrape error. The catalog now carries it as `linkEffect` and drops
   `inheritedEffectText` for this card; the test asserts both.

## Remaining gaps

- **Removed fabricated clause.** A `[When Attacking] … return 1 [Appmon] Digimon card from your
  trash` clause was deleted from this module before this lane. It appears nowhere in the catalog or
  KB, and the deletion is right. Note that EX10-014 Weatherdramon's real link effect has a similar
  shape (`[When Attacking] By trashing 1 of this Digimon's link cards, …`), which is the likely
  source of the mix-up. The only guard is a shape assertion (`no Return action`), not behaviour.
- **`-8000` target choice** is proved with a single opponent Digimon; a two-candidate board that
  proves the controller chooses is not covered.
- **Link cost boundary** (a Lv.5 card refused as a link target) is not covered: no Lv.5 catalog card
  carries a `linkRequirement` and is inert enough to be a safe fixture.
- **`＜Collision＞` negative** (an ineligible blocker not being forced) is not covered.
