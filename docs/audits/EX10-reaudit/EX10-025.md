## Defects found and fixed

The module needed no change; the previous test file was the defect.

1. **No behavioural proof at all.** Every previous clause test drove the card through
   `advance(...).fireForPermanent(EffectTiming.OnPlay, ...)` and
   `advance(...).verb.trashDigivolutionCards(...)` — injected timing, which the brief scores 0
   in the Behavior column. The card was never played, never digivolved and never reacted to a
   real opposing effect. Replaced by public-intent flows throughout.
2. **Q5078 was not proved.** The previous test set `autoSelectCards: true`, which always takes
   the maximum. That shows "2 can be placed", never "1 may not be". The new test asserts the
   published `min`/`max` bounds and that the engine refuses a 1-card answer.
3. **The host filter was not proved.** The previous negative gave the opponent one deletable
   Digimon, so a wrongly-firing second watcher had no legal target and the test still passed.
   Confirmed by mutation: dropping `hostFilter` left the old assertion green. The new fixture
   gives the opponent two play-cost-4-or-less Digimon plus a play-cost-6 one, so exactly one
   deletion is observable.
4. **The evolution route was `{ ok: true }` only.** Replaced with the real breeding route
   (hatch-position egg -> digivolve at 0 memory -> `moveFromBreeding`), asserting memory, the
   bonus draw, stack identity after each step, plus an illegal Red Lv.3 source negative
   (`{ ok: false, reason: "invalid-evolution" }`).

## Catalog discrepancy

`cards.json` stores a NON-BREAKING SPACE (U+00A0) before each occurrence of the word "trait" in
both `effectText` and `inheritedEffectText` for EX10-025 (three occurrences). The official text
uses ordinary spaces. Not edited, per the brief; the test asserts the stored form with an
explicit ` ` escape and a comment. Any client-side text search for "[Rock] trait" with a
normal space will miss this card. Worth a catalog-wide normalisation pass by the coordinator —
EX10-028 carries the same inherited sentence and is likely affected too.

## Remaining gaps

- The placement's card ORDER at the bottom of the stack is asserted as a set, not a sequence.
  `PlaceUnder` only reverses the selection when `order: "any"` is set, which the printed text
  does not grant, so no ruling fixes the relative order of the two placed cards.
- No test covers the inherited clause firing when the opponent has NO play-cost-4-or-less
  Digimon; the watcher would resolve with no legal target, which is uninteresting and untestable
  as an observable endpoint distinct from "did not fire".
- C1 is not exercised against a host in the breeding area. `underFilter` targeting defaults to
  the battle area, which matches the printed "your ... Digimon", so this is a non-gap.
