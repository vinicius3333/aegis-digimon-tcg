## Rulings covered

| Q&A | Question | Covered by |
| --- | --- | --- |
| Q5006 | Does the inherited effect trigger when a card gets linked by an effect to an already linked Digimon whose link card is trashed and replaced? A: No. | `Q5006: gains no memory when a link replacement trashes the old link card` |

Q5006 resolves through the engine, not through card IR: linking past the link limit
lands both cards and the §17-1-3-2-5 rule-check sweep
(`GameEngine.trashExcessLinkCards`) trashes the excess with `byRule: true`, and the
trash seam suppresses `whenLinkTrashed` for a rule trim
(`apps/api/src/engine/linkState.test.ts`, "suppresses whenLinkTrashed for rule trim
but fires it for an effect trash"). The new EX10-001 test proves the suppression at
the card level rather than only at the engine level, and then proves the same host
still pays out for a genuine effect trash, so the assertion cannot pass on a dead
watcher.

## What the previous audit missed

The committed test file scored the clause list only partially:

1. **No `[Your Turn]` proof.** Nothing exercised the opponent's turn, so a watcher
   that fired on both turns would have passed. Confirmed by mutation: changing the
   module's `trigger` from `YourTurn` to `AllTurns` now turns the turn-loop test red
   (it did not fail any committed test).
2. **No once-per-turn reset.** Same-turn refusal was asserted; the next-own-turn
   reset through the real turn loop was not.
3. **Q5006 was not covered at all.** The only listed ruling for this card had no
   test and no documented reason.
4. **A vacuous negative.** `does not gain memory when a non-link card is trashed`
   built a host with **no EX10-001 under it**, so the fixture had no inherited effect
   installed and the assertion was true by construction. It now carries the egg and a
   live link card, so it is a real negative.
5. **Non-public proof seam.** Every trash went through a private
   `(engine as unknown as { primitives }).primitives.trash(...)` reach-in. All trashes
   now go through the production verb `advance(s.engine).verb.trash(ids, byEffectSeat)`
   — the same seam production effects use — with the acting seat named, and the link
   replacement goes through the public `linkCard` intent.
6. **No catalog assertion.** Nothing pinned the printed fields or the exact
   inherited text; a catalog drift would have gone unnoticed.

## Round 2: the Digi-Egg route and carrier movement

Both round-1 gaps are now closed by two new behavioural tests (nine tests in total, up
from seven). Nothing was removed.

**1. The real Digi-Egg route, through public intents and the production turn loop.**
`hatches, digivolves in breeding, moves to the battle area, and pays out on that carrier`
drives the whole route:

| Step | Intent | Asserted endpoint |
| --- | --- | --- |
| hatch | `hatchEgg` (turn 1, Breeding phase) | egg deck empties; `breeding.topCard.instanceId` is the seeded egg instance |
| digivolve | `digivolve` onto the breeding permanent (turn 1, Main phase) | breeding top is BT21-047, `breeding.stack` is exactly the egg instance, same `permanentId`, battle area still empty |
| move | `moveFromBreeding` (turn 3, Breeding phase) | `breeding` is `undefined`; the battle-area permanent carries the same `permanentId`, top BT21-047, stack exactly the egg instance |
| link | `linkCard` (turn 3, Main phase) | one linked card, memory down by exactly `linkCostOf(BT21-047, 0)` |
| payout | `advance(...).verb.trash([link], 0)` | memory +1, `linked` empty, the link card in trash, no pending decision |

Two of the controller's own turns are required, not one: §6-4-1 allows exactly one
breeding action per turn and both `hatchEgg` and `moveFromBreeding` are gated on the
Breeding phase (`validateHatchEgg` / `validateMoveFromBreeding` in
`apps/api/src/engine/actions/breeding.ts`). The turn loop parks in the Breeding phase
whenever a breeding action is legal, so the test settles on `Phase.Breeding` with
`settleAcrossTimers` and sends the breeding intent there, then `waitForMainPhase` for
the Main-phase work — no `s.state.phase` assignment anywhere.

Fixture choice: BT21-047 Navimon is Green Lv.3 with the [Appmon] trait, digivolves from a
Green Lv.2 for 0, prints only an `[On Play]` (which a digivolve never fires), and its own
`[Link] [Appmon] trait: Cost 1` header makes a second copy a legal link card for that
carrier — so the whole route needs no synthetic grant.

**2. Carrier movement.** `keeps the isSelfRef binding on the carrier permanent when the
carrier digivolves again` digivolves the carrier BT21-047 -> BT22-050 Roamon (Green Lv.4,
still [Appmon], so the §17-1-3-2-6 link-legality sweep leaves the link card alone) and
then asserts, on the SAME permanent id: the stack is `["EX10-001", "BT21-047"]`, the link
card is untouched, a neighbouring permanent's link trash pays nothing, and the carrier's
own link trash still pays +1. Mutation-confirmed: dropping `sourceFilter` from the module
turns this test red.
