## What the previous audit missed

The committed test file scored no behavioural credit for the card's main clause:

1. **[On Play] was proved only by injected timing.** It called
   `advance(s.engine).fire(EffectTiming.OnPlay, s.perm("greymon"))` on a pre-seeded board
   permanent. Per the evidence standard that earns 0 in the Behavior column. Replaced with a
   real `playCard` intent from hand, with memory, hand size and battle-area membership asserted.
2. **The duration was proved by hand-driven ledger sweeps.** It set `s.state.turnSeat = 1` and
   called `advance(s.engine).ledgers.continuous.sweep(...)` / `.modifiers.sweep(...)` directly.
   That asserts the ledger API, not that the real turn loop expires the modifier. Replaced with
   a full turn loop, including the intermediate assertion that the buff survives the opponent's
   Main phase.
3. **Q5013 was not covered at all**, despite being listed in KB-INDEX.md.
4. **The substring name gate was untested.** The only digivolve case used EX10-006, whose name
   is exactly "Agumon", so swapping `names` for `namesExact` would not have failed anything.
   Added a ToyAgumon (BT7-007) case that only passes under a substring match.
5. **No illegal-source negative** for the alternate route. Added.
6. **The alternate route was never selected explicitly.** The old case omitted
   `useAlternateCost`. Added, alongside the memory-2 assertion.
7. **`toMatchObject` masked an added controller gate.** The shape assertion accepted extra keys
   on the target filter, so a regression re-adding `controller` (contradicting Q5012) would have
   passed. Tightened to `toEqual` on the actions array.
8. **No catalog field assertion.** Added `getCardDefinition("EX10-007")` field match.

## Engine seam for the coordinator

`controller: "self"` on a `ModifyDP` target filter is silently a no-op. Adding it to this card's
`OnPlay`/`WhenDigivolving` target changed no behaviour: the opponent's Digimon remained a legal
target and the Q5012 case still passed. `controller: "opponent"` on the same filter *does*
restrict correctly. So the two spellings of the field are asymmetric, and a card that means "one
of your Digimon" and writes `controller: "self"` gets no gate at all.

- Seam: the `ModifyDP` target resolution path under `apps/api/src/engine/effects/` (filter
  evaluation for `CardPredicate.controller`, `packages/shared/src/effects/ir/filters/cardPredicates.ts`).
- Expected: `controller: "self"` restricts candidates to the controller's own battle area.
- Actual: the field is ignored; candidates include both players' Digimon.
- Not a defect in EX10-007 (this card must have no gate), but it means any peer card relying on
  `controller: "self"` for a DP buff is unproven. Worth a sweep across the set.

No test is retained red for this card.
