## What the previous audit missed

The committed test proved `[Start of Your Main Phase]`, `[On Play]`, `[When Digivolving]`
and the inherited clause **only** through injected timing (`advance().fireForPermanent` /
`advance().fire`) and proved `＜Fortitude＞` through `advance().verb.deletePermanent`. Under
this run's evidence standard that is structural, not behavioural, so the previous 10/10
Behaviour claim was unsupported. It also had no evolution negative, no `[On Play]` play from
hand, and no coverage of either Q&A id as a ruling (Q5072's ordering was never exercised).

The rewritten file uses **no** injected timing at all: every clause is driven by
`startTurnLoop` / `runOneTurn`, `playCard`, `digivolve`, `attack` and `respondDecision`.

## Findings

- **No card defect found.** The module is faithful to the printed text and to both rulings.
  In particular the `selfTopHasText` gate correctly matches on `"name"`: a `"text"` match
  would fire on a `Belphemon: Rage Mode` host, because EX10-022's own `[Digivolve]` line
  contains the string `[Belphemon: Sleep Mode]`. That is now pinned by a public-route test.
- **Engine behaviour worth recording (not a defect, no red test).** The two
  `[Start of Your Main Phase]` effects only produce the `orderTriggers` decision when the
  Delete clause is *already* activatable, i.e. the opponent has a suspended Digimon or Tamer
  before the window opens. With no suspended target the Delete clause is not collected in the
  first activation tier (`apps/api/src/engine/effects/stack.ts`, `activationTiers` /
  `pickNext`), so it joins a later tier and resolves alone, with no choice offered. The
  observable result matches the ruling in every reachable case — the only order that differs
  is "delete first", which in that board state can delete nothing — so nothing is asserted
  red. The Q5072 tests construct the pre-suspended board that does raise the real prompt.
