## Defects found and fixed in this lane

The file on disk carried a cancelled lane's partial edits. Kept what was correct; fixed three
things, all in the test:

1. Typecheck error at the `＜Fragment (3)＞` attack: `target: { kind: "digimon", … }` is not an
   `AttackTarget`; the union is `"player" | "permanent"`. Corrected to `kind: "permanent"`.
2. Second attack of the same turn: the test declined a block that could not be offered. Blastmon
   suspended itself blocking the first attack, so the second block window opens with no eligible
   blocker and closes on its own. The `declineBlock` intent returned `{ ok: false, reason:
   "wrong-phase" }`. Replaced with a settle on the security drop plus `pendingDecision`
   undefined.
3. Wrong `＜Collision＞` assertion: the test expected the defender to publish a `Blocker` keyword.
   `＜Collision＞` is read at block legality (`apps/api/src/engine/combat/legality.ts`,
   `hasCollision`, CR 16-30), not granted as a keyword on the defender. The assertion now records
   `hasKeyword(chump, "Blocker") === false` and proves the rule behaviourally: `declineBlock` is
   refused and the non-Blocker's `declareBlock` is accepted.
4. The turn loop stalled on seat 1's Main phase; added the missing `endMainPhaseIfOpen(1)` before
   waiting for seat 0's Main phase.

Added: the Purple Lv.5 digivolve route, which the previous file never exercised (only the Black
row was proved).

No module change was needed. The module already matches the printed text and the three rulings.

## Round 3: the Q5101 negative

Three tests were added, all driven from public intents and the production turn loop.

1. **Blastmon against an unaffected recipient.** Seat 0 holds BT8-030 (printed 13000 DP), so
   EX10-010's `[All Turns]` gate — "while your opponent has a Digimon with 13000 DP or more,
   your opponent's Digimon's effects don't affect this Digimon" — is already open (BlackWarGreymon
   reads 15000 DP). Seat 0 then plays two Blastmon copies through `playCard`, aiming the first
   grant at BlackWarGreymon and the second at an ordinary BT1-019 on the same board
   (`preferInstanceIds`). Both grants are installed — the engine deliberately preserves an
   unaffectable selection (Q6740) — but at seat 1's Main Phase only BT1-019 attacks. Endpoints:
   exactly one `blockWindowOpened`, one security card checked, BlackWarGreymon unsuspended, no
   pending decision.

2. **Peer EX10-008, gate shut.** MetalGreymon is 7000 DP, so with it as seat 0's only Digimon the
   gate is shut (BlackWarGreymon reads 12000). Its identical grant lands: BlackWarGreymon gains
   ＜Collision＞ and the attack trigger, then really attacks on seat 1's Main Phase. ＜Collision＞
   is proved at block legality, not as a defender keyword — `declineBlock` is refused with
   `wrong-phase` and the non-＜Blocker＞ MetalGreymon's `declareBlock` is accepted, losing 7000
   to 12000 with security untouched.

3. **Peer EX10-008, gate open.** The same board plus BT8-030. ＜Collision＞ is never conferred
   (`GainKeyword` has no unaffectable-selection exemption and BlackWarGreymon is the only
   opposing Digimon, so there is no legal target), the trigger grant is installed and suppressed,
   and seat 1's whole Main Phase passes with no attack: security 2, no `blockWindowOpened`,
   BlackWarGreymon unsuspended.

Finding worth recording: Blastmon can never grant *into* a shut gate against EX10-010, because
Blastmon is itself a printed 13000 DP Digimon — the moment it enters, its own controller satisfies
"a Digimon with 13000 DP or more" and BlackWarGreymon is immune to it. The gate-shut mirror
therefore has to be staged with a lower-DP granter, which is what the EX10-008 pair does.
