## Defects found

- **Previous test proved nothing behaviourally.** The committed `EX10-002.test.ts` drove the
  clause only with `advance(s.engine).fireSubTrigger("whenAttackTargetSwitched", …)`, which is
  the same injected call for every card and never exercises the combat seam. Both behavioural
  tests were replaced with production `attack` / `declareBlock` flows.
- **No negative case.** There was no test showing the draw does *not* happen without a target
  change. Added.
- **No stack proof.** Koromon was only ever placed with `under:` in a Board Spec, never reached
  through breeding. Added the egg → Lv.3 → battle-area route.
- No defect was found in `EX10-002.ts`. The module is unchanged and its compiled IR still
  matches `effects.json`, so no sync is needed for this card.

## Remaining gaps

- The ＜Raid＞ (`controller.ts:722`) and effect-redirect (`primitives.ts:5731`) switch paths are
  not exercised by this card's tests; the ＜Blocker＞ path is proved and all three call the same
  `fireSubTrigger` seam. Engine-level coverage for the other two lives in

- No knowledge-base entry exists for EX10-002, so the unscoped reading rests on peer text
  (BT17-056 versus BT11-008), not on an official ruling.
