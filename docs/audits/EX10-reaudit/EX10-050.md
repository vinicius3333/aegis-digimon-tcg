## Defect found and fixed

`apps/api/src/cards/EX10/EX10-050.ts`, `[On Deletion]` target filter:
`match: "name"` -> `match: "nameExact"`.

`matchNameOrTrait` (`apps/api/src/engine/effects/interpreter/matching/definition.ts:349`)
implements `"name"` as substring and `"nameExact"` as equality, with the code's own
comment citing KB Q1231/Q1232 ("Cerberusmon: Werewolf Mode" does not match
"Cerberusmon"). `[Beelzemon]` is a bracketed exact-name reference, so the shipped IR
also offered `Beelzemon: Blast Mode` (BT19-074, BT19-074/EX2-074/ST14-10) and
`Beelzemon (X Antibody)` (BT12-085) from the trash for free.

Mutation proof: reverting the single token to `"name"` and rerunning only the
exact-name test fails with the Blast Mode card on the battle area
(`docs/audits/EX10-reaudit/logs/EX10-050-mutation.log`).

## Test coverage rewritten

The committed test proved the two triggered clauses only through
`advance(...).fireForPermanent` and the deletion only through
`advance(...).verb.deletePermanent` — injected timing, which the brief scores 0 for
behaviour. It also had no negative case, no optional-refusal case, no duration proof, no
digivolve route and no exact-name case, and its inherited test asserted a static board
rather than a stack built by intents.

The new file drives every clause through public intents: `playCard`, `digivolve`
(both routes plus two refusals), `attack` into a suspended larger Digimon for the
deletion, and `startTurnLoop` for the duration. One structural test is retained and
labelled as such: it fires `WhenDigivolving` directly on a seeded permanent to show the
two trigger branches share one clause body, and it earns no behavioural credit.

Fixtures: ST10-10 Wizardmon is a fully inert Lv.4 [Wizard] (no main, inherited or
security text); BT2-111 is the only [Beelzemon] with no `[On Play]` clause, so playing
it from the trash cannot open a decision; BT1-009/BT1-013/BT1-014 are the inert
main-deck Digimon; no Digi-Egg and no numeric `security: <n>` form is used.

## Remaining gaps

- ＜Reboot＞ is proved as a granted keyword through `observe(...).hasKeyword`, not by
  observing an unsuspend during the opponent's unsuspend phase. The grant expires at the
  end of the opponent's turn, so the keyword can never reach the controller's own
  unsuspend phase; its only in-window use is combined with an opponent-turn ＜Blocker＞
  block. No behavioural refinement is possible inside the printed duration.
- ＜Blocker＞ is proved as granted, not exercised by a `declareBlock`. The block path is
  engine-shared and already proved by EX10-002; the card-specific fact is the grant and
  its condition.
- `effects.json` will drift for EX10-050 because the compiled IR changed. The coordinator
  owns the sync; the file was not touched.

No red tests retained. No engine seam gap found for this card.
