## What changed

Only `apps/api/src/cards/EX10/EX10-069.test.ts`. The module is unchanged, so
`packages/shared/src/effects/effects.json` does not drift.

The committed test proved every behavioural clause through injected timing
(`advance.fireForInstance`, `advance.fireSubTrigger`) and reached past the seam by writing
`s.perm("emblem").placedByEffect = true` to keep a Board-Spec-seeded Option alive against the
§17-1-3-2-2 rule sweep. Under the brief's evidence standard that scores 0 in the Behaviour
column. The rewrite drives every clause publicly:

- The Option is now **played** with `playCard`, so the engine's own colour gate, its play cost
  and `PlaceInBattleAreaSelf`'s `placedByEffect` marker are all exercised rather than asserted
  into place.
- The ＜Delay＞ window is reached by a **real [Close] suspension**: playing EX10-028 Landramon
  pays its `[On Play]` cost by trashing an inert [Mineral] digivolution card, which fires
  EX10-063 Close's own `[All Turns]` "by suspending this Tamer, gain 1 memory". That suspension
  goes through `primitives.suspend` -> `fireSuspensionTriggers` -> `whenSuspended`.
- §16-17-3 is proved by the **real turn loop**: the same chain run on the turn the Option
  entered play leaves the ＜Delay＞ unspent; run on the next own turn it fires.
- `[Security]` is proved by a **real attack** that checks security, with no ＜Blocker＞ on the
  defending side so the block window closes on its own.

Fixtures follow the brief: no Digi-Egg and no numeric `security: <n>`; BT10-062 Golemon is the
inert [Mineral] card (no main and no inherited text) and doubles as the Black colour anchor;
BT1-009/013/014 fill decks and security.

## Round 2: what was added

Still only `apps/api/src/cards/EX10/EX10-069.test.ts`. The module is unchanged, so
`packages/shared/src/effects/effects.json` does not drift.

1. **The ＜Delay＞'s own decline is now proved.** The round-1 gap was that the window nests two
   optionals (Close's "by suspending this Tamer" cost and the Delay's "trash this card to
   activate" ask) while `autoAcceptOptional` / `autoDeclineOptional` are global. The new test
   drops both flags and answers every `optional` request by hand through the public
   `respondDecision` intent, routed by `DecisionRequest.sourceCardId` read from `s.decisions`
   (helper `answerOptionals`). It accepts the Close suspension and declines EX10-069's own ask,
   then asserts that both prompts really were raised, that the Option stays in the battle area
   and out of the trash (no §16-17-1 cost paid), that the host keeps its top card, that the
   hand card stayed put with no digivolution draw, and that memory is 5.
2. **The `[Rock]` half of the C4 base filter is proved.** BT4-065 Gotsumon is Black Lv.3,
   carries `[Rock]` and NOT `[Mineral]`, and has no main and no inherited text — the only fully
   inert `[Rock]` Lv.3 in the pool. EX8-048 digivolves from any black Lv.3 for 2, so the route
   is legal without help. `delayBoard` now takes the host card id; every existing scenario keeps
   the `[Mineral]` Sunarizamon host.
3. **An illegal-base negative was added.** Board: EX10-063 Close, BT10-062 Golemon (Lv.4,
   `[Mineral]`, inert) carrying an inert `[Rock]` card, and BT3-060 Psychemon (Black Lv.3,
   `[Reptile]`, inert). Landramon's cost trashes the `[Rock]` card from a `[Mineral]` Digimon's
   digivolution cards, so Close suspends and the window really opens — but no legal base exists:
   Golemon and the played Landramon are Lv.4 (EX8-048 needs a black Lv.3), and Psychemon, the
   one black Lv.3, carries neither trait. `preferInstanceIds` biases the selection toward
   Psychemon, so the assertion is that the base filter — not candidate ordering — is what
   refuses it.

## Remaining gaps

1. **The host is Board-Spec seeded, not bred.** The digivolution stack is real after the fact
   (the fuel card is trashed by an effect and the Lv.3 base ends up under the Lv.4), but the
   host itself never came through hatch -> breeding -> battle area. This is a fixture shortcut,
   not an untested clause: the ＜Delay＞ reads the host's traits and level, both of which the
   seeded permanent carries from its real card definition.
2. **The illegal-base negative cannot isolate a single reason on one permanent.** The window
   only opens when a `[Mineral]`/`[Rock]` Digimon loses a digivolution card (that is Close's own
   requirement), so a board where the ONLY Digimon lacks both traits cannot raise the window at
   all. The test therefore keeps a trait-legal but level-illegal Lv.4 as the trigger and puts
   the trait-illegal card at the one legal level; `preferInstanceIds` and the mutation run show
   the base filter is what refuses it.
