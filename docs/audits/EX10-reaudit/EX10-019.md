## What changed

Only `apps/api/src/cards/EX10/EX10-019.test.ts`. The module is byte-identical, so
`packages/shared/src/effects/effects.json` does not drift.

Removed from the previous test (the coordinator's finding, confirmed):

- `advance().fireForPermanent(EffectTiming.WhenDigivolving, ...)` → replaced by a real
  `digivolve` intent.
- `advance().fireSubTrigger("whenLinked", ...)` for the [Once Per Turn] second use →
  replaced by a second real `linkCard` intent in the same turn, after the link slot is freed
  by the card's own link effect paying its cost.
- `advance().ledgers.continuous.addRestriction(...)` → replaced by
  `advance().verb.restrict(...)`, the production primitive every `Restrict` clause compiles to.
- `advance().ledgers.continuous.addLinkMaxGrant(...)` → replaced by BT21-101 Gaiamon's
  **printed** `＜Link +1＞`, asserted through `observe().linkMaxDelta`.
- `advance().verb.suspend(...)` → replaced by a declared block (the blocker suspends), and in
  the turn-loop test by this card's own [All Turns] clause suspending the opponent's Digimon,
  which then feeds its own link effect.
- `advance().verb.appFuseInto(...)` → replaced by the public `appFusion` intent, which does
  exist (`packages/shared/src/protocol/intents.ts`, handled in `GameEngine.ts`).
- `advance().verb.deletePermanent(...)` for ＜Fortitude＞ → replaced by a real battle deletion.

The only remaining arming is one `advance().verb.restrict(target, "beSuspended", Permanent)`
in the Q5054 test: no card in the permitted fixture pool prints "can't be suspended", and
Q5054 is a question about exactly that state. It goes through the production primitive, inside
the seam.

## Defects found

Two expectation defects in the previous test, both of which had blessed wrong numbers:

- it asserted `memory` 0 after linking BT24-053 Protecmon with 3 memory. Protecmon's printed
  link cost is **1**, so the correct endpoint is 2 (the fixture now starts at 1 and ends at 0).
- it never asserted the recipient's DP after the [On Play] link. The correct value is 10000
  (8000 printed + Protecmon's Link DP 2000).

No module defect found. Every clause matches the printed text and the six rulings.

## Remaining gaps

- `[All Turns]` on the whenLinked clause is proved on my own turn only. No public intent links
  a card on the opponent's turn, and no permitted fixture grants an opponent-turn link, so the
  "opponent's turn" half of `[All Turns]` is unproved for clause 4. (Clause 6, the link effect,
  *is* proved on a suspension the opponent causes — a declared block on my attack.)
- The link effect has no `[Once Per Turn]`, so it may fire on every opponent suspension in a
  turn. Only one firing per turn is asserted; a multi-suspension turn is untested.
- App Fusion is proved with Mienumon on top and Sakusimon linked. The reverse orientation is
  proved only through `appFusionCostFor`, not on a board.
- `s.decisions` never carries a `selectCards`/`chooseTargets` request for the `Link` action's
  card choice — only `optional` prompts appear, so the candidate set cannot be asserted
  directly. Both link filters are therefore proved by outcome plus a negative control. Worth a
  seam note for the coordinator: an observable candidate list for `Link` would make these
  filters directly assertable.
