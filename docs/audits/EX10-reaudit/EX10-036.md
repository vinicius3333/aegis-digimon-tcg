### Fixtures

The previous test file used EX10-025, EX10-028 and EX10-032 as the cost pool. All three
print `When effects trash this card from a [Mineral] or [Rock] trait Digimon's digivolution
cards, delete 1 of your opponent's Digimon ...` (EX10-032 prints ＜De-Digivolve 1＞). Trashing
three of them fires three inherited deletions, so the old assertion "the opponent's battle
area is empty" could not tell Magneticdramon's own deletion from the fixtures'. Every fixture
is now a card with no printed and no inherited text at all: BT10-062 ([Mineral]), BT10-064
and BT4-065 ([Rock]), BT2-011 ([Rock Dragon], near-miss), BT1-009/BT1-013/BT1-014/BT1-019,

## Defect fixed locally

`allowCostWithoutTarget: true` added to both `Delete` actions in `EX10-036.ts`.

- Expected: with no opponent Digimon on the board, C3 is still usable — the deletion is the
  impossible part, and comprehensive rules §1-3-2 still performs the rest, so the cost is
  paid and the opponent's top security card is trashed.
- Actual before the fix: nothing happened. Nothing was trashed, the security stack was
  untouched. `apps/api/src/engine/effects/interpreter/actions/runAction.ts` preflights every
  costed `Delete` (`action.kind === "Delete" && action.cost !== undefined &&
  action.allowCostWithoutTarget !== true && candidatePermanents(...).length === 0`) and, with
  `abortOnDecline: true`, aborts the whole action list — including the sibling
  `trashSecurityTop`. The preflight is right for a single-result clause; this clause has two
  results, so it opts out.
- Covered by `trashes the top security card even when the opponent controls no Digimon to delete`.

This changes the compiled IR, so `packages/shared/src/effects/effects.json` now drifts for
EX10-036. The coordinator runs the sync.

## Open question, not a retained red

The `Unsuspend` preflight in the same file aborts a costed `Unsuspend` whose target is not
suspended. C4 is therefore never offered when Magneticdramon is already unsuspended — for
example on a plain [When Digivolving] window during your own turn after the unsuspend phase.
A player might reasonably want to pay the cost anyway, because placing 3 cards under it feeds
＜Fragment (3)＞ and C3's own cost. No ruling in the KB settles whether an effect whose only
result is a no-op may still be activated, so the behaviour is documented rather than changed
or asserted red. Every test here works with the engine's current reading and says so.

Also observed, not asserted as an order: when three cards are placed at the bottom in one
step the engine lays them in reverse selection order. Placement order among simultaneously
placed cards is the placing player's choice, so the test asserts membership of the bottom
three and the exact positions of the cards that were already in the stack.
