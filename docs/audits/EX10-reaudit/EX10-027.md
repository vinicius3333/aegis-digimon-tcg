## Defects found and fixed

**D1 — ＜Save＞ landed in the wrong stack position (fixed, load-bearing).**
The committed `OnDeletion` `PlaceUnder` carried no `position`. `runPlaceUnder`
(`apps/api/src/engine/effects/interpreter/actions/placeUnder.ts:269`) computes
`belowTop: action.position !== "bottom"`, so a positionless action tucked the saved card
directly beneath the Tamer instead of at the bottom of the stack (comprehensive rules 4-3).
Added `position: "bottom"`, matching the accepted sibling `EX10-026.ts:76` and `EX10-025.ts`.

Proved load-bearing by mutation: replacing the `position: "bottom"` line with a comment and
re-running the file fails exactly one assertion for the intended reason —

```
× [On Deletion] ＜Save＞ places it under a Tamer after it loses a battle
AssertionError: expected [ 'inst-254', 'inst-255', 'inst-251' ] to deeply equal
                         [ 'inst-251', 'inst-254', 'inst-255' ]
```

(log: `logs/EX10-027-mutation.log`; the module was restored immediately afterwards.)

**D2 — the committed test was structural.** The `HEAD` version asserted IR shape and used
`EffectTiming` / `advance` injected timing, which earns no behavioural credit under this
brief. Replaced with the public-intent suite described above. The previous lane had already
begun that rewrite; I verified every fixture against the catalog (see the Q5081 table), kept
the parts that hold up, and added the two cases below.

## Remaining gaps and engine observations

**G1 — with no legal return target the cost is skipped as well.** In
`cannot return a Digimon that matches neither [Knightmon] text nor the two traits`, the
engine resolves the whole `Return` action to a no-op: no hand card is trashed. Q5082 says
the player *may* pay and return nothing, so refusing to pay is not itself illegal, but the
choice is being made for the player. It is observable: trashing a hand card feeds
trash-count effects (`AD1-018` reduces its play cost by 5 with four Knightmon-text cards in
the trash). This is an interpreter-wide `Return`-with-cost behaviour, not an EX10-027 defect,
so I recorded it rather than editing the shared seam. Seam:
`apps/api/src/engine/effects/interpreter/actions/` return-action target resolution.

**G2 — no ACE / Security / DigiXros / Link surface.** The card prints none, so nothing is
untested there.

**G3 — the `abortOnDecline` outer prompt.** The printed "may" sits on the return, not on the
cost, and the engine additionally offers an outer accept/decline before the cost. That is
player-favorable and cannot produce an illegal board (declining is equivalent to not
activating), so I left it; it is why `declining the optional pays no cost` is a separate case
from the Q5082 case.
