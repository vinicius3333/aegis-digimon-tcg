Inherited text (the only printed clause set):

> [Opponent's Turn] [Once Per Turn] When one of your opponent's Digimon attacks, by trashing
> 3 [Mineral] or [Rock] trait cards from this Digimon's digivolution cards, end that attack.

Printed clauses:

1. `[Opponent's Turn]` gate.
2. `[Once Per Turn]` gate.
3. Trigger: one of your **opponent's** Digimon attacks.
4. Processing condition ("by"): trash 3 **cards** with the `[Mineral]` or `[Rock]` trait from
   **this Digimon's** digivolution cards. Not "Digimon cards" — the Digi-Egg at the bottom of
   the stack counts, and Tumblemon itself carries `[Rock]`.
5. Result: end that attack.

Catalog agrees with the official text (single `inheritedEffectText`, no main or Security text,
types `Rock` / `LIBERATOR`). No discrepancy found.

## Round 2 additions

1. **The real Digi-Egg route is now proved end to end.** New test: "hatches from the egg deck,
   grows in breeding, moves to the battle area and ends an attack there". It runs on the real
   turn loop and uses only public intents:
   - Turn 1 (seat 0): settle on `Phase.Breeding`, `hatchEgg` — the egg deck goes 1 -> 0, a
     `hatched` event is emitted, breeding holds EX10-003 with an empty stack. A
     `moveFromBreeding` in the same turn is then refused with `wrong-phase` (the single
     breeding action of the turn is spent, Comprehensive Rules 6-4-1).
   - Turns 1, 3 and 5: `digivolve` in the breeding area builds the stack
     EX10-003 [Rock] -> BT4-065 Gotsumon Lv.3 [Rock] -> BT10-062 Golemon Lv.4 [Mineral] ->
     BT10-064 Gogmamon Lv.5 [Rock] top. All four are fully inert (no effect and no inherited
     text), so no fixture effect can move the endpoints. The breeding window on turns 3 and 5
     is skipped with `endPhase`.
   - Turn 7: `moveFromBreeding` carries the stack to the battle area; the permanent keeps its
     `permanentId`, the top card is BT10-064 and `stack` is exactly
     `["EX10-003", "BT4-065", "BT10-062"]`.
   - Turn 8: the opponent attacks the player. The inherited clause fires on that carrier,
     trashes exactly those three cards (asserted by instance-id difference against the trash
     before the attack), leaves the top card in play, keeps security at its previous length,
     emits no `securityChecked`, and leaves no pending decision.

   Three matching cards under the top is the minimum the printed cost can be paid with, which
   is why the chain runs to Lv.5; each digivolve is a separate turn so the memory cost of one
   never ends the turn early.
2. **The last internal cast is gone.** Three tests read
   `(s.engine as unknown as { combat: { isAttacking: boolean } }).combat` to settle on the end
   of the attack. They now use the seam's `observe(s.engine).isAttacking()`. No test in this
   file reaches past `apps/api/src/engine/testkit/` any more.

Gaps found in the inherited suite and closed:

## Retained red

None. The previously retained `it.fails` for Q5009 is now a passing `it`.

Root cause of the old red: the test file never imported the card index
(`import "../index.js";`), so the immunity-granting fixture card EX8-029 was unregistered and
its `[All Turns]` grant never installed. The engine seam named in the earlier report
(`apps/api/src/engine/effects/interpreter/actions/grantStatic.ts`,
`immuneToOpponentDigimonEffects`) is correct as written: with the index imported,
`hasRestriction(attacker, "beAffected", "Digimon")` reads `true` after
`recomputeContinuousEffects()` and the whole scenario resolves as the ruling says.

Follow-on fixture change forced by the same import: with the index registered, EX10-025's
inherited "when effects trash this card from a [Mineral] or [Rock] trait Digimon's digivolution
cards, delete 1 of your opponent's Digimon with a play cost of 4 or less" now actually fires and
deleted the second attacker in the once-per-turn test. That test's cost pool was swapped to the
inert [Mineral]/[Rock] fixtures the brief names (BT10-062, BT10-064). The other tests keep
EX10-025 on purpose: they assert the trashed card ids, and the side deletion does not touch
their endpoints.

## Remaining gaps

- **Q5008 counter-timing half is unproved, and the engine looks wrong here.** In
  `apps/api/src/engine/combat/controller.ts` (`CombatController.resolveAttack`),
  `runCounterWindow` is awaited *before* the `if (this.endRequested)` check, so an attack ended
  during the When Attacking timings — which is where `whenOpponentAttacks` fires — still
  transitions to counter timing. Q5008 says it must not. I could not turn this into a red test:
  no `counterWindowOpened` event is emitted in any fixture I built, because none of the
  battle-area `[Counter]` cards I placed (BT26-055, BT26-103, EX12-017, EX12-052, EX12-057,
  BT15-076, LM-001) is reported by `GameEngine.counterEligibleSources`, even on an attack that
  runs to a full security check. That is a second, independent seam and it is what blocks the
  proof; a false-green `it.fails` would have been worse than reporting it. Coordinator: the
  ordering fix and the counter-eligibility gap both need an engine lane.
- **The `[Opponent's Turn]` gate is not isolated from the trigger.** "One of your opponent's
  Digimon attacks" can only happen on the opponent's turn, so no fixture separates the two.
- **The counter half of Q5008 is still the only unproved printed consequence** (see above).
- **Peer coverage is narrow by nature.** The card has no name gate, no evolution route of its
  own and no Security text, so the peer axis is the trait pool and the host stack.
