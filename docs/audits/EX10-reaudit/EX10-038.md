## Catalog fact that shapes C2

Every card in the catalog carrying the `[Leviathan]` trait also carries `[Appmon]`
(checked over the whole of `cards.json`: 0 Leviathan-only cards, 90 Appmon-only cards). The
two add slots therefore always compete for the same revealed cards. The interpreter
resolves the `[Appmon]` slot first and marks the picked card as taken
(`apps/api/src/engine/effects/interpreter/actions/reveal.ts`, the `taken` set), so a
controller must spend a non-Leviathan Appmon on the first slot to fill both. That is the
correct rules outcome — the slots are two separate cards — and the test steers the two
prompts with `preferInstanceIds` to prove it, while a separate test proves a lone
dual-trait card fills exactly one slot.

## Defects found in the previous audit's test

The committed test claimed 10/10 but proved less than it appeared to:

1. C2 was proved only by `advance(...).fireForPermanent(EffectTiming.OnPlay, ...)`, which
   is injected timing and earns no behavioural credit. Replaced by a real `playCard` from
   hand with the memory payment and the resulting permanent asserted.
2. C1 was asserted only against the compiled IR, never through the `digivolve` intent. Now
   proved with an off-colour Lv.2 `[Appmon]` egg (the alternate route is the only legal
   route there) plus a non-Appmon negative.
3. The Q5117/Q5118 board seeded two link cards on a host with the default link maximum of
   1. The rule sweep trashes the over-cap link at the attack, so the assertion "the cost
   card is in the trash" passed even without the effect running. Rebuilt on BT26-086
   Dantemon (＜Link +6＞) so two links are legal, which turned the case into real proof.
4. No optional-refusal case and no "cost card is itself the only target" case existed.

No change was needed in `EX10-038.ts`; the compiled IR matches the printed text. Only the
test file changed.

## Catalog discrepancy

`cards.json` `EX10-038.linkRequirement` is `"[Link] [Appmon] trait: Cost 1"` — a
non-breaking space (U+00A0) sits between `[Appmon]` and `trait` where every other field
uses a normal space. Cosmetic only (the compiled requirement is correct), reported and not
edited. The catalog test normalizes whitespace and states why.

## Rules question for the coordinator

C4's cost is paid before the return resolves, so the trashed link card is itself in the
trash when the target is chosen. With no other `[Appmon]` Digimon in the trash, the engine
returns the just-paid Copipemon to the hand — the net effect is "pay nothing, return
nothing but this card". Q5117 says the card may pay for itself, so this looks right, but no
ruling in the KB states whether the return may pick the card that just paid. Recorded as
passing behaviour with the reasoning in the test comment.

Related engine note (no test retained red): `runAction.ts` preflights an empty target pool
only for a battle-area `Return` — the `returnsLooseCard` branch deliberately skips the
preflight when the filter names another zone. For this card the skip is harmless because
the cost always supplies a legal target, but a trash-sourcing return whose cost does not
feed the trash can still consume its cost for nothing.

## Remaining gaps

- The `[Appmon]` add slot resolving before the `[Leviathan]` slot is proved with steered
  prompts. A controller who answers the first slot with the dual-trait card fills only one
  slot; the engine offers no guidance. This is a UI concern, not an engine defect.
- No test covers a deck of fewer than 3 cards at `[On Play]` (`fx.reveal` returns what it
  has); the reveal count boundary was judged out of scope for this card.
- Link-effect proof uses a seeded link board. The `linkCard` intent is exercised separately
  in the C3 test, but not chained into the same scenario as C4.
