No catalog discrepancy found. The card has exactly one printed clause.

Printed clause, split into the parts a test must pin:

1. Window: `[Your Turn]` only.
2. Frequency: `[Once Per Turn]`, resetting on your next own turn.
3. Trigger: the **opponent's** deck is trashed from (not your own).
4. Effect: draw 1 card.
5. It is an inherited effect, so it only works from under a Digimon.

## Rules and Q&A

- `Q5011` (2025-09-05): "Does this card's inherited effect trigger if a card is revealed
  from the deck and trashed?" — **No.**
- Backing rule: comprehensive §15-15-3 "Effects That Reveal Cards": *even if cards revealed
  from a deck are trashed, they aren't treated as being trashed from the deck.*

Engine seams read to confirm the semantics:

- `apps/api/src/engine/effects/primitives.ts:2947` `fireOnDiscardLibrary(deckSeat, ids)` —
  the payload's `addedToHand.byEffect.ownerSeat` carries the **milled deck's** seat, not the
  effect owner's seat.
- `apps/api/src/engine/effects/interpreter/actions/subTrigger.ts:247` `discardLibraryGate` —
  compares that seat against the watcher's controller direction.
- Fire sites: `interpreter/actions/resources.ts:126` (`TrashTopDeck`),
  `interpreter/actions/removal.ts:581` (trash target with `zone: "deck"`),
  `interpreter/costs.ts:1109` (deck-trash cost).
- `interpreter/actions/reveal.ts:755` (`returnRevealed === "trash"`) does **not** fire it —
  this is what makes Q5011 correct in the engine today.

## What changed

Only `apps/api/src/cards/EX10/EX10-005.test.ts`. The module needed no change.

The previous test proved three of its four cases with injected timing
(`advance(...).fireSubTrigger("onDiscardLibrary", …)` and hand-built payloads). Under the
re-audit rubric those earn no behavioural credit, and one of them was actively misleading:
the payload named `byEffect.ownerSeat` as if it were the effect owner, when the production
seam puts the milled deck's seat there. All injected cases were replaced with
natural-origin ones driven by public intents (`playCard`, `attack`), the production turn
loop, and the production deletion verb. `EX10-005.test.ts` no longer calls
`fireSubTrigger`/`fireTiming` at all.

Fixture correction after coordinator review: the EX10-009 case still carried the previous
test's seat 1 deck of `BT1-001..BT1-006`, which are Digi-Eggs and must never sit in a deck
fixture. It now uses inert main-deck Digimon (`BT1-009..BT1-014`). No assertion changed —
the case still asserts 5 cards trashed, 1 card left in the deck, and the exact drawn
instance in hand.

Added coverage that did not exist before: the catalog/IR contract case, the once-per-turn
**reset** across a real turn boundary, the own-deck negative, the `[Your Turn]` negative
proved by an opponent's own play on their turn, and Q5011.

## Digi-Egg route (round 2)

Round 1 proved the clause only from pre-seeded `under:` stacks, so the Peer/stack column
scored 1. Round 2 adds the real Digi-Egg lifecycle, driven end to end by public intents on
the production turn loop:

1. `startTurnLoop()`; the loop parks in `Phase.Breeding` because seat 0's egg deck holds
   EX10-005 (asserted: breeding empty, egg deck length 1).
2. `applyIntent(0, { type: "hatchEgg" })` — breeding top card becomes EX10-005, egg deck
   empties. The egg's instance id is captured here and asserted by identity from then on.
3. `applyIntent(0, { type: "digivolve", permanentId: <breeding>, instanceId: BT2-067 })` —
   a Purple Lv.3 DemiDevimon (no printed text) digivolves onto the egg in the breeding area
   for 0 memory and draws 1. Asserted: breeding stack is exactly the egg instance, hand is
   exactly `[skullsatamon, evoDraw]`, battle area still empty.
4. `endPhase` for both seats through `advance().endMainPhaseIfOpen`, one full opponent turn,
   then settle on `Phase.Breeding` for seat 0 again.
5. `applyIntent(0, { type: "moveFromBreeding", permanentId: <breeding> })` — breeding is now
   undefined, battle area holds one permanent whose top card is BT2-067 and whose
   `stack` is exactly the egg instance.
6. `applyIntent(0, { type: "playCard", instanceId: BT14-077 })` in that turn's Main phase —
   the `[On Play]` mills the top 2 of both decks and the inherited clause fires **on the
   hatched carrier**.

Endpoints asserted after settling: seat 0's hand is exactly
`[evoDraw, turnDraw, drawn]` by instance id (the third is the Pagumon draw), seat 0's trash
is exactly `[milled1, milled2]` by instance id, seat 0's deck is `["BT1-014"]`, seat 1's
deck is down to 2, the carrier's stack is still the egg instance, and `pendingDecision` is
undefined. The turn loop is closed with `surrender` and awaited.

No `advance().fire*` call appears anywhere in this case, and no `s.state.phase` is written
by hand — the Breeding windows are the production ones.
