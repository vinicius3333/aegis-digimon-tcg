## What this re-audit changed

The module `EX10-008.ts` was **not** changed. The previous audit's IR is correct as far as
this lane could test it.

The test file was rewritten. The previous version proved C2 and C3 only through injected
timing (`advance.fire(EffectTiming.OnPlay, ...)` and
`advance.fireSubTrigger("startOfYourMainPhase" / "whenAttackTargetSwitched")`), which is
structural evidence only. Every clause now has a natural origin:

- C2 On Play now originates from a `playCard` intent (cost 7 paid, hand and battle area
  asserted), not a fired timing window.
- The gained `[Start of Your Main Phase] This Digimon attacks.` now fires from the real
  turn loop (`engine.runOneTurn()` for seat 1). No intent declares that attack; the test
  waits for the ＜Collision＞-forced block window to open, blocks, and asserts the
  attacker suspended, `hasAttackedThisTurn`, and seat 0's security untouched because the
  attack was blocked.
- The ＜Collision＞ half is now proved by its rules effect (§16-30): a plain Digimon with
  no ＜Blocker＞ becomes an eligible blocker, and `declineBlock` is refused.
- C3 now originates from a real ＜Blocker＞ declaration
  (`combat/controller.ts switchDefenderToBlocker`, the production publisher of
  `whenAttackTargetSwitched`), for the positive case, the once-per-turn case (two real
  attacks and two real blocks in one turn), the name gate and the turn window.
- A catalog conformance test was added.

Also fixed in the test: `expect(perm.stack).toEqual([])` compared a colyseus `ArraySchema`
against a plain array; it now compares `stack.map(card => card.cardId)`.

## Round 3 additions (peer / stack 2/2)

Three tests were added; nothing was removed and every previous assertion still stands.

### (a) Comparative peer case for the target-switch convention

Round 3 settled seam 5: a generic "When attack targets change" watcher has no attacker-is-self
gate; only cards printing "this Digimon's attack target" carry one. The peer chosen is
**BT11-008 Bearmon** — implemented, quiet (its own file passes), and its IR carries
`condition: { kind: "triggerAttackerIsSelf" }`, the gate EX10-008 deliberately lacks. EX9-054 was
rejected as the peer: its printed text is also the unscoped "When attack targets change", so it
is on EX10-008's side of the convention, not the opposite side.

The contrast runs on one board, in one turn, on one switch, with both windows open at once.
EX10-008's window is `[Opponent's Turn]`, so its host sits on the defending seat; BT11-008's is
`[Your Turn]`, so its host sits on the attacking seat. Seat 1's turn, a third Digimon attacks and
a fourth blocks:

- EX10-008's unscoped watcher fires although its host neither attacked nor blocked — seat 1's
  top security card is trashed (2 -> 1).
- BT11-008's self-scoped watcher sees the identical switch with its `[Your Turn]` window open and
  stays silent — its host holds at 5000 DP.

The control test proves that watcher is alive on the same board shape: when the BT11-008 host is
itself the attacker and is blocked, it pays out (5000 -> 8000 DP) while the unscoped EX10-008
watcher fires for that same switch too.

### (b) Q5014 proved end to end through public play

The pre-existing Q5014 test reaches immunity through `advance.verb.restrict`. Two new tests reach
it through cards only, using **EX10-010 BlackWarGreymon** as the grantee: its `[All Turns]` clause
grants "your opponent's Digimon's effects don't affect this Digimon" while its opponent controls a
Digimon with 13000 DP or more.

- Negative (gate opened publicly): seat 0 plays EX10-008 for 7 and grants ＜Collision＞ plus the
  forced attack to the opposing EX10-010 (both halves asserted live). Seat 0 then plays
  **BT8-030** (printed 13000 DP) from hand — the only board change. EX10-010's gate arms, which
  the board shows independently as 12000 -> 15000 DP. ＜Collision＞ goes inactive at once, and
  running seat 1's real turn produces no attack: the grantee is unsuspended, has not attacked, no
  block window opened, and seat 0's security is untouched.
- Mirror positive (gate shut): the same fixture without BT8-030. EX10-010 stays at 12000, the
  granted `[Start of Your Main Phase] This Digimon attacks.` fires from the real turn loop, the
  ＜Collision＞ half forces seat 0 into the block window, and seat 0 blocks.

Q5014 no longer rests on a test-only restriction primitive: the immunity now arrives from a
printed card clause armed by a public `playCard`.

### Engine seam observed on the peer (BT11-008, not this card)

While building the comparison, a two-switch variant showed BT11-008's `[Once Per Turn]` budget
being consumed by a switch its `triggerAttackerIsSelf` condition then rejected: after a
non-qualifying switch earlier in the same turn, a later qualifying switch paid nothing, while the
same qualifying switch alone pays +3000. That points at the frequency gate being decremented
before the action-level condition is evaluated
(`apps/api/src/engine/effects/interpreter/actions/subTrigger.ts`, the `frequency` bookkeeping
around the installed watcher versus the per-action `condition` check in `runAction`). It does not
affect EX10-008, which has no such condition, so no red test is retained here; reported for the
coordinator because it would misprice BT11-008/BT11-010/BT11-014. The two shipped peer tests use
one switch each, so they do not depend on the ordering either way.

## Q5014 — what is actually proven, and what is not

The test plays MetalGreymon, gives the grant, then applies a blanket `beAffected`
restriction to the grantee through the production restriction primitive and runs seat 1's
turn. The observable result matches the ruling: the grantee does not attack, no block
window opens, and seat 0's security is untouched.

The ＜Collision＞ half is genuinely gated: `ContinuousEffects.keywordGrantIsActive`
(`apps/api/src/engine/effects/continuous.ts:1164`) re-checks the recipient's `beAffected`
restriction on every read, so the grant deactivates the moment immunity applies. That is
the mechanism Q5015 needs, and Q5015 is proved end to end.

The gained-trigger half is **not** demonstrably gated the same way. Grep found no
`beAffected` check in `apps/api/src/engine/effects/subtriggers.ts` or in
`apps/api/src/engine/effects/interpreter/actions/subTrigger.ts`. The installed
`startOfYourMainPhase` watcher is a discrete install, not a continuously re-derived grant,
so nothing re-evaluates immunity at the trigger timing. In the fixture used, the absence of
the attack is consistent with the ruling but may be produced downstream (the `Attack`
action failing for an unaffectable subject) rather than by a trigger-timing immunity gate.
This is recorded as a gap rather than claimed as proof — see below.

## Remaining gaps

   endpoint is now proved through a fully public route (EX10-010's printed immunity armed by
   playing a 13000 DP Digimon), so the observable behaviour is card-driven rather than
   primitive-driven. The internal question below is unchanged — the correct outcome is reached,
   but this lane still cannot show which mechanism produces it. Seam:
   `apps/api/src/engine/effects/interpreter/actions/subTrigger.ts`, the gate list built in
   `installGrantedTriggeredEffect` (the `ownerMainPhaseGate` / `grantedPermanentAttackGate`
   family, around line 1254). Expected: a granted triggered effect does not run when the
   grantee has an active `beAffected` restriction against the granting seat at the trigger
   timing. Actual: no such gate exists; the outcome under test happens to match. A coordinator
   with engine scope should confirm whether the correct behaviour is a gate here or a
   teardown of the watcher when immunity is granted. No test is left red because the
   observable endpoint currently agrees with the ruling.
2. **No inherited-effect proof through a real evolution stack.** C3 is proved with a
   board-laid host carrying EX10-008 as a digivolution card. Building that stack by playing
   and digivolving through Lv.3 → Lv.4 → EX10-008 → Lv.6 was out of budget for this lane.
3. ~~**`whenAttackTargetSwitched` has no source filter in the IR.**~~ **Settled in round 3** and
   now proved by the comparative peer case above: the unscoped IR is correct for this printed
   text, and BT11-008 is the gated counterpart. Original note kept for the record: The printed text is
   generic ("when attack targets change"), and the once-per-turn test relies on this: the
   second switch is caused by a different blocker and is still seen by the host's watcher.
   If the intended reading is "when THIS Digimon's attack target changes", the IR and the

   EX9-054 gate on the host being the attacker, EX12-019 and ST15-01 do not — so the
   coordinator should settle the convention. Flagged, not changed.
4. ＜Reboot＞ is asserted only as an active keyword, not as unsuspend-in-the-opponent's-
   unsuspend-phase behaviour.
