### Rules note: the "Then," half after a declined "may"

CR 15-7-2 makes the text after "Then," conditional only when the preceding text is an
*optional processing condition* ("By X, Y"). "You may suspend 2 …" is optional **processing**,
not a processing condition, and CR 15-6-2's worked example has exactly this shape ("you may
play 1 [Kiriha Aonuma] … Then, ＜Save＞" — ＜Save＞ still processes). The implementation
therefore applies the restriction even when the suspend is declined, and the test records
that as the intended reading. No Q&A on this card settles it directly; flagged as the one
remaining interpretation risk.

## Defects found

1. **Test suite rewritten (the real finding).** The committed test proved the `[On Play]`
   clause with `advance(...).fireForPermanent(EffectTiming.OnPlay, …)` and both `[On Deletion]`
   cases with `advance(...).verb.deletePermanent(…)` — injected timing, which earns no
   behavioural credit. It also reached outside the Test Seam with
   `(s.engine as unknown as { mainPhase: … })` and called `s.engine.recomputeContinuousEffects()`
   directly. It never proved: the "in its text" filter (no negative candidate at all), Q5138's
   independence (it asserted only *counts* of 2 and 2, which a `sameTarget` implementation
   would also satisfy), that the unsuspend restriction actually blocks an unsuspend phase, the
   duration boundary, or either evolution route. Its `[On Deletion]` fixtures used EX10-040 /
   EX10-043 / EX10-064 / EX10-065, all of which carry live triggers (`[Start of Your Main
   Phase]`, an `[All Turns]` `[Myotismon]` watcher), so they were not neutral fixtures.
2. **Catalog discrepancy (reported, not edited).** `packages/shared/src/cards/data/cards.json`
   stores a **non-breaking space (U+00A0)** between `[Myotismon]` and `in its text` in
   EX10-054's `effectText`. Harmless for matching (the compiled token is `Myotismon`), but it
   makes exact-text comparison fail confusingly; the test documents it explicitly.

No defect was found in `EX10-054.ts` itself. Its IR is unchanged by this lane.

## Remaining gaps and seams for the coordinator

- **Engine seam, `matchNameOrTrait` (`apps/api/src/engine/effects/interpreter/matching/definition.ts`,
  ~line 337).** The `match: "text"` blob is built from `effectText`, `inheritedEffectText`,
  `securityEffectText`, `linkEffect`, `linkRequirement`, `dualEffect`, `optionEffect`, plus
  name and traits. Q5137 also lists **DNA digivolution, DigiXros, burst digivolve, App Fusion
  and Assembly requirements**. Those are stored structurally, not in any of those strings, so a
  card whose only `[Myotismon]` mention lives in a structured requirement field would be
  missed. In today's catalog `[Digivolve] …` headers are inlined into `effectText`, so no
  current card exposes the gap; it is latent. Not fixed here (outside this lane's allowed
  files). Note that `definitionMatches`'s separate `textContains` path has the same shape.
- **No inert Tamer exists in the catalog.** Every Tamer carries printed text, so the opposing
  Tamer fixtures (ST1-12, ST3-12) were picked for clauses that cannot fire in these boards
  (`[Your Turn]` on the non-turn seat; a Security-Digimon DP static that is never checked).
  Worth a coordinator note if a future brief wants a strictly inert Tamer fixture.
- Not covered, and not applicable to this card: DNA, DigiXros, App Fusion, ACE / Blast
  Digivolve, ＜Save＞, Link, Digi-Egg routes, Security text, inherited text, once-per-turn gates.
- No test is retained red; there is no `it.skip` / `it.fails` in the file.
