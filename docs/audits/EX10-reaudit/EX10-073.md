## Defects found in the committed test (all fixed locally)

1. **Seam violation.** The file defined `primitivesOf(s)` and cast through
   `engine.primitives` three times. The brief scores that 0 for peer/stack. Replaced with
   `advance(s.engine).verb.trash(...)`, which is the sanctioned seam verb over the same
   production primitive.
2. **Injected timing on both link windows.** `[When Digivolving]` and
   `[End of Opponent's Turn]` were proved only by `advance().fireForPermanent(...)` —
   structural, no behavioural credit. Replaced: `[When Digivolving]` now fires from a real
   `appFusion` intent (App Fusion is a digivolution, `digivolve.ts:886` fires
   `WhenDigivolving`), and `[End of Opponent's Turn]` now fires from
   `startTurnLoop()` + `endMainPhaseIfOpen(0)` with Deusmon on seat 1. No
   `advance().fire*` call remains in the file.
3. **`verb.appFuseInto` instead of the public intent.** The brief names this explicitly.
   Both App Fusion tests now use `applyIntent(0, { type: "appFusion", ... })`.
4. **Vacuous Q5188 test.** The old test passed for the wrong reason. Its `setupEngine`
   carried **no** decision-automation flags, so the §17-1-3-2-5 sweep's
   "which excess link card do you give up?" prompt (`GameEngine.chooseExcessLinkCards`,
   Q6370) hung unanswered, the trim never happened, and "the opponent's Digimon survived"
   asserted nothing. Proven by the fix run: with the flags added the board ends at 2 links
   with exactly one old link in the trash; without them it stayed at 3. Added
   `autoAcceptOptional` / `autoSelectCards`, plus assertions that exactly one of the two old
   links reached the trash and that no decision is left pending.
5. **＜Link +1＞ had no behavioural proof at all** — only a `compiled.effects[...].keywords`
   shape assertion. Added a rule-sweep test driven by a real `attack` intent.
6. **Weak App Fusion negative.** "Only one name present" was tested with no link material at
   all, which any refusal reason satisfies. Now the host carries a **wrong** linked material
   (BT21-041 Calendamon), so the refusal is specifically about the `[Cometmon]` name.

## Peer comparison on one board (EX10-030 Cometmon)

`crossFireBoard()` seats EX10-073 Deusmon and EX10-030 Cometmon side by side on seat 0, each
carrying its own link card, against a cost-3 and a cost-5 opponent Digimon at 20 000 DP. Both
cards print the same `[All Turns] [Once Per Turn]` -> `SubTrigger whenLinkTrashed` shape with
`isSelfRef` on the `sourceFilter`; the payloads differ (Deusmon deletes the lowest-play-cost
opponent Digimon, Cometmon gives 1 opponent Digimon -8000 DP for the turn). Each test trashes
**exactly one** link card and asserts both payloads' endpoints:

| trashed link | fires | endpoints asserted |
| --- | --- | --- |
| Deusmon's | Deusmon only | seat 1 battle area is exactly `[oppHigh]` (cost-3 deleted); `oppHigh.currentDP === 20_000` (no -8000); Cometmon still holds its own link; seat 0 trash is exactly the Deusmon link |
| Cometmon's | Cometmon only | `oppHigh.currentDP === 12_000`; seat 1 battle area is still exactly `[oppLow, oppHigh]` (no delete) and `oppLow.currentDP === 20_000`; Deusmon still holds its own link; seat 0 trash is exactly the Cometmon link |

Both tests end with no pending decision and no `actionRejected`. `preferInstanceIds` names the
cost-5 Digimon, so a cross-firing -8000 would land on the very permanent the isolation
assertion reads — the negative is decisive rather than lucky. Deusmon's own Delete is narrowed
to `lowestPlayCost`, so the same preference cannot steer it.

The link trash uses `advance().verb.trash` (the sanctioned seam over the production `trash`
primitive, `byEffectSeat` set). BT25-073 Dragomon's `[On Play]` cost
"By trashing 1 of your Digimon's link cards" was considered as a fully public route and
rejected: its cost sits inside an `optional` + `abortOnDecline` `Modal` that must resolve a
free play or a free Option use of a `[TS]` card, and no inert `[TS]` card with cost 5 or less
exists in the catalog, so the route would either abort the cost or drag a second `[On Play]`
into the board. Recorded as a fixture gap, not worked around.

## Notes for readers of the module

`＜Link +1＞` is *not* a `grantedKeywords` entry. `interpreter/actions/board.ts:422` routes
the `"Link"` (and `"LinkMax"`) keyword to `fx.grantLinkMax`, and `mindLink.linkMax` sums that
delta onto `BASE_LINK_MAX = 1`. The observable is `observe().linkMaxDelta(...)` /
`engine.linkMaxOf(...)`, never `observe().keywordAmount(perm, "Link")` (which reads 0 and is
correct). The test now says so.
