## What changed and why

The committed suite scored the two `[On Play]`-shaped cases and the turn-end deletion with
`advance(...).fire(EffectTiming.OnPlay, ...)` and `advance(...).fireGlobal(EffectTiming.OnEndTurn)`.
Injected timing is structural only, so every behavioural claim in the previous audit rested on
it, and `[When Digivolving]` was never reached at all. The rewritten suite drives the card
entirely through public intents:

- `playCard` from hand inside `startTurnLoop()`, with the cost reduction measured on memory;
- `digivolve` onto a Lv.6 [Dark Masters] host for the alternate cost, plus an illegal-source
  negative;
- `endPhase` and the hand-off to the opponent's Main for every end-of-turn assertion;
- `activateEffect` on EX10-020's own `[Hand] [Main]` play to create the second simultaneous
  end-of-turn processing Q5742 describes.

The `[Hand] [Main]` effect key is read through `observe(s.engine).cardSource(...)`, the Test
Seam affordance, rather than the `engine as unknown as { cardSourceOf }` cast that the
EX10-012 suite uses.

Fixture notes: a blue and a green face-up security card (BT1-038, BT1-080) are seeded in the
turn-loop scenarios so the played [Dark Masters] Digimon's own `[On Deletion]` "place yourself
face up as the bottom security card" clause stays dormant and the turn-end deletion can be
asserted in the trash. Memory is set explicitly before each play: a play is refused when its
cost exceeds `memory - MEMORY_MIN`, and a play that pushes memory below 0 hands the turn over,
which would hide the end-of-turn window under test.
