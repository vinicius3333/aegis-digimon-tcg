### Q5075 phase scope — verified through the real turn loop

The prior audit recorded a "phase scope" correction for this card. It is correct, and it
is now proved without injected timing:

- `TurnStateMachine.activePhase()` sets `Phase.Active`, fires `EffectTiming.OnStartTurn`,
  and only then calls `unsuspendForActivePhase`. Start-of-turn effects therefore run
  **inside** `Phase.Active`.
- `GameEngine.unsuspendAllForSeat` and `unsuspendRebootForSeat` both skip a permanent
  carrying `unsuspendDuringUnsuspendPhase`.
- `apps/api/src/engine/effects/primitives.ts:3996` blocks the effect-driven `unsuspend`
  primitive when `state.phase === Phase.Active`, which is exactly the Q5075 sub-case
  (a start-of-turn effect that unsuspends), and leaves effect-driven unsuspension in any
  other phase legal.

The turn-loop test drives both seats' real unsuspend phases and asserts nothing but
Quartzmon flips, including an opposing ＜Reboot＞ Digimon (§16-11), which is the only
non-turn-player unsuspend path the phase has. The "no card exists" gap: no catalog card
prints a `[Start of Your Turn]` unsuspend, so that literal sub-case of Q5075 has no
behavioural fixture; the `Phase.Active` guard above is its evidence.

## What the previous suite got wrong

The committed test file scored no behavioural or peer/stack credit under this brief:

1. **Injected timing.** `[On Play]`, both `[When Digivolving]` effects and `[When Attacking]`
   were proved only with `advance(...).fireForPermanent(...)`. The shared once-per-turn gate
   was never exercised through a turn boundary at all, so a `sharedUseKey` typo or a missing
   `frequency` would have passed.
2. **Seam violation.** Three tests cast
   `s.engine as unknown as { unsuspendForActivePhase(seat): Promise<string[]> }` to call a
   private `GameEngine` method directly. The brief forbids reaching past
   `apps/api/src/engine/testkit/`; the real unsuspend phase is reachable through
   `startTurnLoop()` + `advance(...).waitForMainPhase(seat)`, which is what the rewrite uses.
3. **Ledger reads standing in for behaviour.** The `[All Turns]` clause was asserted with
   `observe(...).isRestricted(...)` only — that proves a record exists, not that a permanent
   fails to unsuspend.
4. **No ACE proof.** Neither ＜Blast Digivolve＞ from hand in the counter window nor
   ＜Overflow＞ 5 on leaving the battle area was tested, although the brief requires both for
   an ACE card.
5. **No Q5074 test.** The ruling was asserted only in a source comment.
6. **Suspend-count blindness** (REVIEW-NOTES session-1 fixture fact): the old
   once-per-turn proof re-suspended candidates and could not tell a refused use from a
   repeated one.

None of this is a defect in `EX10-023.ts`. The module is correct as committed and I made
no module edits.

## Retained red

`Q5074 raises an orderTriggers decision for the two simultaneous [When Digivolving] effects`
is `it.fails`.

- Seam name: `simultaneous-when-digivolving-ordering`. This is the `[When Digivolving]`
  face of REVIEW-NOTES engine seam 9 (`simultaneous-when-attacking-ordering`, raised by the
  EX10-009 lane against BT24-078).
- Files: `apps/api/src/engine/effects/subtriggers.ts` and the `fireTiming` /
  `fireSubTriggers` queue in `apps/api/src/engine/effects/EffectContext.ts`.
- Expected: digivolving into Quartzmon raises one `orderTriggers` decision to seat 0 whose
  `options.triggerKeys` lists both `[When Digivolving]` effects, per Q5074.
- Actual: `s.decisions` contains no `orderTriggers` request. The engine resolves the suspend
  effect and the delete effect in registration order and never offers the choice.
- Impact: the endpoint happens to be harmless for this card (suspend-then-delete is the
  order a player would usually pick, and the delete filter re-reads suspension at
  resolution), but the ruling is about player agency, so the test is held red rather than
  weakened.
