# BT25-030 Elecmon

## Contract and sources

The committed catalog identifies Elecmon as a yellow level 3, 2000 DP Mammal/Iliad/TS Digimon with alternate evolution from a level 2 TS Digimon for cost 0. Its main effect is: by adding the top security card to hand, gain 1 memory. Its inherited effect is `[When Attacking][Once Per Turn] You may add your top security card to the hand. Then, if you have 0 security cards, Recovery +1.`

`node tools/kb/query.mjs card BT25-030` returns Q6297: with 0 security cards, the inherited effect can activate and perform Recovery +1 even though no card is added to hand. Relevant rules cover legal evolution, security stack movement, Recovery, and once-per-turn timing.

## Implementation and proof

`BT25-030.ts` is IR-only with one `registerIrCard("BT25-030", compiled)`. The main effect uses a paid `securityToHand` cost and therefore gains memory only when a security card is actually added. The inherited effect makes security-to-hand optional, then gates Recovery on the resulting zero-security count and shares one once-per-turn identity across attacks. The stale `@ts-nocheck` was removed.

Focused tests prove legal level 2 TS alternate evolution at cost 0 and rejection over a non-TS level 2; paid Start of Your Main Phase behavior, explicit zero-security unpayability, and refusal without memory gain; inherited security-to-hand followed by Recovery from one security; Q6297 zero-security Recovery when no card can be added; inherited refusal at one security with security retained and no Recovery; and suppression of a second inherited use in the same turn followed by a real opponent turn and a third completed attack on the next own turn, proving the Once Per Turn reset, exact security identities, recovery card, and deck resource transitions.
