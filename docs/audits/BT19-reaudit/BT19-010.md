## The prior audit's Save-source change: verified correct

The brief flagged that the prior audit narrowed this card to source only from its
OWN Digimon's digivolution cards. That is right, and it is what the card prints:
"from **this Digimon's** digivolution cards". The IR encodes it as
`target.filter.hostFilter: { isSelfRef: true }` alongside
`zone: "digivolutionCards"`. Without the `hostFilter` the effect would drain every
friendly stack, which the printed text does not permit. The test
`saves only this Digimon's Xros Heart sources when another stack also qualifies`
pins it: an adjacent BT19-009 Growlmon carrying an Xros Heart BT19-012 keeps that
card while only X4's own BT19-008 is placed.

Two related notes from the KB:

- This clause is NOT the ＜Save＞ keyword (comprehensive 16-20-1 places THIS card
  under a Tamer), and it is not ＜Material Save＞ (16-21-1, which is worded off the
  top card's DigiXros requirements and fires on deletion only). It is spelled out
  in full on this card, so the module correctly declares no keyword.
- comprehensive 4-3: cards placed under a Tamer that already holds cards go to the
  bottom. Not exercised here — see Remaining gaps.

## Clause -> test -> IR

- Clause 1 -> `effects[0]` `AllTurns` / `Replacement`, `event: "wouldLeavePlay"`,
  `sourceFilter: { isSelfRef: true }`, `optional: true`, inner `PlaceUnder` with
  `target { count: 3, upTo: true, from: ["digivolutionCards"], filter { zone:
  "digivolutionCards", kind: ["Digimon"], hostFilter: { isSelfRef: true },
  nameOrTrait [{ tokens: ["Xros Heart"], match: "trait" }] } }` and
  `underFilter { controller: "mine", kind: ["Tamer"] }`.
  - Realistic deletion route: X4 (8000 DP) attacks a 12000 DP suspended opponent
    Digimon through the public `attack` intent and loses the battle. Its stack is
    BT19-008, BT19-012, BT19-009 Growlmon (Dark Dragon — the near-miss source) and
    BT19-031 Starmons. Endpoints: exactly the three Xros Heart instance ids under
    the Tamer, Growlmon and X4 itself in the trash, X4 gone from the battle area,
    the opposing wall still on the board, no pending decision. This proves the
    "up to 3" cap, the exact-trait filter and that the Digimon still leaves.
  - Q3067 hand route, declined: `autoDeclineOptional` -> X4 in hand, Tamer stack
    empty, both digivolution cards in the trash.
  - Q3067 deck route: `verb.returnToDeck(..., { toTop: true })` -> X4 is deck[0],
    both Xros Heart sources under the Tamer, trash empty.
  - Own-stack scoping test as described in the section above.
- Clause 2 -> `compiled.digiXrosRequirement`
  `[{ materials: [{names:["Shoutmon"]},{names:["Ballistamon"]},
  {names:["Dorulumon"]},{names:["Starmons"]}], count: 2 }]`.
  - Full DigiXros: BT10-008 / BT10-049 / BT10-034 / BT10-029 from hand.
    Comprehensive 7-2-2-1 and 7-2-3-3: the play cost is reduced by 2 PER placed
    card, so 8 - (4 x 2) = 0. Endpoints: stack instance ids equal the four
    materials, memory 0 -> 0, hand empty, no pending decision.
  - Partial DigiXros (3 materials): 8 - (3 x 2) = 2 paid, memory 2 -> 0, stack
    length 3. This is what distinguishes "-2 each" from a flat cost.
  - Near-miss material pair in one test: BT5-014 OmniShoutmon has "Shoutmon" as a
    SUBSTRING of its name and no treated-as clause, and the intent is refused with
    `{ ok: false, reason: "invalid-material" }` — board empty, hand still 5, memory
    unchanged. The positive control on the same board is BT19-012 OmniShoutmon,
    which prints "This card is also treated as [Shoutmon] for a DigiXros": the same
    slot then plays for `{ ok: true }` and BT19-012 is in the stack. DigiXros
    material names are exact, and the treated-as clause is honoured.

Injected timing (`advance.fire`, `fireTiming`, `fireSubTrigger`) is not used. The
primary deletion case runs off a real battle; `verb.returnToHand`,
`verb.returnToDeck` and one `verb.deletePermanent` cover zone changes no public
intent reaches. Fixtures contain no Digi-Egg and no numeric `security: <n>` form.

## Defects

None found. The IR is correct on both printed clauses, including the
`hostFilter: { isSelfRef: true }` scoping the brief asked to be re-checked. The
pre-existing test file was sound but thin: it asserted `{ok:true}` on the DigiXros

catalog or the IR shape. Those gaps are closed. No red tests retained.

## Remaining gaps

- Q3067 lists six leave routes; the security-stack, breeding and placed-under-
  another-card routes are untested. No public intent or Advance-Surface verb in
  this lane's reach moves a battle-area permanent into the security stack or into
  breeding, and `verb.placeUnder` takes card instances rather than a whole
  permanent.
- comprehensive 4-3 bottom-placement ordering under a Tamer that already holds
  cards is unasserted — every fixture's Tamer starts empty.
- The `mode: "instead"` on the Replacement is not literally a replacement here: the
  Digimon still leaves in every route. The tests assert the leave happens, so the
  behaviour is right, but the IR's `mode` value is a modelling choice this audit
  did not change.
- `expanderPermanentIds` (BT19-079 Taiki Kudo's "place cards from under your
  Tamers for a DigiXros") is always `[]`; that interaction belongs to the Taiki
  lane.
