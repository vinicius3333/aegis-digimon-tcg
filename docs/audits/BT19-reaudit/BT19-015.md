## Clause -> test -> IR

### `[When Digivolving] Delete 1 of your opponent's Digimon with 8000 DP or less`

IR: `effects[0].actions[0]` — `Delete`, `target.filter { controller:
"opponent", kind: ["Digimon"], dp: { op: "lte", value: 8000 } }`, `count: 1`,
no `optional`.

- `digivolves from a Red Lv.5 source for 4 memory and deletes an 8000 DP
  Digimon` — the only evolution test that goes through the public `digivolve`
  intent from an inert Red Lv.5 source (BT1-024 MetalTyrannomon). Endpoints:
  stack `["BT1-024"]`, top card `BT19-015`, current DP 12000, opponent battle
  area empty and the victim instance in the opponent's trash, memory
  `10 -> 8` (`-4` evolution cost, `+2` from this card's own [Your Turn]
  clause firing on the deletion it caused), hand exactly the bonus-draw card,
  deck empty, no pending decision.
- `refuses a Lv.4 source and a Blue Lv.5 source` — the illegal-source
  negative: BT1-014 Kokatorimon (Red Lv.4) and BT1-038 Monzaemon (Blue Lv.5)
  both return `{ ok: false, reason: "invalid-evolution" }`, memory and hand
  untouched.
- `leaves a 9000 DP Digimon alone ...` — the 8000/9000 boundary; the 9000 DP
  body keeps its DP and stays on the board.

### `If this effect didn't delete, ... ＜Piercing＞ and +3000 DP until the end of your opponent's turn`

IR: `effects[0].actions[1..2]` — `GainKeyword` (Piercing) and `ModifyDP`
(+3000), both `duration: "untilOpponentTurnEnd"`, both gated on
`condition.kind: "ifThisEffectDidNotDelete"`, both `isSelf: true` /
`isSelfRef`.

- Three separate "didn't delete" routes, all natural digivolves:
  the 9000 DP out-of-range body, the undeletable Datamon (Q3071), and
  an opponent with no Digimon at all. Each asserts DP 15000, Piercing live,
  and — for the first two — memory unchanged at 6, proving the memory clause
  did not fire.
- `checks security with the granted Piercing after winning a battle, unlike
  the deleting branch` — the keyword is proved by its rules consequence, not
  by a flag: Gallantmon (15000, Piercing) beats a suspended 9000 DP Digimon
  and the excess trashes one security card (`securityChecked` fires once,
  security 3 -> 2). The paired control on the same board shape takes the
  deleting branch (a pinned 8000 DP body), so Piercing is absent and the same
  battle leaves security at 3 with zero `securityChecked` events.
- `keeps the +3000 DP through the opponent's turn and loses it at that turn's
  end` — the duration is read INSIDE the opponent's open Main phase
  (`runOneTurn` + `advance.waitForMainPhase(1)`): still 15000 with Piercing.
  After that turn closes and continuous effects recompute: 12000, no
  Piercing.

### `[Your Turn] [Once Per Turn] When an opponent's Digimon is deleted, gain 2 memory`

IR: `effects[1]` — trigger `YourTurn`, `frequency: "OncePerTurn"`, one
`SubTrigger` on `onDeletionOf` with `sourceFilter { controller: "opponent",
kind: ["Digimon"] }` and `GainMemory 2`.

Both tests run on ONE real `engine.startTurnLoop()`, which passes the turn
itself. Nothing in this file writes `state.turnSeat`, and every deletion is a
battle outcome produced by a public `attack` intent — no injected timing and
no `deletePermanent` verb.

- `ignores the deletion of your OWN Digimon without consuming the once-per-turn
  window` — proves the `controller: "opponent"` leg. Inside our own open Main:
  our 3000 DP body attacks their suspended 9000 DP body and dies; our trash
  holds exactly that instance and memory stays 0. The window is demonstrably
  untouched, because the very next attack — Gallantmon into their suspended
  2000 DP body — pays out +2 on the same turn.
- `stays silent on the opponent's turn and re-arms on your next own turn` —
  three consecutive turns of the same loop:
  - Turn 1 (ours): we attack the player with a 10000 DP bait body, which
    leaves it suspended and therefore a legal target on their turn. No
    opponent Digimon dies, so the window is still unspent.
  - Turn 2 (THEIRS): their own 3000 DP Digimon attacks the suspended bait
    through a seat-1 `attack` intent and is deleted. That is literally "an
    opponent's Digimon is deleted", but not on our turn: their attacker is
    confirmed gone from their battle area and in their trash, the bait
    survives, and memory is unchanged from the value captured before the
    battle. Their two survivors then attack our 1000 DP security bodies, win,
    and end the turn suspended.
  - Turn 3 (ours): the window is armed again. Gallantmon deletes the first
    suspended body in battle -> memory 0 -> 2. A second attacker deletes the
    second body in the same turn -> memory stays 2 ([Once Per Turn]), with
    both victim instances confirmed in their trash and no pending decision.

  The gate and the reset are proved against each other: the same board, the
  same deletion mechanism, the same clause — only the turn owner differs, and
  only the own-turn deletion pays.

## Defects fixed locally

1. The previous suite proved the two headline branches only through
   `advance.fireForPermanent(EffectTiming.WhenDigivolving, ...)` on a
   hand-laid Gallantmon — injected timing, worth at most 1 in Behaviour, and
   it never exercised the evolution route, the cost, the bonus draw or the
   stack identity. Replaced by public `digivolve` intents from an inert Red
   Lv.5 source.
2. No illegal-source negative existed. Added Lv.4 and wrong-colour refusals.
3. Piercing was asserted only as `observe(...).hasPierce(...)`, a ledger read.
   Added the rules-consequence proof (excess battle damage reaching security)
   with a non-Piercing control on the same board shape.
4. `untilOpponentTurnEnd` was never exercised; the grant could have been
   permanent or expired at once and every old assertion would still pass.
   Added the read inside the opponent's open Main plus the post-turn expiry.
5. The once-per-turn test asserted only "2 then still 2" on a hand-laid
   board. It could not tell a spent window from a closed one, never touched
   the `[Your Turn]` gate, the `controller: "opponent"` leg, or the next-turn
   reset. All four are now separate endpoints.
6. Q3070 was not covered at all. It now has a dedicated
   declined-prompts test plus the IR assertion that the delete is not
   `optional`.
7. Follow-up pass: the replacement tests still reached the opponent's turn by
   assigning `state.turnSeat` directly, which is injected state rather than a
   real flow. All three multi-turn tests now run on a single
   `engine.startTurnLoop()` — the production loop that passes the turn on its
   own — and every deletion is a battle outcome from a public `attack` intent.
   `state.turnSeat` is no longer written anywhere in the file; it is only
   asserted.

No IR change: `BT19-015.ts` differs from HEAD only by exporting `compiled`
so the test can assert the compiled shape. `effects.json` stays in sync.

## Remaining gaps

- Q3071's engine path is proved through BT14-062's blanket "can't be deleted
  by your opponent's effects". A target that is choosable but protected by a
  narrower replacement (＜Evade＞, a would-leave replacement) would exercise
  the same branch from a different direction; see BT19-018's Evade test,
  which reaches the same seam from the other side and there the effect DOES
  count as having chosen.
- The opponent-turn deletion is an opponent Digimon dying in a battle it
  declared itself. A deletion caused by an opponent's printed effect on their
  own turn would exercise the same gate through a different path; no Option
  or effect in this fixture's colour and cost range does that without
  dragging in a second card's clauses.
