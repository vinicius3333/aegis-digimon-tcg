## Defects

None found in `BT19-074.ts`. Every prior manual correction recorded in the module
header was re-derived from the printed text and confirmed behaviourally:

- the 10-trash branch really is an `instead` branch, not an extra deletion
  (proved: with two opponent Digimon and 10 trash cards, exactly one is deleted
  and the level-6 one survives);
- the return cost really does exclude Digi-Eggs (proved: with a Digi-Egg plus
  exactly 10 legal cards in trash, the Digi-Egg is the only card left behind);
- the result really is the opponent's TOP security card, not an arbitrary one
  (proved by asserting the surviving security order by instance id).

`abortOnDecline: true` on the sole action of the `[When Attacking]` effect is dead
(lane 4 / 008 finding). It was left in place rather than churning the IR, since
removing it would trigger a needless `effects.json` resync.

The prior test file was replaced: it asserted only IR shape plus one deletion
scenario, used no turn loop, proved neither evolution route, neither the Blast
Digivolve keyword nor the whole `[When Attacking]` clause.

## Remaining gaps

- **Same-turn refusal for `[Once Per Turn]` is not proved behaviourally.** The
  clause is `[When Attacking]`, and an attacker suspends when it attacks. There is
  no public intent that unsuspends a permanent mid-turn, so a second attack by the
  same Digimon in the same turn cannot be reached through public intents; a second
  copy of the card would carry its own per-permanent counter and prove nothing.
  What IS proved: the frequency is on the effect in the IR, and the clause fires
  again on the controller's next own turn driven by the real turn loop (unsuspend
  phase included), with the intermediate turn-1 endpoint asserted.
- ＜Blast Digivolve＞ is exercised through the production counter window and the
  `blast-digivolve:<permanentId>` effect key; the KB's Q3056-style exclusions do
  not apply to this card (it prints no stack-count route).
