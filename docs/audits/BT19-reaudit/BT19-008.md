## Card summary

Catalog (`packages/shared/src/cards/data/cards.json`): Red/Yellow Digimon, Lv3,
Rookie, Data, Mini Dragon / Xros Heart, play cost 4, DP 1000, evoCosts Red Lv2
and Yellow Lv2 at 1 memory, rarity U, max 4.

Printed clauses:

1. `[Digivolve]Lv.2 w/[Xros Heart] trait: Cost 0` — alternate route, EXACT trait.
2. `[On Play] This Digimon may digivolve into [OmniShoutmon] under your Tamers
   without paying the cost.` — exact name, source zone "under your Tamers",
   optional, cost waived (requirements are NOT waived).
3. `[On Deletion] Reveal the top 3 cards of your deck. Play 1 Tamer card with the
   [Xros Heart] trait among them without paying the cost. Return the rest to the
   bottom of the deck. Then, ＜Save＞.`
4. Inherited: `[Your Turn] This Digimon with the [Xros Heart] trait gains ＜Rush＞.`

Note on wording: this card uses the EXACT trait form ("[Xros Heart] trait"),
unlike BT10-008 Shoutmon which uses the substring form ("[Xros Heart] in
traits"). The IR is right to use `match: "trait"` on both trait filters.

## Defects

**Fixed locally: ＜Save＞ was mandatory.** The `PlaceUnder` action carried
`abortOnDecline: true` but no `optional: true`, and the effect did not declare the
`Save` keyword. Comprehensive 16-20-3 states the processing from ＜Save＞ is
optional, and the accepted BT10-008 module (the other printed ＜Save＞ on a
Shoutmon) uses exactly `optional: true` plus
`keywords: [{ keyword: "Save", raw: "＜Save＞" }]`. Reproduced before the fix: with
`autoDeclineOptional: true` the deleted Shoutmon still landed under the Tamer and
never reached the trash; the only decision raised in the whole flow was an
`orderCards`. `abortOnDecline` was also dead weight — it aborts SUBSEQUENT actions
and ＜Save＞ is the last action in the sequence — so it was dropped in the same
edit. The declined branch is now a passing test.

No red tests retained.

## Remaining gaps

- The alternate route's "cost 0" cannot be told apart from a paid route by memory
  alone in breeding, because the printed evoCosts (1 memory) differ from 0 only by
  1; the test pins memory at exactly 3 before and after, so the 1-memory normal
  route would have shown. The stronger isolation is the seat-1 refusal over a
  non-Xros-Heart Lv2 base.
- ＜Save＞ placing the card at the BOTTOM of a Tamer that already has cards under
  it (comprehensive 4-3) is not asserted; in every fixture here the Tamer stack is
  empty when the Save resolves.
- `excludeToken: true` on the Save's `underFilter` is unexercised — no Tamer token
  fixture exists in this lane's allowed files.
