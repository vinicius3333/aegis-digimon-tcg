## Corrections to the lane brief

The brief asked for "acceptance with each single colour" for the multicolour
Option. That is wrong under CR 4-22-3 ("An Option card with multiple colors can't
be used unless the color requirements are met for all of its colors") and the
engine implements the rule correctly (`GameEngine.printedColorRequirementMet`
uses `required.every`, citing 4-22-3/4-22-4). The tests therefore assert
refusal for green-alone and black-alone, acceptance for green+black, and
acceptance for a single Green/Black Digimon per CR 4-22-4.

## Remaining gaps

- **Q3174** (shuffling a security stack turns every face-up card face down) is
  implemented at the engine seam `apps/api/src/engine/effects/primitives.ts:5480`
  `shuffleSecurity`, which explicitly re-hides every card and cites the KB. It is
  not reachable from BT19-096 itself: this card never shuffles, and driving a
  foreign shuffle card would test the seam, not this card. The seam already has
  its own coverage (EX11-064 Q5929-5931, BT25-102). Documented, not tested here.
- The `DeleteBudget` non-`chooseTargets` branch prompts one optional per
  candidate ascending by printed play cost, so the controller cannot skip a cheap
  target to afford an expensive one. That is a general engine-shape question, not
  a BT19-096 defect, and no KB entry for this card speaks to it.
