## Defect found and fixed (`BT19-039.ts`, changes the IR)

The generated IR modelled the memory gain as a SECOND optional action
(`{ kind: "GainMemory", amount: 1, optional: true, abortOnDecline: true }`) in both
the `OnPlay` and `WhenDigivolving` effects. That let a player pay the security cost,
delete a Digimon and then decline the memory — mandatory processing offered as a
choice (§15-9-1), and a second prompt the card never prints. Removed both flags; the
cost gate stays on the `Delete` action, where `optional: true` + `abortOnDecline: true`
is the correct encoding of §15-7-1/§15-7-2 (`abortOnDecline` there is live, not dead:
it is not the last action).

## Open rules question (documented, not asserted)

If the opponent has no level 4 or lower Digimon, `runAction.ts:516` skips the whole
action before offering the optional condition, so the controller can neither pay the
security card nor take the memory. Comprehensive §15-7 does not obviously permit that
shortcut — a player may generally choose to pay an optional processing condition and
then perform as much of the following processing as possible. No Q&A on this card
settles it, and I did not want to bless either reading with a passing assertion, so
there is no test for the empty-target case. Flagging it for the coordinator: it is an
engine-wide question (every "By X, delete 1 …" card), not specific to BT19-039.
