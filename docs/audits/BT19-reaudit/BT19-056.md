### Peer / near-miss evidence

- Trait near miss: `BT1-009` Monodramon carries `[Mini Dragon]`, not
  `[Dragonkin]`/`[Cyborg]`. It is revealed alongside real matches and is refused —
  proving the exact `match: "trait"` gate rather than a substring one ("Dragon" is a
  substring of both, "Mini Dragon" is not the trait).
- Kind/trait near miss for the second category: `BT19-089` Red Card is an Option
  card with no `[Device]` trait, so the `orFilters` Option arm must reject it.
- Positive control in the same board: `EX2-062` Ryo Akiyama — a different printing
  of the same exact name — IS taken, so the `nameExact` arm matches on the printed
  name, not on a card id.
- Evolution stack / inherited: `inherited [All Turns] ...` builds the stack with a
  real `digivolve` intent — Monodramon -> `BT19-060` Strikedramon (Black Lv.3 base,
  cost 2) — asserts `stack == [Monodramon instance]`, then reads `currentDP` 6000
  (printed 5000 + 1000) inside our own open Main phase AND inside the opponent's own
  open Main phase, which is what separates `[All Turns]` from `[Your Turn]`.
  A second `BT19-060` sits on the same board with nothing under it and reads 5000 in
  both windows.

## Evidence standards notes

- No `advance.fire*`, no `s.state.turnSeat` write. The previous suite proved the
  `[On Play]` reveal twice through `fireForPermanent(EffectTiming.OnPlay, ...)` and
  proved the inherited `[All Turns]` clause by assigning `s.state.turnSeat = 1` and
  calling `advance().recompute()`; both are replaced by the real turn loop.
- The opponent's turn is reached with `startTurnLoop()` + `endMainPhaseIfOpen(0)` +
  `waitForMainPhase(1)`, and closed with `surrender` + `await loop` — never
  `runTurn(1)` after `runTurn(0)`.
- Reveal endpoints are computed from the live deck at Main open (`deckAtMain`).
- Both seats hold security; no Digi-Egg in any deck or security; a spare playable
  card sits in hand so Main does not auto-pass. Breeding fixtures use `s.ready()` +
  intent, because a seeded `breeding` permanent stalls `advance.waitForMainPhase`.
- `BT19-060`'s own `[When Digivolving]` optional (play 1 `[Ryo Akiyama]`) is answered
  with `autoDeclineOptional`, so it cannot perturb the asserted DP endpoints.

## Remaining gaps

- The `nameExact` gate is proved positively (two different printings of the exact
  name "Ryo Akiyama") but not against a card whose name merely CONTAINS
  "Ryo Akiyama": no such card exists in the catalog, so the exact-vs-substring
  distinction cannot be shown by counter-example for this token.
- Q3115's "must" is proved by observing that the maximum is taken under
  `autoSelectCards`; a responder deliberately taking fewer is not simulated.
- The case where a single revealed card would satisfy BOTH categories at once is not
  exercised, because no catalog card is both `[Dragonkin]`/`[Cyborg]` and named
  `[Ryo Akiyama]` or a `[Device]` Option. The interpreter's `taken` set would stop it
  being counted twice, but that is unproved here.
