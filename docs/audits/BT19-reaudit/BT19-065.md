## Card summary

Catalog: Black/Purple Digimon, Lv.6, Mega, Virus, types Machine + Composite, play
cost 11, DP 11000, evoCosts Black Lv.5 at 3 and Purple Lv.5 at 3. Rarity U, max 4
in deck.

Printed clauses:

1. `[On Play] [When Digivolving] Delete 1 level 5 or lower Digimon.`
2. `[On Deletion] You may play 1 level 5 or lower Digimon card with the
   [Cyborg]/[Composite] trait from your trash without paying the cost.`
3. `[Rule] Trait: Has the [Composite] type.`
4. `[DigiXros -1] 5 Lv.5 or lower [Cyborg]/[Composite] trait Digimon cards
   w/different card numbers` (header)
5. Inherited: `[Opponent's Turn] [Once Per Turn] When any of your opponent's Digimon
   attack, you may change the attack target to 1 of your Digimon with the
   [Composite]/[Wicked God] trait.`

## Q&A ids

| Q3129 | The inherited redirect may pick a Digimon that is not affected by effects. | "Q3129: the redirect still lands on a Digimon that cannot be affected by effects" — a `beAffected` restriction is armed on the [Composite] Digimon through the production restriction primitive, and the redirect still moves the attack off the player onto it. |

Comprehensive rules consulted for clause 4 (`node tools/kb/query.mjs rules
"DigiXros"`): §7-2-2-1 reduces the play cost by the printed amount **for each card
placed**, and §7-2-2-4 lets the player place **any number** of the specified cards
(only 0 is forbidden once declared). That settles the two shapes that looked
suspicious in the IR: `count: 1` really is the per-material discount (not a material
count), and there is correctly no minimum-material floor for "5 … cards" — only the
`maxMaterials: 5` cap.

## Clause -> test -> IR

- Clauses 1 -> `effects[0]` (`OnPlay`) and `effects[1]` (`WhenDigivolving`), each a
  single `Delete` with
  `target.filter { kind: ["Digimon"], levelComparison: { op: "lte", value: 5 } }`,
  `count: 1`. No `controller` predicate — that absence is exactly what Q3128 needs,
  and it is asserted in the IR test and proved behaviourally.
  - `[On Play]` positive: a public `playCard` intent for 11 memory (12 -> 1) deletes
    the opponent's Lv.5 (into their trash) and leaves the Lv.6 peer on the board by
    permanent id. No `actionRejected` event.
  - Level near-miss: the Lv.6 HiAndromon on the same board is never chosen.
  - `[When Digivolving]` positive: a public `digivolve` intent from a Black Lv.5
    base deletes the opposing Lv.5, memory 8 -> 5, the base instance id is the single
    stack entry, and the digivolution draw lands in hand.
- Clause 2 -> `effects[2]`: `OnDeletion` / `PlayWithoutCost`,
  `filter { controller: "mine", kind: ["Digimon"], levelComparison lte 5,
  nameOrTrait [{ tokens: ["Cyborg","Composite"], match: "trait" }] }`,
  `from: ["trash"]`, `payCost: false`, `optional: true`. `match: "trait"` is the
  exact-trait form the printed "with the [X] trait" wording requires. Loose-card
  matchers do read `levelComparison` (`interpreter/matching/definition.ts:139-147`);
  only the object `playCost: {op,value}` form is dropped for loose cards, and this
  card does not use it.
  - Positive through a real battle: Machinedramon (11000) attacks a suspended 12000
    DP wall, is deleted, and BT2-060 Megadramon (Lv.5 [Cyborg]) enters the battle
    area as a fresh permanent with an empty stack.
  - Near-miss peers in the same trash: BT2-064 HiAndromon (Lv.6 [Cyborg] — wrong
    level) and BT10-064 Gogmamon (Lv.5 [Rock] — wrong trait) both stay in the trash,
    asserted by instance id, alongside the deleted Machinedramon.
  - Decline (`autoDeclineOptional`): the Megadramon stays in the trash and the
    battle area is empty.
- Clause 3 -> `effects[3]`: `Rule` / `GrantStatic`, `grant: "trait"`,
  `tokens: ["Composite"]` — the `Rule`/`GrantStatic` node the brief's trap list
  requires for a printed `[Rule] Trait:` line, not a comment.
  - Cross-card consequence: `observe(...).hasEffectiveTrait` reads Composite on a
    Machinedramon permanent and not on a Lv.5 [Rock] peer sharing the board (which
    does read its own `Rock` trait, so the observation is not vacuous). This is the
    same trait token clause 5's redirect filter and clause 4's DigiXros recipe read.
- Clause 4 -> `digiXrosRequirement`: one slot, `levelComparison lte 5`,
  `nameOrTrait [{ tokens: ["Cyborg","Composite"], match: "trait" }]`,
  `differentCardNumbers: true`, `count: 1`, `maxMaterials: 5`.
  - Positive: a public `playCard` intent carrying `digiXros.materialInstanceIds`
    with five different-numbered Lv.5-or-lower [Cyborg]/[Composite] cards (including
    BT3-059 and ST5-05 — the SAME name Commandramon on different card numbers, which
    the "different card numbers" wording allows). Memory 6 -> 0 (11 - 5 x 1 = 6), all
    five instance ids are under the played permanent, the spare hand card is
    untouched, and `[On Play]` still fired and deleted the opposing Lv.5 — proving
    the DigiXros play is a play (§7-2-2-7).
  - Negatives, each rejected with memory and hand unchanged: a 6th material
    (`maxMaterials`), two prints of the same cardId (`differentCardNumbers`), a
    non-[Cyborg]/[Composite] material, and a Lv.6 [Cyborg] material.
- Clause 5 -> `effects[4]`: `OpponentsTurn`, `isInherited: true`,
  `frequency: "OncePerTurn"`, a `SubTrigger` on `whenOpponentAttacks` wrapping a
  `RedirectAttack` whose target filter is
  `{ controller: "mine", kind: ["Digimon"], nameOrTrait [{ tokens:
  ["Composite","Wicked God"], match: "trait" }] }`, `optional: true`.
  - Realistic stack + real turn loop: seat 0 has a BT1-014 host carrying a BT19-065
    digivolution card, a 7000 DP [Composite] Deltamon, and a deliberately WEAK

    `endMainPhaseIfOpen(0)` + `waitForMainPhase(1)` reaches seat 1's real turn (no
    `turnSeat` write). Seat 1's 3000 DP attacker declares an attack on the PLAYER;
    the redirect moves it onto the Deltamon, which wins: seat 0's security is still

  - `[Once Per Turn]`: a second attack on the same opponent turn is NOT redirected
    and takes a security card (3 -> 2), with seat 0's board unchanged.

Every behavioural test uses public intents (`playCard`, `digivolve`, `attack`,

  per §7-2-2-4, cost 8) is not exercised.

  filter it feeds. A cross-card case where another card's printed `[Composite]`
  filter reads a Machinedramon permanent is not built.

## Catalog discrepancies

The catalog stores this card's text with **U+00A0 (non-breaking space)** separators:
in `inheritedEffectText` before "you may change", and twice in the DigiXros header
line (`[DigiXros<U+00A0>-1]` and `[Composite]<U+00A0>trait`). Content matches the
official printing; only the separator bytes differ. The test normalizes U+00A0 to a
plain space before comparing and says so inline. Not edited — catalog is out of
lane scope.

Second (non-)discrepancy worth recording: `types` already contains `Composite`
alongside `Machine`, so the `[Rule]` grant is redundant with the catalog rather than
load-bearing. It is still the correct IR node — the printed line must compile to
something — and the behaviour is identical either way.
