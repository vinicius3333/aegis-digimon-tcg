## Clause -> test -> IR

- **Clause 1 alternate route** -> `digivolutionRequirement`
  `[{ namesExact: ["Justimon: Accel Arm", "Justimon: Critical Arm"], cost: 1, isAlternate: true }]`.
  Both named bases (BT11-073, BT10-067) digivolve for exactly 1 memory (10 -> 9)
  with stack identity, hand size and bonus draw asserted. The fallback test
  digivolves from BT19-063 (Black Lv.5) with `useAlternateCost: true` and shows
  the memory delta is 3, not 1 — `{ok:true}` alone would not have discriminated
  the two routes. Illegal sources EX8-054 `Justimon (X Antibody)` (Black Lv.6,
  wrong name, wrong level for the normal route) and BT1-014 (Red Lv.4) are both
  rejected as `invalid-evolution`.
- **Clause 2 ＜Blast Digivolve＞** -> `effects[0]` `trigger: "Counter"`,
  `isFromHand: true`, `keywords: [{ keyword: "BlastDigivolve" }]`.
  Proved inside the real production turn loop: on the opponent's turn the plain
  digivolve intent is refused `not-your-turn`; the opponent then declares a real
  attack, and the same intent with `useBlastDigivolve: true` succeeds with the
  memory unchanged (the cost waiver, `actions/digivolve.ts:662`).
- **Clause 3 ＜Blocker＞ + immunity** -> `effects[1]/[2]`:
  `GainKeyword { Blocker }` and `Restrict { restriction: "beAffected",
  fromSourceKind: ["Digimon"], byOpponentEffectsOnly: true }`, both
  `duration: "untilOpponentTurnEnd"` (a real `EffectDurationRef`).
  - Grant vs peer: `hasKeyword` / `isRestrictedByEffect` true on the digivolved
    Digimon and false on an ungranted peer Digimon on the same board.
  - Immunity consequence: on the opponent's REAL turn they play BT1-055 Angemon
    (`[On Play] 1 of your opponent's Digimon gets -3000 DP for the turn`) pinned
    onto the immune Digimon — nothing moves. A second test pins the identical
    effect onto the unprotected peer, which loses its full 3000 DP. That pairing
    is what makes the first reading protection rather than a dead effect.
  - Blocker consequence: a real opponent attack aimed at the player is taken by
    the granted blocker through a real `declareBlock` intent; the 3000 DP
    attacker is deleted and the security stack is untouched.
  - Duration: the grants are still live at the moment the opponent's effect
    resolves and are both gone once the loop returns to the controller's Main.
- **Clause 4 [Once Per Turn] unsuspend** -> `effects[3]` (`WhenDigivolving`) and
  `effects[4]` (`WhenAttacking`), both `frequency: "OncePerTurn"` with
  `sharedUseKey: "ir-shared-0"`, action `Unsuspend` on `isSelfRef` with a
  `trash` cost over `{ zone: "battleArea", controllerDefault: "any",
  kind: ["Option"], placedInBattleAreaByEffect: true }`.
  - Q3127 payment on the opponent's Option (above).
  - Shared once-per-turn: digivolving onto a suspended base pays one Option and
    unsuspends; the same turn's attack cannot pay again — the second Option
    survives and the attacker ends the attack suspended.
  - Real turn-loop reset plus the printed consequence: attack 1 pays and
    unsuspends (so a second attack is legal), attack 2 finds the use spent and
    stays suspended, and after a full opponent turn the next own turn's attack
    pays the second Option.
  - No-Option control: with only Digimon permanents on the board the attack still
    resolves, nothing is trashed, and the attacker stays suspended.
- **Clause 5 ACE Overflow ＜-4＞** -> catalog `isAce`/`overflowMemory: 4`.
  Proved behaviourally: the ACE loses a real battle to a seeded suspended 20000
  DP wall and memory moves 4 to the opponent (3 -> -1), with the permanent and
  its digivolution card in the trash.

## Defect fixed

`digivolutionRequirement` used `names`, which is the SUBSTRING gate
(`engine/cards/cardData.ts:482-484`, "[X] in its name"). The printed route
`[Justimon: Accel Arm]/[Justimon: Critical Arm]` is a bracketed exact reference
and must use `namesExact` (`cardData.ts:491-494`), which reads the exact-name
channel only. Fixed in `BT19-064.ts`.

Honest limitation: with the current catalog the change is not behaviourally
discriminable. No printed card's name CONTAINS "Justimon: Accel Arm" or
"Justimon: Critical Arm" without being that card, and no card is printed as
"also treated as [Justimon: Accel Arm]", so both modes accept and reject exactly
the same bases today. The tests assert both legal routes, the normal-route
fallback cost and the illegal sources under the corrected gate; the IR assertion
in the catalog test pins the mode itself.

## Remaining gaps

- **Q3126's false case cannot be seeded.** A Board Spec Option permanent with
  `placedByEffect: false` is the illegal state that §17-1-3-2-2's rule sweep
  exists to clean up: the engine removes it from the battle area before the cost
  is ever offered, so it cannot serve as a "still on the board but not choosable"
  near-miss. The nearest available control is the Digimon-only board, which is
  tested. The predicate itself is asserted on the IR.
- **Immunity is applied at resolution, not at targeting.** The immune Digimon is
  still offered in the `chooseTargets` candidate list for an opposing Digimon's
  effect (observed: both permanents offered), and the effect simply does nothing
  when it lands on it. This matches the "can't be returned" pattern in the trap
  list rather than the candidate-pool exclusion described in
  `conformance/ch15-03-targeting-and-selection.test.ts:296`. Not a defect in this
  card's IR; flagged for whoever owns that seam.
- `abortOnDecline: true` sits on the sole action of both once-per-turn effects
  and is dead (lane 4/lane 8 finding). Left alone deliberately: removing it would
  churn the IR for no behavioural change.

## Testkit note for the coordinator

An `async` helper that `return`s the running turn loop AWAITS it — the test then
hangs for the full 15 s vitest timeout. The helper here returns `{ loop }`.
Separately, a value with a `forTheTurn` / `untilOpponentTurnEnd` duration read
after `settle` on the opponent's turn is already expired, because their Main
auto-passes as soon as they have no legal action left; these tests read such
values through `setupEngine`'s `onEvent` hook at `effectResolved` instead.

## Catalog discrepancies

None. The catalog carries `isAce: true` and `overflowMemory: 4` even though the
`effectText` field does not spell out the ACE/Overflow line; that matches how
every other ACE card in the catalog is stored and the behaviour is correct.
