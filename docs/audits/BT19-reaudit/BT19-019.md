## Module defect fixed: `[Yao Qinglan]` was a substring gate

`effects[0].actions[0].target.filter.nameOrTrait[0].match` was `"name"` — the
SUBSTRING form. `[Yao Qinglan]` is a bracketed reference, so it is exact
(`nameExact`) per the brief's naming rule and `cardPredicates.ts`'s own doc
comment ("`nameExact` is literal card-name equality"). This is the same trap
lanes 3 found on BT19-007 and BT19-009. Fixed.

Honest note on impact: no card in the current catalog prints a name that CONTAINS
"Yao Qinglan" without being exactly it, so the change is behaviourally inert
today and no test can separate the two gates. It is the correct IR and it stops a
future printing (a "Yao Qinglan & ..." card) from being wrongly matched.

Two things checked and deliberately NOT changed:

- The `youHave` condition has no `zone: "battleArea"`. The brief lists that as a
  trap ("also counts breeding"), but
  `apps/api/src/engine/effects/interpreter/scaling.ts:95-106` shows an undefined
  `zone` scanning the battle area only — breeding is counted solely when `zone` is
  an ARRAY that includes `"breeding"`. Adding the field would move IR for no
  behavioural change, so the filter is left alone. (Tamers cannot be in breeding
  in any case.)
- `condition.filter.controllerDefault: "mine"` — `conditions.ts:228` spreads
  `controller: "mine"` in before the filter, so "you have" is already read from
  the source's own side.
