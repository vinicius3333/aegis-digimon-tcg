## Clause → test → IR

- Clause 1 (`＜Blocker＞`) → `effects[0]`, `trigger: "Static"`,
  `keywords: [{ keyword: "Blocker" }]`, no actions.
  - Behaviour: `blocks a real attack on the player, and a peer without ＜Blocker＞
    cannot`. Seat 1 declares a real `attack` on the player; the engine opens a block
    window; `declareBlock` with the inert 3000 DP Monodramon peer is REJECTED
    (`ok: false`), `declareBlock` with Huankunmon is accepted, and the redirected
    7000-vs-3000 battle deletes the attacker. Endpoints: seat 1 battle area empty,
    seat 0 battle area `["BT1-009","BT19-023"]`, Huankunmon suspended, seat 0
    security still 1, no pending decision.
  - Near-miss on grant scope: `does not grant ＜Blocker＞ to another Digimon`.
- Clause 2 (`[On Play]`/`[When Digivolving]` battle-deletion protection) →
  `effects[1]`/`effects[2]`, `Restrict` `beDeletedInBattle`, target
  `{ controller: "mine", kind: ["Digimon"] }` count 1 (permanent targeting, so the
  battle area), `duration: "untilOpponentTurnEnd"` (a real `EffectDurationRef`,
  `packages/shared/src/effects/ir/durations.ts:8`).
  - `[On Play] protects the chosen Digimon through a real losing battle on the
    opponent's turn`: real `playCard` intent (memory 10 → 3), the protection pinned
    onto one of two identical 3000 DP peers via `preferInstanceIds`. Then TWO real
    opponent attacks on the opponent's turn, each 12000 vs 3000, each declining the
    block window Huankunmon opens. The shielded peer survives with an empty trash;
    the exposed peer is deleted by the identical battle. Endpoints: trash
    `["BT1-009"]`, board `["BT1-009","BT19-023"]`, no pending decision.
  - `[When Digivolving] protects one Digimon, and the protection expires at the end
    of the opponent's turn`: real `digivolve` intent from Blue Lv4 Xiquemon
    (BT19-021). Endpoints: memory 5 → 2 (the printed Blue Lv4 cost 3), stack
    `["BT19-021"]`, hand holds exactly the digivolve draw, restriction on the chosen
    peer only. The restriction is then asserted STILL ARMED while the opponent's turn
    is open, and GONE after `advance(s.engine).runTurn(1)` — the real turn loop, not
    an injected duration tick.
- Clause 3 (inherited `[Your Turn]` attack target can't be switched) → `effects[3]`,
  `trigger: "YourTurn"`, `isInherited: true`, `Restrict` `attackTargetChange` on
  `{ isSelfRef: true, isSelf: true }`, `duration: "permanent"` (re-derived每
  continuous pass and turn-gated by the `YourTurn` trigger).
  - `forbids an opposing ＜Blocker＞ from switching the target, unlike an identical
    host without it`: two identical Kokatorimon hosts, one with BT19-023 in its
    digivolution cards. The restricted host attacks the player: NO
    `blockWindowOpened` event ever fires, MailBirdramon (printed ＜Blocker＞) stays
    unsuspended, and security drops by one. The plain host attacks: the SAME blocker
    opens a window, `declareBlock` succeeds, and the 12000-vs-5000 battle deletes it.
    This is the rules consequence (`combat/legality.ts:368` — a block IS an
    attack-target switch, CR §12-1-1), not a keyword flag read.
  - `does not restrict the host on the opponent's turn` — the `[Your Turn]` gate.
- Evolution: `refuses an illegal source: Blue Lv.3 and Red Lv.4 both fail the Blue
  Lv.4 requirement`. Swimmon (Blue Lv3) and Kokatorimon (Red Lv4) are both rejected
  with board, hand and memory unchanged. The legal Blue Lv4 route with source-stack
  identity, memory cost and bonus draw is proved in the `[When Digivolving]` test
  above.

## Defects found

None. The IR is unchanged: no `match: "name"` on a bracketed name (this card has no
name references), no `Static` standing in for a printed `[All Turns]` clause
(`＜Blocker＞` is a bare keyword, and the inherited clause correctly uses `YourTurn`),
and the duration string is a real `EffectDurationRef`. The prior test file proved
clause 2 only through `advance().fireForPermanent` and clause 3 only through
`advance().recompute` plus a restriction read; both are now proved through public
intents and real combat.

## Remaining gaps

- The `[On Play]`/`[When Digivolving]` target filter carries no `zone`, relying on
  permanent targeting defaulting to the battle area. A breeding-area Digimon is
  therefore assumed excluded but not proved: seating a `breeding` permanent in a
  Board Spec stalls `advance.waitForMainPhase` (`advance.ts:79`, the known testkit
  limitation), so the exclusion is untested here.
- Clause 2 is proved for a chosen OTHER Digimon; choosing Huankunmon itself is legal
  under the same filter and is not separately exercised.
