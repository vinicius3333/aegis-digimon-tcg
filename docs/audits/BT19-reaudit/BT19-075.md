## Card summary

Purple Lv.7 Mega / Virus / [Wicked God], DP 15000, play cost 15,
EvoCost Purple Lv.6 for 5, SR, max 4 per deck. Not an ACE.

Printed clauses:

1. `[Digivolve][Millenniummon]: Cost 2`
2. `[On Play] [When Digivolving] Your opponent trashes cards in their hand until they
   have 5 left. For every 2 cards trashed by this effect, delete 1 of your opponent's Tamers.`
3. `[All Turns] When this Digimon would leave the battle area, by deleting 1 of your
   Digimon with the [Composite] trait Digimon, it doesn't leave.`

   opponent's top security card.`

The printed text separates `[Composite]` from `trait` with a NON-BREAKING space
(U+00A0, catalog offset 319). The catalog assertion spells that out.

## Defects

### Fixed: the `[Digivolve]` route used the substring gate

`BT19-075.ts` carried `digivolutionRequirement: [{ names: ["Millenniummon"], cost: 2 }]`.
`names` is the SUBSTRING gate (`apps/api/src/engine/cards/cardData.ts`), so it also
matched `BT19-101 ZeedMillenniummon`, letting a Lv.7 ZeedMillenniummon act as a
cost-2 base for a card that prints the bracketed exact name `[Millenniummon]`.
Changed to `namesExact: ["Millenniummon"]`.

The fix is discriminated, not merely asserted: reverting the field to `names` and
re-running `near miss: ZeedMillenniummon only CONTAINS 'Millenniummon', so no route
accepts it` fails with `expected true to be false` on the digivolve intent — i.e.
the old IR really did accept the illegal base. Restored to `namesExact` afterwards.

Because `digivolutionRequirementsFor` reads `compiledEffects` (which
`registerIrCard` overwrites at import time), the change takes effect for the
engine, and `packages/shared/src/effects/effects.json` is now stale for this card.

### Confirmed correct (previously unverified)

- `chooser: "opponent"` on the hand trash matches Q3135.
- The Tamer count is scaled off `trashedThisEffect`, not off any board or hand total.
- The would-leave replacement carries `sourceFilter.isSelfRef` (without it,
  `replacement.ts:238-241` takes the generic branch and would protect both seats).
- The watcher observes both seats' other Digimon and Tamers and uses the canonical
  `SecurityManipulation op "trashTop" controller: "opponent"` operation.

The prior test file was replaced: it seeded a Digi-Egg in security, drove the
watcher through `advance.verb.deletePermanent` (injected timing, no behavioural
credit), and proved neither evolution route, the replacement, the `[Once Per Turn]`
frequency, nor the scaling.

## Remaining gaps

- Same-turn refusal for clause 4 IS proved (two Tamer deletions inside one
  `[On Play]` resolution trash only one security card). The next-own-turn RESET is
  not proved separately; the two-deletions-one-security case plus the IR frequency
  field are what stand behind it.
- The engine's `op: "trash"` / `op: "trashTop"` are aliases
  (`interpreter/actions/security.ts:143-144`); this module uses `trashTop`, its
  lane-mate BT19-074 uses `trash`. Cosmetic, no behaviour difference.
