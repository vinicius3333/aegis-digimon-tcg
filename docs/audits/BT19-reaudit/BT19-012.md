## Clause -> test -> IR

### `[Digivolve][Shoutmon]: Cost 4` and `[Digivolve]Lv.4 w/[Xros Heart] trait: Cost 3`

IR: `digivolutionRequirement` — `[{ namesExact: ["Shoutmon"], cost: 4,
isAlternate: true }, { level: 4, traits: ["Xros Heart"], cost: 3, isAlternate:
true }]`.

- `resolves each alternate requirement to its own cost and rejects a
  non-matching base` — BT19-008 Shoutmon resolves to cost 4; BT19-010
  **Shoutmon X4** and BT19-033 Dorulumon resolve to cost 3 (the Lv.4 trait
  route only); BT19-009 Growlmon (Lv.4, wrong trait) and BT19-005 Hopmon
  (Lv.2, neither) resolve to nothing.
- `digivolves through the named [Shoutmon] route for 4 / Lv.4 [Xros Heart] route
  for 3` — real `digivolve` intents with `alternateRequirementIndex`. The gauge
  starts at exactly the route's cost and lands on 0, so the reduced route is
  what was paid; stack identity, the digivolve bonus draw and the resulting
  `[When Digivolving]` deletion are asserted, with no pending decision.
- `refuses an illegal source that matches neither the name nor the Lv.4 trait
  route` — BT19-005 Hopmon base, `{ ok: false, reason: "invalid-evolution" }`,
  card still in hand.

### `This card is also treated as [Shoutmon] for a DigiXros.`

IR: `effects[0]` — trigger `Static` (the clause prints no timing bracket),
`GrantStatic { grant: "name", tokens: ["Shoutmon"], digiXrosOnly: true,
target: self }`.

- `is a legal [Shoutmon] material for a DigiXros but keeps its printed name` —
  `observe(...).effectiveNames` is `["omnishoutmon"]` (the alias never reaches
  ordinary name matching), and the DigiXros `playCard` for BT10-013 with
  OmniShoutmon in the [Shoutmon] slot succeeds and lands it in the stack.
- Q3068 Material Save test above, plus the unit-level
  `digiXrosMatches("BT10-013", "BT19-012") === false` /
  `digiXrosMatches("BT10-013", "BT19-008") === true` pair, which names the exact
  eligibility function ＜Material Save＞ consults.

### `[On Play] [When Digivolving] -3000 DP, then delete 1 with 3000 DP or less`

IR: `effects[1]` / `effects[2]` — `ModifyDP { amount: -3000, duration:
"forTheTurn", target: 1 opponent Digimon }` then `Delete { target: 1 opponent
Digimon, dp lte 3000 }`.

- `reduces one opposing Digimon by 3000 and then deletes it at the 3000 DP
  boundary` — `playCard` from hand with `preferInstanceIds` steering the -3000
  onto the 6000 DP Digimon: 6000 − 3000 = 3000 lands exactly on the printed
  maximum, so that one dies and the 4000 DP peer keeps its DP and its place.
- `deletes nothing when the reduced Digimon is still above 3000 DP` — a single
  7000 DP target ends the resolution at 4000 DP, alive.
- The `[When Digivolving]` copy is proved by the two route tests above, which
  delete a 3000 DP target through the real digivolve intent.

### `[On Deletion] Place 1 [Xros Heart]/[Blue Flare] Digimon from hand or trash under your Tamers`

IR: `effects[3]` — `PlaceUnder { target: { count: 1, from: ["hand", "trash"],
filter: { controller: "mine", kind: ["Digimon"], nameOrTrait: [{ tokens:
["Xros Heart", "Blue Flare"], match: "trait" }] } }, underFilter: {
controllerDefault: "mine", kind: ["Tamer"] } }`. `match: "trait"` is the exact
trait test the printed "with the [X] trait" wording requires.

- `places a matching Digimon under its own Tamer when it dies in battle` —
  deletion reached by attacking a suspended 20000 DP Digimon, not by a verb.
  Endpoints: the Tamer's stack is exactly `["BT19-016"]` (the [Blue Flare] card
  in the controller's own trash); the [Dark Dragon] BT19-009 stays in hand; the
  opponent's own [Xros Heart] card in THEIR trash is untouched (the
  `controller: "mine"` leg); the controller's trash holds only OmniShoutmon.
- `places nothing when the controller has no Tamer to place under` — the
  matching card stays in the trash and no decision is left pending.

### Inherited `[Your Turn] This Digimon with the [Xros Heart] trait gains ＜Rush＞`

IR: `effects[4]` — trigger `YourTurn` (not `Static`), `isInherited: true`,
`GainKeyword { keyword: Rush, duration: "permanent", target: self with
nameOrTrait trait ["Xros Heart"] }`.

- `grants inherited Rush only to an Xros Heart host during its controller's
  turn` — BT19-013 Shoutmon X5 (Xros Heart) gets ＜Rush＞, BT19-015 Gallantmon
  ([Holy Warrior]/[Royal Knight]) does not; flipping `turnSeat` removes it.
- `lets an Xros Heart host attack the turn it arrives on the inherited Rush` —
  a host seeded with `enteredThisTurn: true` attacks the player and checks a
  security card, which summoning sickness would otherwise forbid.

## Defects fixed locally

1. **IR defect.** The named digivolution route used `names: ["Shoutmon"]`, which
   is the SUBSTRING gate ("[X] in name",
   `apps/api/src/engine/cards/cardData.ts:482`). BT19-010 Shoutmon X4 therefore
   took the named route at cost 4 instead of the Lv.4 [Xros Heart] route at cost
   3 — a real, reachable rules error on a bracketed `[Shoutmon]` requirement.
   Corrected to `namesExact: ["Shoutmon"]`; the near-miss test pins it.
2. The old test asserted `matchingAlternateDigivolutionRequirement(...)?.cost`
   for two bases but used no near-miss whose name CONTAINS "Shoutmon", so it
   could not see defect 1.
3. Both printed timings were proved by `advance.fireForPermanent` — injected
   timing with no endpoints. Replaced with `playCard` and both real digivolve
   routes, asserting memory, stack, hand and DP.
4. The `[On Deletion]` clause was driven by `advance.verb.deletePermanent`.
   Replaced with a real battle death, and given the missing endpoints (trash
   contents, hand contents, the opponent's own matching card left alone, the
   no-Tamer branch).
5. The digivolve tests asserted only `{ ok: true }` and never pinned which route
   was charged. The gauge now starts at exactly the route cost.
6. No catalog assertion and no full IR assertion existed; both added, including
   the `Static` vs `YourTurn` trigger split.
7. The old inherited-Rush test had no behavioural consequence; a real
   summoning-sickness-defeating attack was added.
