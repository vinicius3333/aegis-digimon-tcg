## Verification of the prior audit's changes

The prior audit switched clause 1 to `SetMemory` + `memoryAtMost`. **Confirmed correct**
against the printed text and the KB: "If you have 2 or less memory" -> `memoryAtMost: 2`
(inclusive), "set it to 3" -> `SetMemory { value: 3 }`. `controller` is left at the engine
default `"mine"` (`conditions.ts:228`), which the behavioural tests exercise. Both branches are
now proved behaviourally rather than structurally.

## Clause -> test -> IR

- **Clause 1** -> `effects[0]` `StartOfYourTurn` / `SetMemory { value: 3, condition:
  { kind: "memoryAtMost", value: 2 } }`.
  - Positive: memory 2 -> 3, read **inside** the open Main phase (`runOneTurn` +
    `waitForMainPhase(0)`), not after the pass.
  - Negative: memory 6 stays 6.
- **Clause 2** -> `effects[1]` `YourTurn` / `SubTrigger { event: "whenOneOfYoursDigivolves" }`
  with `sourceFilter { controllerDefault: "mine", kind: ["Digimon"], nameOrTrait:
  [{ tokens: ["Growlmon", "Gallantmon"], match: "name" }] }`, then
  `GainKeyword { keyword: Raid, duration: "forTheTurn", optional: true, abortOnDecline: true,
  cost: suspend self, target.sourceRef: "triggerSubject" }` and
  `Attack { attackPlayer: true, mandatory: true, target.sourceRef: "triggerSubject" }`.
  - `match: "name"` (substring) is **correct** here: the printed wording is "with
    [Growlmon]/[Gallantmon] **in its name**", the substring form. A bracketed `[Name]`
    reference would have needed `namesExact`. Checked explicitly against the set's known trap.
  - `abortOnDecline: true` is **live**, not the dead form the set has seen elsewhere: a second
    action (`Attack`) follows it, and the decline test proves the attack does not happen.
  - Positive (Growlmon, Lv.3 -> Lv.4): the base permanent keeps its identity, the Lv.3 instance
    id is the only card in its stack, `observe().hasKeyword(perm, "Raid")` is true, the Tamer
    is suspended (the paid cost), the attacker is suspended, one of the opponent's three
    security cards is checked, and an `attackDeclared` event names the base permanent.
  - Q3141: exactly one `optional` decision is raised across the whole resolution.
  - Cost declined (`autoDeclineOptional`): no Raid, Tamer unsuspended, attacker unsuspended,
    opponent's security untouched — the whole clause aborts.
- **Clause 3** -> `effects[2]` `Security` / `isSecurity: true` /
  `PlayWithoutCost { payCost: false, from: ["security"], target: { isSelfRef: true } }`.
  - Proved through a **real security check**: BT19-080 on top of seat 1's security, seat 0
    attacks the player; the Tamer's instance id is the only permanent on seat 1's board, gone
    from security, not in the trash, memory unchanged (cost 4 not paid).
  - The check's other outcome: with a plain Digimon on top, that card is trashed and BT19-080
    stays face down in security.

## Remaining gaps

- ＜Raid＞ itself (switching an attack's target to a Digimon) is proved only by
  `observe().hasKeyword`, because the printed clause immediately sends the Digimon at the
  *player*; the keyword's own rules consequence belongs to a Raid-carrying card's audit.
- The KB lists a single Q&A for this card; no ruling covers what happens when the granted
  Digimon cannot attack (no legal target). The IR marks the attack `mandatory`, which the
  engine treats as "attack if possible"; untested here because no fixture in scope can make the
  attack illegal without also blocking the digivolve.
