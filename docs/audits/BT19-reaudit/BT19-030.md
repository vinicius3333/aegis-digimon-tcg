## Defect fixed locally

`[Rika Nonaka]/[Calumon]` is a bracketed EXACT name reference, but the condition
used `match: "name"` — the substring gate (`interpreter/matching/definition.ts:360`
vs `:363`). Corrected to `nameExact`.

Honest limitation: the current catalog holds no card whose name CONTAINS
"Rika Nonaka" or "Calumon" as a proper substring, so the two modes are not
behaviourally distinguishable today. The change is a text-fidelity correction that
prevents a future longer-named card (a "Rika Nonaka & X" Tamer, the shape that
already exists for Tai Kamiya) from wrongly satisfying the condition. The
near-miss test proves the gate is a name gate at all, not the exact/substring
split.

## Remaining gaps

- Q5462's discriminating case (original use cost >= 2, cost TO PAY reduced to 1 or
  less, trigger still fires) has no implemented card: every implemented
  payment-only reducer (BT26-098, BT10-103, BT10-098, BT21-093, P-219, EX5-072)
  leaves the paid cost at 3 or more, so the reduced and unreduced values both clear
  the printed threshold. The free-use test covers the same rule at the extreme
  (paid 0).
- Engine observation, not a defect of this card: cards printed "When you would use
  this card, reduce its use cost by N" (BT21-093, P-219, EX5-072) compile onto the
  `BeforePayCost` payment path, while "Reduce the memory cost of this card in your
  hand" (BT2-099, BT8-097) compile onto `wouldBePlayedSelfReducers`, which is the
  path `optionUseCost` reads. Q5461 treats both wordings as use-cost reductions. No
  implemented card of the first family can cross the "2 or more" line, so nothing is
  observable here; flagged for whoever owns `GameEngine.projectLooseUseCost`.
- External "reduce the play cost of your Option cards" effects fold into
  `modifiers.playCostFor`, which `projectLooseUseCost` also reads, so such an effect
  would lower the notified USE cost. Q5462 says a cost-to-pay reduction must not.
  No implemented card exercises it, so no test was written.
