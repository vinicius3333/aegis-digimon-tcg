### Peer / near-miss evidence

- Filter near miss: `near-miss peers: reveals with no [Knightmon] text and no
  [Twilight] trait add nothing` reveals `BT19-046` Chamblemon (Vegetation),
  `BT1-011` Agumon Expert (Dinosaur) and `BT19-044` Terriermon (Beast). None of the
  three names, traits or prints `[Knightmon]` or `[Twilight]`. Hand and the Tamer's
  stack are unchanged and all three reveals reach the deck bottom in order.
- Positive discrimination inside one board: the Q3113 fixture pairs `BT18-058`
  Kotemon, which qualifies only through the TEXT arm (it literally prints
  "1 card with [Knightmon] in its text"), with `BT10-058` Monitamon, which qualifies
  only through the `[Twilight]` TRAIT arm. Both arms of the `orPrevious` union are
  therefore exercised by distinct cards.
- Evolution stack / inherited: the Reboot test builds the stack with a real
  `digivolve` intent — Monitamon -> `BT19-058` SkullKnightmon (Black Lv.3 base,
  cost 3) — asserts `stack == [Monitamon instance]`, then suspends the host by a
  real attack, ends Main, and reads inside the opponent's own open Main phase (after
  THEIR unsuspend phase). The host is unsuspended; the near-miss peer `BT1-009`,
  suspended the same way by its own real attack and carrying no `Reboot`
  (`observe().hasKeyword(..., "Reboot") === false`), is still suspended.
  This is the "prove a keyword by its rules consequence, not a flag" requirement.

## Evidence standards notes

- No `advance.fire*`, no `advance.verb.deletePermanent`, no `s.state.turnSeat` write.
  The previous suite used `verb.deletePermanent` for all three On-Deletion cases and
  set `turnSeat = 1` plus `runOneTurn()` for Reboot; both are replaced.
- Deletion is a real battle loss (Monitamon, DP 1000, attacks a suspended `BT1-013`,
  DP 5000).
- Reveal endpoints are computed from the live deck at Main open

  `breeding` permanent stalls `advance.waitForMainPhase` (`advance.ts:79`).
- `s.state.pendingDecision === undefined` asserted after every flow.

## Defects found

None in the module. Trap list checked:

- `match: "text"` is correct for "in its text": `matching/definition.ts:358-379`
  makes `"text"` the name ∪ trait ∪ printed-text union, which is what the printed
  wording means; the `[Twilight]` arm correctly uses exact `match: "trait"`.
- `requiresMinRevealed: 2` is live, not a dead key
  (`interpreter/actions/reveal.ts:250-256`), and counts over the whole revealed set,
  which is exactly Q3114's reading.
- `＜Reboot＞` is declared as `keywords: [{ keyword: "Reboot" }]`, so it is a real
  granted keyword rather than a test-only flag.
- No `＜Save＞` clause, so the `withSavePlacementDefaults` trap does not apply. The
  under-Tamer placement here is a printed `RevealAdd` destination, not Save.
- No `abortOnDecline`, no `match: "name"` misuse, no `Static`-for-`[All Turns]`.

Evidence defect fixed locally (test file only, no module change): the previous suite
proved all four clauses through injected verbs/timing, had no evolution route, no
illegal source, no near-miss peer and no realistic evolution stack.

## Remaining gaps

- "under your Tamers" is proved with exactly one Tamer on the board. With two or more
  Tamers the engine must ask which host receives the card; no KB entry covers that
  choice for this card, and the printed wording does not constrain it, so the
  multi-Tamer host choice is untested here.
- Q3113's "must" is proved by observing that the maximum is taken under
  `autoSelectCards`. A hostile responder that tries to take fewer than the maximum
  is not simulated; the harness has no "answer below the minimum" affordance.
