## Verification of the prior audit's hand/trash change

Confirmed correct and load-bearing. `runPlaceUnder`
(`apps/api/src/engine/effects/interpreter/actions/placeUnder.ts:398-409`) resolves the
loose-card source zones as `action.from` > `action.target.from` > `target.filter.zone` >
the legacy sweep `["hand", "trash", "deck"]`. The module carries
`target.from: ["hand", "trash"]`, which is read, and without it the fallback would reach
the deck the card never names. Behaviour is asserted, not just the field: the deletion test
seeds an eligible BT19-047 Ballistamon in the DECK and biases the auto-responder toward it
(`preferInstanceIds`), and it is still never placed.

## Findings

1. **No IR defect found.** Trigger names, the two duration strings, the restriction name,
   the trait match mode, the DigiXros grant shape and the loose-card source field are all
   keys the engine reads. `trigger: "Static"` for the DigiXros alias is correct — the line
   is not a printed `[All Turns]` clause, and the alias must be readable while the card is
   still off the battle area.
2. **[On Deletion] behaviour the previous test mis-framed.** The deleted AtlurBallistamon is
   itself in the trash when its own `[On Deletion]` resolves (CR 4-14-1/2) and it is itself a
   Digimon card with the [Xros Heart] trait, so it is a legal candidate for its own effect.
   The near-miss test therefore asserts the SELF card by instance id as the only placement
   when the hand holds a wrong-trait card, and every hand/trash test pins the intended
   candidate with `preferInstanceIds` instead of relying on candidate order.
3. **A "can't be returned" Digimon can still be chosen as a bounce target.** BT15-090 and
   BT19-092 resolve, the Option is spent, and the move simply does not happen —
   `filterBouncePrevented` sits at the primitive, not at targeting. Because "nothing moved"
   is also what an effect with no legal target looks like, each protection test is paired
   with a control run on the same card and the same preference, where the unprotected peer
   IS returned. Not a defect; recorded so the pass is not read as stronger than it is.
4. **Testkit notes (not defects).** An opponent Option needs a matching-colour permanent on
   its controller's board; and an attack needs a suspended defender, so the deletion tests
   attack a seeded suspended wall on my own turn.

No engine gap was found, so no test is retained red.
