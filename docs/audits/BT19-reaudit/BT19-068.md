## Defects fixed locally

1. **＜Save＞ was untagged.** The `OnDeletion` effect carried a bare positionless
   `PlaceUnder`. `withSavePlacementDefaults`
   (`apps/api/src/engine/effects/interpreter/registration/normalize.ts:115-126`)
   only defaults `position: "bottom"` on an effect whose `keywords` include
   `Save`, so `runPlaceUnder` read `belowTop: action.position !== "bottom"` as
   true and `primitives.ts:2065` pushed the card directly BENEATH the Tamer's top
   card instead of at the bottom — inverting the stack and the inherited effects it
   grants (CR 4-3-2, 16-20). Fix: `keywords: [{ keyword: "Save", raw: "＜Save＞" }]`.
   Proof it mattered: with the tag removed, `＜Save＞ places the card at the BOTTOM
   …` and the IR test fail (3 failed | 11 passed).
2. **DigiXros recipe was uncapped.** A single-slot recipe with no `maxMaterials`
   accepts any number of matching materials (`materialsSatisfyRecipe`,
   `apps/api/src/engine/actions/digiXros.ts:536-556`; the cap check is at
   `:290-294`), so two [Nene Amano] cards bought -4 on a recipe that prints one
   material. Fix: `maxMaterials: 1`, matching the BT21-021 / BT18-065 precedent.
   Proof: without it, `refuses the near-miss Tamer …` fails.

## Remaining gaps

- The `[Rule] Trait: Has [Composite] type.` line is redundant against this
  catalog: `types` already lists `Composite`, so the `GrantStatic` node cannot be
  isolated behaviourally — the trait consequence is proved, but it would hold with
  the node deleted. See the catalog note below.
- The `[Twilight]/[Composite]` trait gate is proved exact only by construction: no
  printed trait in the catalog has "Twilight" or "Composite" as a strict substring,
  so there is no near-miss trait peer to separate `match: "trait"` from
  `traitContains`.
- `PlayWithoutCost.target.filter` narrows to `kind: ["Tamer"]`, which the printed
  text does not say. Every card named exactly "Nene Amano" is a Tamer today, so it
  is unobservable; left alone rather than churning the IR.

## Catalog discrepancies

- `types` for BT19-068 is `["Unidentified", "Twilight", "Composite"]`, i.e. the
  `[Rule]`-granted `[Composite]` is already folded into the printed type list. On
  the physical card the `[Rule]` line exists precisely because `[Composite]` is NOT
  in the printed type box. Reported, not edited (catalog is out of lane scope).
