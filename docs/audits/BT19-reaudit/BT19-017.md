`evoCosts: [{ Blue, level 2, memoryCost 0 }]`, rarity U, max 4.

Printed clauses:

1. `[On Play] Reveal the top 3 cards of your deck. Add 1 card with [Aqua]/[Sea
   Animal] in any of its traits and 1 card with the [LIBERATOR] trait among them
   to the hand. Return the rest to the bottom of the deck.`
2. `[Rule] Trait: Has the [Aquatic] type.`
3. Inherited: `[End of Attack] [Once Per Turn] Gain 1 memory.`

The `effectText` carries two U+00A0 non-breaking spaces (after `[Sea Animal]` and
after `[LIBERATOR]`); the catalog assertion in the test spells them explicitly.

## The [Rule] line: found missing, then supplied by the coordinator

The first pass of this audit reported a catalog discrepancy: Q3073 asks what this
card's `(Rule)` means, so the printed card carries a
`[Rule] Trait: Has the [Aquatic] type.` line, but the catalog `effectText` did not
print it (the result was baked into `types` only). The coordinator has since
appended the line to `packages/shared/src/cards/data/cards.json` in the same form
BT19-019 uses (two spaces, then the clause) and rebuilt shared. No catalog
discrepancy remains; the test now asserts the full text verbatim.

Following that, `apps/api/src/cards/BT19/BT19-017.ts` gained the same
`Rule` / `GrantStatic` node BT19-018 and BT19-019 carry —
`target { filter { isSelfRef: true }, count 1, isSelf true }`, `grant: "trait"`,
`tokens: ["Aquatic"]` — and keeps `coverage: "full"`, `residual: []`. This is the
IR change that needs the resync.

Honest note on what the node adds: `types` still lists `Aquatic`, so the grant is
redundant with the printed data and no test can isolate the granted trait from the
printed one. Both readings agree, which is what Q3073 requires, and the node makes
the module a faithful compilation of the printed text rather than of a lossy
catalog row.

## Defects fixed locally

The pre-existing test file was rewritten. What it got wrong:

1. Seeded `security: ["BT1-001"]` — a Digi-Egg in security, forbidden by the brief.
   Replaced with inert main-deck Digimon (BT1-009 / BT1-013 / BT1-014).
2. Three of its five tests drove the card with `advance.fireForPermanent`
   (injected timing), which earns no behavioural credit. All reveal tests now run
   through the public `playCard` intent; the inherited clause runs through the real
   turn loop with real attacks.
3. Its once-per-turn test fired the timing twice in a row and never proved the
   NEXT-turn reset, and never proved the clause under a real host.
4. Endpoints were partial: no memory, no deck order, no board, no
   `pendingDecision` assertion.
5. No near-miss peer for either trait filter and no catalog/IR assertion at all.

Module: the missing `Rule` / `GrantStatic` node was added once the coordinator
restored the printed line. The two `match` kinds were already the correct
`traitContains` / `trait` pair, and the add was already mandatory.

## Remaining gaps

- Clause 2's grant path is shadowed by the catalog's baked `types`: the trait is
  observable either way, so no test can attribute it to the `Rule` node alone.
  Isolating it would need a catalog change (dropping `Aquatic` from `types`),
  which is out of lane and would misrepresent the printed card anyway.
- The "add as many as possible" rule is proved for the 1-of-2 and 2-of-2 cases. A
  hostile case where the player would rather add nothing cannot be expressed: the
  harness auto-responder always takes the maximum, and the engine offers no
  decline for a mandatory add.
