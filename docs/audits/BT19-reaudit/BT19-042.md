## Defects found and fixed locally

1. **The compound "atomic both-security" cost was wrong.** The prior module modelled
   `by trashing the top card of your security stack, trash the top card of your opponent's
   security stack` as one `kind: "compound"` cost of two trashes, so an opponent with an empty
   security stack made the whole clause do nothing. The printed text makes only YOUR card the
   cost; the opponent's trash is part of the payload, alongside the +6000 DP. Fixed to
   `cost: { kind: "trashSecurityTop" }` plus a `trashSecurityTop` action with
   `controller: "opponent"`. Contrast BT19-043, whose "by trashing BOTH players' top security
   cards" genuinely is atomic and is confirmed so by KB Q3096 — the two cards read differently
   and must compile differently.
2. **Substring `names` on a bracketed `[Digivolve][Dynasmon]` route.** `names: ["Dynasmon"]`
   is a substring gate, so "Dynasmon (X Antibody)" — this very card — could take the cost-1
   route. Changed to `namesExact: ["Dynasmon"]` (the same trap lane 5 found on BT19-012 and
   lane 16 found on BT19-036). Proved by the near-miss test.
3. **Substring `match: "name"` in the digivolution-card gate.** `[Dynasmon]` is bracketed, so
   the reference is exact: changed to `match: "nameExact"`.
4. **`optional: true` on a mandatory "by doing" cost.** The clause prints no "may"; the Rule
   Manual treats "by doing" as a processing condition. The optional prompt was removed, so the
   clause now fires whenever it is payable.
5. **A dead test assertion.** The prior test's recovery case asserted
   `toHaveLength(count === 2 ? 3 : 3)` — the same value on both branches, so it could not fail.
   Replaced with an `it.each` that asserts the recovered card's instance id and the deck size.
6. The prior suite proved clause 4 almost entirely through `advance().fireForPermanent`
   (injected timing, no behavioural credit). Every clause is now driven through public intents:
   `digivolve`, `attack`, `declareBlock`, and `startTurnLoop` / `runOneTurn`.

No test is retained red; no engine gap was found.

- The two arms of the gate cannot be *separated* by a real card: every printed card whose name
  contains "Dynasmon" but is not exactly "Dynasmon" is a "Dynasmon (X Antibody)", which carries
  the [X Antibody] trait and therefore passes through the other arm anyway. `nameExact` is
  asserted structurally and is proved to accept the exact name; a behavioural discriminator
  would need a card that does not exist.
- ＜Raid＞'s "you may" is answered by `autoAcceptOptional`; the decline branch is not asserted.
