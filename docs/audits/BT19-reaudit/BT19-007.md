# BT19-007 Guilmon — re-audit

Lane 3, card lane. Independent re-audit; the 10/10 claim in
`docs/audits/BT19-AUDIT.md` was not used as evidence.

## Card summary

- Red Digimon, Lv.3 Rookie, play cost 3, DP 1000, Virus / Reptile.
- Digivolve cost: Red Lv.2 for 0.
- Printed clause 1: `[Start of Your Main Phase] If you have [Takato

- Printed clause 2 (inherited): `[All Turns] While you have 0 or less memory,
  add 2000 to this Digimon's DP deletion effects' maximums.`

## Q&A ids

| id | ruling | covered by |
| --- | --- | --- |
| Q3059 | "while you have 0 or less memory" is fulfilled when the gauge is at 0 through 10 on the OWNER's side at the moment a DP-based deletion effect activates | `applies the +2000 maximum only while its owner has 0 or less memory (memory 0 / memory 1)` — the 0 edge deletes, the 1 edge does not |
| Q3060 | "add X000 to the maximum" raises the printed numeric maximum of a DP-based deletion effect | `applies the +2000 maximum ... (memory 0)` and `still raises the printed maximum for a target the bonus alone brings into range` (8000 -> 10000: 10000 DP deleted, 11000 DP not) |
| Q3061 | the maximum is NOT raised for an effect that references a Digimon's DP instead of a printed number | `does not add to a DP maximum that references the source Digimon's DP (Q3061)` |

## Clause -> test -> IR

### `[Start of Your Main Phase] If you have [Takato Matsuki]/[Calumon], gain 1 memory.`

IR: `effects[0]` — trigger `StartOfYourMainPhase`, condition
`youHave { controller: "mine", zone: "battleArea", nameOrTrait: [{ tokens:
["Calumon", "Takato Matsuki"], match: "nameExact" }] }`, action
`GainMemory 1`.

- `gains 1 memory with Calumon in the battle area` — the real turn loop
  (`engine.runOneTurn()` + `advance.waitForMainPhase(0)`), memory read INSIDE
  the open Main phase: 0 -> 1.
- `gains 1 memory with Takato Matsuki in the battle area` — 0 -> 4 (Takato's
  own `[Start of Your Turn]` sets 0 to 3 first, then this clause adds 1).
- `does not gain memory for a near-miss Tamer that is not Takato Matsuki` —
  BT19-081 Kiriha Aonuma on the board, memory stays 0.
- `does not count the opponent's Calumon` — BT19-077 under the opponent's
  control, memory stays 0 (proves the `controller: "mine"` leg).

### Inherited `[All Turns] While you have 0 or less memory, add 2000 ...`

IR: `effects[1]` — trigger `AllTurns`, `isInherited: true`, action
`DeletionMaxDpModifier { amount: 2000, scope: "self", duration: "permanent",
condition: memoryAtMost 0 controller "mine" }`.

The deletion effect used for proof is a different card's printed clause reached
through a public intent, never injected timing: BT19-015 Gallantmon's
`[When Digivolving] Delete 1 of your opponent's Digimon with 8000 DP or less`,
digivolved onto a BT19-012 stack that carries BT19-007 in its digivolution
cards.

- `applies the +2000 maximum only while its owner has 0 or less memory` — the
  Gallantmon route costs 4, so the gauge lands on exactly 0 or exactly 1 when
  the effect resolves. At 0 the 9000 DP target is deleted (8000 + 2000);
  at 1 it survives. Endpoints asserted: memory (0 -> 2 via Gallantmon's own
  "gain 2 memory" on the deleting branch, 1 -> 1 on the other), top card
  `BT19-015`, stack `["BT19-007", "BT19-012"]`, opponent battle area, no
  pending decision.
- `leaves the printed 8000 maximum alone without Guilmon in the digivolution
  cards` — identical board with an inert BT1-009 under the stack; the 9000 DP
  target survives. This is the peer/stack near-miss that attributes the
  deletion to Guilmon.
- `still raises the printed maximum for a target the bonus alone brings into
  range` — 10000 DP deleted, 11000 DP survives, pinning the new maximum at
  exactly 10000.
- `does not add to a DP maximum that references the source Digimon's DP
  (Q3061)` — BT19-014 Shoutmon EX6's `[When Attacking] delete 1 of your
  opponent's Digimon with as much or less DP as this Digimon` with Guilmon
  underneath; its 12000 DP does not become 14000 against a 13000 DP target.

## Defects fixed locally

1. The two start-of-main tests both asserted `memory === -3` after
   `runTurn(0)`. That is the post-turn-pass value, identical with and without
   the named support, so the positive case proved nothing. Replaced by reads
   inside the open Main phase.
2. IR `match: "name"` (substring) for a bracketed `[Takato Matsuki]/[Calumon]`
   name list. Corrected to `nameExact`. No catalog card currently makes the
   two modes diverge for these tokens, so the fix is fidelity, not a behaviour
   change.
3. IR condition `memoryAtMost` had no `controller`, so it read the raw gauge
   (turn player's perspective) instead of the owner's side that Q3059
   describes. Added `controller: "mine"`, matching BT19-009's identical clause.
4. IR trigger was `Static` for a printed `[All Turns]` clause. Changed to
   `AllTurns` (both map to the same continuous window, so this is fidelity).
5. IR `youHave` filter had no `zone`, so it also counted the breeding area.
   Added `zone: "battleArea"`.
6. Fixture defect: the Q3061 test seeded `security: ["BT1-001"]` and
   `deck: ["BT1-002"]`, both Digi-Eggs, in main-deck zones no game can reach.
   Replaced with the inert BT1-009 Monodramon.

## Remaining gaps

- The `controller: "mine"` leg of the memory condition is proved for the
  battle-area count, but not for an off-turn gauge reading: every DP-based
  deletion effect reachable from the current card pool activates on its
  controller's own turn, where the raw and controller-scoped readings agree.
  Distinguishing them needs a card with an off-turn numeric DP deletion.
- A breeding-area near-miss for the `zone: "battleArea"` leg could not be run:
  seating a `breeding` permanent makes `advance.waitForMainPhase` time out in
  the Breeding phase (`apps/api/src/engine/testkit/advance.ts:79`). That is an
  engine/harness seam outside this lane; the opponent-controlled near-miss was
  used instead.
