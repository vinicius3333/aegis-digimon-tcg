### Peer / near-miss evidence

The `[When Digivolving]` test seats three permanents at once: the opponent's
suspended `BT1-011`, the opponent's unsuspended `BT1-015`, and our OWN suspended
`BT1-009`. Only the opponent's suspended body reaches the deck bottom (asserted by
instance id, at the deck's last position); both near misses are asserted still in
their battle areas. That separates the `suspended: true` gate from the
`controller: "opponent"` gate in one board.

The evolution-stack case is a real `digivolve` intent from `BT19-050` Rapidmon
(Green Lv.5): the resulting permanent keeps `stack == [Rapidmon instance]`, memory
falls 6 -> 1, the hand shows exactly the bonus-draw card, and the `SecurityAttack`
grant reads 1 on the evolved permanent.

## Defects found

None in the module. The IR was checked against the traps list:

- `keywords: [{ keyword: "SecurityAttack", amount: 1 }]` sits on `trigger: "Static"`,
  which is correct — `＜Security A. +1＞` is a printed keyword, not an `[All Turns]`
  clause, so the `Static`-vs-`AllTurns` trap does not apply.
- The target filter carries no `nameOrTrait`, so the `match: "name"` /
  `nameExact` trap does not apply.
- No `＜Save＞`, DigiXros, replacement or once-per-turn clause is printed.
- No `abortOnDecline` is present, and none was added.

Defect fixed in the test file (pre-existing evidence quality, not a module bug): the
previous suite proved both timings with `advance().fireForPermanent(...)` — injected
timing, worth at most 1 in Behaviour — and had no evolution route, no illegal-source
negative and no near-miss peer. Both timings are now driven by real `digivolve` and
`attack` intents inside the turn loop.

## Remaining gaps

- The `[When Digivolving]` and `[When Attacking]` clauses share one printed sentence
  and one IR action shape, so each timing is proved once; there is no test of both
  firing in the same turn on the same permanent. That combination has no printed or
  KB-documented interaction.
- "Bottom of the deck" is asserted as the last deck position of the card's OWNER.
  No card in this fixture set can put a card into an opponent's deck, so the
  owner-vs-controller distinction is not separately exercised.

## Catalog discrepancies

None affecting behaviour. Cosmetic only: the catalog prints `＜Security A. +1＞`
while the IR's `raw` string reads `＜Security Attack +1＞`. `raw` is descriptive
metadata, the keyword id and amount are correct, and the catalog is not edited.
