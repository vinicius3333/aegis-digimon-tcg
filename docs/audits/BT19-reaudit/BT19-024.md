## Verification of the prior audit's ＜Decode＞ scoping claim

The prior audit restricted playback to the source Digimon's OWN stack. That is
CORRECT, and it was verified rather than trusted:

- Comprehensive rules 16-36-1: "you may play 1 specified Digimon card from **that
  Digimon's** digivolution cards". 16-36-2 makes it an immediate-type effect on the
  would-leave event; 16-36-3 makes the processing optional.
- Q3058's answer describes exactly this: ＜Decode＞ interrupts the inherited return,
  MarineBullmon still goes to the bottom of the deck, and the opponent's Digimon is
  still returned to hand — the bounce belongs to Puyoyomon's effect, not to Decode.
- Engine seam: the IR expresses the scoping as `target.filter.isSelfRef: true` with
  `from: ["digivolutionCards"]`. `targeting/loose.ts:385-393` reads `isSelfRef` on a
  hosted zone as "the candidate's host permanent IS the source permanent", so the
  neighbouring stacks are excluded. This is asserted behaviourally, not just read.

## Trait matching — catalog finding, not a defect

The IR matches `[Aqua]`/`[Sea Animal]` with `traitContains` (substring,
case-insensitive). That is the brief's rule for "with [X] in any of its traits", and
the catalog confirms it is the only workable reading here: **no card in the catalog
carries a bare `Aqua` trait** (0 cards), while 61 carry `Aquatic` and 12 carry
`Sea Animal`. The English `[Aqua]` token is exported as `Aquatic`. An exact trait
match would make clause 2 and clause 4 dead text. Recorded in a comment at the top of
the test file.

## Defects found

None requiring an IR change. The module is a hand-fixed file whose header comment
already states the Q3058 reading, and that reading checks out against CR 16-36-1 and
the Q&A text. Checked against the brief's trap list: no `match: "name"` on a bracketed
name; the `[All Turns]` semantics of ＜Decode＞ use `trigger: "AllTurns"` (not
`Static`) on the replacement, with `Static` used only for the keyword declaration; the
`[Rule]` line has a `Rule`/`GrantStatic` node; the `levelComparison` object form IS
read for loose `digivolutionCards` candidates (`matching/definition.ts:135-142`), so
the lane-6 `playCost: { op, value }` trap does not apply here.

The prior test file proved ＜Decode＞ with `advance().fireSubTrigger` and
`advance().verb.deletePermanent`/`returnToHand`, the placement clauses with
`advance().fireForPermanent`, and the inherited clause with `fireForPermanent` twice.
All of that is gone: the current file contains no `advance.fire*` and no
`advance.verb` call.

## Remaining gaps

- **Same-turn refusal of clause 4 is unreachable from public intents.** CR §11-2-3
  (`engine/actions/attack.ts:93` — `deps.attackedThisTurn`) caps each Digimon at one
  attack per turn, so an `[End of Attack] [Once Per Turn]` clause cannot be offered
  twice in a turn without an extra-attack grant, and no such grant is in this lane's
  fixture set. The reset across a real turn boundary IS proved. This is a rules
  limit, not an engine gap; nothing is retained red for it.
- The `[Rule]` node is behaviourally redundant with the catalog, which already lists
  `Aquatic` in `types`. The test proves the card is treated as `[Aquatic]` and that
  another card's `[Aqua]` filter accepts it, but it cannot isolate the grant from the
  printed trait.
- Clause 2's `underFilter` allows placing under MarineBullmon itself; only the
  "another of your Digimon" case is exercised.
- In `reads only its OWN digivolution cards…` the attacker's security check does not
  land within the settle window, so that test asserts the trash contents and the
  neighbour's stack rather than the security count. Not a defect in this card.
