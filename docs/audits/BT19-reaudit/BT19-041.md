## Clause -> test -> IR

- Printed requirement -> catalog `evoCosts`, no `digivolutionRequirement`.
  - Both printed routes exercised publicly: a Lv3 -> Lv4 -> **yellow Lv5**
    (BT1-059) stack and a Lv3 -> Lv4 -> **red Lv5** (BT1-024) stack each cost
    memory 5 -> 2, produce the stack `["BT1-045","BT1-051",<base>]` with the base
    pinned by instance id, and draw exactly one digivolution-bonus card.
  - Near-miss peers rejected in the same parameterised test: BT19-020 (blue/black
    Lv4 — wrong colour and level) and BT1-051 (yellow Lv4 — right colour, one level
    short). BT3-038 Antylamon (yellow Lv5) is the positive control in the same
    shape, so the discriminator is the source, not the harness.
- Clause 1 -> `effects[0]` (`OnPlay`) and `effects[1]` (`WhenDigivolving`), each
  `ModifyDP` +6000 `duration: "untilOpponentTurnEnd"` with
  `cost { kind: "trash", target: { zone: "security", position: "top", count: 1 } }`,
  `optional: true`, `abortOnDecline: true`, followed by `GainKeyword` Blocker with
  `sameTarget: true` and the same duration.
  - `[On Play]` through a real `playCard` intent (memory 10 -> -1): the top security
    card (pinned by instance id) is the only card in trash, the security stack is
    exactly the remaining two, and the grant lands on the chosen peer (BT1-059,
    9000 -> 15000, Blocker true) while the Dynasmon itself stays 11000 with no
    Blocker. `preferInstanceIds` pins the pick, so `sameTarget` is proved against a
    named near-miss rather than by chance.
  - `[When Digivolving]` through a real `digivolve` intent: 11000 -> 17000, Blocker
    true, top security card trashed by instance id.
  - Declined cost: security stack and trash untouched, DP 11000, no Blocker.
  - Unpayable cost (empty security stack): the Digimon still enters play, security
    and trash stay empty, no DP and no Blocker.
  - Duration: through `startTurnLoop`, +6000 and Blocker survive the rest of our
    turn AND the whole of the opponent's turn, and are gone when our next Main
    phase opens — the exact endpoint of `untilOpponentTurnEnd`.
- Clause 2 -> `effects[2]` `AllTurns` + `frequency: "OncePerTurn"`, a `Replacement`
  on `wouldLeavePlay` with `sourceFilter { isSelfRef: true }` and a single
  `SecurityManipulation` `addTop` from `deck`, amount 1, gated by
  `condition { kind: "zoneCount", seat: "mine", zone: "security", op: "lte",
  value: 2 }`.
  - Threshold, through a REAL opponent effect: on the opponent's Main phase they
    play BT11-096 Magma Bomb, which deletes our lowest-DP (and only) Digimon. At 2
    security the top deck card becomes the new top security card; at 3 security
    neither deck nor security moves. In both runs the Dynasmon still leaves — the
    clause is a Recovery, not a prevention — and its whole stack
    (`["BT1-045","BT1-051","BT1-059","BT19-041"]`) reaches the trash.
    Paying for the Option crosses the memory gauge, so the opponent's turn ends and
    our next draw phase runs inside the same drain; the zones are therefore sampled
    through the `onEvent` hook at the instant the battle area empties.
  - Once per turn (same turn): with Tapirmon underneath, two successive
    opponent-effect leaves in one turn. The first recovers; the second recovers
    nothing (security and deck identical by instance id) and the Dynasmon leaves.
  - Next-turn reset: through `startTurnLoop`, the opponent plays a Magma Bomb on
    each of two consecutive turns. Each time the Recovery fires again (the deck top
    of that turn ends up in the trash, paid by Tapirmon's prevention) and the board
    holds at 2 security cards.

Behavioural coverage runs on public intents (`playCard`, `digivolve`, `attack`-free
paths, `endPhase`, `respondDecision`, `surrender`) and the real turn loop. The

## Defects fixed locally

The IR was already correct on every printed clause. `abortOnDecline: true` sits on
the FIRST of two actions, so it is live (not the dead last-action form the set's
trap list warns about): declining the cost must also cancel the Blocker grant, and
the declined-cost test asserts exactly that. `untilOpponentTurnEnd` is a real
`EffectDurationRef` (`packages/shared/src/effects/ir/durations.ts:8`). The
`[All Turns]` clause uses the `AllTurns` trigger, not `Static`.

The old test file was the problem:

1. `[On Play]` and `[When Digivolving]` were proved only by
   `advance().fireForPermanent(timing, ...)` — injected timing, worth at most 1 in
   Behaviour. Both now run from real `playCard` / `digivolve` intents.
2. The duration test set `s.state.turnSeat = 1` and negated `state.memory` by hand
   to fake the opponent's turn. Replaced with `startTurnLoop`.
3. The threshold test was degenerate: `it.each([2, 3])` asserted
   `toHaveLength(count === 2 ? 3 : 3)` — the same value on both branches — and its
   deck assertion `count === 2 ? 0 : 1` passed for the wrong reason because the
   deck held one card. It could not have failed if the condition were ignored.
   Replaced with instance-id comparisons under a real opponent deletion.
4. The evolution coverage never exercised an illegal source, and the "legal route"
   test used BT19-037 / BT19-011 — cards with their own [On Play]/[When Digivolving]
   effects — as bases. Replaced with inert Lv5 bases plus three requirement checks.
5. `compiled` is now exported so the IR shape can be asserted from the test (same
   pattern as BT17-007 and BT19-029). No IR field changed, so `effects.json` stays
   valid and **no resync is needed for this card**.

No red tests retained; no engine gap found.
