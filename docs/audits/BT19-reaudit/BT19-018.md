## Clause -> test -> IR

### `＜Evade＞`

IR: `effects[0]` — `trigger: "Static"`, no actions,
`keywords: [{ keyword: "Evade" }]`. `Static` is correct here: the printed
line is a bare keyword, not a bracketed `[All Turns]` clause.

Proved by its rules consequence through a real opponent effect, never a
flag-only read:

- `survives an opponent's deletion effect by suspending, where the peer is
  deleted` — seat 0 digivolves BT19-015 Gallantmon through the public
  `digivolve` intent; its `[When Digivolving] Delete 1 of your opponent's
  Digimon with 8000 DP or less` is pinned onto Swimmon with
  `preferInstanceIds`. The engine raises an `evadePrompt`, seat 1 answers with
  the public `respondEvade` intent (`accept: true`), and the endpoints are:
  the same permanent id still on the board, `isSuspended === true`, opponent
  trash empty, battle area still 2, no pending decision.
- `is deleted when its controller declines Evade` — identical board,
  `accept: false`: Swimmon's instance is the only card in the trash and the
  battle area holds only the peer.
- `offers no Evade window for the near-miss peer, which is simply deleted` —
  the near-miss control. BT19-017 Sangomon is the same colour, level and DP
  (Blue Lv.3, 1000) and even prints the same `[Rule] Aquatic` line, but has
  no ＜Evade＞: no `evadePrompt` event is ever emitted and it goes straight to
  the trash while Swimmon is untouched.
- `keeps Evade with the top card only: a host it sits under does not gain
  it` — ＜Evade＞ is not inherited; the BT19-019 host with Swimmon underneath
  reports no Evade.

### `[Rule] Trait: Has the [Aquatic] type.`

IR: `effects[1]` — `trigger: "Rule"`, one `GrantStatic` with
`grant: "trait"`, `tokens: ["Aquatic"]`, `target.filter.isSelfRef: true`.

- `is Aquatic and has Evade; a plain Blue Lv.3 peer has neither` — Swimmon is
  Aquatic and still Tropical Fish; the near-miss BT1-027 Armadillomon (Blue
  Lv.3, Mollusk) is not, which proves the grant is self-scoped rather than
  board-wide.

### Inherited `＜Jamming＞.`

IR: `effects[2]` — `isInherited: true`, `keywords: [{ keyword: "Jamming" }]`,
and the suite asserts this is the ONLY inherited effect on the card.

- `gives its evolution host inherited Jamming, which survives a lost security
  battle` — the realistic evolution stack: BT19-019 Shellmon (Blue Lv.4,
  4000 DP, the printed digivolution line for Swimmon) with Swimmon as its
  digivolution card, attacking the player through the public `attack` intent
  into a security stack whose top card is a 5000 DP Security Digimon. The
  host loses the battle and survives (§16-9-1): host still on the board, own
  trash empty, the Security Digimon in the opponent's trash, no pending
  decision. The paired control is the same host with the near-miss BT19-017
  underneath instead — no Jamming, and it is deleted by the same battle.
- `does not extend Jamming to an ordinary Digimon battle` — the clause-scope
  proof. The same Jamming host attacks a suspended 5000 DP opponent Digimon
  and IS deleted, because §16-9-1 covers only battles against Security
  Digimon.
- `keeps Evade with the top card only ...` — the mirror direction: the host
  has Jamming and no Evade, the standalone Swimmon has Evade and no Jamming.

## Defects fixed locally

1. Both keywords were proved only as `observe(...).hasKeyword(...)` reads
   plus, for ＜Evade＞, an `advance.verb.deletePermanent` call. A test-only
   keyword flag proves nothing; ＜Jamming＞ in particular had no behavioural
   test at all. Both now have a rules-consequence proof through public
   intents, each with a control that must fail.
2. The ＜Evade＞ deletion source was a bare production verb. It is now a real
   opponent card effect (BT19-015 Gallantmon's `[When Digivolving]`) reached
   through the public `digivolve` intent, with the decline branch added.
3. No near-miss peer existed for either keyword. BT19-017 Sangomon — same
   colour, level, DP and `[Rule]` line — is now the control for ＜Evade＞ and
   for the inherited ＜Jamming＞ stack.
4. The scope of ＜Jamming＞ was never bounded: nothing distinguished it from
   "cannot be deleted in battle". Added the ordinary-Digimon-battle case
   where the host dies.
5. No catalog assertion existed. Added; it surfaced the `types` observation
   below.
6. The old fixture seeded no security for either seat, which is the trap the
   brief names (an opponent with no security trips the security win check on
   every attack). All boards now seed inert BT1-009/BT1-010/BT1-013 security
   and no Digi-Eggs anywhere.

No IR change: `BT19-018.ts` differs from HEAD only by exporting `compiled`.
`effects.json` stays in sync.

## Remaining gaps

- Q3074 cannot be proved as a GRANT. The catalog already lists `Aquatic` in
  `types` (see below), so `hasEffectiveTrait` returns true from the printed
  types regardless of whether the `GrantStatic` node runs. A consumer test
  would need a card that filters on the `[Aquatic]` trait and could take
  Swimmon; the only such cards in the pool (EX12-031, EX12-036, BT21-031)
  require a Lv.4 or Lv.5 source or a digivolve INTO an Aquatic card, none of
  which a Lv.3 Swimmon can satisfy. Recorded as a gap rather than papered
  over.
- ＜Evade＞ is proved against an effect deletion. §16-22-1 also covers a
  battle deletion; that path is not separately exercised here (Swimmon
  suspends itself to attack, so a self-declared attack cannot pay the Evade
  cost, and an incoming attack requires it to already be suspended).

## Catalog discrepancies

Not a discrepancy so much as a modelling note the coordinator should record:
`types` for BT19-018 is `["Tropical Fish", "Aquatic"]`, i.e. the catalog has
already baked the `[Rule]` trait into the printed type list. The same is true
of BT19-017, BT19-019, BT19-021 and EX6-013, which all print the identical
`[Rule]` line. The IR's `GrantStatic` node is therefore redundant at runtime
and — more importantly — untestable in isolation. Everything else
(`effectText`, `inheritedEffectText`, `evoCosts`, DP, level, play cost)
matches the printed card exactly.
