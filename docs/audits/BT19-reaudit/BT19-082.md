## Defects

### Fixed in this lane (module IR)

**"in one of its traits" was compiled as an exact trait match.** Both refs carried
`match: "trait"` (the exact form, reserved for "with the [X] trait"). The printed form
"with [Aqua]/[Sea Animal] **in one of its traits**" is a substring gate. This is load-bearing, not
cosmetic: **no card in the catalog carries a trait spelled exactly `Aqua`** — the printed reference
reaches `[Aquatic]`, `[Aquabeast]` and `[Ancient Aquabeast]` — so under the exact form the entire
`[Aqua]` half of both filters was unreachable and every [Aquatic] Digimon in the set was silently
excluded from its own Tamer's ability. Changed both refs to `match: "traitContains"`
(`interpreter/matching/definition.ts`, `matchNameOrTrait`). Every [Aquatic] fixture in the test
file is a live proof: all of them fail under the old shape.

`levelComparison { op: "lte", value: 5 }` on a hand-card target was checked against the
loose-card seam and is honoured there (`definitionMatchesFilter`, definition.ts ~line 143) — it is
*not* an instance of the `playCost: { op, value }` object-form trap, which affects only play-cost
keys on loose cards. The level-gate near-miss test proves it behaviourally.
