## Defects fixed locally (IR changed — resync needed)

1. `match: "name"` (substring) for the bracketed exact `[Kiriha Aonuma]` ref -> `nameExact`.
   No catalog fixture discriminates the two modes for this token (the only card whose name
   CONTAINS "Kiriha Aonuma", EX4-062, prints "The name of this card/Tamer is also treated as
   [Kiriha Aonuma]/[Nene Amano]", so it satisfies the exact gate legitimately). The fix is
   therefore correctness-of-IR, not a behaviour change; the peer table pins both the
   qualifying and non-qualifying halves so a future regression to substring matching that
   DOES change behaviour is caught.
2. The `Then, ＜Save＞` placement carried `abortOnDecline: true` and no `optional` and no
   `keywords: [{ keyword: "Save" }]`. `abortOnDecline` on the last action of an effect is
   dead, so the ＜Save＞ was mandatory (comprehensive 16-20-3 makes it optional), and without
   the keyword the registration normalizer
   (`apps/api/src/engine/effects/interpreter/registration/normalize.ts`,
   `withSavePlacementDefaults`) did not default the `PlaceUnder` to `position: "bottom"`.
   The card therefore landed directly beneath the Tamer instead of at the stack bottom,
   inverting the order comprehensive 4-3-2 requires. Both confirmed red before the fix:
   removing the `keywords` block again fails `compiles every printed clause` and the
   bottom-placement assertion in the Q4714 test.
3. `condition.filter` for "you have 1 or fewer Tamers" gained `zone: "battleArea"` so the
   count cannot pick up permanents outside the battle area.

`BT19-020.ts` also now exports `compiled` so the test can pin the IR.
