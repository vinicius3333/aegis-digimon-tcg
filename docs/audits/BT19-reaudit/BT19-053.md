### Evidence notes

- **Route cost.** Memory 5 -> 2 (cost 3) from BT18-052 CannonBeemon with a real two-card
  digivolution stack, with the stack's instance ids and the bonus draw asserted. The
  near miss BT1-076 MegaKabuterimon (Green, Lv.5, `[Insectoid]`, no `[Royal Base]`) is
  rejected with `invalid-evolution` and then digivolves by colour for 4; BT1-022
  Garudamon (Red Lv.5) is rejected outright with board, memory and hand unchanged.
- **"reduced by 8", not "free".** The cost-reduction test plays a second BT19-053 (play
  cost 12) out of face-up security and asserts memory 6 -> 2. The once-per-turn test uses
  BT19-052 (play cost 8) and asserts memory does not move at all — the two together pin
  the modifier at exactly 8.
- **Once per turn through the real loop.** Attack 1 plays one Vespamon; a second attack in
  the same turn, reached publicly by playing BT9-100 Grandis Scissor, plays nothing; after
  a real opponent turn a third attack plays the second Vespamon. The second face-up
  Vespamon sits in security the whole time, so the refusal is the frequency gate and not a
  missing candidate.
- **Near misses for clause 3.** A face-up BT1-066 Tentomon (Green `[Insectoid]`, no
  `[Royal Base]`) and a face-DOWN BT19-052 are both ignored: after the attack the board
  still holds only QueenBeemon, security is unchanged by instance id, and memory is
  unchanged.
- **＜Alliance＞ (Q3106).** Real attack; the engine's `alliancePrompt` lists the Digimon
  the `[When Attacking]` clause just played out of security as an eligible ally;
  `respondAlliance` on it suspends it and QueenBeemon's DP reaches 20000 (12000 + 8000).
  The battle-scoped bonus is sampled through the `onEvent` hook because it expires with
  the battle.
- **Clause 4 with a real opponent effect.** The leave event is the opponent publicly
  playing BT2-018 MetalGreymon (`[On Play] Delete all of your opponent's Digimon with
  4000 DP or less`) inside their own Main phase. No `advance.verb.deletePermanent`
  anywhere. Endpoints: my battle area empty, the two `[Royal Base]` Digimon (QueenBeemon
  herself included — Q3107) at the bottom of security in that order and face up, and the
  near-miss BT1-066 Tentomon in the trash. No selection decision is raised, matching
  Q3108's "affects all Digimon without having to choose them".
- **"you may" and "other than in battle".** Declining the optional sends both Digimon to
  the trash and leaves security untouched. A real battle deletion (a 20000 DP attacker
  killing QueenBeemon on the opponent's turn, after she suspended herself attacking on
  mine) also sends her to the trash with security unchanged — `leaveCause:
  "otherThanBattle"` proved from both sides.
- **Q3099 / Q5304.** BT19-048 ForgeBeemon and BT19-045 FunBeemon share the board with a
  4000 DP QueenBeemon; `preferTriggerKeys: ["BT19-048"]` puts ForgeBeemon's replacement
  first. Endpoint: security becomes
  `[BT1-009 (face down), BT19-048, BT19-053, BT19-045]` with the last three face up, the
  battle area empty and the trash empty — ForgeBeemon paid itself into security to save
  the others, and QueenBeemon's clause then still placed every affected Digimon, exactly
  as the ruling describes.
- **Peer / stack.** Near-miss peers appear in every filter test (Tentomon and
  MegaKabuterimon for the `[Royal Base]` trait, a face-down copy for `faceUp`), and the
  digivolve test runs QueenBeemon on a real FunBeemon/Waspmon/CannonBeemon stack and
  reads ＜Alliance＞ and `[Insectoid]` off the resulting permanent.

## Defects fixed locally

The previous test file proved clause 4 only through `advance().verb.deletePermanent(...,
"byEffect")` and `"byBattle"` and clause 3 only through
`advance().fireForPermanent(EffectTiming.OnUseAttack, ...)`; it covered none of the nine
listed Q&A ids by name, seeded no deck or opponent security, used no near-miss peer, and
proved the cost reduction only as "memory did not change" against a card whose reduced
cost is 0 (which "play for free" would satisfy equally). All of that is replaced by real
opponent effects, real attacks and the real turn loop, with the cost modifier pinned by a
12-cost card.

No IR change was needed: every clause behaves correctly as compiled, including the
hand-written fixes recorded in the module header.

None. All 14 tests are green; nothing is `it.fails` or `it.skip`.

## Remaining gaps

- Q3111 is proved only in the persistent-`[Security]` form, because no `[Royal Base]`
  Digimon prints a check-time `[Security]` clause (see the caveat above). A future card
  that does would give the stronger proof.
- The `[Rule] Trait` node is redundant with the catalog, which already lists `Insectoid`
  in `types`; its own necessity is therefore unprovable from this card alone.
- The `Q3099/Q5304` test reads BT19-048's compiled module, which lane 3's owner is
  editing concurrently. If that lane changes ForgeBeemon's replacement shape, this test
  is the one that will notice; the assertion is written against the ruling's endpoint,
  not against ForgeBeemon's internals.

## Catalog discrepancies

None against the official card. Same observation as BT19-052: `types` already contains
`Insectoid`, making the printed `[Rule]` line redundant with the catalog data.
