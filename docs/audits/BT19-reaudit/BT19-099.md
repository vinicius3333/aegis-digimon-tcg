Printed clauses:

The pair of tests is the testable half of Q3175: the same board, the same two `[Wicked God]`
candidates in hand, and a different leaving Millenniummon, which is what pins the cost reference to
*that* Digimon rather than to a fixed number. The literally-simultaneous case is not reachable: no
printed card in the corpus deletes two Lv.7 Millenniummon at once, and the IR's `pickOne: true`
documents (per `packages/shared/src/effects/ir/actions/subTrigger.ts:167-174`) that the runtime
already fires per-leaving-permanent, so the single-subject default is the field behaviour.

## Retained red — engine gap

`relativeToLeavingDigimon` never resolves, so the ＜Delay＞ body prompts twice ("Trash this card to
activate its ＜Delay＞ effect?", then "Play from zone") and then plays nothing.

- **Seam:** `apps/api/src/engine/effects/interpreter/actions/play.ts:836-853`, the `PlayFromZone`
  `relativeToLeavingDigimon` branch. It resolves the leaving Digimon with
  `ctx.game.permanentById(ctx.trigger.deletedPermanentId ?? ctx.trigger.subjectPermanentId)` and,
  when that is `undefined`, sets `ctx.lastEffectActed = false` and returns without playing.
- **Why it is `undefined`:** the branch's own comment claims "whenLeavesPlay fires with
  `deletedPermanentId` BEFORE removal, so the permanent is still live". The SubTrigger bus states
  the opposite at `apps/api/src/engine/effects/interpreter/actions/subTrigger.ts:299-303`
  ("Deletion/leave events resolve after the causing effect or rule-processing seam may have moved
  the permanent") and therefore gates `whenLeavesPlay` through the removal **snapshot**
  (`deletionSourceFilterGate`, `subTrigger.ts:360-385`) instead of the live board. That gate is
  what makes the passing near-miss test discriminate correctly, so the trigger payload is present
  and its name filter works; only `play.ts` lacks the same snapshot fallback
  (`deletedTopCardId` / `deletedPermanentSnapshots`) and so reads no play cost.
- **Expected vs actual:** expected — BT19-075 MoonMillenniummon (play cost 15) enters seat 0's
  battle area when the play-cost-14 BT18-019 Millenniummon leaves. Actual — nothing is played and
  the `settle` times out.
- **Confirmed by bisection:** removing only the
  `playCost: { op: "eq", relativeToLeavingDigimon: 1 }` filter from the module makes the same test
  pass, so `PlayFromZone` itself works in this context and only the cost reference is dead. The
  module was restored afterwards; the assertion is kept at full strength rather than weakened.
- **Battle route:** attacking a suspended 20 000 DP wall with the Millenniummon (a real battle
  deletion, `apps/api/src/engine/combat/controller.ts:1584`) fails identically and for the same
  reason. It is not repeated as a separate red.
- **Blast radius:** BT19-099 is the only card in the corpus using `relativeToLeavingDigimon` (one
  hit in `packages/shared/src/effects/effects.json`), so the feature appears to have been built for
  this card and is currently dead corpus-wide. The fix belongs in the engine, which this lane may
  not edit.

## Defects fixed locally

None in `BT19-099.ts` — the IR was checked against the trap list and is correct as written:

- `[Millenniummon] **in its name**` is the substring form, so `match: "name"` is right here (not
  `nameExact`, which would exclude MoonMillenniummon and ZeedMillenniummon).
- `with the [Composite] trait` / `[Wicked God] trait` are the exact trait form, `match: "trait"`.
- "without paying the cost" is `payCost: false`; "with the play cost reduced by 4" is
  `costReduction: 4`.
- "You may play" is `optional: true` on both plays; no dead `abortOnDecline` was added.
- The ＜Delay＞ keyword marker is load-bearing: the engine reads
  `keywords: [{ keyword: "Delay" }]` and raises the "Trash this card to activate its ＜Delay＞
  effect?" decision even on an `AllTurns` block, and BT19-099 is trashed when it is accepted.

The previous test file was replaced. Its two tests were one thin happy path and one large
`toMatchObject` on the compiled IR; the IR-shape assertion is kept (tightened) and every clause now
has a real behavioural route.

  `apps/api/src/engine/effects/interpreter/actions/play.ts:836-853`: when
