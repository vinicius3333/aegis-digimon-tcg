## Defects fixed locally

1. **`names` (substring) used for a bracketed exact `[Name]` route.**
   `digivolutionRequirement[0]` carried `names: ["Sakuyamon: Maid Mode"]`. The
   printed `[Digivolve][Sakuyamon: Maid Mode]` is an exact-name gate; `names` is
   documented in `packages/shared/src/effects/ir/requirements/digivolve.ts` as the
   SUBSTRING form. Changed to `namesExact`. No catalog name is a proper superstring
   of "Sakuyamon: Maid Mode" today, so the change is behaviour-preserving now and
   correct for any future print. **This changes the IR: `effects.json` still holds
   the old `names` form and `BT19-catalog-sync.test.ts` will fail for BT19-040
   until the coordinator resyncs.**
2. **The test file proved clause 3 only through injected timing.** Four of the six
   old tests called `advance().fireSubTrigger("whenOptionUsed", { usedOptionCost })`
   with a hand-made payload, one called `fireForPermanent(WhenDigivolving, ...)`,
   and one set `state.turnSeat = 1` directly. Every one of those is replaced with a
   real Option use through `playCard` or through a real card's own free-use effect.
   The old "Q5471" test asserted a hand-made `usedOptionCost: 1`, which proved only
   that the condition compares numbers, not that production computes the use cost
   the way the ruling requires.
3. Module header comment was garbled (truncated sentences, a dangling
   ":118-176" reference). Rewritten against the KB.

No red tests retained; no engine gap found.
