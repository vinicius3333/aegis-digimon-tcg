## Defects

### Fixed in this lane (module IR)

1. **The [All Turns] clause was modelled as the wrong node.** It carried a `PlaceUnder` with
   `target { zone: "underTamer", count: "all", upTo: true }` and `asDigiXrosMaterial: true`.
   That describes a card-moving action the printed clause never performs. The clause widens the
   DigiXros material *source zones*; how many materials are placed is fixed by the played card's
   DigiXros recipe, never by a player-chosen subset of what sits under the Tamers — so the
   `count: "all", upTo: true` shape the previous typed revalidation introduced is not supported by
   the printed text or by Q3142–Q3144. Replaced with the canonical
   `Replacement(wouldBePlayed) → DigiXrosMaterialZoneExpansion { zones: ["underTamers"] }`, the
   exact shape its printed sibling BT19-079 (Taiki Kudo) carries.
2. **The paid condition on clause 1 was mandatory.** "By placing …, gain 1 memory" is a paid
   processing condition and paying it is the controller's choice (comprehensive 15-7-4). Without
   `optional: true` the placement was forced on every Main-phase entry that had a legal hand card.
   Added `optional: true`; both branches are now proved.
3. `from: ["hand"]` made explicit on the place cost (the interpreter already defaults to the hand,
   so this is documentation of the printed zone rather than a behaviour change; the trash near-miss
   test pins it either way).

None. The seam below was closed by the coordinator during this lane; all 15 tests pass.

### Engine/shared seam found and closed by the coordinator

The audit originally landed `it.fails("Q3142/Q3143: an under-Tamer material is legal when
BT19-081 is suspended")` because the `[All Turns]` permission was inert at the real play seam:

- Seam: `packages/shared/src/cards/zoneExpanders.ts`, `DIGIXROS_ZONE_EXPANDERS` /
  `digiXrosZoneExpanderFor`, read by `apps/api/src/engine/actions/digiXros.ts` (~line 240) when a
  play intent names `expanderPermanentIds`.
- BT19-081 had **no entry** in that registry. The `DigiXrosMaterialZoneExpansion` node records
  `["underTamers"]` in the per-seat ledger, but `digiXros.ts` reads only `trash` out of that
  ledger (`ledgerZones.includes("trash")`), so an under-Tamer material was refused as
  `{ ok: false, reason: "invalid-expander" }`.

The coordinator added
`"BT19-081": { appliesTo: (def) => hasAnyTrait(def, ["Blue Flare"]), underTamerMax: 100, trashMax: 0 }`
with **no** `underTamerHostScope` (Q3143: any of your Tamers may host) and rebuilt shared. The
`it.fails` is now a plain `it` and passes: the under-Tamer card lands as a digivolution card of the
played Digimon, BT19-081 suspends, and the hosting Tamer does not. `packages/shared` was outside
this lane, so the registry edit is the coordinator's, not this lane's.

The temporary control test that pinned the old refusal
(`today the under-Tamer material is refused because BT19-081 is not a registered expander`) has
been removed — it asserted the pre-fix result and would now fail by design. The two durable
controls stay:

- `peer control: BT10-088, which IS registered, legalizes an under-Tamer material for the same play`
  — an independent expander reaching the same endpoint.
- `the trait gate is per registration: BT19-079's [Xros Heart] gate refuses this [Blue Flare] card`
  — the gate BT19-081's own registration inverts.
- `without naming any expander, an under-Tamer material is illegal for every seat` — the
  permission is not ambient.

`EX4-062` was tried first as the peer control and rejected: its own `[All Turns]` effect is a bare
`AllTurns` with an unconditional suspend cost, so it suspends itself on any All-Turns window and
is then refused as `invalid-expander` (not this lane's card; noted for whoever audits EX4-062).
