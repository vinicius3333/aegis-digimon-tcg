### Peer / near-miss coverage

- DigiXros: `[MetalGreymon]` (name contains "Greymon" — the slot is exact) and a
  Red `[Greymon]` (BT1-015 — exact name, wrong colour) are both rejected with
  `invalid-material`.
- `＜Material Save 2＞`: BT1-015 sits in the same stack as the two real materials
  and is trashed with the rest of the permanent, proving the eligibility gate is
  the card's own DigiXros recipe (16-21-1) and not "everything underneath".
- `[When Attacking]` route: BT19-021 (Blue, Avian/Aquatic) sits under the same
  Tamer and is never the digivolve target — the `[Blue Flare]` trait match is exact.
- Inherited clause: BT19-021 (Lv.4, wrong trait) and BT19-025 itself (right
  trait, Lv.5) both stay under the Tamer across two turns and three attacks.
- `＜Rush＞`: a freshly played BT1-014 peer is refused the attack the same turn.

### Evolution-stack proof

with BT19-025 as its digivolution card, attacking three times across two of its
own turns through `startTurnLoop` / `waitForMainPhase`, with the once-per-turn
refusal asserted between the first and second attack of the same turn.

## Defects

Fixture defect fixed locally: the prior `BT19-025.test.ts` seeded `security: ["BT1-001"]`,
a Digi-Egg, in the opponent's security. Every fixture now uses inert main-deck
Digimon (BT1-009 / BT1-013 / BT1-014) for both security and deck, and no test uses
the numeric `security: <n>` form.

The prior suite also proved `＜Material Save 2＞`, `[On Play]`, `[When Attacking]`
and the inherited clause only through `advance.fire*` injected timings. Every
clause is now driven by a public intent (`playCard`, `digivolve`, `attack`) or by
the real turn loop.

No module IR change. `BT19-025.ts` gained only `export` on `compiled` so the test
can assert the compiled shape; the IR object itself is byte-identical, so no
`effects.json` resync is needed for this card.

Verified as CORRECT (no change required):

- `Static` is the right trigger for the `＜Material Save 2＞` keyword marker — it is
  a keyword, not an `[All Turns]` clause; `combat/keywords.ts:208` and
  `primitives.ts:2122` read it trigger-agnostically.
- `match: "trait"` (exact) is right for both `[Blue Flare]` references.
- The inherited `PlayWithoutCost` target filter carries no `zone`, but candidates
  come from `action.from` (`actions/play.ts:480-482`), so the source is already
  scoped to `digivolutionCardsUnderTamers`.
- `levelComparison` IS honoured for loose (under-Tamer) candidates
  (`matching/definition.ts:140-146`), so the Lv.4 gate is not the dropped-key trap
  lane 6 hit with `playCost: { op, value }`.
- DigiXros `count: 2` is the PER-MATERIAL cost reduction, not a material count
  (`ir/requirements/xrosLink.ts`), matching comprehensive 7-2-2-1: 7 - 2×2 = 3.

## Remaining gaps

- Q3085's own trigger (BT19-027's `[End of Your Turn]` + `＜Decode＞` would-leave
  replacement) is driven through `advance.verb.returnToDeck` rather than a real
  end-of-turn window. The clause belongs to BT19-027, outside this lane's allowed
  edits; the DigiXros half — what BT19-025 owes — is asserted on real board state.
- `＜Material Save＞` is proved on the battle-death path only
  (`combat/controller.ts:1606`). The effect-deletion path shares the same
  `materialSave` primitive (`primitives.ts:2110`), so it is not separately covered.

## Catalog discrepancies

- `effectText` stores U+00A0 (non-breaking space) where the printed card has
  ordinary spaces, at two positions (inside `[DigiXros -2]` and after
  `＜Material Save 2＞`); `inheritedEffectText` has three more. Tests normalize
  before comparing. Reported, not edited.
- `effectText` prints `＜Rush＞for the turn` with no space after the keyword. Cosmetic.
