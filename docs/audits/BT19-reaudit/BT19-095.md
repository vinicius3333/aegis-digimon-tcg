## Defects fixed locally

1. Both [Main] `duration` fields were `forTheTurn` against a printed "until the
   end of your opponent's turn" -> `untilOpponentTurnEnd`. Mutation-checked:
   reverting either one fails the [Main] expiry test (the grant is swept at the
   controller's own turn end) as well as the IR test.
2. `match: "name"` (substring) on the bracketed exact `[Knight Device]` reference
   in the colour-waiver condition -> `match: "nameExact"`. This is the set-wide
   trap #1. Honest note: no printed card name contains "Knight Device" as a
   strict substring, so the fix is not separable behaviourally for this card; the
   IR test pins it, and the Queen Device test proves the gate is a name gate and
   not a trait gate.

## Remaining gaps

- Q3170's literal scenario (the card is trashed *during the opponent's turn*)
  is not reachable in this lane: the only battle-area trash of an own Option in
  the catalog is a controller-side `deleteOwn` cost on the controller's own Main
  phase (BT19-086), and the one card that trashes an opponent's battle-area
  Option (BT25-093) does not target Options in the battle area. The test proves
  the equivalent and stricter fact: the grant survives the controller's own turn
  end, lives through the whole opponent turn, and expires exactly at that
  opponent turn's end — which is the duration Q3170 states, from the harder
  direction. The trigger also carries no `turnCondition`, so it is turn-agnostic
  (asserted by `BT19-092-102.test.ts`, not editable here).

## Catalog discrepancies

Two were found and BOTH have been corrected by the coordinator in
`cards.json` (see `SOURCE-RECONCILIATION.md`); nothing is outstanding.

1. **Clause 2 wording.** The record read `When this card is trashed in your
   battle area`; every sibling in the Device cycle prints `When an effect trashes
   this card in your battle area`. The engine trigger
   `whenTrashedFromBattleArea` fires only on an effect-driven trash
   (`primitives.ts:3852`), which matches the corrected wording.
2. **Both durations.** The record read `for the turn` in clauses 2 and 3; the
   cycle prints `until the end of your opponent's turn` in both places, and Q3170
   is the same question and answer BT19-093 carries as Q3166 — a question that
   only makes sense for that wording. Corrected; the module now uses
   `untilOpponentTurnEnd` in all four grant actions and the behavioural test
   proves the boundary in both directions.
