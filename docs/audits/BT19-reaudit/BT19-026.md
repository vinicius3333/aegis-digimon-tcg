## Defect fixed locally (IR CHANGED — resync needed)

The `OnDeletion` `PlaceUnder` is the printed `＜Save＞` keyword. The module carried
it as `optional: false` with no keyword declaration, and its header comment
asserted `＜Save＞` is mandatory. Comprehensive 16-20-3 says the processing from
`＜Save＞` is optional, and 4-22 makes the declared keyword the handle other cards
use for "a card with `＜Save＞` in its text". Fixed to `optional: true` plus
`keywords: [{ keyword: "Save", raw: "＜Save＞" }]`, matching the accepted BT19-008
shape. `BT19-026.ts` also gained `export` on `compiled`.

**This changes the IR**, so the persisted record in
`packages/shared/src/effects/effects.json` is stale for BT19-026 and
`BT19-catalog-sync.test.ts` will fail for that card until the coordinator resyncs.

The prior test suite proved `[On Play]`, `[When Digivolving]`, Q3079 and Q3080
only through `advance.fire*` injected timings, and its "declining the optional
source play still performs the independent Save" case relied on the blanket
`autoDeclineOptional` flag, which could not have distinguished a mandatory Save
from an optional one. Every clause is now driven by `playCard`, `digivolve`, a
real deletion or the real turn loop, and the two OnDeletion optionals are
answered individually by a small in-test decision script.

Verified as CORRECT (no change required):

- `AllTurns`, not `Static`, for the printed `[All Turns]` line.
- `duration: "permanent"` is a real `EffectDurationRef` (`ir/durations.ts`), so it
  does not silently expire at turn end.
- `playCostLte: 5` is the loose-card key form; the object form
  `playCost: { op, value }` would have been dropped (lane 6's BT19-013 trap).
- `zone: "underTamers"` on the target filter plus `from: ["underTamers"]` are
  consistent; `underTamers` is a zone alias for `underMyTamers`
  (`targeting/loose.ts:95-113`).

## Remaining gaps

- `＜Save＞` places ZeigGreymon BENEATH the Tamer's existing digivolution cards.
  The tests assert that order, but no KB ruling states it for `＜Save＞` itself —
  comprehensive 16-21-6 states it only for `＜Material Save＞`. Recorded as engine
  behaviour, not as a proven rule.
- The `[On Deletion]` window is opened with `advance.verb.deletePermanent(...,
  "byEffect")`. That is the production deletion primitive, not an injected
  timing, but the deletion is not sourced from another card's printed effect.
- The "2 or more Digimon" count is taken from the opponent's battle area only
  (`actions/digivolution.ts:51`); no ruling in this card's KB set exercises an
  opponent breeding-area Digimon, so that boundary is untested.
