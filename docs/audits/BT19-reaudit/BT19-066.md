## Defects

Fixed locally: `digivolutionRequirement[0]` used the SUBSTRING gate
`names: ["Pagumon"]` for a printed bracketed `[Digivolve][Pagumon]` route. Per the
brief's trap list (lane 5, BT19-012) a bracketed route name must be `namesExact`.
Changed to `namesExact: ["Pagumon"]`.

Honest note on the blast radius: today the catalog contains no card whose `nameEn`
merely CONTAINS "Pagumon", so the two forms are behaviourally identical right now
and no test can discriminate them. The change is a correctness fix against a future
printing, not a live bug fix; it is the reason for the effects.json resync.

The generator's boilerplate header comment ("Behavior is executed by the shared
interpreter …") was replaced with a clause summary naming why the route is exact.

The pre-existing test file (55 lines) was replaced: it asserted an IR skeleton and
proved the draw clause once, with no catalog assertion, no near-miss trait, no
decline branch, no [Wicked God] token, no evolution route at all, no illegal source
and no behavioural test for the inherited ＜Blocker＞. No red tests retained.
