## Card summary

- Red Digimon, Lv.5 Ultimate, play cost 5, DP 8000, Virus / Cyborg, ACE with
  Overflow ＜3＞.
- Digivolve cost: Red Lv.4 for 3.
- Printed clause 1: `[Hand] [Counter] ＜Blast Digivolve＞`.
- Printed clause 2: `[On Play] [When Digivolving] Delete any of your opponent's
  Digimon with DP adding up to 3000. For each of your opponent's Digimon, add
  2000 to this DP-Based deletion effect's maximum. Then, for each Digimon
  deleted by this effect, gain 1 memory.`
- Printed clause 3 (inherited): `[All Turns] Add 3000 to this Digimon's DP
  deletion effects' maximums.`

## Q&A ids

| id | ruling | covered by |
| --- | --- | --- |
| Q6016 | if the source is removed from the battle area while the first process of this effect is resolving, the part after "then" is still processed | `finishes the 'then' clause even when the source leaves mid-resolution (Q6016)` — BT6-064 Mamemon's `[On Deletion]` fires from inside this effect's own `deletePermanent` call and deletes WarGrowlmon (play cost 5); the memory gain still resolves, and the ACE Overflow ＜3＞ is charged. Endpoints: 10 − 5 (play) + 1 (gain) − 3 (overflow) = 3, WarGrowlmon in trash, opposing 20000 DP bystander untouched |

The interleave Q6016 literally describes is an immediate-type "would leave"
replacement removing the source. No catalog card pair reaches that shape (no
printed "when this Digimon would leave the battle area" clause deletes an
opponent's Digimon). The route above is the closest reachable one and does put
the source in the trash before the "then" step runs, because deletion triggers
fire inside `deletePermanent` (`apps/api/src/engine/effects/primitives.ts:3296`)
and that call is awaited before the `GainMemory` action.

## Clause -> test -> IR

### `[Hand] [Counter] ＜Blast Digivolve＞`

IR: `effects[0]` — trigger `Counter`, `isFromHand: true`, keyword
`BlastDigivolve`, empty action list (the keyword is routed by
`registerBlastDigivolveFromEffects`, not by the marker's actions).

- `blast digivolves from hand in the opponent's counter window without paying
  the cost` — real turn loop (`startTurnLoop`), seat 1 attacks, and seat 0
  answers the open counter window with
  `respondCounter { effectKey: "blast-digivolve:<permanentId>" }`. Endpoints:
  top card `BT19-011`, stack `["BT19-009"]`, memory unchanged (the cost is
  waived entirely, not reduced), the digivolve bonus draw in hand, the 20000 DP
  attacker still on the board (out of the 5000 maximum), attack resolved. A bare
  `digivolve` intent cannot reach this window, so the route itself is the proof.

### `[On Play] [When Digivolving] Delete ... adding up to 3000 (+2000 each) ... then gain 1 memory each`

IR: `effects[1]` (`OnPlay`) and `effects[2]` (`WhenDigivolving`), identical
action lists — `DeleteByDPBudget { baseBudget: 3000, budgetBonus: { per: 2000,
unit: "cards", filter: opponent Digimon }, target: all opponent Digimon }` then
`GainMemory { amount: 1, scaling: { per: 1, unit: "cards", filter:
deletedByThisEffect Digimon } }`.

- `deletes the whole opposing board within the scaled budget and gains 1 memory
  per deletion` — `playCard` from hand. 3 opponent Digimon give 3000 + 3 × 2000
  = 9000, and 2000 + 3000 + 4000 = 9000 exactly. Endpoints: opponent battle area
  empty, opponent trash in order, controller's own 1000 DP Digimon untouched
  (the opponent-only leg), memory 10 − 5 + 3 = 8, spare hand card left, no
  pending decision.
- `pins the single-Digimon maximum at exactly 5000 (target 5000/6000 DP)` — one
  opponent Digimon, so the maximum is 3000 + 2000. 5000 dies and gives 1 memory;
  6000 survives and gives none, which also pins the "then" clause to what was
  actually deleted.
- `counts only battle-area Digimon for the +2000, not the opponent's breeding
  Digimon` — 1 battle-area Digimon at 7000 DP plus an opponent breeding Digimon.
  Counting breeding would make the maximum 7000 and delete it; it survives.
- `resolves the same clause through a real digivolve, and refuses an illegal
  source` — the `digivolve` intent onto BT19-009 (Red Lv.4). The Lv.3 BT19-008
  base is rejected `invalid-evolution` first. Endpoints: stack `["BT19-009"]`,
  memory 5 − 3 + 1 = 3, bonus draw, opponent board empty.
- Q6016 test above.

### Inherited `[All Turns] Add 3000 to this Digimon's DP deletion effects' maximums`

IR: `effects[3]` — trigger `AllTurns` (not `Static`), `isInherited: true`,
`DeletionMaxDpModifier { amount: 3000, scope: "self", duration: "permanent" }`.

- `raises a host's printed numeric maximum only from under it (BT19-011 /
  BT1-009)` — BT19-015 Gallantmon's printed `[When Digivolving] delete 1 of your
  opponent's Digimon with 8000 DP or less`, reached through the real digivolve
  intent onto a BT19-012 stack. 8000 + 3000 = 11000 deletes an 11000 DP target;
  the same board with an inert BT1-009 in the digivolution cards leaves it
  alive. Stack identity asserted in both rows.
- `stacks the inherited +3000 onto its own aggregate maximum` — WarGrowlmon
  digivolving over a stack that already carries WarGrowlmon: 3000 + 2000 + 3000
  = 8000 deletes an 8000 DP target. The dedicated budget bonus and the generic
  deletion-maximum bonus are shown to combine on the aggregate action.

## Defects fixed locally

1. The test file proved both timings only through injected timing
   (`advance.fire(EffectTiming.OnPlay/WhenDigivolving, ...)`), which earns no
   behavioural credit. Every clause is now driven by a public intent
   (`playCard`, `digivolve`, `attack` + `respondCounter`).
2. `[Hand] [Counter] ＜Blast Digivolve＞` was proved only by asserting the IR
   marker's shape — no game ever entered the counter window. A real
   opponent-turn counter-window blast digivolve was added.
3. The old inherited-effect test seeded a three-card `under: [...]` stack and
   fired `WhenDigivolving` by hand; it never proved the bonus was WarGrowlmon's.
   Replaced with a real digivolve plus a same-board control that swaps
   WarGrowlmon for an inert Lv.3.
4. No boundary, no negative and no own-side control existed. Added the exact
   5000/6000 maximum edge, the zero-deletion memory case, an own Digimon that
   must not be a candidate, and the illegal-source digivolve rejection.
5. No catalog assertion existed. Added a field-by-field `getCardDefinition`
   check including `isAce` / `overflowMemory`.

Module change: `compiled` is now exported so the test can assert the IR
directly (the accepted BT19-009 shape). **The IR content itself is unchanged**,
so no `effects.json` resync is needed for this card.

## Remaining gaps

- Q6016's literal immediate-type "would leave" interleave is not reachable from
  the catalog (see the Q&A note above); the ruling is proved on the closest
  route, where the source really is gone before the "then" step.
- `budgetBonus` carries no `zone`, which is correct here:
  `countMatching`'s default scan is the battle area only
  (`apps/api/src/engine/effects/interpreter/scaling.ts:22`), and the breeding
  test pins that behaviour. Adding `zone: "battleArea"` would be cosmetic and
  would cost an `effects.json` resync, so it was not made.
