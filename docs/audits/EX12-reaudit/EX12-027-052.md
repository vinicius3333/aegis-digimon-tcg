## Method and result

Each catalog record was read from `packages/shared/src/cards/data/cards.json`, and each card was queried with `node tools/kb/query.mjs card <ID>`. The direct module, compiled IR registration, shared primitives used by the module, and colocated tests were inspected. Existing 10/10 reports were treated as hypotheses. The focused command was run for every card:

```text
pnpm --filter @aegis/api exec vitest run src/cards/EX12/<ID>.test.ts --maxWorkers=1 --no-file-parallelism
```

All 26 focused files passed, with 268 tests passing and zero failures. The seven suites affected by fixture hygiene were rerun after correction: EX12-028 (16), EX12-039 (6), EX12-040 (8), EX12-042 (7), EX12-043 (9), EX12-047 (12), and EX12-048 (11). `git diff --check` was also run after the edits. No card module required an implementation change; every module remains exclusively registered through `registerIrCard`.

The fresh sweep found invalid Digi-Egg fixtures in security and deck setup. Since the brief forbids Digi-Eggs in those setup zones, the fixtures now use neutral Digimon cards: EX12-028 (`BT1-001` → `BT1-010`, both attack redirect cases), EX12-039/040/043 (`BT1-005` → `BT1-010`), EX12-042 (`BT1-005` → `BT1-010`) plus its deck tail (`BT1-008` → `BT1-011`), EX12-043's draw deck (`BT1-001`,`BT1-002` → `BT1-010`,`BT1-011`), and EX12-048 (`BT1-001`,`BT1-002` → `BT1-010`,`BT1-011`).
