# Comprehensive Rules v4.3 source drift

Checked on 2026-09-22 against the [official rules downloads page](https://world.digimoncard.com/rule/) and the [published comprehensive PDF](https://world.digimoncard.com/rule/pdf/general_rule.pdf?20260918).

The official PDF header says **Ver. 4.3, Last Updated: 2026/09/18**. The committed `data/kb/rules/comprehensive.md` header and `data/kb/rules-index.json` title chunk say **Ver. 4.2, Last Updated: 2026/08/18**. The official page also dates its illustrated rule manual September 18, 2026; the committed illustrated manual is an OCR-derived `for Web ver. 6.0` corpus, and its publication date cannot be established from its text header alone.

The v4.3 PDF update history names these changes:

| Updated | 2-3-3-3, 2-3-3-4, 10-1-2-1, 11-5-1-4, 11-5-1-4-1, 15-1-2, 15-3-3, 15-7-4, 15-13-3, 15-15-3-9-2, 15-15-3-9-3, 15-15-7-2, 15-15-7-4 |
| Merged  | 4-27-3 into 4-27-2                                                                                                                |

A mechanical extraction comparison found 1,116 numbered units in the committed text and 1,121 in the new PDF, with 6 newly observed IDs, 1 missing ID, and 111 IDs whose extracted text differs. These counts include formatting and extraction shifts; they are **not** a semantic change count. The PDF's own update history above is the review starting point.

The reviewed update path is: download the current PDFs into a temporary location; compare the named changed rules and illustrated manual against their committed text; run the existing `index-rules.mjs` reconciliation on a controlled branch; review ID retirement and conformance citation drift; adjust engine behavior and tests where the rules require it; then commit the KB and test changes together. The new `node tools/kb/check-rules-freshness.mjs` command compares the live PDF's extracted version and full text with the committed Markdown and every comprehensive index chunk. It accounts for the 16 reviewed chapter-number artifacts in the current PDF extraction. It reports the current stale state with exit code 1 and does not rewrite the corpus. The command is deliberately separate from routine `test:tools` while this known drift is unresolved.

## Reconciliation attempt and semantic blockers

On 2026-09-22, `node tools/kb/index-rules.mjs --force --source=comprehensive` downloaded the current PDF and extracted 27,906 words into 287 comprehensive chunks. It stopped **before writing committed KB files** with `Ambiguous changed rule chunks: ["comprehensive",null,"Update History"]`. Six old and six new update-history chunks changed because the new PDF inserts page artifacts and appends the v4.3 history. A dry comparison found no other ambiguous section/title group. The history group requires an explicit, reviewed retirement or mapping policy; positional reassignment would misrepresent citation identity.

## Follow-on migration scope

The 15 changed or newly introduced rule IDs in the official v4.3 history plus the merge affect at least nine existing comprehensive chunks. Those nine chunks currently have **24 pinned `cite()` calls across 14 conformance test files**. A dry reconciliation that excludes update-history chunks for measurement only yields 78 changed normative chunks, 13 new chunks, and 11 removed chunks. These larger counts include PDF extraction/layout changes and are **not** safe to adopt without reviewing identities, fingerprints, and citation notes. The dry run did not write files; its allocated IDs are provisional because excluding history releases reserved IDs.

This is a multi-part migration: (1) add a reviewed history-chunk policy and reconcile all source identities; (2) review 78 changed chunks and the 24 immediately affected citations, distinguishing actual rule changes from PDF artifacts; (3) update engine behavior and public tests for the semantic reversals and other boundaries listed above; (4) OCR and compare the illustrated manual; (5) refresh the September Card Q&A and add a Rule Q&A ingestion or explicit coverage boundary; (6) run citation integrity, focused mechanism/collection tests, and full typecheck. The current source does not support a smaller “version bump” change.
