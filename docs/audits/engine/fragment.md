# Fragment parameter lifecycle

The §16-37 contract says that when a Digimon with Fragment would be deleted, its controller may choose and trash the printed number of its own digivolution cards; if that payment is executed, preventing the deletion is mandatory.

The bounded conformance file drives public attacks against EX8-051 Fragment (3) and EX12-060 Fragment (2). It asserts exact selected physical source instances, host retention after accepted payment, and host deletion with normal source cleanup when only two sources exist (the insufficient case does not claim a Fragment payment). These cases use actual printed providers and public battle flow; they do not certify all Fragment producers, replacement interactions, or non-battle deletion paths.

Rules basis: comprehensive rules 16-37-1 through 16-37-3 and immediate-effect processing in 15-8-5.
