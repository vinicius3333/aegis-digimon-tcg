This does not establish a real catalog consumer. Complete alias priority, positive standardizations and all consumer encodings remain open.
- **DP-valued scaling unit — bounded correction.** `selfDP` reads the source's live effective DP after the preceding color buff and counts whole units. EX13-020 public plays prove 7000/9000/10000/11000/13000 boundaries with a printed 17000-DP opponent; the retained expected failure is now ordinary. Coverage/residual metadata closes this expressibility gap, without a whole-card certificate. See [live-dp-scaling.md](engine/live-dp-scaling.md).
- **EX13-035 normal loose aggregate cap: repaired 2026-09-12.**
  `pickLoose` now forwards six/twelve to the existing decision API's aggregate
  clamp. Public tests cover both timings, both over-budget orders, exact
  equality, empty selection and the ten-card return. The retained expected
  failure is now an ordinary passing test; executable and persisted IR have
  `coverage: "full"`, `residual: []`. Broader specialized selection compositions
  remain open in [the engine budget ledger](engine/selection-play-cost-budgets.md).
  This targeted repair does not certify EX13 or award a whole-card 10/10 score.
- **EX13-053 own-vs-inherited `[On Deletion]` flake: fixture, closed.**
  The host was BT6-064 Mamemon, which prints its own "[On Deletion]
  delete 1 of your opponent's Digimon with a play cost of 7 or less".
  In the failing runs the engine collected that body alongside the
  inherited De-Digivolve and it deleted the de-digivolve subject, which
  is correct per the printed text. The host is now BT10-022 Brachiomon
  (Black Lv.5, no text); 3 full-directory runs green. Why it only
  failed alongside other files: the test never imported BT6-064's
  module, so alone the host had no registered body. With vitest
  `isolate: false`, a file that had loaded the full card index earlier
  in the same fork left BT6-064 registered, and the body fired. Not an
  engine defect; a fixture that depends on another file's imports.
- **Option-use scaled reduction — bounded correction.** EX13-043 now forwards
  the same per-suspended-Digimon scaling through Option affordability and
  payment. Public attack controls prove costs one/zero/zero, refusal and
  missing White eligibility, plus a Beastkin DUAL Option face. The card's
  Use branch permits multiple colors without waiving actual requirements.
  The old expected failure is ordinary; full card certification remains
  capped at eight. See [option-use-reductions.md](engine/option-use-reductions.md).
- **Per-holder Guard — bounded correction.** The canonical keyword reaction
  binds optional self-payment to each live holder. Both EX13-063 expected
  representations are ordinary proofs; executable/persisted coverage is full
  with no declared residual. Public cases include saving the grantor and a paid
  grantor protecting two targets after aura loss. Public source races, failed
  replacement costs and complete simultaneous exceptions remain open.
  See [guard-lifecycle.md](engine/guard-lifecycle.md).
- **Resolved direct-battle `UntilEndBattle` leak (2026-09-12).**
  EX13-076 now crosses an awaited battle boundary after battle reactions.
  Its supplemental and public evolution/security-attack proofs pass.
  Attack-scoped grants survive that boundary. Security-specific and
  nested-battle duration obligations remain open in
  [the engine ledger](engine/battle-duration-boundaries.md).
- **DUAL Digimon play color gate — corrected and pushed September 13.**
  Commit `5e08e3b01` restricts Option-side color requirements to Option
  use. EX13-065/066 public Digimon plays without a White anchor pass;
  restoring the old expression makes both regressions fail. This is a
  bounded mechanism correction, not a collection certificate.

## Mechanisms

### continuous-tier-tag-leak

`GameEngine.inContinuousPass()` fell back to the shared `continuousMode` field when the
`continuousScope` AsyncLocalStorage held no store, so a watcher body drained from a timing
window while another play's `recomputeContinuousEffects()` was still in flight had its
one-shot modifiers tagged `continuous: true` and cleared by the next recompute. EX13-060's
Tamer-driven re-run of its own [When Digivolving] body lost its -8000 DP for exactly this
reason, while the Digimon-driven path happened to have no recompute in flight. The fallback
now reads `?? false` and the `continuousMode` field is deleted, because every recompute pass
already runs inside `continuousScope.run(true, ...)`. Delivered as `abb48f07b`; see
[continuous-tier-tag-leak.md](engine/continuous-tier-tag-leak.md).

### during-attack-mid-attack-digivolve

No engine gap. EX13-057's "If during an attack" rider was reported against
`conditions.ts`, but the failure came from a fixture that opened the [When Attacking] window
with `advance().fireForPermanent(EffectTiming.OnUseAttack, ...)`. Injected timing declares no
attack, so `combat.currentAttackerId` is undefined and the rider correctly does not apply.
Fixture rule for this set: open an attack window through the public `attack` intent, never
through an injected timing — which is also what earns behavioural credit here. See
[during-attack-mid-attack-digivolve.md](engine/during-attack-mid-attack-digivolve.md).

### kindless-play-pool-options

Settled as a rules reading, with no engine change. Comprehensive rules §6-5 lists playing a
Digimon or Tamer card and _using_ an Option card as distinct Main-phase actions, so a
kind-less "play 1 card" pool reaches Digimon and Tamer cards only; the printed rider "It gains
＜Rush＞ for the turn" describes a permanent an Option would never become. `playableCandidates`
keeps dropping Option-only cards, EX13-060's retained `it.fails` is deleted and replaced by a
positive negative, and the reading is recorded in the module comment. See
[kindless-play-pool-options.md](engine/kindless-play-pool-options.md).
