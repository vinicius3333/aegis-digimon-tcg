# EX13 audit

## Status

EX13 (EXTRA BOOSTER CHIVALROUS XIII) is an announced, not-yet-released product
(official release date 2026-10-02). The catalog carries the 60 cards revealed so
far by the community database as of `88241f0fc`; 17 numbers in the set remain
unrevealed and are not yet in `cards.json`. **All 60 revealed cards now have an
authored module with independent behavioral proof**, following
`.agents/skills/verify-card-implementation`, in 10 batches on 2026-09-11. Six
cards carried a declared residual at the authoring checkpoint. The 2026-09-12
normal loose-selection repair resolves EX13-035's aggregate cap, and the
battle-duration repair resolves EX13-076's direct-battle grant leak. The standardized-name repair also resolves EX13-002's Vee exclusion. Three
remain (EX13-020, EX13-043, EX13-063; see Open engine seams).
No card-specific KB rulings exist for this set (pre-release). `status: incomplete`
reflects the 17 still-unrevealed numbers and the pending full closing test run,
not missing per-card work. Until
the set is fully released and every open engine seam above is closed, EX13 is
gated to the beta battle-mode flag rather than exposed in the default legal pool.

## Open engine seams

- **Standardized name exclusion — bounded correction delivered by the current working implementation.** EX13-002's printed `[Vee]` exclusion and the official English `[Veemon]` exclusion now use shared `nameIncludesToken`; the production matcher verifies exclusion, exact full identity, OR and negation. Its `it.fails` is converted to an ordinary proof and resolved coverage/residual metadata is synchronized. See [name-standardization.md](engine/name-standardization.md). No printed consumer can publicly select this Digi-Egg by `[Vee]` today; this is a named matcher proof, not a public selection certificate. Complete alias priority, positive standardizations and all consumer encodings remain open.
- **DP-valued scaling unit.** `Scaling.unit` has no unit derived from a
  permanent's live DP. First hit: EX13-020's "-4000 DP for every 5000 DP
  this Digimon has", retained as `it.fails`, `coverage: "partial"`.
  Single-card seam so far.
- **EX13-035 normal loose aggregate cap: repaired 2026-09-12.**
  `pickLoose` now forwards six/twelve to the existing decision API's aggregate
  clamp. Public tests cover both timings, both over-budget orders, exact
  equality, empty selection and the ten-card return. The retained expected
  failure is now an ordinary passing test; executable and persisted IR have
  `coverage: "full"`, `residual: []`. Broader specialized selection compositions
  remain open in [the engine budget ledger](engine/selection-play-cost-budgets.md).
  This targeted repair does not certify EX13 or award a whole-card 10/10 score.
- **EX13-053 own-vs-inherited `[On Deletion]` flake: fixture, closed.**
  The host was BT6-064 Mamemon, which prints its own "[On Deletion]
  delete 1 of your opponent's Digimon with a play cost of 7 or less".
  In the failing runs the engine collected that body alongside the
  inherited De-Digivolve and it deleted the de-digivolve subject, which
  is correct per the printed text. The host is now BT10-022 Brachiomon
  (Black Lv.5, no text); 3 full-directory runs green. Why it only
  failed alongside other files: the test never imported BT6-064's
  module, so alone the host had no registered body. With vitest
  `isolate: false`, a file that had loaded the full card index earlier
  in the same fork left BT6-064 registered, and the body fired. Not an
  engine defect; a fixture that depends on another file's imports.
- **`UseOptionWithoutCost` has no scaled cost reduction.** Only the
  sibling `PlayWithoutCost` path calls `scaleFactor`. First hit:
  EX13-043's per-suspended-Digimon reduction on the Option-USE branch,
  retained as `it.fails`, `coverage: "partial"`.
- **Pooled ＜Guard＞ can't express per-holder "other than itself".**
  Leave-prevention `Replacement`s are registered per source permanent.
  First hit: EX13-063, retained as `it.fails`, `coverage: "partial"`.
- **Resolved direct-battle `UntilEndBattle` leak (2026-09-12).**
  EX13-076 now crosses an awaited battle boundary after battle reactions.
  Its supplemental and public evolution/security-attack proofs pass.
  Attack-scoped grants survive that boundary. Security-specific and
  nested-battle duration obligations remain open in
  [the engine ledger](engine/battle-duration-boundaries.md).
- **CONFIRMED production bug (not an EX13 card defect):**
  `printedColorRequirementMet` (`GameEngine.ts:6131`) applies a DUAL
  card's Option-side color requirement even when played on its Digimon
  side. Affects every DUAL card in the game. See REVIEW-NOTES for the
  fix shape.
- **CONFIRMED production bug (not an EX13 card defect):** a `place`
  cost's payability preflight ignores `distinctLevels`/`distinctNames`
  (unlike the sibling trash-return cost, which groups correctly),
  risking an irreversible partial payment for a future card printing "N
  materials of different levels/names" as a placement cost. Found while
  authoring EX13-071, which avoids the shape entirely. See REVIEW-NOTES.
