## KB check

`node tools/kb/query.mjs card EX13-072` → `(no knowledge-base entries)`. **None —
set is pre-release.** General rules consulted in `data/kb/rules/comprehensive.md`:

- §4-23-1 — a bracketed reference such as `[X Antibody]` is an exact card NAME, not a
  trait. The catalog holds exactly one card named "X Antibody" (BT9-109, a White Option),
  so the first branch of clause 2 is `match: "nameExact"`.
- §4-23-2 — "with the [X] trait" is an exact trait token, so every [Chronicle] gate uses
  `match: "trait"`, never `traitContains`. This matters on this card specifically: every
  printed [Chronicle] card in the game also carries the sibling [X Antibody] trait, and
  many [X Antibody] cards do **not** carry [Chronicle].
- §7-2 — `[Start of Your Main Phase]` resolves once, at the start of the controller's own
  main phase.
- §15-7 — "By &lt;cost&gt;, &lt;effect&gt;" gates the whole sentence; declining costs nothing.
- §4-22-3 — "with the cost reduced by 1" reduces the cost; it does not waive the Option's
  colour requirement, so the module keeps `payCost: true` and sets no
  `waiveColorRequirement`.

## Findings for the coordinator (not fixed here — outside a card lane)

1. **BT20-095 vanishes when used through a cost-reducing "use" effect.** Using
   BT20-095 Fellowship of Hope's Keepers via this card's `UseOptionWithoutCost`
   leaves its instance in **no zone at all** — not hand, battle area, trash, deck or
   security — while the memory payment and the suspend cost resolve correctly.
   BT20-095's own `[Main]` ends in `PlaceInBattleAreaSelf`
   (`apps/api/src/cards/BT20/BT20-095.ts`), and the self-place appears to race the
   use lifecycle in `runUseOptionWithoutCost`
   (`apps/api/src/engine/effects/interpreter/actions/borrowed.ts:522`), which also
   stalls the in-flight attack (the defender's security was never checked). The
   sibling Chronicle Option P-204, whose `PlaceInBattleAreaSelf` is `optional`,
   resolves cleanly to the trash. Expected: the used Option ends in one observable
   zone. Actual: the instance is unreachable. Worked around by choosing P-204 as the
   clause-2 fixture; no assertion was weakened.
2. **Fixture trap confirmed, extending the existing review note.** EX5-070
   "X Antibody Proto Form" is *not* a valid `nameExact` near-miss for `[X Antibody]`:
   it prints `[Rule] Name: Also treated as [X Antibody].`, which `effectiveStaticNames`
   folds into the name list, so it is a genuine exact-name match. The test file records
   this so a later worker does not re-adopt it as a negative.
3. **Auto-accepted suspend cost with an empty candidate set.** With `autoAcceptOptional`
   and no eligible Option in hand, the suspend cost is still paid ("a chosen 'may' pays
   first, finds nothing to hit, and the cost is not refunded" — existing review note).
   The test asserts this observable and explicitly does not claim it as a rules result;
   a human controller simply declines.
