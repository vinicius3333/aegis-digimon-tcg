## Knowledge-base check

`node tools/kb/query.mjs card EX13-047` → `(no knowledge-base entries)`. **No KB rulings
available; EX13 is pre-release.** General rules consulted instead:

- `§4-22` / `§4-22-1` (via `tools/kb/query.mjs rules "in its text"`): a card "with XX" is one
  with that term or icon in the information printed on it, and the official rule manual §1
  enumerates the zones — names, traits, effects, **inherited effects**, Link / Rule /
  digivolution and DigiXros requirement lines. That union is exactly what `match: "text"`
  reads in `matching/definition.ts`, and `keywordToken.ts` additionally anchors a printed
  keyword token to its `＜＞` delimiters, so `＜Material Save＞`-style substring collisions
  cannot qualify.
- `§4-23` traits: "with the [Royal Knight] trait" is the exact reading (`match: "trait"`),
  the shape already shipped on EX13-020 and EX13-026. `traitContains` would widen it.
- `§16-36` ＜Blocker＞: read directly off printed text by `combat/keywords.ts`; the `Static`
  IR entry is a record-completeness entry, consistent with EX13-020 / EX13-028.

## Remaining ambiguity

- The printed second slot says "1 card with ＜Blocker＞", not "with ＜Blocker＞ **in its
  text**". The implementation reads it as the §4-22-1 "with XX" wording (printed information,
  inherited line included), which is the only reading the rules define and which the
  `BT1-079` test pins. If a post-release ruling narrowed it to "a card that *has* the
  ＜Blocker＞ ability" (i.e. its own main effect box only), the fix is one field —
  `printedTextOnly`-style scoping is not it; it would need the slot filter restricted to a
  main-effect-only text match, which no current `Filter` field expresses. Flagging as
  pre-release ambiguity, not as a gap.
- Slot ORDER is the printed order (trait slot first). With a single card matching both
  qualifiers and no other match, that order decides which slot it fills; behaviourally the
  outcome is identical (one card to hand) either way, so the test asserts the card count and
  identity rather than the slot that consumed it.
