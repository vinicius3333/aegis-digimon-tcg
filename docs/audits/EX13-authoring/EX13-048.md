### Encoding decisions

- **Two different filters, not one reused.** Unlike EX13-027/EX13-026 (one filter on both
  slots), the printed sentence names two different readings, so slot 1 is `match: "text"`
  and slot 2 `match: "name"`. Every name match is also a text match, so slot 1 is strictly
  the wider of the two.
- **No `requiresMinRevealed`.** `reveal.ts:253` counts matches of the slot's **own** filter
  over the full revealed set. A `2` on the name slot would wrongly skip it in the common
  "one text-only card + one named card" reveal, which the printed sentence resolves by
  adding both. The unguarded shape is already correct: a card taken by slot 1 is in `taken`
  and cannot be taken twice. (Contrast EX13-027, where both slots share one filter and the
  guard is merely inert.)
- **`controller: "mine"` on the leave cost**, the deliberate contrast with EX13-027's bare
  "1 other Digimon" (`controller: "any"`, BT11-040/BT13-065 prior art). EX13-027's own
  comment names this card as the "of your" counterpart; the opponent-payment negative test
  pins it.
- **No `printedTextOnly`.** Per REVIEW-NOTES, that flag scopes a HOST-identity gate whose own
  printed line prints the tokens it filters by. Here the host identity is carried by
  `isSelfRef` and the host is removed from the cost pool by `excludeSelf`; the filter only
  ever looks at *other* permanents, where the whole-stack text reading (§4-23 / Q3208) is
  correct. A mutation that drops `excludeSelf` makes seven tests fail because the host then
  pays with itself via its own EX13-048 stack card — confirming the stack reading is live and
  that `excludeSelf`, not `printedTextOnly`, is the load-bearing field.

## Remaining ambiguity

- **Slot order vs. "do as much as possible".** Slot 1 (the wider text filter) resolves first
  and may legally be pointed at the only `[Knightmon]`-**named** card, leaving slot 2 empty
  even though a text-only card was also revealed. The rules' "do as much as possible"
  principle arguably forbids that choice. The engine offers the full matching set as a
  `selectCards` decision rather than restricting the pick, so this is left as controller
  choice; if a later ruling forces maximisation it is an engine-level targeting concern, not
  a per-card field. Printed slot order is preserved.
- No card-specific rulings exist for EX13-048 (pre-release), so the two readings rest on
  comprehensive §4-22/§4-22-1 plus the established in-repo encodings (EX13-027/EX13-028 for
  names, EX13-008/EX13-018/EX13-039 for text).
