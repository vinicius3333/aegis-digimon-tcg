### Design decisions

- **One cost-bearing `PlayWithoutCost`, not a `CostGatedBlock`.** P-187 Mastemon prints the
  identical sentence ("By trashing your top security card, you may play 1 … from your hand or
  trash without paying the cost") and is encoded exactly this way. It also matters
  behaviourally: the interpreter's "do not offer an optional play when no legal loose card
  exists" preflight (`apps/api/src/engine/effects/interpreter/actions/runAction.ts`) runs only
  for an *optional action*, so with no reachable [Richard Sampson] the whole clause is dropped
  **before** the security card is spent. An `EX10-041`-style `CostGatedBlock` pays first and
  discovers the empty target afterwards.
- **`sharedUseKey` across all three timings.** One printed `[Once Per Turn]` governs the three
  headers, so all three `CardEffect`s carry the same key (`registration/module.ts` collapses
  them to one `UseTracker` entry). Prior art: P-187 (two timings), EX13-014/EX13-012.
- **`nameExact` with no kind or colour qualifier.** The printed sentence brackets only the name,
  so both catalog printings (BT13-098 and EX13-071) qualify; the test plays each from a
  different zone. No `kind: ["Tamer"]` was added — nothing printed says so.
- **Alternate header widens the source, not the cost.** The printed cost (2) equals the catalog
  EvoCost cost; the only widening is "any colour Lv.3 with the exact [DATA SQUAD] trait". The
  negatives are both off-colour so the trait is the only variable between them and the
  off-colour positive.

## Remaining ambiguity

- **Does declining the window spend the `[Once Per Turn]` use?** The engine's trigger-level
  accounting (`apps/api/src/engine/effects/stack.ts`, `resolveOne` → `env.tracker.register`
  after the body runs) treats the window as spent even when the inner optional action is
  declined; the `preserveOncePerTurnOnDecline` release path exists but is consumed only by
  `SubTrigger` `oncePerTurnKey` handling in `apps/api/src/engine/effects/subtriggers.ts`, not by
  `CardEffect.frequency` / `sharedUseKey`. Comprehensive §15-14-1-1 ("each activation counts
  toward 1 use") supports the engine; manual §1 ("once the player chooses to perform the 'by'
  condition, it will count toward 1 use") can be read the other way. With no KB ruling for a
  pre-release card, this module matches its printed twin P-187 and the test asserts only the
  unambiguous part of a decline (nothing paid, nothing played). **Not flagged as an engine gap**
  — it is a corpus-wide reading, not a missing primitive.
- The catalog's `effectText` for this card is the community pre-release transcription; a printed
  errata at release could change the bracket content (e.g. `[Richard Sampson]` wording).
