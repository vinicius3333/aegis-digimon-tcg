| `play or use` (two verbs) | `Modal`, `choose: 1`, branch 0 `PlayWithoutCost`, branch 1 `UseOptionWithoutCost` |
| `You may` | `optional: true` on each branch action |
| `1 card ... from your hand` | `from: ["hand"]`, `count: 1`, `zone: "hand"`, `controllerDefault: "mine"` |
| `with [Dracomon] or [Examon] in its text` | one `nameOrTrait` reference, `tokens: ["Dracomon", "Examon"]`, `match: "text"` (tokens are an OR-list, so this stays a union) |
| `with the cost reduced by 1` | `payCost: true` + `reduceCostBy: 1` on each branch action |

Design notes carried in the module comments:

- The reduction lives on the action, not on a sibling `wouldBePlayed` reduceCost
  Replacement. The replacement shape installs an unscoped subscription that discounts
  every play in the window and has no Option-use path at all. This matches EX12-013 and
  BT26-006, which compile the same sentence.
- `runModal` skips a branch with no legal candidate and auto-selects when one remains
  (`actions/modal.ts` `optionIsAvailable` / `runModal`), so a hand with only an Option
  goes straight to the use branch. Proven by the Option test.
- No `allowDigiXros`: no catalog card with [Dracomon] or [Examon] in its text carries a
  DigiXros requirement, so BT26-006's allowance would widen the clause past anything it
  can reach.

## Engine gaps

None. No test is retained red; no `it.fails` / `it.skip`; no `@ts-nocheck`.

One engine behavior worth recording (not a gap, and not caused by this card):
`optionUseCandidates` in `apps/api/src/engine/effects/interpreter/actions/borrowed.ts`
rejects a multicolored Option unless the action sets `allowMultiColor`. The only other
Option in the catalog printing `[Examon]` is EX3-070 Avalon's Gate (Green/Blue), so it is
unreachable by this clause as written. This card prints no multicolor allowance, so the
module correctly omits one; BT20-093 is used as the use-branch fixture instead.
