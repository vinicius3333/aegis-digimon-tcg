### Authoring decisions

- **Single verb, no Modal.** The printed body says only "play", so one `PlayWithoutCost`, unlike
  EX13-012's "play or use" which needs a `Modal` with a `UseOptionWithoutCost` branch.
- **Scoped discount.** `payCost: true` + `reduceCostBy: 2` discounts exactly the card this
  activation chooses. A `wouldBePlayed` reduceCost replacement would install an unscoped
  subscription discounting every play in the window.
- **Kind, not token, excludes Digimon.** `kind: ["Tamer"]` — EX13-017 Veemon prints
  `[Veedramon]` in its text and must be refused; the discrimination test proves it stays in
  hand.
- **Near-miss token.** BT2-086 Rina Shinomiya prints `[Vee]` and never "Veedramon". "Vee" is a
  prefix of "Veedramon", not the reverse, so substring matching on "Veedramon" correctly
  refuses it. This is the same `[Vee]` token the coordinator's REVIEW-NOTES flags on EX13-002;
  nothing here needs the unrepresentable per-card name exclusion, because this card's gate
  reads the *token it prints*, not DemiVeemon's identity.
- **No `sharedUseKey`.** One printed `[Once Per Turn]` governs one printed timing, so a plain
  `frequency: "OncePerTurn"` is correct; a shared key is only needed for the
  two-timings-one-gate shape (EX13-012, EX12-024).
- **Alternate route value.** Its cost (2) equals the catalog EvoCost, so the alternate's only
  function is to widen the base pool past blue — a red Lv.3 `[CS]` (BT22-008 Agumon) reaches
  this card, a red Lv.3 without `[CS]` (BT1-010) does not, and neither does a Lv.4 (BT1-014).

## Remaining ambiguity

- **"in its text" breadth.** The engine's `match: "text"` is a substring over the full printed
  information union, so a Tamer printing `[AeroVeedramon]` or `[UlforceVeedramon]` would also
  qualify. That is the established codebase reading for the "w/[X] in text" idiom
  (EX13-011, EX13-012, EX12-051) and is consistent with §4-22-1, but with no EX13 KB entries
  there is no card-specific ruling confirming it for this card. Flagged, not worked around.
- **Cross-worker fixture coupling.** The test uses EX13-017 Veemon as a base and as a non-Tamer
  token fixture. EX13-017 now has a module on disk from a sibling worker but is not yet in
  `apps/api/src/cards/EX13/index.ts`, so it is currently inert catalog data here. Once the
  coordinator registers it, its effects become live; both uses place it directly in the battle
  area or hand (never played or moved), and its inherited replacement only fires on *opponent*
  effects, so no assertion in this suite should shift. Worth a re-run after integration.
