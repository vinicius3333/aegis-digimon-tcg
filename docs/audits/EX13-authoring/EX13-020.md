## Knowledge-base check

`node tools/kb/query.mjs card EX13-020` → `(no knowledge-base entries)`. **None — EX13 is
pre-release.** No card-specific ruling was invented.

General rules consulted in `data/kb/rules/comprehensive.md`:

- **§7-3 / §7-3-2 Assembly.** Materials come from the player's **trash only**, the exact printed
  count must be placed, and the reduction is the flat printed `-N`. This is engine-resident
  (`apps/api/src/engine/actions/assembly.ts`), so the IR only declares the recipe.
- **§16-19 ＜Armor Purge＞.** An immediate-type deletion replacement paid by trashing this
  Digimon's own top card, promoting the card beneath. Engine-resident
  (`apps/api/src/engine/effects/primitives.ts`, `apps/api/src/engine/combat/controller.ts`).
- **Trait definition.** `staticTraitsOf` (`apps/api/src/engine/cards/cardData.ts`) is
  forms ∪ attributes ∪ types, which is why the printed **attribute** `[Free]` answers a
  `match: "trait"` reference.

### Trait-filter discrimination

The brief's three-way requirement is met in "discriminates the trait filter three ways":

- matching: BT2-021 Veemon, attribute `[Free]` → unsuspends;
- near-matching: BT18-044 FunBeemon, type `[Royal Base]` → refused (trait matching is exact
  equality after whitespace/hyphen normalization, so the shared "Royal" word does not leak);
- non-matching: BT1-010 Agumon (`[Rookie]`/Vaccine/`[Reptile]`) and the BT1-009 Monodramon host
  → refused.

BT6-111 Alphamon (`[Royal Knight]`, Vaccine) covers the other half of the union in its own test,
so each token is proven to fire on its own.

## Retained red — engine gap

`it.fails("scales the opponent debuff by every 5000 DP this Digimon has")`.

- **Clause:** "give -4000 DP until their turn ends **for every 5000 DP this Digimon has**".
- **Seam:** `Scaling.unit` in `packages/shared/src/effects/ir/predicates/scaling.ts` has no
  DP-valued unit, so `scaleFactor` in
  `apps/api/src/engine/effects/interpreter/scaling.ts` cannot derive a multiplier from the source
  permanent's live DP. It can count cards, colors, security, trash, stack cards, link cards,
  memory and named counters — never a permanent's DP.
- **Expected vs. actual:** with four colors in the trashes Magnamon sits at 11,000 DP when the
  second sentence resolves (2 units of 5000), so the chosen opponent Digimon must take **-8000**;
  the engine applies **-4000**.
- **Current encoding:** the action carries the printed base `-4000` with no `scaling`, which is
  exactly right while Magnamon has 5000–9999 DP (its printed 7000 before modifiers), under-applies
  at 10,000+ DP, and over-applies if it is ever pushed below 5000 DP. `coverage` is `"partial"`
  and the sentence is listed in `residual`.
- **Prior art:** none. EX13-020 is the only card in the whole catalog printing this sentence, so
  there is no existing encoding to copy.

## Remaining ambiguity

- **"in trashes" (plural).** Read as both players' trashes, matching BT26-016's "3 cards in
  trashes" (which the committed IR models with an `orFilters` union over both seats). Encoded as
  `controller: "any"`, which `seatsForController` expands to both seats. If the eventual ruling
  scopes the phrase to the controller's trash only, the fix is one field (`controller: "mine"`).
- **Stacking of the two sentences.** The second sentence reads "this Digimon has", i.e. its DP
  *after* the first sentence resolves. The IR sequences the two actions in printed order, so once
  the engine gains a DP-valued scaling unit the multiplier will naturally read the buffed value.
  No ruling is available to confirm that reading.
