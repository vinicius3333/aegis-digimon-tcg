## Reading decisions

- `[Veedramon] in its name` is a **substring** name ref (`nameOrTrait` with
  `match: "name"`), not `nameExact`. So AeroVeedramon and UlforceVeedramon hosts qualify
  and a plain `Veemon` host does not. Proven both ways (positive substring test,
  three-way negative test).
- `when any of your blue Tamers are played` is the `whenPlayed` sub-trigger bus with
  `sourceFilter: { controllerDefault: "mine", kind: ["Tamer"], colors: ["Blue"] }` — the
  same shape BT11-032 (UlforceVeedramon, "When you play a blue Tamer, unsuspend this
  Digimon") and BT6-019 already use. `whenPlayed` covers effect-driven plays too, which
  matches "are played" rather than "you play".
- `[Your Turn]` is the effect trigger, so the runtime stamps `turnScope: "yourTurn"` on
  the installed watcher; it is not hand-written in the IR.
- `[Once Per Turn]` sits on the watcher-installing effect (`frequency: "OncePerTurn"`),
  the accepted shape for a continuous `[... ][Once Per Turn] When X, ...` clause
  (BT6-019's first effect).
- `may unsuspend` → `optional: true`, no cost.
- `this Digimon` → `isSelfRef: true` + `isSelf: true` (the host carrying this Digi-Egg as
  a digivolution card), never an arbitrary board Veedramon.

## Retained red (engine gap)

`it.fails("does not treat DemiVeemon's name as including [Vee]")`.

- **Seam**: `matchNameOrTrait` in
  `apps/api/src/engine/effects/interpreter/matching/definition.ts` (the
  `if (ref.match === "name") return names.some((name) => name.includes(nameToken));`
  branch). It resolves a `[Vee]` name ref by plain substring over `effectiveNames`, and
  there is no per-card name-exclusion registry anywhere in the engine or shared package
  (`GrantStaticObjectGrant` offers `name`/`trait` *additions* only — no subtraction).
- **Expected vs. actual**: expected `false` for `EX13-002`; actual `true`.
- **Why the proof is taken at the matcher rather than through a public intent**: the only
  other card in the catalog that references `[Vee]` is BT2-086 Rina Shinomiya, whose
  `[On Play]` reveal-and-add is gated to `kind: ["Digimon"]`, and EX13-002 is a
  `DigiEgg`. No shipped card can therefore observe the exclusion on the board today. The
  clause is real but currently unobservable; the matcher-level red flips green the moment
  the engine grows a name-exclusion seam, and a behavioural test becomes possible as soon
  as any card refers to a Digi-Egg by `[Vee]`.

## Remaining ambiguity

- "are played" vs. "you play": read as any play of a blue Tamer the host's controller
  owns, including an effect-driven play, because `whenPlayed` fires on both and the
  printed passive voice is the wider form. With no KB entry for the set this stays a
  reading, not a ruling.
- Whether `[Once Per Turn]` is counted per host Digimon or per copy of the Digi-Egg is not
  separately exercised; the tested board always has a single EX13-002 under a single host.
- The `[Rule]` clause's intended scope (own name only, as read here, vs. also affecting
  how this card is referenced as a digivolution card) cannot be settled pre-release.
