### Notes on the modelling decisions

- **C5 is one pooled trash with a multiplier, not N single-host trashes.** Each printed iteration
  picks "any 1 … from your opponent's Digimon", i.e. across the whole board, which is EX12-035's
  `scope: "acrossDigimon"` pool with the amount scaled instead of its flat printed 4.
  `unit: "digivolutionCards"` is the SOURCE permanent's own stack size (`scaleFactor`'s self-stack
  branch), and `runDigivolutionAction` folds the factor into `amount` exactly once (the comment in
  `runTrashDigivolution` records that recomputing it squared the multiplier in BT25-103).
- **C6 deliberately omits `digivolutionCards: "hasAny"`.** A stackless Digimon has the fewest
  digivolution cards, so C5's own trash can create the set C6 returns. The test seeds two
  source-free Digimon and asserts both are returned, which is the superlative's tie behavior
  (BT24-030, AD1-013; KB Q6025/Q6026 for the general superlative rule).
- **C7 prints no "other than in battle".** BT20-027's otherwise identical inherited sentence does,
  so this card carries NO `leaveCause` at all and watches battle deletion too. There is a
  dedicated test for that difference.
- **C7's cost is a board filter, not the host.** "by suspending 1 of your SUCH Digimon" carries the
  same `[Dracomon]`/`[Examon]`-text predicate rather than `isSelfRef` (contrast BT20-027's
  `isSelf: true`), so any unsuspended matching ally can pay. `costs.ts`'s `"suspend"` branch
  requires `isSuspended === false`, which is what the "cannot pay when every matching Digimon is
  already suspended" test exercises.
- **C7 and C8 are separate printed instances**, each with its own `[Once Per Turn]`, so each effect
  carries its own `frequency` and no `sharedUseKey`. Pooling them would let the main copy starve
  the inherited one on the same turn.
- **Slayerdramon itself matches its own filter**: its printed text contains `[Dracomon]` and
  `[Examon]`, so it protects and can pay for itself. Proven by a dedicated test.

## Peer divergence the coordinator should arbitrate (not an engine gap)

C7/C8 carry **`printedTextOnly: true`** on both the protected-set filter and the suspend-cost
filter. By default a live `match: "text"` reference also reads a permanent's digivolution-card
INHERITED text (`permanentMatchesFilter`'s live-text branch in
`apps/api/src/engine/effects/interpreter/matching/permanent.ts`, justified by EX1-021 Q3208). That
default makes any Digimon merely carrying this card — or any other `[Dracomon]`/`[Examon]` card —
in its stack count as a "[Dracomon] or [Examon] text Digimon". Comprehensive rules **§4-23-2**
says the opposite in as many words: a Digimon does not GAIN a digivolution card's text, only its
effects. `printedTextOnly` exists for exactly this narrowing (its own doc comment cites §4-23-2;
LM-012's `[Angoramon]`-text watcher is the prior art), so it is used here.

**BT20-027 Slayerdramon — the same card name, with the same "[Dracomon]/[Examon] in its text"
filters in both its `[All Turns]` unsuspend clause and its inherited prevention — omits the flag**
and therefore counts an inheriting host as matching. One of the two readings is wrong; §4-23-2 says
it is BT20-027's. This is a pre-existing card, outside this lane's allowed edits, so it is reported
rather than changed. Observed concretely while authoring: with the flag absent, a plain `BT1-014`
Kokatorimon carrying EX13-024 as its single digivolution card appeared in the suspend cost's
`chooseTargets` candidate list and paid the cost.

## Remaining ambiguity

- **Can the leaving Digimon pay its own suspend cost?** "by suspending 1 of your such Digimon"
  names no exclusion, and the engine lets the leaving permanent be the payer when it is
  unsuspended. No ruling addresses it for this sentence shape; the permissive reading is kept
  (and the "protects the printed host itself" test pins the behavior) because the printed text
  prints no "other".
- **Whether the `printedTextOnly` reading above is the one the set's oracle expects**, given
  BT20-027's committed opposite. Flagged for the coordinator.
- `＜Raid＞` and `＜Blocker＞` are engine keywords; their rules correctness is the engine's, not this
  card's. The tests prove they are published and operate from this card.
