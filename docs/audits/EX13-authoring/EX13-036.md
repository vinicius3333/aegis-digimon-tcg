# EX13-036 Kentaurosmon — authoring audit

## Card summary

Yellow Lv.6 Mega Digimon, Vaccine, `[Holy Warrior]` / `[Royal Knight]` / `[DATA SQUAD]`,
12000 DP, play cost 12, printed EvoCost Yellow Lv.5 for 3, SR, max 4 per deck.

Printed clauses (from `packages/shared/src/cards/data/cards.json`):

1. `[Digivolve] Lv.5 w/[Holy Beast]/[DATA SQUAD] trait: Cost 3`
2. `[Assembly -5] Lv.5 × Lv.4 × Lv.3, all Yellow w/[Holy Beast] trait`
3. `[Security] [On Play] 1 of your opponent's Digimon gets -7000 DP for the turn. If there
   are 6 or fewer total cards in both players' security stacks, instead all of their Digimon
   get -7000 DP for the turn.`
4. `[When Digivolving] By trashing the top security card of 1 player with the most security
   cards, you may activate 1 of this Digimon's [Security] effects.`
5. `[When Digivolving] [End of Attack] [Counter] [Once Per Turn] You may place 1 of each
   player's Digimon as the top security cards.`

No inherited text and no separate `securityEffectText`: the `[Security]` clause is printed
inside `effectText`, so the compiled Security `CardEffect` carries an explicit `description`
for log and decision provenance.

## Knowledge-base check

`node tools/kb/query.mjs card EX13-036` → `(no knowledge-base entries)`. **None — EX13 is
pre-release.** No ruling was invented.

General rules consulted in `data/kb/rules/comprehensive.md`:

- §7-3 / §7-3-2 Assembly — materials come from the **trash** only, the exact printed slot
  count must be placed, the reduction is the flat printed `-5`, and §7-3-2-6 stacks the
  leftmost listed material (the Lv.5) closest to the played card.
- §11-3 Counter Timing — a `[Counter]` effect is activated by the defending seat inside the
  open counter window, which is why the third copy of the placement body is a separate
  `trigger: "Counter"` effect (same shape as EX13-015 in this set).
- §15-16-15-1 `[End of Attack]` — the window binds to the host's **own** attack unless a card
  opts out. The printed `[Counter]` tag is what covers the opponent's attack here, so the
  `EndOfAttack` copy deliberately keeps the default binding instead of `attackScope: "any"`.
- §3-4-5-8 — breeding-area cards can't be referenced, so every board filter pins
  `zone: "battleArea"`.
- §6-5 — a Security Digimon resolves its `[Security]` effect and then still battles the
  attacker (cross-checked against BT26-030's proven behaviour).

Also re-read `REVIEW-NOTES.md` before authoring. None of the listed seams apply to this card:
there is no `[Rule] Name:` exclusion, no DP-derived scaling unit, no `match: "text"`
self-match (so no `printedTextOnly` needed), and no `whenSuspended` SubTrigger. The
`useAlternateCost` fallback note **did** shape the route tests: every alternate-route positive
uses an off-colour Lv.5 source that **no** printed EvoCost can legalise, so `{ok: true}` there
can only mean the trait route fired, and every negative asserts `ok: false` plus an unchanged
memory gauge rather than trusting the boolean.

Design notes worth keeping:

- `ownerSecurity: true` (LM-020's "on top of its owner's security stack") is what makes "the
  top security card**s**" — plural, one per player — land in the right two stacks rather than
  both in the resolving player's.
- The own-board half is ordered first on purpose, not arbitrarily: Kentaurosmon is itself one
  of its controller's battle-area Digimon, so that half always has a candidate and the single
  printed prompt is always reachable. Declining it aborts the opponent half too (`runEffect`
  stops at an aborting leading action) — proven by the decline test.
- Because Kentaurosmon is an eligible candidate for its own placement, the placement tests
  bias the selection with `preferInstanceIds` so the proof is about the clause, not about
  which permanent the auto-responder happened to grab.
- The two `[When Digivolving]` clauses share a timing, so each reactivation test declines the
  placement (`autoDeclineOptional`) and each placement test runs with empty security stacks —
  isolating one clause per proof.

## Retained reds

None. `coverage: "full"`, `residual: []`, no `it.fails` / `it.skip`, no `@ts-nocheck`, and
every action kind used is an existing engine primitive. No engine gap found — every clause
landed on a primitive that already exists (`RecoverByTrashingMostSecurity` with
`recover: false`, `ReactivateEffect` with `fromTrigger: "Security"`, `SecurityManipulation`
with `ownerSecurity`, `totalSecurityCount`).

## Remaining ambiguity

- `ReactivateEffect { fromTrigger: "Security" }` is the first use of that trigger value with
  this primitive (prior cards use `OnPlay` / `WhenDigivolving` / `Main` / `OnDeletion`). The
  runner is generic — it filters `compiled.effects` by trigger and calls `runEffect` with the
  source permanent — and the behavioural tests confirm the borrowed body resolves and reads
  the post-cost security total. Worth a coordinator glance since it is novel usage, not novel
  code.
- Whether the printed single "You may" in clause 5 is truly one bundled choice (modelled here)
  or two independent ones is not settled by any ruling, because no pre-release Q&A exists. The
  bundled reading matches the printed sentence's single "may" and is the conservative choice;
  if a release ruling splits them, the fix is dropping `abortOnDecline` and marking the second
  action `optional`.
- The `[End of Attack]` / `[Counter]` split (own attack vs. opponent's attack) follows
  §15-16-15-1 plus the EX13-015 precedent for a printed `[Counter]` tag on a battle-area
  Digimon. A release ruling could instead read the pair as one "any attack" window, which
  would be `attackScope: "any"` on the `EndOfAttack` copy.
