## Knowledge-base check

- `node tools/kb/query.mjs card EX13-046` → `(no knowledge-base entries)`. **None — the set
  is pre-release**, so no card-specific rulings exist yet.
- General rules consulted in `data/kb/rules/comprehensive.md`:
  - §16-12 / §16-12-1 ＜De-Digivolve＞ — the controller declares a number from 1 up to the
    printed number, then that many cards are trashed from the chosen stack starting with the
    top card. The engine's `DeDigivolve` action with `amount: 1` is exactly this keyword;
    `peelStackTops` (`apps/api/src/engine/effects/primitives.ts:1871`) trashes the old top and
    promotes the card beneath, and stops once a level-3 card is on top.
  - §4-22-1 "in its text" — the token anywhere in the card's printed information (name,
    traits and every printed text field), which the IR models as `match: "text"`.
  - Exact-trait wording ("with the [X] trait") → `match: "trait"`, as opposed to
    `traitContains` for "with [X] in any of its traits".

## Harness notes worth carrying forward

- `settle(predicate)` returns the moment the predicate first holds, which can be **mid
  resolution**. An `amount: 2` mutation initially slipped past a test that settled on
  `trash.length === 1`; adding a bare `await settle()` after the predicate settle is what made
  the mutation bite. Worth copying into any test that counts cards an effect produces.
- `peelStackTops` stops a repeated ＜De-Digivolve＞ once a **level-3** card is on top
  (`levelFloor = 3`). A "De-Digivolve 1 vs 2" discrimination therefore needs the promoted
  source to be level 4 or higher — a stack of level-3 sources makes `amount: 1` and
  `amount: 2` behaviourally identical.
- In a `setupEngine` `under: [...]` list the **last** element is the topmost source card.
- De-Digivolve sends the demoted top card to the **trash**, not the deck bottom — the
  `Primitives.deDigivolve` doc comment in `EffectContext.ts:845` says "bottom of its owner's
  deck", which contradicts the implementation and §16-12-1. The implementation is right; the
  comment is stale. Out of scope for this card-only lane.

## Remaining ambiguity

- Whether "Add 1 card with [Mamemon] in its text and 1 card with the [Mutant] trait" lets a
  single card satisfy both qualifiers is not settled by any pre-release ruling. The two-slot
  encoding makes each slot consume a distinct card (one card fills slot 1 only), which
  matches the universal handling of "add 1 X and 1 Y" reveals elsewhere in the codebase
  (EX13-009, ST20-02). A later ruling to the contrary would be a slot-shape change, not an
  engine change.
