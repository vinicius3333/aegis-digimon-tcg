### Design decisions

- **`texts` vs `names`**: "w/[Huckmon] in text" is the printed-information union, not a name
  substring, so the requirement uses `texts: ["Huckmon"]`. This is strictly wider than the
  catalog EvoCost (Red Lv.4): a White Lv.4 Sistermon Ciel (BT10-085) reaches the card only
  through the alternate path, which the test proves by color.
- **Modal, not a cost replacement**: "play or use" is two verbs, matching EX13-005 / EX12-013.
  `payCost: true` + `reduceCostBy: 3` scopes the discount to the one chosen card; a
  `wouldBePlayed` reduceCost replacement would discount every play in the window and has no
  Option branch at all.
- **`colors: ["White"]` (OR-matched)**: "1 white card" only requires white to be present, so a
  Red/White dual-color card still qualifies — `colorsAll` would wrongly demand white alone.
- **One shared `[Once Per Turn]`**: the two printed timings share a single bracket, so both
  windows carry `sharedUseKey: "ir-shared-0"` and a digivolve activation spends the attack
  activation too (EX12-024 / EX12-058 precedent). The test asserts exactly that.
- **No `allowDigiXros`**: no white card with [Huckmon] in its text carries a DigiXros
  requirement, so the allowance would widen the clause beyond anything it can reach.

## Remaining ambiguity

- No card-specific rulings exist (pre-release), so the interaction between this card's
  once-per-turn offer and EX13-014 Jesmon's own [When Digivolving] play clause is untested
  against an official answer. The encoding keeps the two ledgers separate (different cards),
  which is the default rule.
- Whether a future errata restricts "white card" to Digimon/Tamer only is unknowable now; the
  printed word is "card", so Options are included, which is why the Option branch exists.
- The module is not reachable from `apps/api/src/cards/EX13/index.ts` yet — that file is
  outside this lane's allowed edits. The test imports `./EX13-012.js` directly to register it.
