### Deliberate readings

- **`printedTextOnly: true` on the battler filter.** By default a live `match: "text"` ref also
  reads a permanent's digivolution-card inherited text (EX1-021 / Q3208), which would make any
  Digimon merely carrying this card in its stack a "[Dracomon]/[Examon] text Digimon". §4-23-2 says
  a Digimon does not gain a digivolution card's text. Same call EX13-024 makes for the identical
  printed phrase; per REVIEW-NOTES this is a one-field fix, not an engine gap. Mutation-confirmed
  load-bearing.
- **`restriction: "unsuspend"`, not `unsuspendDuringOwnUnsuspendPhase`.** The printed wording is a
  bare "can't unsuspend until their turn ends", which is the whole-turn lock (any effect, any
  phase). Mutation-confirmed load-bearing: swapping to the narrower scope fails the
  effect-driven-unsuspend assertion.
- **Suspend pool is both seats.** The printed sentence names no controller, so
  `controllerDefault: "any"` — the BT25-059 / BT9-069 encoding. Mutation-confirmed load-bearing.
- **`useAlternateCost` fallback negative** asserts the memory actually charged (4, not 3), never
  `ok: false`, per REVIEW-NOTES.
- **No `leaveCause`, no `blocksCombatSuspend`, no binding** of the locked permanents to the
  suspended ones: nothing printed calls for any of them.

## Remaining ambiguity / not behaviourally provable

1. **Keyword entries are declarative, not behavioural.** `printedKeywordsOf`
   (`apps/api/src/engine/combat/keywords.ts:128-133`) parses ＜Blocker＞ and ＜Piercing＞ straight out
   of `effectText`, so combat honours both with no IR at all. Deleting `{ keyword: "Blocker" }`
   leaves the block test green; deleting `{ keyword: "Piercing" }` leaves the security-check
   behaviour green and only breaks `observe().hasPierce`, which reads the IR. The entries are kept
   for record completeness, as every peer does — this report does **not** claim them as proven by
   behaviour. The tests do prove the real combat behaviour (block accepted and won; excess damage
   reached security).
2. **`namesExact` vs substring `names` is not discriminable for these tokens.** No card in the
   catalog carries "Groundramon" or "Wingdramon" as a *proper* substring of its name, so both
   readings admit the same pool today. The bracket-only header means `namesExact` is correct
   (EX13-024's identical header, EX13-020/-021/-041/-043 precedent); the test records it
   structurally only.
3. **Which 2 opponent permanents get locked** when more than 2 are eligible is a free controller
   choice; the test asserts the count (2) and that a third stays free, not a specific pair.
4. **Per-printing [Once Per Turn] pooling.** The clause is printed twice with two separate
   `[Once Per Turn]` gates, so each gets its own `frequency` and no `sharedUseKey` (EX13-024's call
   for its twice-printed clause). An inheriting host carrying this card therefore has one use from
   the inherited copy; a host that *is* this card has one from the main copy. No pre-release ruling
   settles whether a card could ever hold both instances at once, so nothing is pooled.
