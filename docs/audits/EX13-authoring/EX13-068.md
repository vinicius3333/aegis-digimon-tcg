## KB check

- `node tools/kb/query.mjs card EX13-068` → `(no knowledge-base entries)`. **None —
  EX13 is pre-release**, as the brief expects.
- General rules that do apply, all from `data/kb/rules/comprehensive.md`:
  - **§6-2-1** (Unsuspend Phase): the start-of-turn memory floor resolves *before* the
    unsuspend processing. The rule's own worked example is literally this card's
    sentence: *"[Start of Your Turn] If you have 2 or less memory, set it to 3"*.
  - **§4-1-3** (Memory): "If you have X or less memory" reads the gauge on the
    controller's side — hence the plain `memoryAtMost` condition with no `controller`
    override (BT26-096's shape).
  - **§3-4-5-8** (Breeding Area): breeding-area card information can't be referenced
    unless an effect names that area, so "if you don't have a Digimon" is battle-area
    only.
  - **§15-7 / §15-7-4** (Optional Processing Conditions): "By returning this Tamer…"
    is an optional processing condition the controller may decline, and the processing
    after the condition only happens if the condition was executed successfully.

### "After," vs the peers' "Then,"

BT20-085, BT22-086, BT22-088, BT23-087, BT24-082 and EX10-063 all print the same
sentence with **"Then,"**; EX13-068 prints **"After,"**. "Then," makes the tail
conditional on the preceding processing having happened; "After," only orders it. Two
sibling `optional` actions inside one `CostGatedBlock` give exactly the "After,"
reading — declining the first still offers the second — and that is proved
behaviourally by "pays the cost once and reaches the Guilmon tail even when the Takato
play is declined", which hand-answers the three optional prompts `accept / decline /
accept` and asserts the Guilmon arrives while the hand Takato stays in hand.

Two honest caveats from those last two rows:

- `zone: "battleArea"` is declarative. `countMatching`
  (`apps/api/src/engine/effects/interpreter/scaling.ts:95`) only scans the breeding
  area when the filter's `zone` array *names* `"breeding"`, so the default already
  excludes it. The field is kept because §3-4-5-8 is the rule that decides the scope
  and the filter should say so. This matches the existing REVIEW-NOTES entry
  ("an explicit `zone: "battleArea"` on such a gate is declarative, not
  load-bearing"). The behavioural test "still plays Guilmon when the only Digimon is
  in the breeding area" proves the *scope*, not the field.
- `abortOnDecline: true` is likewise declarative **for a `CostGatedBlock` that is the
  only action of its effect**: `controlFlow.ts:98` returns
  `action.abortOnDecline === true` when the cost goes unpaid, and that return value
  only tells the *caller* whether to skip later **sibling** actions — the nested
  actions are already skipped either way. It is kept for peer consistency
  (BT24-082/BT22-086/BT23-087/EX10-063 all set it) and because it states the printed
  "the whole sentence stops" intent. Same class of finding as the REVIEW-NOTES note
  about a redundant `oncePerTurnKey`; no engine change is warranted.

## Harness notes worth carrying forward

- A board whose only hand card is the one the chain plays makes the Main phase
  auto-pass the instant the chain empties the hand; the turn then ends and
  `state.memory` reads as the *negated* opponent-side value. Every turn-loop test here
  keeps a spare playable card in hand.
- This card prompts its own start-of-main cost on the very turn a memory-floor test
  runs, so the three memory tests pass `autoDeclineOptional: true` to isolate clause 1.
- A seeded breeding-area Digimon parks `runOneTurn` in the breeding phase waiting on a
  hatch/move action, so `waitForMainPhase` throws. The §3-4-5-8 test fires
  `EffectTiming.StartOfYourMainPhase` directly instead.

## Remaining ambiguity

- Whether "After," and "Then," differ in any engine-visible way for this shape is a
  reading, not a ruling: there is no comprehensive-rules entry for either connective
  and no pre-release Q&A. The implementation takes the more permissive "After,"
  reading (tail reachable after a declined first play), which is also what the
  peers' IR shape happens to produce, so no peer is contradicted.
