## KB check

`node tools/kb/query.mjs card EX13-074` → "(no knowledge-base entries)". EX13 is
pre-release, so no card-specific rulings exist. General rules consulted in
`data/kb/rules/comprehensive.md`:

- §6-2-1 / §6-2-1-1 — start-of-turn processing happens at the unsuspend phase and
  runs **before** the unsuspend processing. The rule's own worked example is this
  card's exact sentence ("If you have 2 or less memory, set it to 3").
- §4-1-3 — "if you have N or less memory" reads the controller's own side.
- §5-3 — a "By &lt;cost&gt;, &lt;effect&gt;" clause is skipped whole when the cost
  is not paid (the `optional` + `abortOnDecline` shape of every peer).
- §15-14 — [Once Per Turn] limits the physical card, so "played **or** deleted" is
  one use per turn shared by both event forms.
- §4-23-2 — a Digimon gains its digivolution cards' effects, not their text.

Peers used: EX10-058 (the "played or deleted" two-watcher shape with a shared
`oncePerTurnKey`), BT20-092 (`SetMemory` floor + the "by placing … under this
Tamer, ＜Draw 1＞" cost shape), EX10-064 / BT21-088 (place-cost optionality),

## Retained ambiguity / non-provable fields

- `printedTextOnly: true` on the live-board filter is the §4-23-2 reading
  (EX13-024, LM-012 prior art) and is kept for record completeness, but it is
  **not behaviourally provable on this card**: both event forms reach the filter
  through a definition-matching path, and a card being *played* has an empty
  stack anyway. Mutation-confirmed green without it. Documented in the module and
  at the relevant test.
- Clause 3's `[Once Per Turn]` cannot be distinguished from "the source left the
  battle area": a successful activation turns the Tamer into a digivolution card,
  so nothing can activate the clause a second time. The test asserts the only
  observable endpoint (the second `activateEffect` is refused and the board is
  unchanged) and says so in a comment.
- "1 such card" is read as "a [Knightmon] text **Digimon** card" (the antecedent
  of "such" is "your [Knightmon] text Digimon"). The clause-3 gate, by contrast,
  prints "[Knightmon] text **cards**" with no kind, so the gate filter carries no
  `kind` — another effect could put a non-Digimon [Knightmon] text card under
  this Tamer and it counts.
- `match: "text"` follows the codebase convention (the full printed-information
  union, KB Q4317 via EX13-024), so a card merely NAMED LordKnightmon/Knightmon
  answers a `[Knightmon]` text reference as well as one printing the bracketed
  token.
