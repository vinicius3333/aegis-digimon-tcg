# EX13-052 Gladimon — authoring audit

## Card summary

Black Lv.4 Champion, [Warrior], Vaccine, play cost 4, DP 4000, rarity C.
One printed EvoCost: Black Lv.3 for 2. No [Digivolve] header, no DigiXros/Assembly/ACE
fields, no security effect.

Printed clauses:

1. `＜Guard＞`
2. `[On Play] [On Deletion] ＜De-Digivolve 1＞ 1 of your opponent's Digimon.`
3. Inherited: `[All Turns] [Once Per Turn] When this Digimon would leave the battle area
   other than by your effects, by deleting 1 of your other Digimon with [Knightmon] in its
   text, it doesn't leave.`

## KB check

`node tools/kb/query.mjs card EX13-052` → no rulings; EX13 is pre-release. General rules
consulted instead:

- §16-45 ＜Guard＞ — "When any of a player's other Digimon would leave the battle area by an
  opponent's effect, by deleting the Digimon with this effect, it doesn't leave"; immediate
  type (§16-45-2), optional processing (§16-45-3).
- §16-12-1 ＜De-Digivolve n＞ — trash digivolution cards starting from the top.
- §4-23-1 and Official Rule Manual §1 — "with XX in its text" is the token anywhere in the
  card's printed information (names, traits, effects, inherited effects, Link, Rule and
  requirement lines). §4-23-3 confirms a token printed in an *inherited* effect still counts.

### Design notes

- **＜Guard＞ has no engine hook.** `combat/keywords.ts` only tokenizes the icon and
  `leavePrevention.ts` consults IR `Replacement` subscriptions, never a keyword grant. This
  is not a new gap: EX12-056 (the only other card with printed ＜Guard＞) and EX12-072 (which
  grants it) already execute the keyword as an explicit `wouldLeavePlay` prevention, and this
  card reuses that accepted shape verbatim.
- **No `printedTextOnly`** on the inherited cost filter. That flag narrows a host-identity
  gate whose own printed line prints the tokens it filters by (EX13-021/EX13-024). Here the
  filter never looks at the host — `isSelfRef` carries host identity, `excludeSelf` keeps the
  host out of the cost pool — so the default whole-permanent text read (§4-23, KB Q3208) is
  correct. It does make a second Gladimon payable off its own printed inherited line, which
  §4-23-3 endorses.
- **No `oncePerTurnKey`** on the inherited replacement: `frequency: "OncePerTurn"` alone
  enforces the budget (EX13-015/EX13-027 mutation finding), and the once-per-turn test
  confirms it.
- The card's two clauses interact by design: paying ＜Guard＞ deletes Gladimon, whose own
  [On Deletion] then de-digivolves. Proven in one test.

| inherited cost `controller: "mine"` → `"any"` | opponent's-Knightmon negative fails |
| `frequency: "OncePerTurn"` removed | once-per-turn test fails |
| `OnDeletion` effect removed | 2 behavioural tests fail |
| `Static` `keywords` entry removed | only the IR-shape test fails |

The last row is an honest caveat: `combat/keywords.ts` parses `＜Guard＞` straight out of the
printed `effectText`, so the keyword stays observable without the IR entry. The entry is kept
per the coordinator note that Static keyword grants are load-bearing in general (they feed the
continuous ledger that legality checks read first), but this card's keyword visibility is
**not** behaviourally provable.

## Remaining ambiguity

- Whether the engine should make ＜Guard＞ an automatic keyword behaviour rather than
  per-card IR is an open design question, not a blocker: the per-card encoding matches the
  two existing Guard cards. If an engine lane later adds a Guard hook, this card's
  non-inherited `AllTurns` replacement becomes the duplicate to remove.
- Pre-release: no card-specific ruling confirms that a Digimon whose *digivolution card*
  prints [Knightmon] counts for the inherited cost. The implementation follows the engine's
  documented whole-permanent default; §4-23-1's "printed on that card" could be read more
  narrowly, which would be a one-field `printedTextOnly` change.
