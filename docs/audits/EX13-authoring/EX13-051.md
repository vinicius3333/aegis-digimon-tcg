- General rules consulted in `data/kb/rules/comprehensive.md`:
  - §16-5 ＜Blocker＞ and §12-1 Blocking / §11-4 Block Timing — the keyword is a persistent effect
    that lets the non-turn player switch an attack onto this Digimon; blocking suspends the
    blocker, which is what makes the inherited clause reachable through real combat.
  - §15-7 Optional Processing Conditions — a "by `<cost>`, `<result>`" clause performs the result

    opponent's effect both still reach the watcher.

### Design notes

- The watched set is a **board** filter, not `isSelfRef`, because the printed subject is "any of
  your other Digimon with ＜Blocker＞". `runReplacement`'s non-self `protects` path checks the
  leaving permanent's seat against the reaction's owner before running the filter, so
  `controller: "mine"` is honoured there.
- `keywords: ["Blocker"]` on a live permanent (`matching/permanent.ts:838`) reads **granted**
  keywords too, not only printed ones. That is the correct reading of "a Digimon with ＜Blocker＞";
  the same filter shape is used by BT2-101's Unsuspend.
- The inherited SubTrigger deliberately does **not** use `sourceFilter: { isSelfRef: true }`. Per
  REVIEW-NOTES, a bundled self gate on a `whenSuspended` watcher hits the dedicated
  `whenSuspendedSelfGate` payload comparison (`actions/subTrigger.ts:461`), which ignores the rest
  of the filter. The board filter used here is evaluated in full (AD1-014 prints the same sentence
  in main text and uses the same shape).

## Remaining ambiguity

- Whether declining the leave window on an already-triggered `[Once Per Turn]` spends the use is
  moot here: the leave clause prints no `[Once Per Turn]`. For the inherited clause the decline
  path is proven only in the unambiguous half ("declined → host stays suspended"); whether the
  declined use is spent for the rest of that turn is the open `CardEffect.frequency` question
  recorded in REVIEW-NOTES, so no test asserts it.
- "Any of your other Digimon with ＜Blocker＞" is read as including **granted** ＜Blocker＞. No
  pre-release ruling confirms it for this card; it follows the general keyword reading and the
  codebase's existing `keywords` filter behaviour.
