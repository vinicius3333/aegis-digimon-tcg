### Authoring decisions

- **Assembly keyword gate.** `AssemblyMaterial` has no `keywords` field, but `matchNameOrTrait`
  routes a bracketed keyword token through `textPrintsKeyword` (delimiter-anchored), so
  `nameOrTrait` + `match: "text"` expresses "w/＜Blocker＞" without a new primitive. It also
  satisfies `materialMatchesAssemblySlot`'s hard rule that every slot carry a name/trait/text
  anchor — a colour-plus-level slot alone is rejected as unenforceable. **Not an engine gap.**
- **Blanket vs Digimon-only immunity.** The printed sentence names no card kind, so
  `immuneFrom: "opponentEffects"` is correct; `EX13-061`'s `Restrict` + `fromSourceKind: ["Digimon"]`
  would let opposing Options and Tamers through. The test discriminates the two by running the
  opponent's delete from an `Option`- and a `Tamer`-kinded effect frame.
- **`whenSuspended` self gate.** `sourceFilter` carries ONLY `isSelfRef`, per REVIEW-NOTES'
  `whenSuspendedSelfGate` note (any other predicate bundled there would be silently inert).
- **No `frequency` on the unsuspend clause.** The printed line has no [Once Per Turn], and the
  "stacks to +6000" test proves the absence behaviourally.

## Remaining ambiguity

- **Declining the optional sweep and the once-per-turn budget.** Whether a declined "you may"
  still spends the printed [Once Per Turn] is unresolved pre-release (REVIEW-NOTES records the same
  open question for cost-gated windows). Only the unambiguous half is asserted: an accepted sweep
  spends the use and a second same-turn suspension does not sweep again. The decline test does not
  assert anything about the budget afterwards.
- **Keyword predicate over-read.** `textPrintsKeyword` scans `effectText` and
  `inheritedEffectText`, so a trash card whose ＜Blocker＞ is only inherited would satisfy an
  Assembly slot. This is engine-wide behaviour shared by every printed-keyword predicate, not a
  per-card choice; no fixture in this card's tests exercises it.
- **Harness note (not a gap).** `advance(...).verb.suspend(ids, byEffectSeat)` bypasses target
  resolution, so it is not a valid probe for a `beAffected` immunity (an early draft wrongly read
  it as one). The immunity is proven through `deletePermanent` inside an opponent effect frame plus
  the continuous-ledger read.
