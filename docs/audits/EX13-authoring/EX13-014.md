## Knowledge-base check

`node tools/kb/query.mjs card EX13-014` → `(no knowledge-base entries)`. **None — EX13 is
pre-release**, so no card-specific rulings exist. General rules consulted instead:

- `comprehensive §7-3` / `§7-3-2` / `§7-3-2-6` (Assembly): materials come from the **trash**, are
  placed under the played card, reduce the play cost by the printed amount, and stack left-most
  material on top. This is why the module puts the three slots in printed left-to-right order.
- `comprehensive §2-3-10` (Assembly requirements are a structured header, not an effect).
- `comprehensive §4-22-1` ("in its text" = the token anywhere in the printed information), which
  the engine models as `match: "text"` — the name ∪ traits ∪ every printed text field union.

### Encoding notes

- The Option clause is a single `UseOptionWithoutCost`, not a Modal: the printed verb is "use"
  only and the printed kind is "Option card". EX13-012 / EX13-005 need a Modal because they print
  "play **or** use"; this card does not.
- The action carries both `filter` (required by the type, and what sets the cost cap in
  `optionUseCandidates`) and `target` (the same predicate plus `source: "thisDigimon"`, because
  only the `target` form reaches the instance-level zone scoping in `candidateLooseInstances`).
  `source: "thisDigimon"` narrows **only** the hosted zone, leaving the hand pool intact — the
  EX12-034 shape. A bare `from: ["digivolutionCards"]` would span every stack the controller owns.
- `playCostLte: 5` is spelled out rather than leaning on the action's historical default of 5
  (EX8-037), so the printed cap is an intentional value.
- The two Option timings share one printed `[Once Per Turn]`, so both carry
  `sharedUseKey: "ir-shared-0"`. Clause 4 prints its own `[Once Per Turn]` on a separate line and
  therefore carries **no** shared key — pooling it would let one clause starve the other.
- `[Atho or René & Por]`: the engine's canonical identity for this token is the synthetic
  registry card `TOKEN-AthoRenePor-Token`, whose `nameEn` is `"AthoRenePor Token"`
  (`packages/shared/src/cards/tokens.ts`); `PlayToken` maps the printed descriptor
  `"Atho, René & Por"` onto that alias. The `youHaveNone` condition therefore matches
  `nameExact: "AthoRenePor Token"` — a `nameExact` ref against the printed descriptor would never
  match anything. `zone: "battleArea"` keeps the count off the breeding area, which `countMatching`
  would otherwise include.
- `superlative: "lowestDP"` is the EX12-017 / BT23-024 (Q6025/Q6026) server-side narrowing: all
  tied extrema remain eligible and a client intent naming a permanent outside the resolved set is
  rejected.

## Remaining ambiguity

1. **The alternate `[Digivolve]` widening cannot be isolated behaviourally.** Every Lv.5 card with
   `[Huckmon]` in its text in the catalog is red, so it also satisfies the printed Red Lv.5
   EvoCost. The test proves the alternate route resolves at cost 3 on EX13-012 and asserts the
   structured header the engine reads (`digivolutionRequirementsFor`), but no fixture can separate
   the two routes until a non-red Lv.5 `[Huckmon]`-text card exists.
2. **`useAlternateCost: true` is permissive, not selective.** A `digivolve` intent carrying
   `useAlternateCost: true` still succeeds when only the printed EvoCost matches (observed on
   BT1-020 Groundramon, a red Lv.5 with no `[Huckmon]` token). This is an engine-wide property,
   not a gap in this card; it means `useAlternateCost: true` alone cannot prove which route the
   engine took. Noting it because the EX13 peers' negative tests lean on bases that are illegal
   for **both** routes, which masks it.
3. **Single-colour Option default.** `UseOptionWithoutCost` admits only single-colour Options
   unless the action sets `allowMultiColor`. The printed clause names no colour restriction, so a
   dual-colour `[Huckmon]`-text Option card (EX13-065 / EX13-066's Option faces, use cost 5) is
   excluded by the engine default rather than by the card. The module keeps the default to stay
   identical to its EX13 peers (EX13-005, EX13-012, BT23-013), all of which also print no colour
   language. If the coordinator wants the rules-faithful widening, `allowMultiColor: true` is the
   one-line change — but it cannot be proved today because neither EX13-065 nor EX13-066 has a
   card module yet.
4. **Splitting the two "you may" halves of clause 4.** The harness answers every optional prompt
   uniformly, so the tests prove accept-both and decline-both. That a *declined delete* still lets
   the token half run (the sentence is "Then", not "if this effect deleted") is encoded — the
   token action carries no `ifThisEffectDidNotDelete`-family condition, only the `youHaveNone`
   gate — but is not separately observed.
5. **`[All Turns]` vs `[Your Turn]`.** The watcher's `trigger: "AllTurns"` is asserted in the IR
   test. Exercising it on the opponent's turn needs an opponent-turn Digimon play by an effect,
   which no fixture in this lane sets up.
