## Reading decisions

- "with [Gallantmon] in its name" is the **substring** reading (`match: "name"`), not
  `nameExact`. ChaosGallantmon (BT5-081) therefore qualifies and is proven to qualify.
- "1 Digimon card with [Gallantmon] in its name **or** 1 red Tamer card" is a union
  across two different kinds. It cannot be expressed by widening `kind` (that would let
  a red Digimon without the name through), so the Tamer branch is a `filter.orFilters`
  alternative, which the loose-card targeting path unions
  (`apps/api/src/engine/effects/interpreter/targeting/loose.ts:259,295`).
- "By trashing 1 card in your hand, **you may** ..." — `optional: true` with
  `abortOnDecline: true` and the trash cost attached to the `Return` action, matching
  EX10-027 and BT20-070, so declining never pays the cost.
- The inherited clause carries **no** condition. Its BT19-007 / BT19-009 twins print
  "While you have 0 or less memory"; EX13-007 does not, so the `condition` field is
  deliberately absent and a test asserts the bonus applies at positive memory.

### Evidence notes

- Both public entry routes are exercised: `playCard` for `[On Play]` and
  `moveFromBreeding` inside a real turn loop for `[When Moving]`. No verb shortcuts.
- The inherited clause is proven through the smallest legal evolution stack that reaches
  a printed numeric maximum: BT19-012 OmniShoutmon with EX13-007 beneath it, digivolving
  into BT19-015 Gallantmon ("[When Digivolving] Delete 1 of your opponent's Digimon with
  8000 DP or less") via the public `digivolve` intent. Source identity is asserted after
  the transition (`stack` = `["EX13-007", "BT19-012"]`, top card BT19-015), and the
  deletion is corroborated by Gallantmon's own "gain 2 memory" rider.
- The negative control swaps EX13-007 for an inert BT1-009 under the same stack: the
  9000 DP target survives and memory lands on 1, so the raised maximum is Guilmon's.
- The boundary test pins the bonus at exactly 2000: 10000 DP deleted, 11000 DP not.
- Memory is left positive (5 → 1 after the cost) in every inherited test, proving the
  clause is unconditional unlike its BT19-007 twin.
- Endpoints asserted: instance ids per zone (hand / trash / deck / battle area), memory,
  stack contents, opponent battle area, and `pendingDecision === undefined`;
  `assertNoLoudGap(s)` on every play/move test.
- Fixtures are inert main-deck Digimon (BT1-009 / BT1-010) with explicit `dp` overrides;
  no Digi-Egg in security or deck, no numeric `security: <n>` form.

## Remaining ambiguity

- **Pre-release text.** The catalog text comes from the community database for an
  unreleased set. If the printed card turns out to read "[Gallantmon]" as a bare
  bracketed name (exact), the `match: "name"` token would need to become `"nameExact"`
  and the ChaosGallantmon test would invert. The current reading follows the printed
  "in its name" wording, which is the substring convention in this codebase.
- **Empty-target edge.** With a payable hand cost but no legal trash target, the engine
  pays nothing and returns nothing (asserted). No KB ruling exists for this card to
  confirm, but it matches the general rule that a cost is not paid for an
  impossible-to-perform effect.
- `apps/api/src/cards/EX13/index.ts` is still an empty placeholder, so the module is only
  registered by the test's direct import. The coordinator owns that file.
