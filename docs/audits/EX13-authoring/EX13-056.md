### Encoding decisions

- **`sourceFilter: { isSelfRef: true }` is the only predicate on the main watcher.** The
  `whenSuspended` branch of `registerSubTrigger` gates `isSelfRef` through a dedicated payload
  comparison (`whenSuspendedSelfGate`, `engine/effects/interpreter/actions/subTrigger.ts:461`) that
  never evaluates the rest of the filter, so bundling anything else in would be silently inert.
  "This Digimon" is the whole printed subject, so nothing else needs to be there.
- **The inherited watcher deliberately has NO `isSelfRef`** — its printed subject is "any of your
  Digimon", so the board filter must be evaluated in full by the generic `subjectMatchesFilter`
  path. This is the EX13-044 / EX13-051 encoding of that same printed subject.
- **Two independent `frequency: "OncePerTurn"` values, no `sharedUseKey`.** Each printed clause
  carries its own `[Once Per Turn]`; pooling them would let the main copy starve the inherited one
  in the same turn.
- **`keywords: ["Blocker"]` rather than a text/name scan.** `definitionHasKeyword`
  (`interpreter/matching/definition.ts:265`) answers it from the card definition, which is the only
  thing available for a card still in deck or hand — and the correct reading there, since a private-
  zone card has no granted keywords.
- **`levelComparison: {op:"lte"}` + `colors` + `kind`** is BT17-058's shape for the identically
  printed "level N or lower black Digimon card" over a revealed card.

## Remaining ambiguity

- **`colors: ["Black"]` vs. a stricter mono-black reading.** "black Digimon card" is §2-3-1's
  inclusive reading, so a multicolour card containing black qualifies. Not behaviourally
  discriminated here: no multicolour-black Digimon fixture at Lv.≤5 with printed ＜Blocker＞ exists to
  separate the two readings, so the choice rests on the rule, not on a test.
- **`textHasKeyword` reads `inheritedEffectText` as well as `effectText`** when the
  printed-text fallback is used (`matching/definition.ts:286`). A card whose ＜Blocker＞ appears only
  in its INHERITED text would therefore satisfy `keywords: ["Blocker"]` as a deck/hand candidate,
  which is arguably wrong (the inherited keyword is not the card's own when it is the top card).
  No fixture in this test exercises that shape, and it is an engine-wide reading shared by every
  card using the `keywords` predicate (EX13-051 included), so it is flagged here rather than
  worked around in this module.
- **"Trash the rest" when a revealed card is itself a Digi-Egg or an Option** is not exercised;
  `rest: "trash"` is kind-agnostic and peers behave the same way.
