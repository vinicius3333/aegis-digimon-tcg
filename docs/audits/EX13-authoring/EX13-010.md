Printed clauses:

1. `[When Moving] [When Digivolving] Delete 1 of your opponent's Digimon with 4000 DP or
   less.` — one clause printed under two timings; mandatory, opponent-only, one target,
   printed numeric maximum 4000.
2. `If this effect didn't delete, this Digimon gains ＜Raid＞ and +3000 DP for the turn.` —
   a conditional follow-up on the same clause, self-referential, `forTheTurn`.
3. Inherited: `[All Turns] Add 2000 to this Digimon's DP deletion effects' maximums.` —
   unconditional, permanent while this card sits in the digivolution cards.

No `[Digivolve]` alternate route, no Ace/Link/DNA fields, no Once Per Turn.

## Knowledge-base check

- `node tools/kb/query.mjs card EX13-010` → `(no knowledge-base entries)`. **None —
  EX13 is pre-release (official street date 2026-10-02), so no card-specific rulings
  exist.** Not a gap introduced by this work.
- General rules consulted:
  - `comprehensive §16-23` `<Raid>`: a trigger-type keyword that can switch the attack
    target to the opponent's unsuspended Digimon with the highest DP. Nothing about
    `<Raid>` changes how the grant itself resolves.
  - `comprehensive 15-15-4-1`: an effect that adds to the numerical value of an effect adds
    to the value **shown in text**. This is why the inherited `DeletionMaxDpModifier` only
    raises a printed numeric maximum — and why it raises this card's own printed 4000 when
    another copy of the wording (EX13-007 Guilmon) is underneath.
  - `ifThisEffectDidNotDelete` semantics (KB BT23-069 Q5338, already encoded in
    `packages/shared/src/effects/ir/predicates/conditions.ts:70`): an immune or prevented
    target counts as **not deleted**, and so does an empty candidate pool.

### Cross-card and stack verification

- Host used for the inherited clause: **BT19-015 Gallantmon** (`[When Digivolving] delete 1
  of your opponent's Digimon with 8000 DP or less`), reached through the public `digivolve`
  intent off BT19-012 with EX13-010 in the digivolution cards. 9000 DP target dies with
  Growlmon underneath and survives without it.
- **EX13-007 Guilmon** prints the identical inherited wording, so a Guilmon beneath this
  Growlmon raises **this card's own** printed 4000 to 6000. Two tests prove it both ways:
  a 6000 DP Digimon is deleted (and the Raid branch therefore stays shut) while a 7000 DP
  Digimon survives and the Raid branch fires. This also asserts `Permanent.stack ===
  ["EX13-007"]` — the stack holds only the cards beneath the top card.
- Style peers: `EX13-007.ts` (same `WhenMoving` + inherited `DeletionMaxDpModifier` shape),
  `EX11-007.ts` / `BT25-012.ts` (`GainKeyword` Raid + `ModifyDP` `forTheTurn`),
  `EX10-009.ts` / `BT19-015.ts` (`ifThisEffectDidNotDelete` gating a follow-up action).

### Fixtures

## Retained reds / engine gaps

None. Every printed clause is expressed with existing primitives (`Delete`, `GainKeyword`,

invented and no test is `it.fails`/`it.skip`.

## Remaining ambiguity

- `<Raid>`'s own attack-retarget behaviour is engine-wide keyword machinery (proven by the
  `<Raid>` keyword's own tests), so this card's proof asserts the **grant** via
  `observe().hasKeyword(..., "Raid")` rather than re-testing retargeting. The card grants the
  keyword to itself on a turn it just digivolved, so it is summoning-sick and cannot attack
  that turn on the digivolve route anyway.
- No pre-release errata exists for EX13, so the English text in `cards.json` is the sole
  contract. If Bandai's release text differs (for instance making the delete optional), the
  `Delete` action's absent `optional` flag is the single place to revisit.
