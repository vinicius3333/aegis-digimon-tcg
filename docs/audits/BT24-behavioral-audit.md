## BT24-096 — Seventh Graviton — 10/10

1. **Catalog identity and surfaces.** Purple Option, use cost 7, `[Seven Great Demon Lords]`. `{Trash} [Your Turn]` reacts when one of the controller's Digimon digivolves into exact-name `[Creepymon (X Antibody)]`; returning this card to deck bottom is the activation cost; it then activates Main. Main deletes 1 opposing level 6+ Digimon; only if that deletion did not happen, it trashes the opponent's top 3 deck cards. Security activates Main. No evolution/link/fusion/assembly/inherited/dual surface applies to this Option.
2. **KB.** Exact command: `node tools/kb/query.mjs card BT24-096`. Q5702 is enforced by `isFromTrash: true` plus the explicit cost target `zone: "trash"`; the source cannot install/activate from another zone. Q5703 says the trash reaction and Creepymon X's When Digivolving effects trigger simultaneously and the player chooses their order; the real digivolution test exercises both windows in the same evolution resolution, using the harness's public trigger-order decision handling.
3. **Every clause to code.** Trash watcher/exact-name filter/return cost/ActivateMain are in `BT24-096.ts:10-48`; deletion and failed-delete mill are `:49-78`; Security/ActivateMain are `:79-91`. The missing `zone: "trash"` on the return cost was corrected.
4. **Requirements and traits.** A realistic stack evolves BT8-111 Creepymon into BT24-078 Creepymon (X Antibody) through its printed alternate name requirement for cost 2. This proves exact evolved top-card identity and the `whenOneOfYoursDigivolves` filter; unrelated level/name boundaries remain excluded by the exact-name code filter.
5. **Costs and failures.** Normal Option use pays exactly 7. Trash activation returns the exact source instance to deck bottom before Main; decline keeps it in trash and produces no mill. Successful deletion suppresses mill; failed deletion mills exactly 3. No partial cost is observed.
6. **Decisions and controllers.** The owner controls the optional trash activation; accept and decline are both tested. Delete and mill affect only the opponent. The exact named digivolution belongs to the watcher owner.
7. **Zones, order, face, identity.** The same face-up trash instance moves to the bottom after an existing deck card. The opponent's first three deck instances move to trash in top order while the fourth remains. Main deletion precedes conditional mill. Security activates without changing memory.
8. **Complex interactions.** Public `digivolve` builds BT8-111 -> BT24-078, pays alternate evolution cost 2, opens BT24-078's When Digivolving window and BT24-096's simultaneous trash watcher, returns BT24-096, and executes its failed-delete fallback. 9. **UI applicability.** No presentation-only behavior; all selections/order and state changes are engine decisions/intents and observable `GameState`, so browser validation is not applicable.
10. **Verification gates.** `pnpm --filter @aegis/api exec vitest run src/cards/BT24/BT24-096.test.ts --pool=forks --maxWorkers=1 --minWorkers=1` passed 5/5. Oxfmt passed for module/test. Collection type/diff gates remain cumulative for the next checkpoint.
