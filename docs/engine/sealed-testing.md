# Testing Sealed play

Use two independent browser profiles or private windows for Private Sealed. Each profile uses its existing account display name or automatic guest name.

1. Open **Play → Private Match → Advanced settings → Card pool & rules → Rules → Sealed Format**. Choose a released booster product before Create, then share the invitation with the second profile. Join from the invitation or the same setup's Join tab without entering another player name. No saved constructed deck is required. Back to Play returns to Rules; selecting Sealed Format again resumes the existing room.
2. Before opening, verify **0 / 6 packs opened** and no card-pool Add controls. Enter the original booster, select a pack and let its normal animation run. Return during a partial reveal and reload: the builder must still have no cards, and reopening must resume that reveal.
3. Finish all twelve reveals. Return to the regular builder: only those twelve pulls are available, including their actual quantities and artwork. Open another pack for twenty-four eligible cards, then finish the remaining packs for all seventy-two. The original Skip animations and Open all controls may complete remaining packs.
4. On a phone, swipe the card pool to its last currently available card. Swiping must not add cards. Inspect a card, return, add/remove cards and open/close the deck panel. Check the short viewport as well as portrait, both themes, and that Ready remains reachable.
5. Build forty main cards and zero to five Digi-Eggs in both profiles, then Ready. Reload and reconnect: the pool and locked deck must persist. Start game one, make mulligan choices and play a turn. End it through the normal surrender confirmation.
6. Between games, exchange an owned card with the sideboard and Ready again. The pool must stay identical. Complete game two and verify the series score and result. Active-game deck changes must remain locked.

For Swiss, use an organizer and two to four separate signed-in participant profiles. Create a **Sealed Swiss · six packs** event and select a released product. Register/check in the participants and close check-in. Each participant must follow the same opening prerequisite before building and submitting a deck. Verify pairing, first-game deck locks, reload/reconnect, a completed round, and the next preparation window with the original pool. A bye should also open the ordinary between-match preparation window.

The automated `apps/web/e2e/sealed-swiss-rounds.spec.ts` case uses four independent signed-in browser contexts and the real application. It signs up and checks in through the UI, opens all six allocated packs, builds each forty-card deck, plays two complete Swiss BO3 rounds, exchanges sideboard cards and checks the immutable game snapshots and original pools. Eight games each include native mulligan, turn and surrender controls. The four-player event has three planned rounds, so the test checks the third-round preparation window rather than expecting the event to finish. Its eight-minute scenario budget includes four deck builds and eight games; action and assertion deadlines remain the ordinary browser defaults. The browser contexts use reduced motion. Public Playwright clock controls advance only the original booster presentation and resume before building and gameplay. This supplements manual opening-animation checks.

Run it with `SEALED_TEST_DATABASE_URL=postgres://postgres@127.0.0.1:55439/aegis_sealed_test pnpm --filter @aegis/web test:browser sealed-swiss-rounds.spec.ts`. The server refuses other database hosts and ports, uses a fresh UUID schema and drops it afterward. The PostgreSQL API lifecycle suite covers bye preparation separately.

The full API command is `pnpm --filter @aegis/api test`. On an eight-GiB host, use `TEST_MAX_WORKERS=1 TEST_HEAP_MB=2048 NODE_OPTIONS=--max-old-space-size=2048 pnpm --filter @aegis/api test --isolate --maxWorkers=1 --no-file-parallelism`. Isolation matters: Vitest groups all native files into one run request when both isolation and file parallelism are disabled with one worker, retaining their module graphs. The supported `--isolate` override releases workers between files while retaining card batching and every heavy engine, card, conformance and fuzzer suite. Set the isolated `SEALED_TEST_DATABASE_URL` above to include sealed persistence/admission cases; opt into transaction atomicity with `POSTGRES_TESTS=1 POSTGRES_TEST_URL` set to the same isolated URL. Run compiler and browser lanes sequentially with these tests.

Repeat ordinary solo `/booster` opening with an existing practice box: sealed opening must not alter it. Check a normal constructed deck and match as well.

[Rules and BO3 policy](sealed-rules.md) distinguish official between-match sideboarding from the Aegis between-game policy. [Product coverage](sealed-products.md) documents supported English/world products and estimated collation. Browser opening progress is tab/session scoped; independent tabs or devices open their existing allocation themselves. Server allocation, submitted decks and recorded series progress remain durable. A server restart does not recover an active in-memory game.
