The looping match ambience is an original three-tone open-fifth pad with slow amplitude breathing. It uses continuously running oscillators, so there is no file-loading or loop-boundary gap. `aegis.music.enabled` and `aegis.music.volume` follow the existing local SFX preference conventions and remain independent from effects mute/volume. English and Portuguese settings use the existing Aegis layout.

Mixing caps effects at eight oscillator voices, coalesces identical recipes within 75 ms, keeps at most 512 presentation IDs, and uses a shared compressor. The ambience uses three audible oscillators plus three quiet LFOs. Mute ramps avoid abrupt cuts; disabling music stops its voices. Hidden tabs stop effect tails and suspend the context; match exit stops ambience; app teardown/pagehide closes the context and removes listeners. Browser history restoration waits for fresh trusted input before recreating audio.

No AudioContext is created by an animation, server receipt, synthetic input, or autoplay. App-scoped trusted pointer/key input warms/resumes it. The leased Chromium run measured cold context construction at **151.3 ms**, which supports moving that work away from delayed animation playback; this is a single headless-browser observation, not a hardware-wide latency claim.

## Practical limits

Play cost means printed catalog cost: the current play presentation does not expose final paid memory. Assembly is a card-text flavor accent, not a claim that an unreported Assembly declaration occurred. Missing source-level data uses a neutral evolution recipe. Reduced motion retains queued receipt feedback for static-board actions whose decorative presentations are collapsed. Hidden tabs, replay, fast-forward and pre-unlock cues are intentionally silent; they are never replayed as an audio backlog. The generated WAV ambience is a faded excerpt for listening; the shipped pad is continuous. Validation used the already-available offline dependencies with Node 24.21.0; pnpm warned that the repository requests Node 26.

## Causal metadata correction

Integration review found that recipe metadata read the live board ahead of queued presentation and could choose a different permanent with the same printed card ID. `GameScreen` now computes its existing presented seats before the unconditional audio hook and passes only their painted fields and separately held breeding slots, preserving hook order. Burst metadata uses the physical permanent ID and actual painted slot; showcase source metadata requires a matching arrival occurrence key and physical host, otherwise it stays neutral. No past occurrence is reconstructed from a later stack.

The duplicate-host regression failed before the correction (source level 4 instead of the physical host's level 3). Follow-up cases cover held Agumon (ST1-03, source 2 / target 3) while live breeding has Garudamon (ST1-08, target 5), viewer seat reversal, unidentified duplicate showcases and neutral future-stack fallback. Bounded routing/mixer tests, web typecheck, scoped lint and diff checks passed; no browser jobs or full build were needed for this correction.

Integration observer expectation: while ST1-03 is actually painted, the evolution recipe's base sweep is 396 Hz to 792 Hz (target level 3), with a second rise to 990 Hz for source level 2 or the neutral source fallback. It must not use the future ST1-08 target-level-5 sweep of 484 Hz to 968 Hz. When an identified painted host evolves from level 3 to level 5, its second rise ends at 1452 Hz; unidentified showcase sources retain the neutral source fallback. All frequencies follow the unchanged `soundTones` recipes.
