# Profile, recent matches and replay sharing

The profile gets a dedicated `/profile` route, a compact identity header, the ten most recent completed matches, and links to its saved replay library. Editing identity remains available without displacing match history. Existing settings remain accessible. ImageGen prototype: `docs/design/replay-profile/profile-prototype.png` (built-in image generation; desktop/mobile profile plus sharing/export dialogs). Implement only real available data, not the prototype's illustrative rank, country or all-time statistics.

Recent match metadata is bounded to ten per account and captured server-side for casual, private, bot and competitive games. It is independent from the ten manually saved replay slots: older favorites survive new matches. Existing competitive history remains available as a fallback, merged without duplicate rooms. Missing recordings explicitly show that no replay was saved. Saved files are linked by authoritative recording ID.

Saved recordings are private by default. Owners can switch a ready file to public, copy its canonical `/replays/:id` link, then revoke access by switching back to private. Both metadata and file endpoints authorize every request; S3 remains private and never issues a persistent public URL. Anonymous and other-account reads of a private ID return the same not-found response. Downloads already obtained cannot be revoked, which is explained before sharing. Completed recordings contain both hands.

MP4 export records the actual player locally using the browser's display-capture and MP4 MediaRecorder support. A user action opens the browser's capture picker, the player restarts from the beginning and automatically finalizes the video after the last animation. Export has cancellation, bounded size/time, track cleanup and an explicit unsupported-browser state (especially mobile). No WebM file is relabeled MP4, no microphone is requested, and no videos are stored on the VPS. Alternatives considered: server rendering adds a browser/encoder job queue and substantial CPU cost; client DOM-to-canvas reconstruction risks missing animation layers. Direct local tab capture preserves the tested presentation.

Validation covers ownership, publication/revocation, no-store headers, ten-item history retention and replay linkage, responsive profile states, direct public/private URLs, export cancellation/completion and a real MP4 file. Existing replay pacing regressions remain required. The PR stays closed and production deployment is not part of this change.

Browser API references: https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia and https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static .
