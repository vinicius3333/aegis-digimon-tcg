# BT22 implementation audit ledger — wave 1

Scope: exactly BT22-102, BT22-101, BT22-100, BT22-099, and BT22-098, audited in descending order on 2026-08-20. Each numbered item below corresponds to the mandatory rubric. A score is awarded only where the catalog, KB, executable IR, and behavioral/shared-primitive evidence agree.

## BT22-102 — Sayo — 10/10

1. **Catalog.** Purple/blue Tamer, play cost 4, traits `Night Claw`/`CS`, deck limit 4. Printed clauses: `[Start of Your Main Phase]` opponent-Digimon gate then gain 1 memory; `[Your Turn]` attacking owned Digimon with 2+ same-level cards in its stack, suspend this Tamer as a cost, then digivolve that attacker into a trash Digimon with `Night Claw`, `Light Fang`, `Galaxy`, or `CS`, reducing cost by 2; Security plays self free.
2. **KB.** Exact query output: Q4931 (2025-07-04), “I have EX5-064 [Koh & Sayo] in the battle area. Can I use this card's [When Digivolving] effect to play BT22-102 [Sayo]?” Answer: “Yes, you can.” (related EX5-064). Q4977 (2025-07-04), “What does ‘if this Digimon's stack has 2 or more same-level cards’ mean, exactly?” Answer: “It refers to when there are 2 or more cards with the same level among all of the stacked cards. Examples include when a level 5 Digimon has a level 5 digivolution card or when a level 6 Digimon has 2 level 5 digivolution cards.” Q4931 affects Sayo's identity/traits for EX5-064, not her own resolution; Q4977 maps to `stackHasSameLevelCards: 2` across the whole stack.
3. **Every clause.** `StartOfYourMainPhase` → conditioned `GainMemory(1)`; `YourTurn` → `whenAttacking` watcher and trash `Digivolve`; Security → `PlayWithoutCost(isSelfRef, payCost:false)`. No inherited/link text.
4. **Evolution/traits.** Tamer has no evolution requirement. Attacker is owned Digimon; destination is a Digimon matching any one of the four exact traits. Same-level test is count-based, not adjacent-card based.
5. **Costs/failures.** Suspending this exact Tamer is the cost. If already suspended, if no matching trash evolution exists, or if the evolution requirements are illegal, no digivolution occurs; `optional:true` preserves refusal. Reduction is 2, not fixed cost/free evolution.
6. **Decisions/controllers.** Owner chooses whether to activate and which legal trash card/evolution; opponent makes no choice. Trigger source is bound as the digivolution target.
7. **Zones/order/face.** Destination source is trash; the selected card becomes the attacker's top card through the public digivolution path. Security self-play uses the checked physical card.
8. **Interactions.** Q4977's level-pair examples, multi-trait OR matching, attack-source binding, paid suspension, and ordinary evolution legality were traced through `SubTrigger`, digivolution preflight, and the shared evolution action.
9. **UI.** No presentation-only behavior. Existing server decisions expose optional activation/card selection; browser validation is not applicable.
10. **Regression evidence.** Colocated assertions cover every IR boundary; shared public engine suites cover attack events, suspension costs, effect digivolution legality, security self-play, and state transitions. Focused test passed in the five-card run; score 10/10.

## BT22-101 — Kyoko Kuremi — 10/10

1. **Catalog.** Black/yellow Tamer, play cost 5, `CS`, deck limit 4. Printed clauses: memory setter; all-turns deletion reaction for owned level-4+ CS Digimon, suspend this Tamer to return one CS Digimon from own trash; your-turn once-per-turn self-unsuspend reaction that may evolve this Tamer into hand Alphamon with cost reduced by 2 only if no Alphamon is owned; Security free self-play.
2. **KB.** Exact query output: Q4976 (2025-07-04), “Can I use this card's [Your Turn] effect to digivolve this card into an [Alphamon] that doesn't meet the digivolution requirements?” Answer: “No, you can't. The digivolution requirements have to be met.” Q5774 (2025-12-25), “I have BT22-063 [Alphamon] with just BT22-101 [Kyoko Kuremi] in its digivolution cards. Can I activate this card's <Delay> effect to place that BT22-063 [Alphamon] under BT22-101 [Kyoko Kuremi] and gain 2 memory?” Answer: “Yes, you can.” (related BT22-063). Q4976 maps to ordinary `Digivolve` legality; Q5774 concerns BT22-063's Delay and confirms physical Kyoko/Alphamon stack interaction, not an extra Kyoko effect.
3. **Every clause.** `StartOfYourTurn/SetMemory(3)` with ≤2 gate; `AllTurns/onDeletionOf` exact source filter and trash return; `YourTurn/whenUnsuspended`, self-bound Alphamon digivolution, absence condition, once-per-turn; Security free self-play.
4. **Evolution/traits.** Kyoko has none printed. Returned card must be Digimon+CS. Deleted source must be owned, Digimon, CS, and level ≥4. Alphamon name matching still obeys its printed evolution requirements per Q4976.
5. **Costs/failures.** Tamer suspension is encoded on the optional return and aborts on decline/failure. No return if source filter misses or no legal trash card. Alphamon reduction is 2 and cannot bypass legality.
6. **Decisions/controllers.** Kyoko's controller pays suspension, chooses the trash card, and decides/chooses the Alphamon evolution. Opponent has no decision. Once-per-turn identity belongs to this printed Kyoko effect.
7. **Zones/order/face.** Return is own trash→hand. Alphamon is own hand→top of this Tamer stack, retaining Kyoko as a source. Security uses the checked physical card.
8. **Interactions.** Deletion reaction is all turns, not simultaneous-deletion-only; absence gate includes the controller's field; unsuspend watcher is self-only; Q5774's inverse Alphamon-under-Kyoko state remains legal for BT22-063.
9. **UI.** Standard optional/card-selection/digivolution decisions only; no presentation-specific path, so browser is not applicable.
10. **Regression evidence.** Exact colocated IR assertions plus shared memory, deletion, suspension-cost, evolution-legality, once-per-turn, and security behavior suites passed; focused five-card test passed; score 10/10.

## BT22-100 — Cyberspace EDEN — 10/10

1. **Catalog.** Black Option, cost 2, `CS`, deck limit 4. Clauses: color waiver while no face-up security; while face-up in Security all owned CS Digimon +2000 DP; Main moves bottom own security to hand, then places this exact Option face up at bottom security; Security optionally plays one hand CS card of play cost ≤5 free.
2. **KB.** Exact output: Q4971 asks whether no-face-up is met at 0 security; answer yes. Q4972 says face-up security stays revealed and otherwise follows normal security rules. Q4973 says checks leave it revealed. Q4974 says its Security effect triggers. Q4975 says security shuffle first turns face-up cards face down, then shuffles all face down. These map respectively to the zero-count condition, `faceUp:true`, normal check routing, Security effect registration, and shared security-shuffle normalization.
3. **Every clause.** Static `WaiveColorRequirement`; face-up-security `AllTurns/ModifyDP(+2000, all owned CS)`; ordered Main `toHand(bottom)` then `placeAsSecurity(self,bottom,faceUp)`; optional Security hand play with exact trait/cost limit.
4. **Evolution/traits.** Option has no evolution. CS matching is trait-only. Security play accepts any card kind with CS because printed text says “card,” correctly omitting a kind filter.
5. **Costs/failures.** Main is ordered and mandatory; with no bottom security, the first move is a no-op but “Then” still places EDEN. Security play is optional, free, and unavailable without a legal hand card.
6. **Decisions/controllers.** Owner chooses the Security-play target/refusal. All DP and security operations use the owner; opponent has no choice.
7. **Zones/order/face.** Bottom security is removed before this physical Option is placed face up at the bottom. Face-up state and bottom ordering are explicit; checked face-up cards retain visibility per Q4972–4974.
8. **Interactions.** Empty security satisfies waiver (Q4971), existing face-up security disables it, static DP only exists while EDEN is face-up security, security shuffles normalize face state (Q4975), and cost-limit boundary is inclusive at 5.
9. **UI.** Visibility is derived from server `faceUp` state; no unique UI logic requires browser validation.
10. **Regression evidence.** Colocated exact clause assertions plus shared face-up-security visibility/check/shuffle tests, option color gating, security placement, DP ledger, and free-play primitives passed; focused five-card test passed; score 10/10.

## BT22-099 — Kuremi Detective Agency — 10/10

1. **Catalog.** Black/yellow Option, cost 3, `CS`, deck limit 4. Clauses: waive color with owned CS Digimon or Tamer “on the field”; Main reveal top 3, add one CS card, bottom the rest, then place self in battle area; separate Main Delay gains 2 memory; Security places self in battle area.
2. **KB.** Exact output: Q4970 (2025-07-04), “What does ‘while you have (the specified card) on the field’ mean, exactly?” Answer: “It refers to when you have the specified card in the battle area or breeding area.” This maps to the `anyOf` battle-area and `zone:"breeding"` conditions.
3. **Every clause.** Static color waiver, ordered `RevealAdd` then `PlaceInBattleAreaSelf`, separately keyed Delay Main `GainMemory(2)`, and Security placement are present.
4. **Evolution/traits.** No evolution. Waiver requires CS plus Digimon/Tamer. Reveal may add any CS card kind, correctly omitting kind. Near-match/non-CS cards go to bottom.
5. **Costs/failures.** Reveal handles fewer than three/as-many-as-possible through the shared reveal primitive. With no CS hit, all revealed cards bottom and placement still occurs. Delay pays the universal trash-self cost and cannot activate on entry turn.
6. **Decisions/controllers.** Owner chooses one CS hit where multiple exist and may activate Delay; opponent has no decision. Reveal/rest ordering is server-controlled.
7. **Zones/order/face.** Deck top→reveal→one hand/rest deck bottom, then the same used Option becomes a battle-area permanent. Security places the checked physical card in battle area. Delay trashes that permanent.
8. **Interactions.** Q4970 breeding coverage is explicit; normal and Security placement converge on the same permanent representation; Delay is a separate Main clause and therefore does not fire during initial Option use.
9. **UI.** Existing reveal/choice and Delay activation decisions are generic; no presentation-specific validation applies.
10. **Regression evidence.** Exact colocated assertions plus shared reveal ordering, option placement, Delay entry-turn/trash-cost, color waiver, and Security placement behavior suites passed; focused five-card test passed; score 10/10.

## BT22-098 — Unique Emblem: Fable Waltz — 10/10

1. **Catalog.** Yellow Option, cost 3, `LIBERATOR`, deck limit 4. Clauses: Main may play one Shoemon or Arisa Kinosaki from own hand/trash free, then mandatory self-placement; your-turn when any owned Arisa suspends, Delay, one owned Puppet may evolve into a hand Digimon having both Puppet and LIBERATOR with cost reduced by 3; Security activates Main effects.
2. **KB.** Exact output: Q4969 (2025-07-04), “If I would use this card's <Delay> effect to digivolve my Digimon, can it digivolve into a Digimon card with the [Puppet] or [LIBERATOR] trait?” Answer: “No, it can't. It can only digivolve into a card with both the [Puppet] and [LIBERATOR] traits.” This maps to conjunctive `and` trait filters, not OR.
3. **Every clause.** Main play filter/zones/free/optional and unconditional following placement; reactive `whenSuspended` watcher; intrinsic Delay on that watcher; nested digivolution; Security `ActivateMain`.
4. **Evolution/traits.** Target is owned Puppet Digimon. Destination is own-hand Digimon satisfying Puppet AND LIBERATOR, preserving normal evolution legality. Shoemon/Arisa are exact name matches.
5. **Costs/failures.** Main play can be declined or have no candidate without preventing mandatory placement. Delay uses universal trash-self cost, is unavailable on entry turn, and its digivolution may be declined/unavailable; reduction is 3, not free/fixed-cost.
6. **Decisions/controllers.** Owner chooses play source/card, Delay activation, target Puppet, and legal destination. Trigger matches any owned Arisa; opponent has no decision.
7. **Zones/order/face.** Main candidate is hand or trash→battle area, then this physical Option→battle area. Delay trashes self before hand→stack evolution. Security activates the same ordered Main effects on the checked physical card.
8. **Interactions.** Mixed Puppet-only/LIBERATOR-only/both filters follow Q4969; reactive Delay is event-gated. Audit found and fixed the prior defect where digivolution was a free-standing continuous action and the watcher merely granted a non-consumable keyword.
9. **UI.** All choices use generic server decisions; no presentation-specific behavior, so browser is not applicable.
10. **Regression evidence.** Colocated assertions now require the digivolution nested under the Arisa suspension watcher and require intrinsic Delay plus conjunctive traits. Shared Delay trash/entry-turn, digivolution legality, option placement, optional refusal, and Security ActivateMain suites plus the focused five-card suite passed; score 10/10.
