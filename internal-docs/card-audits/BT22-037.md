# BT22 implementation audit — BT22-037

## BT22-037 — Chirinmon — 10/10

1. **Catalog.** Yellow level 5, play cost 7, 7000 DP, Vaccine/Holy Beast/CS; alternate evolution is a level-4 CS Digimon for 3. The security-trash clause is -8000 DP for one opponent Digimon for the turn, the When Digivolving clause trashes the top security card and optionally effect-digivolves into a hand Digimon named Kentaurosmon/Mitamamon or with the CS trait with its evolution cost reduced by 2, and the inherited clause is When Attacking OPT -4000 DP to one opponent Digimon for the turn.
2. **KB and Q&A.** `node tools/kb/query.mjs card BT22-037` returns no card-specific entry. The complete local Q&A search contains no BT22-037 ruling; the unrelated BT1 Chirinmon references were not treated as BT22 evidence.
3. **Clauses.** The direct module maps `OnDiscardSecurity`, `WhenDigivolving`, and inherited `OnUseAttack` to executable effects; the secondary evolution is optional and filters the hand by exact name fragments or the CS trait.
4. **Requirements and identity.** The initial evolution remains the normal level-4 CS path. The effect-selected destination intentionally ignores its printed evolution requirement because the effect supplies the name/trait restriction, while `digivolveFromInstance` retains the destination's printed cost baseline.
5. **Costs and failures.** The initial evolution pays 3; the effect trashes exactly one top security card and pays the destination cost minus 2, floored by the engine. No qualifying hand card or no security card prevents the optional branch without a partial payment.
6. **Targets and controllers.** Security belongs to Chirinmon's controller; the -8000/-4000 choices are restricted to one opponent Digimon and are resolved through the source controller's context.
7. **Zones, order, and face state.** Effect-trash moves the security card to trash before `OnDiscardSecurity` fires; effect evolution moves the selected hand card face up onto the existing stack and preserves the base stack/source identity.
8. **Timing and duration.** Security trash is effect-only `OnDiscardSecurity`, not a security check. DP changes last for the turn. The inherited attack effect uses the shared once-per-turn guard.
9. **Engine seams and peers.** `trashFromSecurity`/`fireDiscardedFromSecurity` and `digivolveFromInstance` were inspected, including cost reduction, requirement bypass, stack placement, draw, and resulting When Digivolving timing. ST22-10 and BT15-084 provide the matching security-trash seam precedent; BT22-038 provides the neighboring evolution/once-per-turn patterns.
10. **Public proof.** `BT22-037.test.ts` proves effect-driven security trash and exact -8000 DP, reduced paid effect evolution (memory 3 + 2, not free), top-security payment, stack transition, and the no-eligible-card failure path. The direct timing module assertions cover all three clauses. Focused Vitest was attempted with the required single-fork command but is blocked because dependencies cannot be downloaded in this network-restricted environment.

**Implementation change:** changed the secondary effect evolution from free to `payCost: true`, `costDelta: -2`, `ignoreRequirements: true`.
