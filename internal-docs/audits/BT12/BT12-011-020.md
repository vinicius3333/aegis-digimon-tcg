# BT12-011–020 Card Audit

## Scope and audit posture

This report covers BT12-011 through BT12-020 in strict ascending order. The
catalog contract for each card was read from the exact supplied Git blob
`efbecc002fb9000789123e2f91f201466e1e5b0a` (the blob itself contains the
catalog array). For every card, the local knowledge base was queried with
`node tools/kb/query.mjs card <CARD-ID>`, the applicable local comprehensive
rules were read, and the direct TypeScript module, colocated test source,
generated effects snapshot, shared interpreter/primitive seams, neighboring
peers, and realistic evolution/play stacks were inspected.

Before inspection, the fresh branch fetched `origin/audit-bt-card-by-card` and
integrated it with `git merge --no-edit origin/audit-bt-card-by-card`; the
result was a fast-forward to `c36ec71e4`. `BT12-STATIC-AUDIT.md` and
`packages/shared/src/effects/effects.json` were preserved unchanged. Every
card module has exactly one `registerIrCard` call and no `registerCard` call.
BT12-015 is called out separately because its registered object is an empty
compiled record whose `effectsForTiming` is then replaced by a handwritten
runtime implementation.

The dispatch explicitly forbade focused, mechanism, collection, typecheck,
lint, formatting, browser/UI checks, and `git diff --check`. Accordingly,
execution is 0/2 for every card, no test result is represented as passing, and
no card or collection is claimed complete. The BT12-016 test source was
strengthened for Q2147, but that new proof is also intentionally unexecuted.

The relevant shared rule evidence is:

- Comprehensive §4-23 defines “with [Save] in its text,” including the
  distinction between the printed Save icon and Material Save.
- Comprehensive §15-6 defines processing conditions and the “instead” branch
  boundary; §18-2 defines overwrite processing using “instead.”
- Comprehensive §16-20 makes Save processing optional; §15-16-15 defines the
  End of Attack timing; §15-3 defines inherited effects.
- Comprehensive §14-2-1-3 confirms that equal-DP battle participants both
  lose and are deleted, which is used by the BT12-016 Q2147 proof.

## Snapshot drift summary

The generated snapshot was read-only evidence and was not edited. Three cards
match the direct executable representation exactly (BT12-013, BT12-019, and
BT12-020). Seven entries have intentional or known representation drift:

- BT12-011: the snapshot has the trash-to-Tamer placement and a Save keyword,
  but omits the optional self-Save action and retains a raw inherited Save-text
  condition. The direct module adds the self action before the mandatory Then
  placement and uses a structured text predicate.
- BT12-012: the snapshot omits the suspended placement flag on Flamemon and
  records the Takuya alternate route at cost 0. The direct module sets
  `suspended: true`, while the shared `ALTERNATE_DIGIVOLUTION_OVERRIDES`
  supplies the printed effective cost 2.
- BT12-014: the snapshot retains raw “4 or more digivolution cards” and
  “has Save in its text” conditions. The direct module replaces them with
  source-stack and live-host predicates.
- BT12-015: the snapshot contains a generated Main placement/evolution chain,
  while the module registers an empty compiled object and installs its
  handwritten `effectsForTiming`; the snapshot therefore does not describe
  the actual registered runtime behavior.
- BT12-016: the snapshot retains a raw no-deletion condition and a nested
  cost-reduction Replacement. The direct module uses structured
  `ifThisEffectDidNotDelete`, `reduceCost: 1`, removes the ineffective wrapper,
  and structures the inherited no-opponent-Digimon/name condition.
- BT12-017: the snapshot makes the red-Tamer alternative a raw conditional
  second delete after the base delete. The direct module makes the two
  mutually exclusive branches explicit and checks for a red Tamer card in
  the source stack.
- BT12-018: the snapshot leaves the security fallback as a raw “no Digimon was
  deleted” condition. The direct module binds that condition to the preceding
  deletion result with `ifThisEffectDidNotDelete`.

### BT12-015 — Aldamon — 7/10 provisional

#### Contract and KB

The exact catalog contract is a red level-5 Hybrid/Variable/Wizard Digimon
costing 8 with 8000 DP and normal red level-4 evolution for 3. Its hand Main
effect places one Agunimon and one BurningGreymon from trash under one Takuya
Kanbara card in any order, then digivolves into this card as if the Tamer were
a level-4 red Digimon for the printed evolution cost. On Deletion it returns
one Takuya Kanbara card from trash to hand.

The card query returned Q6548–Q6553. They confirm Tamer-as-Digimon treatment,
the bonus draw, summoning-sickness preservation, Tamer source transition, and
that inherited effects but not Security effects are gained from Tamer source
cards. Ambiguity count is zero.

#### Implementation and proof

`apps/api/src/cards/BT12/BT12-015.ts` contains a handwritten `EffectModule`.
It preflights the Takuya host, both named trash materials, and the cost;
selects both materials, requests their “in any order” ordering, places them
under the same selected Takuya, then performs a cost-3 virtual level-4 red
digivolution. Its On Deletion effect selects a Takuya card from trash and
returns it to hand. The module does call `registerIrCard`, but it passes
`{ effects: [], coverage: "full", residual: [] }` and then assigns the
handwritten `effectsForTiming` to the returned object. The executable behavior
therefore remains outside compiled IR. This is the one unresolved
implementation limitation in the collection and is why Direct IR is 1/2;
the limitation is explicit rather than silently treated as compiled.

The generated snapshot has a declarative Main placement/evolution sequence
and the On Deletion return, but it cannot enforce the same host for both
materials, the shared ordering decision, or the atomic preflight as the
handwritten implementation does. It is read-only evidence and is not the
registered runtime record. The colocated test source covers the ordered two
material stack and exact cost/draw/source transition, missing-material,
wrong-Tamer, and unaffordable-cost non-activation, plus the On Deletion
Takuya return. BT12-012/013 provide the adjacent Frontier Tamer-evolution
peers. Tests were reviewed but not run.

No new correction was made; porting this custom atomic procedure to compiled
IR was not attempted without executable proof. Prior relevant history is
`d9a78b10d` (`test(cards): revalidate BT12-015`), `bca495c76` (`fix(cards):
correct authored IR that the type gap let through`), `4d26c9276` (`Model
BT12-015 virtual Tamer base`), and `20ea55da4` (`Verify BT12-015 Aldamon hand
effect`).

Contract 2/2; direct IR 1/2; seams/peers 2/2; proof/stacks 2/2; execution
0/2. Total 7/10 provisional; unresolved ambiguity count 0. The handwritten
runtime limitation must be ported or separately justified in a future audit.
