# BT26-001 through BT26-010 static audit

## Scope and authority

This audit covers BT26-001 through BT26-010 in the required ascending order. It is a static audit only: no tests, typecheck, lint, formatter, browser/UI check, focused/mechanism/collection gate, or `git diff --check` was run.

- Catalog authority: `packages/shared/src/cards/data/cards.json`, immutable catalog blob `efbecc002fb9000789123e2f91f201466e1e5b0a`.
- Rules authority: `data/kb/rules/manual.md` and `data/kb/rules/comprehensive.md`.
- Card-specific authority: exactly one local `node tools/kb/query.mjs card <CARD-ID>` query per card, with no repeated query.
- Read-only effect snapshot: `packages/shared/src/effects/effects.json` was inspected and contains no BT26 entry; its observed hash is `86ec3ff83ca6458c357c14cd63bde5061c63f9d6`.
- Shared generated digivolution metadata was inspected but not changed. The BT26-008, BT26-009, and BT26-010 alternate requirements in `packages/shared/src/effects/generated-digivolve-overrides.json` are consumed by the existing shared lookup path.
- Registration authority: every audited module is imported from `apps/api/src/cards/BT26/index.ts` and has exactly one `registerIrCard(cardId, compiled)` call. No audited module has a duplicate or legacy `registerCard` registration.

The five scored components are exactly two points each: Catalog/rules, IR trace, Behavioral proof, Peer and stack proof, and Executed delivery gates. Executed delivery gates are intentionally 0/2 for every card because the requested gates were prohibited. Consequently, these are provisional static scores capped at 8/10, not collection-complete scores.

## Card findings

### BT26-001 Yokomon — 6/10

- Catalog: Red level-2 Digi-Egg, Bulb, Iliad/TS. Its inherited effect is `[Your Turn] [Once Per Turn] When your effects add to decks, this Digimon may digivolve into a Digimon card with [Chronomon] in its text in hand with the cost reduced by 1.`
- IR: `BT26-001.ts` compiles an inherited `YourTurn`/`OncePerTurn` `whenEffectAddsToDeck` subtrigger. The destination is one Digimon from hand with `Chronomon` in its text, `payCost: true`, `costDelta: -1`, and optional processing. The module declares `coverage: "full"` and `residual: []`.
- Runtime trace: the subtrigger map recognizes `whenEffectAddsToDeck`; its provenance gate distinguishes an effect adding to a deck from reveal/restore and permits the source player’s effect to add to the opponent’s deck. Canonical text matching includes the catalog text union required by Q6948-Q6951. Digivolution candidate and signed cost reduction are resolved by the existing hand-digivolution interpreter.
- Behavioral proof: the source proof produces the deck-add event through the `returnToDeck` primitive and checks the reduced Chronomon evolution, decline, once-per-turn, and negative restore path. A natural producer of a deck addition is feasible, so the primitive-origin positive is 1/2.
- Peer/stack proof: the source stack uses BT26-013 directly over the Digi-Egg, omitting a legal level-3 intermediary. The trait and target identity are realistic, but the host stack is incomplete, so 1/2.

### BT26-002 Budmon — 6/10

- Catalog: Green level-2 Digi-Egg, Vegetation/DATA SQUAD. Its inherited effect is `[Your Turn] [Once Per Turn] When effects trash cards from under your Tamers, Draw 1.`
- IR: `BT26-002.ts` uses an inherited `YourTurn`/`OncePerTurn` `whenDigivolutionTrashed` subtrigger scoped to a controller-owned Tamer and `byEffect` provenance, followed by one controller draw. It is `coverage: "full"` with `residual: []`.
- Runtime trace: the runtime emits one event per trashed digivolution card with by-effect provenance; the source filter matches the Tamer host and the event is constrained to the owning player. The once-per-turn ledger and turn gate are applied by the common subtrigger interpreter.
- Behavioral proof: source assertions and positive/negative cases use `advance.verb.trashDigivolutionCards` with an explicit by-effect seat. That proves provenance, controller, turn, and frequency handling but injects the event directly; a natural Tamer effect can trash under-stack cards, so 1/2.
- Peer/stack proof: the positive host is BT1-009 directly over the green BT26-002 Digi-Egg, an off-color/incomplete synthetic stack. The watcher logic is correctly anchored, but the stack is not a legal realistic host, so 1/2.

### BT26-003 Kyaromon — 7/10

- Catalog: Black level-2 Digi-Egg, Lesser/Glowing Dawn/BEATBREAK. Its inherited effect is an opponent-turn once-per-turn redirect: trash the bottom face-down card under any Tamer and change an opponent attack target to one of the controller’s Glowing Dawn Digimon.
- IR: `BT26-003.ts` compiles an inherited opponent-turn `whenOpponentAttacks` subtrigger with a `RedirectAttack` action. The cost is `trashBottomFaceDownUnderTamer` for the controller, the target is a controller-owned Glowing Dawn Digimon, and the action is optional with `abortOnDecline` and `allowCostWithoutTarget`; coverage is full with no residual.
- Runtime trace: the attack subtrigger is emitted by combat once per opponent attack. Cost payment and target filtering are distinct; `allowCostWithoutTarget` implements Q6953, while the runtime’s target filter rejects ineligible Progress/other non-Glowing-Dawn targets as in Q6952. Bottom face-down selection and face-up trash routing follow the common cost/primitives path.
- Behavioral proof: the source test uses public `applyIntent(type: "attack")` for the opponent attack, then covers redirection, no-target cost payment, decline, unaffected attacker, once-per-turn, and face-up-vs-face-down boundaries. This is a natural public origin, so 2/2.
- Peer/stack proof: the primary fixture places a red BT26-010 directly over the black Digi-Egg, which is not a legal color/level stack. The target/cost behavior is realistic, but the host stack limitation keeps this component at 1/2.

### BT26-004 Pagumon — 8/10

The generic hand target intentionally has no `kind` filter; coverage is full and residual-free.
- Runtime trace: generic place costs default to hand, preserve the destination Tamer’s bottom ordering, and call `placeUnder` with `faceUp: false`. The Tamer filter is controller-, kind-, and trait-scoped. Face-down visibility, no reorder, opponent privacy, and face-up trash conversion match Q6954-Q6957.
- Behavioral proof: the original boundary cases cover placement ordering, draw, privacy, controller/trait scope, once-per-turn, and decline. The additive proof in `BT26-004.test.ts` uses a public attack with BT1-089 (a Tamer, not a Digimon) in hand and verifies that it is accepted and placed face down, so the generic-cost correction has a natural non-Digimon positive. This earns 2/2.
- Peer/stack proof: the additive proof uses BT26-065, a purple level-3 Digimon over the purple BT26-004 Digi-Egg, which is a realistic ordinary stack, and a BT25-088 Glowing Dawn Tamer. This supplies the requested natural non-Digimon cost path and earns 2/2 despite older boundary fixtures using synthetic stacks.
