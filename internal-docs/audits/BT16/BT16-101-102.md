## Shared runtime and evidence trace

- `selfDigivolutionStackHasTrait` uses the live source permanent's stack and
  `definitionMatches`; name and trait references are disjunctive. This makes
  BT16-101's Rapidmon/X Antibody aura and BT16-102's Magnamon (X Antibody)/
  Armor Form condition observable from realistic stacks.
- The continuous aura path applies BT16-101's -4000 DP to every suspended
  opposing Digimon while its source condition is true. The shared DP-zero
  deletion seam publishes `deletedByDpZero` only when the by-rule deletion
  sees current DP zero, while battle deletion publishes its removal cause.
- `withSubTriggerFrequency` gives both BT16-101 deletion branches and BT16-102
  security activation their declared once-per-turn scope. The security-removal
  gate defaults an omitted controller direction to `mine`; explicit
  `controller: "any"` is therefore required for BT16-102's printed direction-
  neutral trigger.
- The public attack, battle, security-check, play, and digivolve paths are the
  natural origins used by the added source tests. No manual subtrigger/timing
  injection is used as the behavioral substitute.

## Ordered card findings

### BT16-101 — Rapidmon (X Antibody) — provisional 8/10

Catalog/rules: The immutable record identifies a Yellow/Green Level-6 Mega
Digimon with play cost 11, 11,000 DP, Yellow and Green Level-5 evolution
routes at cost 3, Vaccine, and Holy Warrior/X Antibody traits. The printed
contract is Armor Purge; on digivolution, suspend all opposing Digimon and
optionally attack; while Rapidmon or X Antibody is in its stack, all opposing
suspended Digimon get -4000 DP; and once per turn, when an opponent's Digimon
is deleted in battle or by having 0 DP, gain 2 memory. The local KB returned
Q2698, which confirms that a digivolution effect cannot declare another attack
while an attack is already resolving, and Q5452, which covers the ordering
where the aura makes a small attacking Digimon reach 0 DP before its
When Attacking effect can resolve.

IR trace: `BT16-101.ts` is full/residual-free IR with Armor Purge, the
When Digivolving suspend-all plus optional attack sequence, the conditional
all-opponent suspended-Digimon aura, and two independent all-turns once-per-
turn `onDeletionOf` watchers. The first watcher is conditioned on
`triggerRemovalCause: byBattle`; the second is conditioned on
`triggerDeletedByDpZero`. The module has exactly one
`registerIrCard("BT16-101", compiled)` call.

Corrections: The original second watcher used a custom `deleteCause:
"dpReachedZero"` source filter, which the shared deletion gate interpreted
as any by-rule deletion rather than a Digimon actually reaching zero DP. It
now uses the dedicated `triggerDeletedByDpZero` condition. The natural battle
deletion payload also previously omitted `removalCause`, so the by-battle
watcher could not fire from a real attack; `combat/controller.ts` now publishes
`removalCause: "byBattle"` for that deletion event. These are scoped
production corrections, not test-only annotations.

Behavioral and peer/stack proof: The source tests now cover the immutable
catalog contract, legal Rapidmon evolution, suspension of already-suspended
and unsuspended opposing Digimon, the Rapidmon/X Antibody source condition,
direct-play negative, two natural battle deletions with the once-per-turn
memory boundary, natural aura-driven DP-zero deletion, and a negative
effect-deletion cause. BT8-039 Rapidmon supplies the legal evolution/source
stack; the deletion and frequency behavior was compared with inherited
deletion peers and the shared battle/seam path. The natural DP-zero case uses
an attack, not a manually fired event, and preserves the defender's security
stack to distinguish DP-zero deletion from the attacker's security check.

### BT16-102 — Magnamon (X Antibody) — provisional 8/10

Catalog/rules: The immutable record identifies a Yellow/Blue/Black Level-6
Mega Digimon with play cost 12, 12,000 DP, Yellow/Blue/Black Level-5
evolution routes at cost 4, Vaccine and Free attributes, and Holy Warrior/X
Antibody/Royal Knight traits. The printed contract is a two-color Digimon
with Magnamon in its name for cost 5, Blocker, Armor Purge, a When Digivolving
conditional +3000 DP and opponent-effect immunity through the opponent's turn,
then unsuspend, and an all-turns once-per-turn optional activation of one
When Digivolving effect when a card is removed from a security stack. The
printed Rule line also grants the Free attribute. Local KB Q2699 confirms
that opponent-effect immunity can make this Digimon a valid Raid target,
Q2700 confirms that removal from the controller's own security can activate
the trigger, and Q2701 confirms that the post-condition `then unsuspend`
still resolves when the condition is absent.

IR trace: `BT16-102.ts` is full/residual-free IR with Blocker and Armor Purge,
the conditional ModifyDP and GrantImmunity actions followed by unconditional
Unsuspend, and an all-turns once-per-turn security SubTrigger that optionally
activates the When Digivolving effect. Its rule-granted Free trait is a
continuous GrantStatic action. The two-color Magnamon alternate evolution is
represented by `colorCount: 2`, `names: ["Magnamon"]`, cost 5, and
`isAlternate: true`. The module has exactly one
`registerIrCard("BT16-102", compiled)` call.

Correction: The printed security trigger says “a card” from “a security
stack” without limiting the controller. The shared security gate defaults an
omitted source filter to the watcher's own stack, so the direct IR now carries
`sourceFilter: { controller: "any" }`. This matches the direction-neutral
security peers ST15-12 and BT16-013 and is required for the opponent-stack
natural path; no shared runtime or protected generated snapshot was changed.

Behavioral and peer/stack proof: The source tests now cover the immutable
catalog and alternate requirement, natural evolution from Armor Form
Magnamon BT21-036 with the +3000 DP/unsuspend result, natural evolution from
multicolor Magnamon BT13-040 without the conditional stack source, natural
opponent-stack security removal, natural own-stack security removal, the
once-per-turn boundary across two natural security removals, and declining
the optional activation. BT21-036 is the Armor Form positive stack; BT13-040
is the Magnamon-name/multicolor negative for the conditional boost. ST15-12
and BT16-013 are the closest direction-neutral security SubTrigger peers.
The two security-origin cases use public attacks and security checks rather
than calling the event bus directly.

Commit: `c9aefb196` (`Audit BT16-102 Magnamon X Antibody`).
