# BT16 static card-by-card audit: BT16-001 through BT16-010

## Audit frame

This report audits exactly BT16-001 through BT16-010 in strict ascending
card-ID order. The immutable catalog source is Git blob
`efbecc002fb9000789123e2f91f201466e1e5b0a`. The protected
`BT16-STATIC-AUDIT.md` and `packages/shared/src/effects/effects.json` were
read but not changed. Each card was independently checked against the local
KB, its catalog record, direct TypeScript module, compiled IR and shared
runtime primitives, useful neighboring cards, legal evolution/stack behavior,
and natural source-level behavioral proofs.

The current truthful queue snapshot is: BT16-001-010 was completed by this
worker and is pending integration; BT16-011-050 is
Luna-active; and BT16-051-102 is unassigned. This report covers only BT16-001
through BT16-010; it does not claim collection completion, and the Orca
worktree was not marked completed.

## Scoring and execution boundary

Each card receives five exact two-point components: Catalog/rules, Direct IR,
Shared mechanism, Behavioral proof, and Executed gates. The Executed gates
component is fixed at 0/2 because the requested campaign prohibited tests,
typecheck, lint, formatters, browser checks, focused/mechanism/collection
gates, and `git diff --check`. No prohibited command was run. Therefore every
card has a provisional maximum of 8/10; source-level assertions below are
Evidence to be executed by a later gate.

Structural assertions are not treated as behavioral proof by themselves. The
new positive and boundary tests use public play, evolution, attack, deletion,
Security, and turn intents wherever a natural origin was feasible. The only
timing helper retained is `runTurn(1)` for the natural end-of-opponent-turn
boundary on BT16-010; no manual event or subtrigger injection remains in the
audited tests.

## Shared IR and runtime trace

- All ten direct modules are compiled IR with `coverage: "full"` and
  `residual: []`. Each registers exactly once through
  `registerIrCard(cardId, compiled)`; none has a duplicate `registerCard`.
- The registration/module and effect-wrapper layers apply inherited-stack,
  source ownership, turn-scope, and `OncePerTurn` behavior. The
  `SubTrigger` event map routes the natural battle-deletion, generic deletion,
  play, evolution, and attack events used by these cards.
- `selfColorCount` and `permanentMatchesFilter` use the live effective
  permanent identity: current colors, controller, kind, DP, trait, keyword,
  zone, and stack state. This is important when an inherited Digi-Egg is
  retained under a different-color evolution or when a target's DP changes.
- The continuous keyword ledger supplies conditional Blocker, Jamming, Raid,
  Armor Purge, and Retaliation behavior to the public attack/battle path.
  Battle resolution publishes the surviving/deleted permanent context;
  deletion snapshots preserve source stacks and permit inherited On Deletion
  effects to resolve. Equal-DP simultaneous deletion is resolved together.
- The cost primitives make BT16-006's hand-trash cost transactional and
  BT16-010's `allowCostWithoutTarget` behavior explicit: Helloogarmon may
  delete itself even when the opponent has no legal Digimon target. Turn
  boundaries clear temporary DP changes and reset frequency tracking.

## Card-by-card evidence

### BT16-001 — Poromon

Catalog/rules: The immutable record is a red Level-2 Digi-Egg. Its inherited
effect is `[When Attacking] [Once Per Turn]` delete one opponent Digimon at
2000 DP or less when the host has two or more colors. The independent local KB
query returned no entries.

IR/mechanism: `BT16-001.ts` compiles an inherited `WhenAttacking` `Delete` with
the opponent-Digimon/DP boundary filter, `selfColorCount: 2`, and
`OncePerTurn`. The shared attack and live-DP target resolver execute this
effect from the inherited stack.

Behavior/peer/stack proof: The source tests retain the exact 2000-versus-3000
boundary and one-color negative. A new natural attack deletes the first
2000-DP target, a production BT1-036 play unsuspends the host, and a second
attack leaves the second 2000-DP target alive, proving the frequency limit
through a real public origin. The host is a legal multicolor BT16-007 stack;
the one-color comparison exercises the same live color gate used by
BT16-002/003/004.

Correction: No production module correction was needed; the behavioral proof
was strengthened in commit `be4922698`.
