## Authority, method, and score

The printed source for this pass was the immutable catalog blob
`efbecc002fb9000789123e2f91f201466e1e5b0a`, read directly with
`git cat-file blob`. Each card was processed in ascending order. For every
card, I queried the local card knowledge base with
`node tools/kb/query.mjs card <cardId>`, inspected the direct TypeScript module
and its compiled IR, inspected the generated effects snapshot as read-only
Evidence, traced relevant shared interpreter/mechanism seams, and read the
colocated test source plus relevant peers and realistic stacks.

The direct card module is the executable authority through the exclusive
`registerIrCard(cardId, compiled)` path. The aggregate
`packages/shared/src/effects/effects.json` snapshot was inspected but not
edited; it contains historical drift for some cards. `BT13-STATIC-AUDIT.md`
was also treated as read-only and not edited.

The five two-point components are catalog/rules, IR trace, behavioral proof,
peer/stack proof, and executed delivery gates. The executed component is fixed
at `0/2` by the task constraint: no focused tests, typecheck, lint, formatting,
browser/UI checks, mechanism or collection gates, or `git diff --check` were
run. Behavioral `2/2` is reserved for cards with actual behavioral source
cases covering the relevant effect clauses; a structural assertion alone is
not treated as runtime proof.

## Rules and shared primitive trace

The relevant local rules and shared seams were traced as follows:

- Comprehensive Rules §3-1-2 and §3-7 (`data/kb/rules/comprehensive.md:430-610`)
  establish private hand/security information, face-down security placement,
  and security order. This supports BT13-044's top-security payment and
  BT13-046's face-down hand-card placement.
- §4-27 (`data/kb/rules/comprehensive.md:982-1001`) and §15-5 through §15-8
  (`data/kb/rules/comprehensive.md:1952-2208`) define trigger timing,
  simultaneous events, processing-time references, and once-per-turn
  activation. These support BT13-044's security-removal watcher, BT13-045's
  On Play/When Digivolving clauses, and BT13-049/050 inherited reductions.
- §15-12 (`data/kb/rules/comprehensive.md:2451-2470`) covers effects that add
  information and overwrite DP/level/play-cost information; the direct IR's
  conditional Aura and replacement structures preserve the host's identity.
- §16-11 (`data/kb/rules/comprehensive.md:2897-2910`) defines Reboot as a
  mandatory persistent unsuspend during the opponent's unsuspend phase. This
  supports BT13-042's inherited keyword-only representation.
- §16-25 (`data/kb/rules/comprehensive.md:3098-3110`) defines Barrier as an
  immediate-type deletion-prevention keyword whose optional processing
  condition is trashing the top security card. This supports the actual
  Barrier source cases for BT13-041 and BT13-043.
- `apps/api/src/engine/effects/interpreter/registration/module.ts:323-341`
  normalizes compiled IR, updates the shared compiled record, and installs the
  runtime module. Every direct module in this range uses only
  `registerIrCard(cardId, compiled)`; none contains a second card-local
  `registerCard` registration.
- `apps/api/src/engine/effects/interpreter/matching/definition.ts:273-339`
  distinguishes substring `match: "name"` from literal `match:
  "nameExact"`. BT13-041's bracketed `[Kudamon]` and BT13-049's bracketed
  `[Yoshino Fujieda]` use exact matching; BT13-042/045/048 retain substring
  semantics for “in name” or traits.
- `apps/api/src/engine/effects/interpreter/conditions.ts:351-355` implements
  `totalSecurityCount` by summing both players' security arrays, matching
  BT13-046 and Q2291.
- `apps/api/src/engine/effects/interpreter/actions/reveal.ts:79-93` executes
  `HandRevealAdd`: it selects/reveals a hand card and adds it face down to
  security only when the `securityFilter` matches; otherwise the card remains
  in hand, which is the BT13-046 non-yellow branch.
- `apps/api/src/engine/effects/interpreter/effect.ts:394-403` and
  `apps/api/src/engine/effects/interpreter/registration/module.ts:242-243`
  carry `OncePerTurn` into action/watcher scopes. This is used by BT13-044,
  BT13-049, and BT13-050.
- The direct Digivolve runner in
  `apps/api/src/engine/effects/interpreter/actions/digivolve.ts:439-457`
  accepts the folded positive `reduceCost` field and converts it into a signed
  digivolution-cost delta. This supports BT13-050's effect-local reduction.
- `apps/api/src/engine/effects/interpreter/actions/board.ts:153-223` resolves
  one-shot DP changes against live permanent filters and applies their
  durations; `runAction.ts` abort-on-decline handling gates a dependent “then”
  action after a declined cost.

The generated snapshot was inspected as read-only. It agrees with the direct
IR for BT13-042, BT13-043, BT13-047, BT13-048, and BT13-049's overall shape,
but it is stale or less precise in several places: BT13-041's snapshot retains
substring Kudamon matching; BT13-044's snapshot
cost filter omits the security/top boundary; BT13-046 decomposes the hand
reveal into old Reveal/SecurityManipulation/Return actions and omits the direct
DP action after the cost gate; BT13-049's snapshot retains substring Yoshino
matching; and BT13-050 retains the older two-action digivolve-plus-replacement
shape. These protected snapshot differences were not copied back or edited.
