## Shared mechanism and rules trace

The following seams were traced and then applied to the per-card findings:

- `apps/api/src/engine/effects/interpreter/matching/definition.ts:273-335` and `packages/shared/src/effects/ir/filters/cardPredicates.ts:96-105` distinguish `match: "name"` substring matching from `match: "nameExact"` normalized literal equality. Comprehensive Rules §2-3-1-2 requires bracket-only references such as `[Thomas H. Norstein]` and `[Veemon]` to be exact; §2-3-1-3 supports substring matching only when wording says “with [X] in its name,” as in BT13-035 and BT13-039.
- `apps/api/src/engine/effects/interpreter/actions/subTrigger.ts:64-80, 220-285, 628-650` maps opponent attacks, security removal, and effect-driven opponent-hand additions. Security-removal watchers default to the source owner's security stack when no opposing direction is specified; the hand-add event is restricted to effect-driven additions to the opponent's hand.
- `apps/api/src/engine/effects/interpreter/actions/play.ts:100-190, 250-330` handles filtered/free plays and the dedicated `fromOwnDigivolutionStack` source. `targeting/loose.ts:220-350` applies OR-branch zones and `hostFilter`, which is essential for BT13-040's own-stack Veemon branch. `actions/replacement.ts`/`runAction.ts` process would-leave replacement sequencing.

- Comprehensive Rules §15-7 covers optional processing/costs; §15-8-3-9-3 covers trigger-type conditions; §15-15-3 covers reveal/add/bottom ordering; §15-16-3/§15-16-4/§15-16-5 cover When Digivolving, On Deletion, and When Attacking; §16-11 covers Reboot; §16-22 covers Evade; and the official manual's Blocker and hand/stack procedures were consulted.
