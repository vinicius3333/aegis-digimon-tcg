# BT13-101–BT13-110 static implementation audit

## Scope, method, and authority

This follow-up audits BT13-101 through BT13-110 in exact ascending order. The
printed authority is immutable catalog blob
`efbecc002fb9000789123e2f91f201466e1e5b0a` (a Git blob), with
`packages/shared/src/cards/data/cards.json` used for definitions and
`data/kb/qa.json` queried for every card. The required synchronization was
performed first with `git fetch origin audit-bt-card-by-card` followed by the
regular merge of `origin/audit-bt-card-by-card`; no rebase, squash, amend,
force push, or history rewrite was used.

Each direct module and colocated source test was read card by card, followed by
the shared interpreter seams, matching/targeting, costs, timing, conditions,
zones, and relevant peers/stacks. `packages/shared/src/effects/effects.json`
was inspected only as read-only generated-snapshot drift evidence. No audit
edit was made to that file or to `BT13-STATIC-AUDIT.md`; the latter is a
protected collection ledger and was not used as executable authority. Every
audited card module registers only through `registerIrCard(cardId, compiled)`;
there is no duplicate `registerCard` path.

Scores have five two-point components: catalog/rules, IR trace, behavioral
proof, peer/stack proof, and executed gates. Tests, typecheck, lint, formatting,
browser/UI, collection/mechanism gates, and `git diff --check` were expressly
not run, so executed gates are 0/2 for every card and 8/10 is the maximum.
Behavioral scores below are source-level evidence from behavior-driving cases;
they are not claims that those cases were executed in this audit.

## Shared interpreter seams

- `colorsAll` plus `multicolor` is the all-required-colors boundary used by
  BT13-101; `colors` alone is not sufficient for a black/yellow requirement.
- `whenPlayed` with `byEffect: true` distinguishes BT13-102's effect-play
  watcher from an ordinary main-phase play. The opponent-directed optional
  hand-trash seam records a zero-card decline as `lastOpponentDeclined`, which
  drives the gain-memory/Draw continuation.
- `ifThisEffectActed` is evaluated after an action returns. BT13-101's optional
  suspend processing cost uses `abortOnDecline`, so declining it skips both Draw
  and the conditional memory tail.
- `SelectBind` stores BT13-107's own DP ceiling and the Return filter compares
  opposing suspended Digimon against that bound via `relativeTo`.
- Loose digivolution-card candidates honor `topCardOnly` in both `canPayCost`
  and payment. BT13-107's `hostFilter` is evaluated against each candidate's
  host permanent, while the selected stack card may have any name.
- `GrantAuraToOpponents` routes BT13-108's two quoted effects through the
  shared granted-effect library, preserving the host anchor, opponent-turn
  timing, dynamic play-cost comparison, and Option-only immunity.
- A Delay activation owns its optional activation choice. BT13-110's nested
  Royal Knight play is therefore mandatory after activation, matching the
  printed “Play 1” rather than asking a second optional question.

## Card-by-card findings

### BT13-101 — Miki Kurosaki & Megumi Shirakawa

**Catalog and KB.** The immutable entry prints On Play: play one Digimon with
`[PawnChessmon] in its name` from hand without paying; All Turns: when one of
your two-color black/yellow Digimon is played, by suspending this Tamer, Draw 1
and gain 1 memory; Security plays this Tamer without paying. Q2348 at
`data/kb/qa.json:5876` confirms either order of the two colors. Q2349 at `:5883`
confirms the trigger still fires when a played Digimon is immediately deleted
by an already-activated DP-zero effect.

**Implementation and snapshot.** `apps/api/src/cards/BT13/BT13-101.ts` uses a
substring PawnChessmon filter, an All Turns `whenPlayed` watcher with
`multicolor: true` and `colorsAll: ["Yellow", "Black"]`, a self-suspend Draw
cost, conditional GainMemory, and Security self-play. The suspend processing
cost is now explicitly `optional: true` and the Draw action retains
`abortOnDecline: true`, so declining the “by suspending” condition aborts the
Draw and memory tail. The snapshot at `effects.json:23642-23707` retains the
old any-color `colors` shape and optional payload representation and is drift
evidence only.

**Behavior and peers.** `BT13-101.test.ts` contains the PawnChessmon On Play
case, a live black/yellow PawnChessmon positive, and a red/yellow Shoutmon X4
negative. The new natural decline case ordinarily plays BT13-035 while the
Tamer is ready with a deck card available and `autoDeclineOptional`; it asserts
that the Tamer stays ready and no card is drawn. This is source proof of the
optional processing and abort boundary, alongside the two-color boundary and
shared Tamer trigger seam.

**Score: 8/10.** Catalog/rules 2/2; IR trace 2/2; behavioral proof 2/2;
peer/stack proof 2/2; executed gates 0/2.

### BT13-102 — Keenan Crier

**Catalog and KB.** The immutable entry prints an On Play choice for the
opponent to trash one Tamer or Option from hand; if they do not, the activating
player gains 1 memory and Draws 1. During the opponent's turn, when an effect
plays a Digimon, by suspending this Tamer, gain 1 memory. Security plays it
without paying. Q2350 at `data/kb/qa.json:5892` assigns the reward to the
activating player. Q2351 at `:5899` says either player's effect-played Digimon
qualifies, while Q2352 at `:5906` excludes a normal DigiXros play but includes a
DigiXros performed inside an effect-played Digimon event.

**Implementation and snapshot.** `BT13-102.ts` uses an opponent chooser,
optional/up-to hand target restricted to Tamer or Option, structured
`opponentDeclinedTrash` continuations, and an Opponent's Turn `whenPlayed`
watcher with `byEffect: true` plus the suspend cost. The snapshot at
`effects.json:23708-23762` drifts with `upTo: false`, raw conditions, and no
executable `byEffect` predicate; the direct module is authoritative.

**Behavior and peers.** The shared optional hand-removal seam records a
zero-card opponent decline, allowing the reward branch to resolve. The
colocated tests prove trashing a real opposing Tamer, declining with no hand
candidate and receiving memory/Draw, and effect-playing BT13-035 through
BT13-101 on the opponent's turn to suspend Keenan. The added ordinary-play
negative directly plays BT13-035 from the opponent's hand during that turn and
asserts Keenan remains ready, preventing a broad “any Digimon play” claim.

**Score: 8/10.** Catalog/rules 2/2; IR trace 2/2; behavioral proof 2/2;
peer/stack proof 2/2; executed gates 0/2.

### BT13-107 — Vulcan Crusher

**Catalog and KB.** The catalog prints: choose one own Digimon; return one
suspended opposing Digimon whose DP is less than or equal to that chosen
Digimon's DP; then, by returning the top card of one own standalone
`[Leopardmon: Leopard Mode]` stack to hand, unsuspend all own Digimon. Security
suspends one opposing Digimon and then adds this card to hand. Q2359 at
`data/kb/qa.json:5947` says a Leopardmon: Leopard Mode without digivolution
cards cannot pay the processing condition and therefore does not unlock the
unsuspend. Q2360 at `:5954` says a host with only a level-2 Digi-Egg is payable;
after the top card is returned, that level-2 card has no DP and is trashed by
rules.

**Implementation and snapshot.** `BT13-107.ts` now uses mandatory `SelectBind`
to bind the chosen own DP as `chosenDigimon`; the opposing Return uses
`relativeTo: { attr: "dp", op: "lte", selectionRef: "chosenDigimon" }`. The
processing action's cost is optional and `abortOnDecline: true`, matching the
“by returning” processing choice. Its loose target is restricted by
`hostFilter` to an own Digimon whose top card has exact name
`Leopardmon: Leopard Mode`; the stack-card target itself has no Leopardmon name
predicate, retains `topCardOnly: true`, and thus returns that host's top card
regardless of the stack card's own name. The shared cost seam enforces
`topCardOnly` in both payability and payment. The snapshot at
`effects.json:23929-23980` retains the unsupported `dpOfChosen`, generic name
and no top-card enforcement, so it is stale drift evidence only.

**Behavior and peers.** `BT13-107.test.ts` retains Security proof and now has
four natural Main source cases in addition to structural evidence: (1) an own
Leopardmon: Leopard Mode with no stack card leaves both own Digimon suspended
after the legal opposing return (Q2359); (2) a host with only BT13-001 Pinamon
under it pays the top-card cost, unlocks the other own Digimon, and leaves the
level-2 card to the rule-check trash path (Q2360); (3) a host with BT13-056
Leopardmon under top BT13-058 returns the arbitrary BT13-056 top stack card,
proving host-vs-card matching; and (4) declining the optional cost leaves the
host and another own Digimon suspended and returns no stack card. The tests use
real cards and the loose stack-return seam rather than injecting a synthetic
event.

**Score: 8/10.** Catalog/rules 2/2; IR trace 2/2; behavioral proof 2/2;
peer/stack proof 2/2; executed gates 0/2.

## Correction ledger

Eight focused correction groups are delivered across the prior audit and this
follow-up:

1. BT13-101 now requires both Yellow and Black via `colorsAll` rather than an
   any-color predicate.
2. BT13-101's “by suspending this Tamer” Draw processing cost is optional and
   aborts the Draw/memory continuation on decline; a natural decline source
   case proves the boundary.
3. BT13-102's shared optional opponent hand-trash seam records zero-card
   decline for the printed reward, and its source proof now includes a natural
   ordinary-play negative.
4. BT13-104's standalone `[Marcus Damon]` hand target uses exact-name matching
   with a real near-name negative.
5. BT13-107 binds the chosen own DP, uses supported relative DP matching, and
   changes the processing target to an exact Leopardmon: Leopard Mode
   `hostFilter`; generic `topCardOnly` payability/payment remains enforced.
6. BT13-107 makes the by-returning processing cost optional with abort semantics
   and adds natural no-stack, level-2, arbitrary-top-card, and decline cases.
7. BT13-109's standalone `[Belphemon: Sleep Mode]` evolution target uses
   exact-name matching.
8. BT13-110's standalone King Drasil target uses exact-name matching, and its
   Delay payload no longer carries a second nested optional choice.

No duplicate registration path was introduced. The protected snapshot and
collection ledger remain outside the audit's deliberate edits.
