## Rules and shared primitive trace

The applicable local rules are:

- Comprehensive Rules §3-4-7-3 through §3-4-7-8 (`data/kb/rules/comprehensive.md:542-575`)
  exclude breeding-area cards from being affected, selected, triggered, or
  referenced unless an effect explicitly names or references the breeding area.
  This is decisive for Jesmon's “other Digimon in play” scaling and for
  Gankoomon's explicit breeding-area stack source.
- §8-3 (`data/kb/rules/comprehensive.md:1531-1574`) defines Burst Digivolve as
  returning the specified battle-area Tamer before paying the cost, then
  placing the Burst card; §8-3-2-1 makes the prior top card end-of-turn
  pending processing.
- §15-3 through §15-9 (`data/kb/rules/comprehensive.md:1925-2340`) cover
  inherited source identity, activation/trigger state, simultaneous effects,
  optional processing, and durations. These support BaoHuckmon/SaviorHuckmon
  ordering, once-per-turn scopes, and the inherited RizeGreymon clauses.
- §18-1 (`data/kb/rules/comprehensive.md:3419-3430`) defines the predetermined
  timing for pending processing. This is the reason BT13-020's end-of-turn
  behavior belongs in the structured Burst requirement, not in a duplicated
  ordinary Static effect.

The shared implementation seams were traced as follows:

- `apps/api/src/engine/effects/interpreter/registration/module.ts:323-341`
  normalizes a compiled card, updates the shared compiled record, and installs
  the runtime effect module. Each audited direct card module calls only
  `registerIrCard(cardId, compiled)`; no audited module contains a separate
  `registerCard` path.
- `apps/api/src/engine/effects/interpreter/matching/definition.ts:273-333`
  implements substring `match: "name"` and literal `match: "nameExact"`.
  Consequently, the `[Agumon] in name` and `[RizeGreymon] in name` clauses
  remain `names`, while bracketed `[GeoGreymon]`, `[ShineGreymon]`, and
  `[Marcus Damon]` boundaries use exact matching where required.
- `apps/api/src/engine/effects/interpreter/targeting/permanents.ts:373-401`
  reuses `lastResolvedPermanentIds` for `sameTarget`. BT13-018 uses this for
  the restriction and Blocker actions after selecting the one exact Marcus,
  so the three properties cannot be split across different matching Tamers.
- `apps/api/src/engine/effects/interpreter/scaling.ts:1-105,157-210` defaults
  board counts to include breeding, while `zone: "battleArea"` explicitly
  excludes it. BT13-017's three scale filters now carry that zone.
- `apps/api/src/engine/effects/interpreter/actions/security.ts:310-350`
  supports BT13-015's deletion observer by admitting the currently deleting
  Marcus top card as a virtual trash candidate before the generic deletion
  mover runs, then placing that exact instance face down on security.
- `apps/api/src/engine/actions/digivolve.ts:525-527,719-767` and
  `apps/api/src/engine/GameEngine.ts:1757-1790` read the structured Burst field,
  return an exact-name battle-area Tamer before payment, mark the permanent for
  pending processing, and at end of turn trash the immediate prior top only if
  it is still a Digimon card.

`packages/shared/src/effects/effects.json` and `BT13-STATIC-AUDIT.md` were
read-only. The aggregate snapshot contains historical drift: BT13-012 still
uses Search instead of private security play; BT13-015 and BT13-018 retain
substring Marcus references; BT13-017 omits the battle-area scale boundary;
BT13-019 retains the inert unsupported cannot-play Restrict record; and
BT13-020 carries the obsolete ordinary alternate `{ names: ["ShineGreymon",
"Marcus Damon"], cost: 0, isAlternate: true }` encoding. The direct modules
are therefore the runtime authority through `registerIrCard`.
