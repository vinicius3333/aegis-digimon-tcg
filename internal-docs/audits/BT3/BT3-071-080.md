# BT3-071 through BT3-080 Card Implementation Audit

Audit date: 2026-08-27

This range was audited in strict ascending card-ID order against the committed
catalog, card-specific local KB output, comprehensive rules, direct TypeScript
modules, the committed compiled-effects snapshot, shared interpreter
primitives, colocated behavioral tests, same-mechanism peers, trait boundaries,
and legal evolution/source stacks. Every executable card module in the range
uses exactly one `registerIrCard(cardId, compiled)` registration; no duplicate
`registerCard` registration was added or retained.

The requested static-only scope was followed. No focused tests, mechanism tests,
aggregate tests, typecheck, lint, formatting, browser/UI validation, or
`git diff --check` were run. The executed-gates component is therefore 0/2 for
every card, every score below is provisional, and no card is claimed as 10/10 or
as collection-complete.

## Shared interpreter and primitive evidence

- `docs/ARCHITECTURE.md:48-51` states that direct card modules are
  authoritative when they differ from the committed `effects.json` snapshot.
  `apps/api/src/engine/effects/interpreter/compiledCards.ts:7-20` reads the
  registered direct compiled record before falling back to the shared snapshot,
  and `apps/api/src/engine/effects/interpreter/registration/module.ts:323-341`
  normalizes/registers the direct module.
- `apps/api/src/engine/effects/interpreter/effect.ts:576-602` materializes
  keyword-only static effects and recognizes Reboot markers. A legacy generated
  Reboot record may contain an adjacent self-Unsuspend action, but the runtime
  intentionally skips that action and lets `GameEngine.ts:1335-1418` perform
  the mandatory opponent-unsuspend phase. This explains the BT3-071 and
  BT3-073 snapshot/direct shape difference without adding executable behavior
  to the card modules.
- `apps/api/src/engine/effects/interpreter/actions/reveal.ts:170-280` handles
  RevealAdd matching, optional play, and returning the remaining revealed
  cards. `apps/api/src/engine/effects/interpreter/scaling.ts:1-120` and
  `:210-260` count the scaling board and reveal candidates. The loose-card
  matcher at `actions/targeting/loose.ts:225-280` and the reveal `orFilters`
  path at `actions/reveal.ts:200-220` preserve BT3-073's Black/Red union.
- `apps/api/src/engine/effects/interpreter/actions/restrictions.ts:56-120`
  resolves Restrict and RestrictMemoryGain actions. The continuous ledger at
  `apps/api/src/engine/effects/continuous.ts:520-605` stores target and
  opponent-effect-only restrictions, while
  `continuous.ts:754-780` gates memory gain by source kind and honors the
  Tamer exception. Combat legality reads `cantBeBlocked` and Blocker in
  `apps/api/src/engine/combat/controller.ts:180-210` and
  `apps/api/src/engine/combat/legality.ts:315-365`.
- `apps/api/src/engine/effects/interpreter/matching/permanent.ts:145-195`
  evaluates `keywords` on the live permanent and `stackKeywords` against
  inherited text in its digivolution cards. This is the seam used by BT3-075
  to protect both Craniamon's own Blocker and a host carrying BT3-072.
- `apps/api/src/engine/combat/controller.ts:1198-1246` implements Retaliation's
  post-battle deletion, while
  `apps/api/src/engine/effects/interpreter/actions/subTrigger.ts:44-84` and
  `:1219-1248` map event source/host identity for inherited triggers. The
  BT3-080 test exercises this production battle path after correcting its host
  to a legal higher-level stack.

## Per-card findings

### BT3-071 MetalMamemon — provisional 8/10

- Catalog: Black Lv.5 Ultimate, 7000 DP, play cost 8, Black Lv.4 evolution
  cost 3, `Data`/`Cyborg`. It has mandatory Reboot and a When Digivolving
  effect returning exactly one level-7 Digimon with the `Virus` attribute from
  trash to hand.
- KB: no card-specific entry. Comprehensive rules §16-11 and §15-3 govern
  Reboot and inherited/source behavior.
- Implementation: `BT3-071.ts:8-47` publishes a Static Reboot keyword and a
  When Digivolving Return action limited to mine's trash, Digimon, level 7,
  and the `Virus` trait, with count 1 and destination hand. It is full
  coverage with no residual.
- Snapshot comparison: `effects.json:103246-103274` carries the same return
  filter and an extra legacy self-Unsuspend action beside Reboot. The direct
  keyword-only module is authoritative; the shared runtime's Reboot marker
  handling prevents that legacy action from firing immediately after an
  attack.
- Proof: `BT3-071.test.ts:7-11` verifies Reboot. The added `:13-42` legal
  BT3-066 Lv.4 Black to BT3-071 Lv.5 evolution returns a level-7 Virus BT2-083
  while leaving a level-6 Vaccine BT3-075 in trash, proving both level and
  attribute boundaries. BT3-068 and BT3-070 were compared as nearby Black
  Ultimate/Reboot/Blocker implementations, and the engine Reboot conformance
  suite was inspected.
- Status: Reboot timing, return destination, mine ownership, level 7 bound,
  Virus trait filter, count, and legal evolution path are mapped. The
  snapshot's legacy action is a resolved representation discrepancy, not an
  unresolved card-rules ambiguity.
