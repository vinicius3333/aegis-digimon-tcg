## Shared interpreter and peer evidence

- `registerIrCard` makes the direct module authoritative over the old generated aggregate (`apps/api/src/engine/effects/interpreter/registration/module.ts:312-341`). Each assigned module was inspected and has exactly one `registerIrCard(cardId, compiled)` call; no assigned module has a duplicate `registerCard` path.
- `runEffect` resolves actions in order and stops when `runAction` returns an abort signal (`apps/api/src/engine/effects/interpreter/effect.ts:597-618`); `runAction` documents that true means an optional action declined with `abortOnDecline` (`apps/api/src/engine/effects/interpreter/actions/runAction.ts:35-53`). Its empty-security preflight now returns `action.abortOnDecline === true` for an optional `SecurityManipulation` `toHand` action (`:276-309`). This is required by BT4-048 Q1210: before the correction, the preflight returned false, skipped the cost, and allowed the following unsuspend and DP reduction actions to resolve.
- Security `toHand`, `trashTop`, and recovery operations dispatch through `runSecurityManipulation` (`apps/api/src/engine/effects/interpreter/actions/security.ts:49-110,209-235,539-551`). Effect-driven security trash uses `trashFromSecurity`, not a security check; it moves from the top, emits movement/removal events, and does not invoke attack security-check processing (`apps/api/src/engine/effects/primitives.ts:2606-2662`). This supports BT4-047 Q1206-Q1208.
- A generic field `Trash` action resolves permanent targets and trashes a source from each target (`apps/api/src/engine/effects/interpreter/actions/removal.ts:531-571`). Digi-Burst's source cost is instead paid through the dedicated cost path, which selects the source stack named by the self reference (`apps/api/src/engine/effects/interpreter/actions/runAction.ts:451-511`). This distinction proves the stale extra `Trash` actions in the generated BT4-046 and BT4-049 records were behavior gaps.
- Zone-count conditions read the live security stack (`apps/api/src/engine/effects/interpreter/conditions.ts:283-304`), while trigger-derived turn guards enforce Your Turn/Opponent's Turn/End of Opponent's Turn ownership (`apps/api/src/engine/effects/interpreter/effect.ts:460-483`). The Once Per Turn frequency is carried through effect registration and scope handling (`apps/api/src/engine/effects/interpreter/effect.ts:380-403`).
- Same-mechanism peers inspected include BT5-046's cost-bearing compiled action (`apps/api/src/cards/BT5/BT5-046.ts:8-48`), BT5-050's Digi-Burst source watcher (`apps/api/src/cards/BT5/BT5-050.ts:8-24`), BT7-035 and BT7-071's compiled alternate-digivolution metadata (`apps/api/src/cards/BT7/BT7-035.ts:10-38`, `BT7-071.ts:10-38`), P-086's structured attack restriction (`apps/api/src/cards/P/P-086.ts:6-32`), and BT3-030's live source-stack condition (`apps/api/src/cards/BT3/BT3-030.ts:8-50`). These peers confirm the direct target, source, turn, keyword, and registration shapes used in the range.
