## Shared interpreter and peer evidence

- Inherited source identity is preserved by the `onDigiBurstCardDiscarded` self-source gate (`apps/api/src/engine/effects/interpreter/actions/subTrigger.ts:715-726`), while the Digi-Burst primitive trashes the selected source batch and emits the event before later effect processing (`apps/api/src/engine/effects/primitives.ts:2189-2259`).
- `RevealAdd` reveals exactly `revealCount`, matches each add slot against the revealed definitions, leaves unmatched slots empty, and returns untaken cards using `rest: "deckBottom"` (`apps/api/src/engine/effects/interpreter/actions/reveal.ts:108-125,202-220,277-301,511-550`). This supports BT4-023's two independent category slots and its partial-match ruling.
- Tamer-onto IR is registration metadata: `registerTamerOntoFromEffects` records a Static `Digivolve` action's `asLevel` (`apps/api/src/engine/effects/interpreter/registration/keywords.ts:272-295`), and metadata-only Digivolve actions without a runtime target return without resolving (`apps/api/src/engine/effects/interpreter/actions/digivolve.ts:203-207`). `matchingAlternateDigivolutionRequirement` then requires a Tamer base sharing the evolving card's color and derives the printed evo cost at that `asLevel`, ignoring stale gateless metadata (`apps/api/src/engine/cards/cardData.ts:336-344,520-560`). The manual digivolve path validates the alternative, pays memory, stacks the card, draws, and fires digivolution effects (`apps/api/src/engine/actions/digivolve.ts:430-514,650-815`).
- A generic field `Trash` action resolves permanent targets and trashes their top source (`apps/api/src/engine/effects/interpreter/actions/removal.ts:531-571`), whereas `TrashDigivolution` uses the dedicated source-trash primitive (`apps/api/src/engine/effects/interpreter/actions/placeUnder.ts:680-701`). This distinction is the proven BT4-026 defect and the reason its cost now sits on the Draw action.
- `selfDigivolutionStackCountAtLeast` evaluates every source definition with the complete filter, and `allOf`/`anyOf` preserve BT4-030's turn-plus-source condition (`apps/api/src/engine/effects/interpreter/conditions.ts:653-695`). `canAttackTarget` rejects a defender with `cantBeAttacked` but still allows a player attack and later block redirection (`apps/api/src/engine/combat/legality.ts:230-306`).

Same-mechanism peers inspected include BT5-046's cost-bearing `RevealAdd` (`apps/api/src/cards/BT5/BT5-046.ts:8-48`), BT5-050's Digi-Burst source watcher (`apps/api/src/cards/BT5/BT5-050.ts:8-24`), BT7-035 and BT7-071's tamer-onto Static Digivolve records (`apps/api/src/cards/BT7/BT7-035.ts:10-38`, `BT7-071.ts:10-38`), P-086's `cantBeAttacked` restriction (`apps/api/src/cards/P/P-086.ts:6-32`), and BT3-030's live stack keyword condition (`apps/api/src/cards/BT3/BT3-030.ts:8-50`). These peers confirm the target, source, color, duration, and registration shapes used by the direct range modules.
