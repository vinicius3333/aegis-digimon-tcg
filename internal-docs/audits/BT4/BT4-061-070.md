## Executive summary

All ten assigned cards have direct TypeScript compiled IR with `coverage: "full"`, empty `residual` arrays, and one card-module registration call: `registerIrCard(cardId, compiled)`. The direct modules match the committed catalog and the relevant local rules knowledge base after tracing each action through the shared interpreter; two direct card behavior gaps were proven and corrected in this range: Nidhoggmon now records the printed “in any order” deck-bottom choice, and Baboongamon now binds Digi-Burst payment to the actual De-Digivolve action instead of first trashing an unrelated own Digimon target.

The two direct corrections required two shared interpreter seam changes: permanent `Return` to a deck now supports controller ordering and preserves the selected order at deck bottom, while cost-bearing `DeDigivolve` now preflights its target pool before paying the activation cost. The generated `packages/shared/src/effects/effects.json` shadow remains stale for BT4-062 and BT4-068 and was deliberately not edited; the directly registered modules are authoritative at runtime.

This pass did not run tests, typecheck, lint, formatting, browser/UI validation, or `git diff --check`, as required. Every card therefore scores 0/2 for executed validation and is reported as **8/10 provisional**, never 10/10; this report does not claim collection completion.

### Shared interpreter trace and corrections

The action pipeline in `apps/api/src/engine/effects/interpreter/actions/runAction.ts:80-205` processes conditions, preflights target-bearing costs, pays costs, and dispatches actions. Its existing Return/Delete preflights avoid paying costs when their legal target pools are empty. The shared correction at `runAction.ts:176-188` extends that contract to cost-bearing `DeDigivolve` alongside the existing `TrashDigivolution` and `SelectBind` cases, while respecting `allowCostWithoutTarget` and the existing `abortOnDecline` behavior. This is required for BT4-068: before the correction, its Digi-Burst could trash two own sources before a no-target De-Digivolve was discovered.

The generic cost path at `runAction.ts:430-525` pays an action's attached cost before dispatching the action. Binding BT4-068's Digi-Burst cost to the actual De-Digivolve action, rather than to a generic field `Trash`, prevents both source over-trashing and cost payment when no legal opponent target exists. The De-Digivolve dispatcher at `runAction.ts:697-703` reaches `actions/digivolution.ts:16-61`, which resolves the selected opponent permanent and calls the shared `deDigivolve` primitive.

The permanent Return path in `actions/removal.ts:722-790` resolves all selected top cards, asks the controller for an order when `order: "any"` is present, and calls `returnToDeck` with that order. `primitives.ts:3671-3795` moves the returned permanent's top card and trashes its attachments as rule teardown. BT6-002 Q1399 proves this must not be followed by an effectful source-trash action, so review removed the former no-op trailing `TrashDigivolution`.

Other direct shared paths were traced without modification: `actions/board.ts:50-95` resolves and suspends actual board targets; `actions/reveal.ts:108-210` handles BT4-063's three-card reveal and `:380-550` returns unrecruited revealed cards; `actions/subTrigger.ts:44-112`, `:715-726`, and `:984-1007` map `onDigiBurstCardDiscarded` and preserve an inherited source watcher; `costs.ts:733-873` pays fixed self-stack Digi-Burst costs through `trashDigivolutionCards` and marks Digi-Burst source events; `actions/statics.ts:45-85` feeds Golemon's DP modifier into the continuous ledger; and the keyword path supplies Blocker and Reboot behavior.
