## Shared primitive and peer trace

The following reusable seams were inspected before assigning the IR and
behavioral components:

- `runStaticAction` in `apps/api/src/engine/effects/interpreter/actions/statics.ts`
  continuously re-evaluates `Aura` conditions and sends `modifyDP` through the
  continuous ledger. `apps/api/src/engine/effects/primitives.ts` records
  duration-scoped DP modifiers against the selected permanent.
- `conditions.ts` implements live `selfHasNameContaining`, `selfHasTrait`, and
  `selfHasKeyword`. Name matching reads the current top card; trait matching
  uses the live Form/Attribute/Type union; keyword matching reads the live
  keyword ledger. This is important after evolution and for conditional
  inherited auras.
- `effect.ts` maps `WhenEffectAddsToHand` to the effect-driven hand-add event
  and carries `OncePerTurn` onto the watcher identity. `subTrigger.ts` applies
  controller and fire-time gates. The hand movement and draw seams in
  `primitives.ts` emit the event with the receiving seat, while normal draw
  phase is distinct from effect-driven additions.
- The security-add seam in `primitives.ts` emits `whenAddSecurity` with the
  receiving seat; the `triggerSecurityIsYours` fire condition in the
  interpreter enforces Tokomon's controller boundary.
- `RevealAdd` is defined in `packages/shared/src/effects/ir/actions/reveal.ts`
  and executed by the reveal action path as one process: reveal three, take
  the applicable cards, and return the rest to the deck bottom. This matches
  §15-15-3's reveal ordering and mandatory maximum behavior.
- `DeletionMaxDpLedger` and the `DeletionMaxDpModifier` action implement the
  producer/consumer seam for BT9-009. The deletion action reads only numeric
  DP ceilings, preserving Q1800's source-relative nonnumeric boundary.
- Peer modules/tests inspected include `BT2-005` for the symmetric keyword
  aura shape, `BT15-002` and `BT16-011` for hand-add watcher behavior,
  `BT9-011` for the same DP-deletion ceiling modifier, and `BT9-012` for
  inherited stack identity and evolution-source handling. BT9-007 and BT9-010
  share `effectlessAudit.testkit.ts` for empty-effect and evolution legality
  proof.

The rules support these traces: a Digimon gains inherited effects from cards
under it (§4-3-2/3 and §15-3), stacked cards retain order (§4-7), a standard
digivolution places the new card on top and pays its selected requirement
(§8-1), and effects that use `[Your Turn]`/`[Opponent's Turn]` resolve only in
their stated turn window (§15-16-8).
