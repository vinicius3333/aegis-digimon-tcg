## Shared interpreter and peer evidence

- The direct registration path is normalized by
  `apps/api/src/engine/effects/interpreter/registration/module.ts:312-341`.
  It registers each card's compiled IR idempotently, and all ten modules in
  this range use this path exclusively. Controller/seat resolution is shared
  by `matching/permanent.ts:107-129`; this is material for own/opponent
  Digimon, Tamer, and Security-side effects.
- `GrantStatic` and grant-library dispatch in
  `apps/api/src/engine/effects/interpreter/grantedEffects.ts:279-287` and
  `actions/board.ts:32-36,115-169` support BT5-091's level-3 attack trigger.
  The `seatsForController` implementation makes the opponent grant explicit,
  while the direct module's separate own-level-3 trigger completes the global
  printed effect.
- `CostModifier` in
  `apps/api/src/engine/effects/interpreter/actions/resources.ts:243-446`
  checks a digivolution's `into` filter at cost query time and enforces the
  `suspendThisTamer` restriction. `changeEvoCost` applies the reduction only
  for the active evolution. This supports BT5-092's name filters, exact
  exclusions, optionality, and one-time suspend cost.
- `Return` in
  `apps/api/src/engine/effects/interpreter/actions/removal.ts:574-801` routes
  to the hand/deck primitives. `returnToHand` in
  `apps/api/src/engine/effects/primitives.ts:3523-3668` and `returnToDeck`
  beginning at `:3678` move the top card while trashing attached
  digivolution cards; the primitive test at
  `apps/api/src/engine/effects/primitives.test.ts:755-768` explicitly proves
  that returning to hand trashes the stack. This validates BT5-095/096/097
  stack behavior and the source/target distinction for BT5-097.
- `TrashDigivolution` in `actions/placeUnder.ts:517-702` uses
  `fromTop: false` for BT5-097's bottom-card selection. `RepeatPerCount` in
  `actions/board.ts:110-123` obtains its explicit count filter and runs the
  nested action once per matching Digimon; `scaling.ts:14-98` confirms that
  BT5-099's explicit battle-area count excludes breeding-area cards and
  non-Digimon permanents. `ModifyDP` at `board.ts:153-225` applies the
  -3,000 amount for the turn.
- `RevealAdd` in
  `apps/api/src/engine/effects/interpreter/actions/reveal.ts:95-125,202-350,
  353-591` reveals the requested count, tracks selected instances so one card
  cannot fill multiple add slots, sends the selected card to hand, and orders

  `payCost: false`; this is the relevant mechanism for BT5-098. The same
  reveal mechanism is exercised by BT5-049 and other reveal peers.
- Name, exact-name, color, level, kind, and keyword matching are implemented
  in `matching/definition.ts:68-130,150-180,280-342`. This is material for
  Nokia's exact Agumon/Gabumon play filter, Greymon-family exclusions,

- Main Option and Security timing map to `OnUseOption` and `SecuritySkill` in
  `effect.ts:122-132,185-215,300-356`. Security-side self-add and
  Security-side Main activation therefore use the same typed action path as
  their direct modules.
- Same-mechanism peers inspected included BT5-031 and BT5-072 for return and
  stack handling, BT4-100 for optional free play and Security Main activation,
  BT5-049 for reveal/add and deck-bottom handling, and BT8-043 for explicit

  memory interaction described by Q1370; BT5-099's focused tests cover the
