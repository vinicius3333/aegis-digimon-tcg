### Runtime seams whose real semantics I verified before trusting them

- `SubTrigger.cost` / `optional` / `abortOnDecline` are honored **at fire time** inside
  `runSubTrigger`'s `run` closure (`canPayCost` gate, then the optional prompt, then `payCost`).
  `runAction` explicitly excludes `SubTrigger` from the install-time cost path, so EX11-021's shape
  is right and the persisted nesting is not needed.
- `filterMatch` is a constant `true` when a SubTrigger declares no `sourceFilter`, and
  `whenLinked` / `whenSuspended` are board-wide buses. An unfiltered watcher therefore fires for
  every event of that kind, which is exactly the EX11-029 defect.
- `match: "trait"` is exact equality after case/space normalization; `match: "traitContains"` is the
  substring matcher. This is the EX11-026 defect.
- `SecurityManipulation.toHand` reads `faceDownOnly` to skip revealed security cards; without it the
  literal top card is taken.
- The `place` cost supports `zone: "linked"` sources, `destination: "digivolutionStack"` and
  `position: "bottom"`, and `isSelfRef` on a `linked`-zone branch resolves to "this Digimon's link
  cards". This is what makes EX11-027's link effect expressible without an engine change.
- Link legality and link cost are read from the **catalog string** `linkRequirement`
  (`linkEligible`, `linkCostOf`, `GameEngine.linkRequirementSatisfied`), not from
  `CompiledCard.linkRequirement`, so EX11-027 is fully linkable at cost 2 without that field.

### EX11-026 Pteromon — 2 defects corrected, 1 escalated

Clauses: `[When Moving] [On Play]` you may suspend 1 Digimon; if this effect suspended **your**
Digimon, 1 of your Digimon with [Avian] or [Bird] **in any of its traits** or the [Vortex Warriors]
trait gets +3000 DP until your opponent's turn ends; inherited `[Your Turn] [Once Per Turn]` gain 1
memory when this Digimon wins a battle. Green, Lv.3, 1000 DP, [Bird Dragon]/[LIBERATOR].

**Defect 1 — exact trait matching on a partial-trait clause.**

- Before: `nameOrTrait: [{ tokens: ["Avian","Bird"], match: "trait" }, { tokens: ["Vortex Warriors"], match: "trait" }]`
- After: the first reference becomes `match: "traitContains"`; the [Vortex Warriors] reference stays
  exact.

`definition.ts` 355-357: `match: "trait"` is `traits.some(x => x === token)` and
`match: "traitContains"` is `traits.some(x => x.includes(token))`. The printed sentence deliberately
uses two different phrasings in one clause — "in any of its traits" versus "the [Vortex Warriors]
trait" — and the KB reproduces the same distinction (Q839, Q6517). Under exact matching the card
could not buff **itself** ([Bird Dragon]), nor its own line's [Bird Dragon] Digimon (EX11-028,
EX11-032, EX11-074). BT24-044 Muchomon prints the identical clause and already compiles it as
`{ tokens: ["Avian","Bird"], match: "traitContains" }` + exact [Vortex Warriors]; EX12-031 and
EX12-036 use `traitContains` for the same wording.

**Defect 2 — the "your Digimon" gate ignored the controller.**

- Before: `condition: { kind: "ifThisEffectActed", raw: "this effect suspended your Digimon" }`
- After: `condition: { kind: "lastSuspendedIsMine", raw: "this effect suspended your Digimon" }`

`conditions.ts` 751-758: `ifThisEffectActed` is true whenever the prior action moved anything —
`Suspend` sets `ctx.lastEffectActed = suspendedIds.length > 0` for **any** controller. Q5816 confirms
the suspension may take the opponent's Digimon, so the two are routinely different. The engine
already carries the exact predicate this clause needs: `lastSuspendedIsMine` reads
`ctx.lastSuspendedPermanentIds` and checks `controllerSeat === mine`. BT24-044 again is the
precedent, using `lastSuspendedIsMine` for the same sentence.

The two defects masked each other: the existing test "may suspend an opposing Digimon but then does
not grant the conditional DP bonus" passed only because the source's [Bird Dragon] trait failed the
exact match — the broken condition was never exercised. Fixing only the trait match would have
turned that test red, which is the evidence that both belong to one clause.

Tests: the encoding assertion now pins `traitContains`, `lastSuspendedIsMine`, `controller: "mine"`
and `duration: "untilOpponentTurnEnd"`; a new trait-mix case
`offers partial-trait and Vortex Warriors allies but never a non-matching trait` builds a board of
the [Bird Dragon] source, EX8-074 ([Vortex Warriors], no Avian/Bird), and BT1-009 ([Mini Dragon]),
answers the decisions manually, and asserts the candidate set contains the first two and not the
third before applying +3000 to the source; the opposing-suspension case gains a comment naming it as
the controller guard.

Mutation check: `traitContains` → the new candidate-set assertion (exact matching drops the
[Bird Dragon] source); the exact [Vortex Warriors] branch → EX8-074 appearing in the same set;
`lastSuspendedIsMine` → the opposing-suspension test (`currentDP` stays 1000 on a legal buff
target); `untilOpponentTurnEnd` → the +3000 assertions; `controllerDefault: "any"` on the Suspend →
the opposing-suspension candidate assertion; the inherited once-per-turn memory → the stack test.

**Escalated, not fixed — the spurious alternate digivolution route (seam request S-1).** The module
declares `digivolutionRequirement: [{ level: 2, cost: 0, isAlternate: true }]`, i.e. **any** level-2
Digimon of **any** color may digivolve into Pteromon for 0 memory. The catalog `effectText` for
EX11-026 prints **no `[Digivolve]` header** (every other card in this batch that has one — 021, 022,
023, 025, 027, 029, 030 — carries it verbatim in `effectText`), and its `evoCosts` is the single
ordinary row `{Green, level 2, memoryCost 0}`. The persisted record corroborates this: the compiler
emitted **no** `digivolutionRequirement` for EX11-026 and for EX11-028/EX11-024 (also headerless),
while emitting one for every card that prints a header. The entry therefore looks like a
hand-authored mistake in `packages/shared/src/effects/data.ts`
(`"EX11-026": [{ level: 2, cost: 0, isAlternate: true }]`, commented "prints an unrestricted
[Digivolve] Lv.2: Cost 0 route"), whose only observable effect is to strip the printed **color**
restriction from the ordinary evolution route. I did not change the module field, because
`digivolutionRequirementsFor` reads `ALTERNATE_DIGIVOLUTION_OVERRIDES` **first**: removing it from
the module alone would change nothing at runtime while making the module and the live legality
source disagree. The override and the module field must be removed together — see S-1. Scored below
maximum for this reason.

### EX11-027 Maquinamon — 1 defect corrected (a missing printed clause)

Clauses: `[Digivolve] Lv.2 w/[Maquinamon] in text: Cost 0`; `[On Play]` reveal the top 3, add 1
[Maquinamon] and 1 card with [Maquinamon] in its text, rest to deck bottom, then you may link this
Digimon or a [Maquinamon] from hand to 1 of your **other** Digimon free; `[Link] [Maquinamon] in
text: Cost 2`, link DP 2000; link effect `[All Turns]` when this Digimon would leave the battle
area, by placing 1 of its link cards as its bottom digivolution card, it doesn't leave.
`maxCountInDeck: 50`.

**Defect — the printed link effect was not encoded while the module claimed
`coverage: "full", residual: []`.** The catalog `linkEffect` field is a real clause of this card and
nothing in the module represented it. Added:

```ts
{
  trigger: "AllTurns",
  isLinked: true,
  actions: [{
    kind: "Replacement",
    event: "wouldLeavePlay",
    sourceFilter: { isSelfRef: true },
    actions: [],
    cost: {
      kind: "place",
      target: { filter: { isSelfRef: true, zone: "linked" }, from: ["linked"], count: 1 },
      destination: "digivolutionStack",
      position: "bottom",
      host: "self",
      raw: "by placing 1 of its link cards as its bottom digivolution card, it doesn't leave",
    },
  }],
}
```

(`kernel.ts` 136: the effect is live only while `ctx.source.instanceId` is in the host's `linked`

### S-2 (non-blocking) — `canActivateEffect` silently drops all-gated effects from simultaneity groups

`interpreter/effect.ts` 779-789 returns `false` when every action of an effect is "gated" and none is
currently possible. That is right for offering a lone effect, but it also removes the effect from an
`orderTriggers` group, which changes an observable rules outcome: CR/§Q5810-style simultaneity is
about *triggering*, and a triggered effect that can do nothing still occupies its slot in the order.
No card in this batch depends on the difference (I fixed the EX11-022 test fixture instead of the
engine), so this is recorded, not requested as a behavioral change. If it is ever addressed, the
regression test is the original EX11-022 Q5810 fixture with EX11-070 as the partner: two trigger
keys must be offered even though EX11-070's DNA digivolve and ＜Mind Link＞ are both impossible.
