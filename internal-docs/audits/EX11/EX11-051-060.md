### EX11-053 Omekamon — two defects corrected

Clauses: `[On Play]` by placing 1 [Royal Knight] trait Digimon card from hand as the bottom
digivolution card of any of your [King Drasil_7D6]s on the field, ＜Draw 1＞; `[On Deletion]` if you
have 1 or fewer security cards, you may play 1 [Omnimon (X Antibody)] from hand or from under your
[King Drasil_7D6]s on the field without paying the cost, then place this card as the played
Digimon's bottom digivolution card; `[Rule] Name: Also treated as [X Antibody]`.

IR trace: the place cost uses `underFilter` with `or: [{zone:"battleArea"},{zone:"breeding"}]`,
which is correct under CR 3-4-6 — "the field" includes the breeding area. The `[On Deletion]` play
pools `from: ["hand","digivolutionCards"]` with a per-branch `or`: the hand branch is unrestricted,
the stack branch carries `hostFilter`. `candidateLooseInstances` flattens `filter.or` into
common+branch filters and evaluates `hostFilter` per branch, and `looseCardsInZone("digivolutionCards")`
enumerates battle-area AND breeding stacks — again matching "on the field". The `Rule` compiles to
`GrantStatic grant: "name"`, which `effectiveStaticNames` feeds into name matching, so Q5907's
"[X Antibody] is in the digivolution cards" is satisfied once the placement lands.

Defect 1 — **bracketed names were substring matches.** `[Omnimon (X Antibody)]` and
`[King Drasil_7D6]` both used `match: "name"`, which `matchNameOrTrait` implements as
`names.some(name => name.includes(token))`. CR 2-3-1-2 makes a bracketed name exact.
Before / after:

```
- nameOrTrait: [{ tokens: ["Omnimon (X Antibody)"], match: "name" }]
+ nameOrTrait: [{ tokens: ["Omnimon (X Antibody)"], match: "nameExact" }]
- hostFilter: { controller: "mine", nameOrTrait: [{ tokens: ["King Drasil_7D6"], match: "name" }] }
+ hostFilter: { controller: "mine", nameOrTrait: [{ tokens: ["King Drasil_7D6"], match: "nameExact" }] }
- underFilter: { …, nameOrTrait: [{ tokens: ["King Drasil_7D6"], match: "name" }], … }
+ underFilter: { …, nameOrTrait: [{ tokens: ["King Drasil_7D6"], match: "nameExact" }], … }
```

No card in the current catalog has a name that strictly contains either token, so this fix has no
behavioral witness today — it is correctness by construction against the catalog growing. Stated
here rather than claimed as a proven fix.

Defect 2 — **a mandatory clause was optional.** "Then, place this card as the played Digimon's
bottom digivolution card" is not a "may", but the `PlaceUnder` carried `optional: true`, so the
controller was given a second decline that the printed card does not offer (the brief's declinable
"By …" defect class, inverted). Removed:

```
- { kind: "PlaceUnder", target: {…}, underFilter: {…}, position: "bottom", optional: true }
+ { kind: "PlaceUnder", target: {…}, underFilter: {…}, position: "bottom" }
```

Safe with no play: `runPlaceUnder` resolves `underFilter.lastPlayed` from
`ctx.lastPlayedPermanentIds`, and `destIds.length === 0` returns quietly with no `unsupported()`
call, so a declined or target-less play still ends cleanly.

**Baseline failure — cause identified.** `EX11-053.test.ts > can also play Omnimon (X Antibody)
from under King Drasil` failed on the untouched branch for a fixture reason, not a card or Decode
reason. The module has no `playedByDecode`, so `applyDecodeHostScope` is a no-op for it and the
new host scoping is irrelevant. What happens instead:

1. `GameEngine.fireTimingForInstance` calls `shouldDeferNestedTiming()`, so the played
   BT20-102's `[On Play]` is deferred until EX11-053's `[On Deletion]` finishes — which is exactly
   the ordering Q5907 describes, and means Omekamon is already under Omnimon when it activates.
2. BT20-102's `[On Play]` is `Delete { count: "all", except: { count: 1, selector: "any" } }`
   gated on `selfDigivolutionStackHasTrait([Omnimon]/[X Antibody])` — now satisfied. It deletes
   every Digimon except one chosen survivor.
3. In this fixture the board is `[King Drasil, played Omnimon]`. `resolveExceptSurvivors` opens a
   `chooseTargets`, and `autoSelectCards` takes candidates in board order, keeping King Drasil and
   deleting the played Omnimon. `battleArea.find(topCard.cardId === "BT20-102")` is then
   `undefined` and `expect(undefined).toBe(true)` fails.
4. The sibling hand-play test passes because after Omekamon dies the board holds only the played
   Omnimon, so "delete all others" deletes nothing.

Fix applied to the test, not the module: pass `preferInstanceIds` (populated after setup, the
EX12-014 pattern) so the survivor choice is the played Omnimon, and assert on the omnimonX
*instance* rather than its cardId so the assertion proves the exact card left King Drasil's stack.
The King Drasil assertion was replaced (King Drasil is now the deleted one) by "no other permanent
still holds that instance".

Tests added: the rewritten under-King-Drasil case; a negative where the host is Agumon instead of
King Drasil_7D6 and Omnimon stays in the stack; an IR assertion that the `PlaceUnder` carries no
`optional`.

Mutation checks: restore `optional: true` on the `PlaceUnder` → the new IR test fails. Drop the
stack `or` branch → the under-King-Drasil test's `played` lookup fails. Drop `hostFilter` → the
non-King-Drasil negative fails. Change `securityAtMost` to 2 → the existing 2-security test fails.
Drop the `Rule` grant → the existing `effectiveNames` test fails.

### EX11-058 Yao Qinglan — two defects corrected (the batch's most serious)

Clauses: `[Start of Your Main Phase]` by placing 1 level-5-or-lower card with [Aqua] or
[Sea Animal] in any of its traits from hand as the bottom digivolution card of any of your Digimon
with [Aqua] or [Sea Animal] in any of their traits, gain 1 memory; `[All Turns]` when your Digimon
are played or digivolve, if any has [Aqua] or [Sea Animal] in any of their traits, by suspending
this Tamer ＜Draw 1＞; if played by ＜Decode＞, 1 of your opponent's Digimon can't suspend until their
turn ends; `[Security]` play without cost.

Defect 1 — **"in any of its traits" was compiled as an exact trait match, which killed the entire
Aqua half of the card.** The printed wording is CR 2-3-2-4, not 2-3-2-3. No card in the catalog
carries a bare `[Aqua]` trait: the real traits are `[Aquatic]`, `[Aquabeast]` and
`[Ancient Aquabeast]`. With `match: "trait"` (`traits.some(x => x === "aqua")`) every one of them
failed, so the placement cost, the host filter and both watchers only ever saw `[Sea Animal]`.
The existing suite never noticed because all its fixtures were `[Sea Animal]` (BT14-008, BT23-023).

```
- { tokens: ["Aqua"], match: "trait" }
- { tokens: ["Sea Animal"], match: "trait", orPrevious: true }
+ { tokens: ["Aqua"], match: "traitContains" }
+ { tokens: ["Sea Animal"], match: "traitContains", orPrevious: true }
```

`matchNameOrTrait`'s `traitContains` normalizes whitespace/hyphens then uses `includes`, so
`[Aquatic]`/`[Aquabeast]`/`[Ancient Aquabeast]` now match, `[Sea Animal]` still matches, and
`[Sea Beast]` correctly does not.

Defect 2 — **the placement payment was narrowed to Digimon.** The printed cost is "1 level 5 or
lower CARD with …", but the filter reused the Digimon-scoped `aquaOrSeaAnimal`. Split into a
separate `placeableAquaOrSeaAnimalCard` with no `kind`, keeping `kind: ["Digimon"]` on the host
filter and both watchers where the text does say "Digimon". No non-Digimon card in the current
catalog has a level and one of these traits, so this fix has no behavioral witness today — it is
recorded as catalog-limited, and pinned by an IR assertion instead.

Decode clause: `Restrict` with `condition: {kind: "triggerPlayedByDecode"}` sits only inside the
`whenPlayed` SubTrigger and not inside `whenOneOfYoursDigivolves`, which is Q5911/Q5912 exactly.
It also follows the `abortOnDecline` draw, so refusing the suspend suppresses the lock too — the
"by" processing condition governs everything after it.

Tests added:
- an `[Aquatic]` card placed under an `[Aquatic]` host, asserted at stack position 0 (bottom) with

## 6. Seam requests

### Seam 1 — `PlayWithoutCost` with an activation cost has no no-candidate preflight

`apps/api/src/engine/effects/interpreter/actions/runAction.ts` pays an action's activation cost
(the `payCost(...)` block, around line 465) BEFORE the `PlayWithoutCost` candidate preflight, which
sits inside the "You may" block (around line 517) and returns `false`, not an abort. `Delete`,
`TrashDigivolution`, `SelectBind`, `DeDigivolve`, `Unsuspend`, `RedirectAttack`, `PlaceUnder` and
`UseOptionWithoutCost` all already have a cost-guarded preflight ABOVE the payment; `PlayWithoutCost`
does not.

Consequence for this batch: EX11-055's `[All Turns]` suspends Chitose even when the controller
holds no [Gazimon] or [Gizamon], so a cost is paid for a guaranteed no-op. EX11-060's Overclock
branch and EX11-051's trash play share the shape but pay their costs at a different level, so they
are unaffected.

Proposed minimal diff (alongside the existing target-bearing preflights, before the cost block):

```ts
if (
  action.kind === "PlayWithoutCost" &&
  action.cost !== undefined &&
  action.allowCostWithoutTarget !== true &&
  !action.target?.isSelf &&
  action.target?.filter?.isSelfRef !== true &&
  action.fromOwnDigivolutionStack !== true &&
  playWithoutCostCandidates(ctx, action).length === 0
) {
  return action.abortOnDecline === true;
}
```

(where `playWithoutCostCandidates` is the candidate computation already written inline in the
optional block, extracted so both sites share it.)

Failing test it needs — add to `EX11-055.test.ts` once the seam lands:

```ts
it("does not suspend when no Gazimon or Gizamon can be played", async () => {
  const s = setupEngine(
    { 0: { battleArea: [{ card: "EX11-055", as: "chitose" }, { card: "AD1-006", as: "composite" }],
           hand: [{ card: "BT1-009", as: "notGazimon" }] } },
    { autoAcceptOptional: true, autoSelectCards: true },
  );
  await advance(s.engine).verb.deletePermanent([s.perm("composite").permanentId], "byEffect");
  await settle(() => false, 60);
  expect(s.perm("chitose").isSuspended).toBe(false);
});
```

Not made here: it is an `apps/api/src/engine` change, outside the batch's edit scope.

### Seam 3 — `Filter.nameOrTrait` doc contradicts the interpreter

`packages/shared/src/effects/ir/filters/cardPredicates.ts` documents multi-entry `nameOrTrait` as
"Entries AND by default", while `definitionMatches`
(`apps/api/src/engine/effects/interpreter/matching/definition.ts`) always unions
(`filter.nameOrTrait.some(...)`) and its own comment says both paths are OR. Every EX11 card in
this batch needs OR, so nothing is broken today, but a future "fix" toward the doc would silently
break any module relying on the implicit default. Proposed change: correct the doc comment to say
the array is always a union and that `orPrevious` is a redundant explicit marker — a
`packages/shared` comment-only edit, outside the batch's edit scope. No test needed; the batch
already declares `orPrevious` explicitly everywhere it matters.
