### Baseline failure: `EX11-049.test.ts` "can evolve into a Dark Dragon just trashed by the cost …"

Confirmed to be the EX12 route-prompt class, and it is a **test** defect, not a module defect.

`actions/digivolve.ts` (≈ line 430) opens
`ctx.ask.chooseOption(["Printed digivolution requirement (cost N)", "Alternate digivolution requirement (cost M)"])`
whenever an effect-driven digivolve is **paying** (`payCost: true`) and *both* a printed evoCost and
an alternate requirement match the base. EX11-049 Punkmon is Lv.4, Purple/Red, [Dark Dragon]. The
card it evolves into, EX11-050 Loudmon, prints evoCosts `Purple Lv.4 / 4` and `Red Lv.4 / 4` **and**
the alternate `Lv.4 w/[Dark Dragon]/[Evil Dragon]: Cost 3`. Both match, so the prompt opens and the
suite never answers it. The comparable EX11 digivolves in this batch (EX11-041 → EX11-043,
EX11-045 → EX11-033, EX11-046 → [Galacticmon]) are all `payCost: false`, so the same guard skips the
prompt and they are unaffected.

Fix applied in `EX11-049.test.ts`: pass `autoChooseOption: true` (index 0 = the printed route,
cost 4 − 2 = 2 ⇒ memory 5 → 3, which is exactly what the case already asserted). A second case pins
the other branch with `preferOptionIndex: 1` (alternate cost 3 − 2 = 1 ⇒ memory 5 → 4).

## 4. Per-card findings

### EX11-041 Oblivimon (Black/Blue, Lv.5, [Cyborg]/[LIBERATOR], 7/7000)

Clauses: alternate `Lv.4 w/[Cyborg] or [Machine]: Cost 3`; `[Security] [End of Opponent's Turn]` free self-play;
`[On Play] [When Digivolving]` flip the opponent's top **face-down** security card face up +
＜De-Digivolve 1＞ one of their Digimon, then **if it's their turn** this Digimon may digivolve into
[Invisimon] in hand for free; `[Your Turn]` when any of your Digimon check a face-up security card,
you may place this Digimon's top stacked card face up as the bottom security card; inherited
`[Your Turn]` attack target can't change.

IR trace: `SecurityManipulation{op: flipUp, controller: opponent}` → `security.ts` flips the top
face-down card (Q5867). `DeDigivolve{amount: 1}`. `Digivolve{from: ["hand"], payCost: false,
optional: true, condition: {kind: "isOpponentsTurn"}}` — `payCost: false` means the printed/alternate
route prompt is skipped, and no `ignoreRequirements` is correct because Oblivimon (Lv.5 [Cyborg])
legally satisfies Invisimon's requirement. The `[Your Turn]` clause is a `whenCheckedFaceUpSecurity`
SubTrigger; `securityCheck.ts` snapshots `faceUp` before the reveal and fires that event only for an
already-face-up card, carrying `attackerPermanentId`.

**Defect corrected.** "this Digimon's top stacked card" is the permanent's **own top card**, not its
top digivolution card. Q5875 is decisive: with only BT15-086 [Marvin Jackson] underneath, placing
that card leaves a **Tamer** permanent, so the card that left is Oblivimon/Invisimon itself; Q5888
says the promoted card performs the next security check. The same reading is forced by the
"place this Digimon's top stacked card as its **bottom digivolution card**" printings (BT23-008,
BT23-018, P-225), where only the permanent's own top card makes the clause meaningful.

The module already resolved the right card (`source: {filter: {isSelfRef: true}, isSelf: true}` →
`addSecurity(seat, [ctx.source.instanceId])`), but it did **not** pass `detachPermanentTop`. Without
that flag, `primitives.ts addSecurity` runs `collectForReturn`: the whole permanent leaves the battle
area, the top card becomes security and **every digivolution card is trashed**. With it, only the top
card is shed, `popFromStack` promotes the next card, `baseDP` and continuous effects are recomputed,
and the permanent survives — exactly Q5875/Q5888. Precedent: `BT20-055.ts` (also an Invisimon) sets
the flag, and `BT20/AUDIT.md` records the same defect being fixed there.

Before / after (both `EX11-041.ts` and `EX11-043.ts`):

```ts
- source: { filter: { isSelfRef: true }, count: 1, isSelf: true },
- faceUp: true,
+ source: { filter: { isSelfRef: true }, count: 1, isSelf: true },
+ detachPermanentTop: true,
+ faceUp: true,
```

Tests added: an IR assertion for `detachPermanentTop`; "sheds only its own top card to the security
bottom and promotes the stack" (stack `[BT1-009, BT1-019]`, asserts the permanent survives, its new
top is the previously-top digivolution card, one card remains in the stack, and the trash is empty);
and a decline case proving nothing moves under `autoDeclineOptional`.

Mutation check: `detachPermanentTop` → the survivor lookup, the promoted-top assertion and the
empty-trash assertion all fail. `condition.kind: "isOpponentsTurn"` → the IR assertion at line ~44
plus the existing behavioural case (which sets `turnSeat = 1` before asserting the evolution). The
`flipUp` controller → the existing security face-up assertions. `DeDigivolve.amount` → the existing
`opponent.stack` / `topCard` assertions. `restriction: "attackTargetChange"` → the IR assertion only
(no runtime redirect fixture); recorded as a gap.

Open ambiguity: whether "as the bottom security card" could mean the opponent's stack. Every peer
printing of this clause (BT20-055, BT24-093) places into the controller's own stack, and Q5874/Q5886
discuss the controller's own security count, so `controller: "mine"` is kept.
