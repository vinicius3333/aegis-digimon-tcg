## 4. Per-card findings

### EX11-031 Vespamon

**Clauses.** Lv.5 / 8000 DP / play cost 8 / Green+Black / Ultimate / Virus / Cyborg · X Antibody ·
Royal Base · LIBERATOR · Insectoid; alternate `[Digivolve] Lv.4 w/[Royal Base] trait: Cost 3`;
`[Security] [Opponent's Turn]` Blocker grant to your [Royal Base] Digimon; `[On Play]`
`[When Digivolving]` scaled suspend + "Then," unsuspend restriction; inherited `[All Turns]`
`[Once Per Turn]` leave-prevention paid by flipping your top face-up security card face down.

**IR trace.** The `[Security] [Opponent's Turn]` pair is not a security-check skill: `effect.ts`
routes `isSecurity` + `YourTurn`/`OpponentsTurn`/`AllTurns` to the `securityStatic` builder, whose
base guard is `inFaceUpSecurity`. So the grant is a continuous effect that runs while this card sits
face up in security during the opponent's turn — which is why `duration: "permanent"` is the right
shape here and matches the whole family (BT18-052, BT19-052, BT23-043, EX11-025, EX11-030).
`Suspend`'s `scaling` multiplies `target.count` in `board.ts`; `scaling.ts`'s `"security"` case
counts only `faceUp` cards. A zero count aborts the `Suspend` early but not the following
`Restrict` — correct under CR 15-6-2, since "Then," is only chained to an **optional processing
condition** ("by …"), which this clause does not have. Q5837 confirms the two targets are
independent, which two separate `Target`s already give. The inherited replacement installs with
`mode: "prevent"`, `protects` = `sourceFilter` (mine, Digimon, [Royal Base]) and
`causeAllows` = `otherThanYourEffect` → `!(cause === "byEffect" && resolvingSeat === ownerSeat)`.
`cost.kind: "flipSecurity"` calls `fx.flipTopSecurity(ownerSeat)` and returns false when no face-up
card exists, so the prevention is all-or-nothing.

**Defects corrected.** (1) Removed the dead `filter: { isTriggerSubject: true }` (see §3).
(2) The header comment claimed CAP-H-08 (`faceUp` on a security scaling filter) and CAP-H-09
(flip-face-down cost) were missing capabilities; both are live (`scaling.ts`, `costs.ts`). Replaced
with a description of what actually runs.

**Tests added.** "suspends nothing without a face-up security card but still restricts unsuspending"
(scale 0 leaves a second, unsuspended opponent Digimon untouched while the restriction still lands)
and "does not protect a Digimon without the Royal Base trait" (a plain Digimon is deleted and the
face-up security card is not spent).

**Mutation check.** `scaling.filter.faceUp` → the new zero-face-up test (the face-down security card
would otherwise scale the suspend to 1 and suspend the bystander).
`sourceFilter.nameOrTrait` [Royal Base] → the new non-Royal-Base test.
`leaveCause: "otherThanYourEffect"` → **not pinned**: no test deletes with `resolvingSeat` equal to
the owner. `duration: "permanent"` on the Blocker grant → pinned only as "granted while face up in
security on the opponent's turn" by the existing test.

**Open ambiguity.** The printed Blocker grant states no duration. `permanent` is family-consistent
and, under the `securityStatic` routing, is recomputed while the card stays face up; a "for the
turn" reading would look identical in every state I can construct without an executed gate.

### EX11-032 GrandGalemon

**Clauses.** Lv.5 / 8000 / cost 8 / Green / Ultimate / Data / Bird Dragon · Vortex Warriors ·
LIBERATOR; `[Hand] [Main]` conditional digivolve-from-hand for a fixed cost 3 ignoring requirements,
paid by placing a [Galemon] from trash as a [Pteromon]'s bottom digivolution card;
`[When Digivolving]` optional suspend then optional free play of a ≤3000 DP green [Avian]/[Bird]
Digimon with a +1000 DP ceiling per suspended Digimon; inherited `[Your Turn] [Once Per Turn]`
"when this Digimon wins a battle, this [Vortex Warriors] trait Digimon may unsuspend".

**IR trace.** The hand route is a `Digivolve` with `isFromHand`, `into: {isSelfRef: true}`,
`costOverride: 3`, `payCost: true`, `ignoreRequirements: true`, `condition: youHave [Shoto Kazama]`,
and a `place` cost with `host: "target"`, `destination: "digivolutionStack"`, `position: "bottom"` —
so the [Galemon] lands under the very [Pteromon] being digivolved. The ceiling raise rides on
`PlayWithoutCost.dpCeilingModifier` (`play.ts` line ~369 adjusts the `dp` filter's ceiling before
resolving candidates) and counts suspended Digimon on either side, per Q5840's companion reading of
"For each suspended Digimon". `whenBattleWon` exists on the SubTrigger bus and fires after the loser
is deleted (Q5841-Q5845).

**Defect corrected.** The inherited unsuspend targeted `{ isSelfRef: true }` with no trait gate.
The printed subject is "this **[Vortex Warriors] trait** Digimon", which in an inherited effect
gates the **host**: a host without the trait inherits the watcher but unsuspends nothing. Precedents
in already-audited sets: BT26-066 (`{isSelfRef: true, nameOrTrait: [[Titan] trait]}`) and ST22-13,
whose ESS uses the identical "this Digimon with the [Vortex Warriors] trait may unsuspend" phrasing
and the identical IR shape. Before: `filter: { isSelfRef: true }`. After:
`filter: { isSelfRef: true, nameOrTrait: [{ tokens: ["Vortex Warriors"], match: "trait" }] }`.
`targeting/permanents.ts` still runs a self target through `permanentMatchesFilter` when the
permanent has a `topCard`, so the added predicate is live rather than short-circuited.

**Tests added/changed.** The existing inherited test used EX11-033 (Beast · LIBERATOR) as the host,
which the fix now correctly excludes; it was re-pointed at EX7-034 GrandGalemon (Bird Dragon ·
Vortex Warriors · LIBERATOR), and a new negative case keeps EX11-033 as the host and asserts it
stays suspended.

**Mutation check.** `nameOrTrait` [Vortex Warriors] → the new negative host test (it would unsuspend
without the gate). `frequency: "OncePerTurn"` → the second `whenBattleWon` fire in the positive test.
`costOverride: 3` → the hand-route test asserts memory 3 → 0. `place` cost `position: "bottom"` →
the same test asserts the stack order `["EX11-028", "EX11-026"]`.

**Open ambiguity.** Q5838 (a further reduction from EX7-031 brings the fixed cost 3 down to 2) is
carried by the primitive: `digivolveFromInstance` receives `costOverride` and the engine's own
reduction ledger, but no test in this batch pins the interaction, and I could not execute one.

opponent's Digimon. Then, 1 of their Digimon can't unsuspend until their turn ends"; inherited
`[All Turns] [Once Per Turn]` "when this Digimon deletes your opponent's Digimon in battle, this

**IR trace.** `texts: ["Maquinamon"]` is the right requirement encoding per Q5846. The `whenLinked`

**Defect corrected.** "from your hand or **this Digimon's** digivolution cards" was unscoped:
`looseCardsInZone(ctx, seat, "digivolutionCards")` enumerates **every** stack the seat controls, so
the card could take a [Maquinamon] out from under any other Digimon. Added
`hostFilter: { isSelfRef: true }` to both Link targets (the shape the brief prefers);
`candidateLooseInstances` applies a `hostFilter` only to hosted zones, so the hand pool is
unaffected.

**Tests added.** "links Maquinamon out of its own digivolution cards" (positive, proves the

**Mutation check.** `hostFilter.isSelfRef` → the new negative test. `from: ["hand","digivolutionCards"]`

the existing inherited test's second fire and its host-scoped assertions. `texts` requirement → the

**Open gap (seam request 1).** The printed verb is "**play** … to 1 of your Digimon", not "link"

actions). Q5850 asks whether the played EX11-027's `[On Play]` can be activated before a rule check

action, because replacing `Link` with a play would lose the link itself, which is strictly worse.
EX11-042 carries the identical printed text and is in another batch's scope.

**Defects corrected.** None.

**Tests added.** "never digivolves itself at end of turn, even into a card it legally could become"

## 6. Seam requests

### 1. Play a card as a link card, so the played card's `[On Play]` fires (EX11-033, EX11-042)

*Need.* "You may **play** 1 [Maquinamon] from your hand or this Digimon's digivolution cards **to**
1 of your Digimon without paying the cost". Playing and linking are distinct actions (CR line 98,
§10-1), and Q5850 treats the played card's `[On Play]` as live. `runLink` → `primitives.link` fires
`whenLinked` and `whenLinking` only.

*Minimal proposed change.* Add an optional `asPlay?: boolean` to `LinkAction`
(`packages/shared/src/effects/ir/actions/xrosLink.ts`) and, in
`apps/api/src/engine/effects/interpreter/actions/link.ts`, after `await ctx.fx.link(recipientId, chosen)`
succeeds with `action.asPlay === true`, open the same `[On Play]` window the play path uses for the
newly linked instances (the `firePlayed`/`OnPlay` dispatch `playInstances` already performs), before
the rule-check sweep result is asserted. Then set `asPlay: true` on EX11-033 and EX11-042.

*Failing test it needs.* In `EX11-033.test.ts`: board = EX11-033 alone, hand = EX11-027
[Maquinamon] (whose `[On Play]` reveals the top 3 cards and adds up to two to hand), deck stacked
with a [Maquinamon] and a [Maquinamon]-text card. Fire `EffectTiming.OnPlay` on the source and
assert the linked card is on the source **and** that the two revealed cards reached the hand. Today
the hand assertion fails because no `[On Play]` window opens.

### 2. Type the security-placement selection filter (EX11-034, BT25-037, BT19-036)

*Need.* `runSecurityAdd`'s `"hand"`/`"handOrTrash"` branch reads `(action as { filter?: Filter }).filter`,
a field `SecurityManipulationAction` does not declare. Any module using the documented shape fails
to typecheck; I routed EX11-034 through the typed `source: Target` branch instead, which is
equivalent, but the cast remains a trap for the other cards named in that comment.

*Minimal proposed change.* Either declare `filter?: Filter` on `SecurityManipulationAction`
(`packages/shared/src/effects/ir/actions/security.ts`) with a comment scoping it to loose-source
placements, or delete the cast branch and normalize `"hand"`/`"handOrTrash"` into the object-source
path. I did not make either change (shared package is out of scope for this batch).

*Failing test it needs.* A typecheck of any module that sets `filter` on a `SecurityManipulation`
— for example the pre-fix `EX11-034.ts` — reports
`Object literal may only specify known properties, and 'filter' does not exist in type 'SecurityManipulationAction'`.
