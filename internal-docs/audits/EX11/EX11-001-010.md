### EX11-006 Flickmon (DigiEgg, White, Lv.2, Appmon/Flick/LIBERATOR)

- **Clauses.** Inherited `[When Attacking] [Once Per Turn]`: this Digimon **linked with
  [Maquinamon]** *may* digivolve into a Digimon card with [Maquinamon] **in its text** in the hand
  with the digivolution cost reduced by 2.
- **IR trace.** `WhenAttacking` + `isInherited` + `OncePerTurn`; effect-level condition (evaluated
  at `registration/module.ts:91`), then `Digivolve` `from: ["hand"]`, `reduceCost: 2`,
  `payCost: true`, `optional: true`, `into.nameOrTrait[{tokens:["Maquinamon"], match:"text"}]` —
  the Q5793 broad matcher, correctly applied to the destination only.
- **Defect corrected (before → after).**
  - Before: `condition: {kind: "hostHasLinkedWith", filter: {nameOrTrait: [[Maquinamon] name]}}`.
    `hostHasLinkedWith` is in no union and in no interpreter switch, so `evaluateCondition` fell
    through `default: return false` and **the entire clause was dead**. The module comment claimed
    it was "a new engine capability (see LANE_F.md)"; no such capability exists.
  - After: `condition: {kind: "selfLinkCountAtLeast", value: 1}` — a live kind
    (`conditions.ts:676`) reading `ctx.source.permanent()?.linked.length`, which for an inherited
    source is the **host** permanent's link list.
  - The link card's *identity* is still unchecked: no condition kind, no `Filter` predicate and no
    scaling helper reads link-card names (`countLinkCards` also only counts). That is seam request
    **S-2**. The approximation is over-broad only when a host carries a link card that is not
    [Maquinamon]; EX11-027 Maquinamon is the only card in the archetype with a ＜Link＞ requirement.
  - `coverage` stays `"full"` and `residual` stays `[]` because every clause now executes and the
    frozen `EX11.audit.test.ts` asserts both for all 74 cards; the over-breadth is recorded in the
    module comment and here instead.
- **Test defect corrected.** The suite's "positive" case was **vacuous**: it asserted
  `stack == ["EX11-006"]` and `memory == 10`, both of which are satisfied when *nothing happens*,
  and `settle()` returns silently when its predicate never becomes true. So the dead clause left
  the suite green. It now asserts the new top card is the Turbomon instance and the stack grew to
  `["EX11-006", "EX11-027"]`. The "linked card that merely mentions Maquinamon" case was flipped to
  pin the current over-broad behaviour, with a comment naming S-2 and the assertions to restore.
- **Mutation check.** Delete the condition entirely → the "does not trigger without a linked
  Maquinamon" case fails. Set `value: 2` → the positive case fails. Change `match: "text"` to
  `"name"` → the Turbomon positive fails (Turbomon is not named Maquinamon). Change `reduceCost`
  → the `memory === 10` assertion fails. Drop `frequency` → the once-per-turn case fails.
- **Open ambiguity.** None in the text; the gap is engine capability, not rules reading.
