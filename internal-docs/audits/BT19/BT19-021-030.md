## Scope and authority

This report covers exactly BT19-021 through BT19-030 in strict ascending card-ID order. The catalog source was the immutable catalog blob `efbecc002fb9000789123e2f91f201466e1e5b0a`; the local rules knowledge base was queried card by card, and each audit inspected the direct TypeScript module, read-only generated IR, shared interpreter/runtime, peer cards, legal stacks, and behavior-driving test source.

The direct card modules are the executable source of truth. All ten have full compiled coverage with empty residual coverage and register executable behavior exclusively through `registerIrCard(cardId, compiled)`. No audited card has a second `registerCard` registration. The generated `packages/shared/src/effects/effects.json` snapshot and `BT19-STATIC-AUDIT.md` were not modified.

This is a static/source-proof audit. The execution-gate component is fixed at `0/2` because this dispatch explicitly prohibited all test, typecheck, lint, formatter, browser/UI, focused/mechanism/collection gate, and `git diff --check` commands. Manual timing/event-bus calls are counted only as supplemental evidence; the behavioral score is reduced where no natural originating event is present in the existing source proof. This report makes no collection-completion claim and does not mark the Orca worktree completed.

## Fixed scoring model

Each card receives exactly five two-point dimensions:

1. Catalog/rules — catalog fidelity and applicable KB rulings.
2. IR trace — direct compiled trigger/action/requirement trace and exclusive registration, with the generated snapshot recorded as read-only comparison evidence.
3. Behavioral proof — observable state changes from behavior-driving tests; structural assertions and injected events alone do not earn 2/2.
4. Peer and stack proof — useful peer/runtime comparison and legal stack/target coverage.
5. Executed delivery gates — fixed at `0/2` by the task boundary.
