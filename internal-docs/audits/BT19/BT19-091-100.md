## Registration, generated IR, and runtime trace

All ten direct modules use exactly one exclusive
`registerIrCard("BT19-NNN", compiled)` registration and no legacy
`registerCard` registration. Every direct module reports `coverage: "full"`
and `residual: []`. The protected generated file
`packages/shared/src/effects/effects.json` and `BT19-STATIC-AUDIT.md` were not
modified.

The generated snapshot was read-only evidence, not an edit target. Its
material divergences from the direct executable modules are:

- BT19-091 (`effects.json:55600`) combines the three token plays, does not
  carry the executable attack after the double Alliance grant, and retains a
  weaker generated representation of the no-same-name token rule. The direct
  module keeps three independently gated `PlayToken` actions, then targets one
  non-token level-5 Digimon for Alliance twice and the mandatory attack.
- BT19-092 (`effects.json:55662`) orders the level-4 return before the
  upgraded return and uses the wrong cost-decline behavior. The direct module
  attempts the optional level-6 return by returning a blue Digimon to the
  bottom, binds success, and only then falls back to level 4.
- BT19-093 (`effects.json:55705`) has an incomplete trash-trigger/main
  restriction trace. The direct module carries the same-target -3000 DP and
  `cannotActivateWhenDigivolving` restriction through the opponent's turn,
  plus battle-area placement and Security return.
- BT19-094 (`effects.json:55759`) separates the trash return from the
  opponent's optional security-trash decision and does not preserve every
  effect-result boundary. The direct module binds the opponent-trash result,
  recovers only when the opponent declines, tracks actual Main deletions, and
  plays Lucemon from trash on Security.
- BT19-095 (`effects.json:55842`) lacks the executable Piercing grant and
  carries an insufficient trash-trigger representation. The direct module
  grants Piercing and +4000 DP to the same target for the appropriate duration
  in both Main and trash-trigger paths.
- BT19-096 (`effects.json:55894`) has a broad generated Royal Base source and
  does not encode the face-up-only security budget as the direct
  `DeleteBudget` scaling. The direct module selects a face-up Royal Base
  Digimon card from trash, adds 2 to the deletion budget per face-up security
  card, and keeps the Security/Main activation seam.
- BT19-097 (`effects.json:55929`) does not carry the exact deck-trash watcher
  and Delay lifecycle as executable actions. The direct module uses the
  `whenTrashedFromDeck` watcher, Main mill placement, intrinsic Delay, and
  Security placement.
- BT19-098 (`effects.json:55972`) omits key Device placement and effect-trash
  targeting details. The direct module uses the effect-only trash watcher,
  cost-3 Device filtering, self placement, and Security hand return.
- BT19-099 (`effects.json:56030`) models the Composite cost reduction and
  Millenniummon leave replacement too generically. The direct module uses
  `PlayFromZone` with cost reduction 4 and a Delay-gated, single-choice
  `whenDigimonWouldLeave` watcher whose Wicked God cost is relative to the
  leaving Digimon.
- BT19-100 (`effects.json:56101`) leaves the all-D-Reaper gate raw, omits the
  Mother D-Reaper play-cost ceiling, and uses broad name matching. The direct
  correction adds the non-vacuous Digimon/Tamer domain, exact Mother D-Reaper
  references, and a target-level `playCostLte` plus
  `playCostLteScaling` ceiling. The generated snapshot remains protected and
  stale by design.

Runtime seams inspected included `SubTrigger` event aliases and source gates,
effect-only trash versus deck-trash events, Delay arming and consumption,
same-target resolution, Security manipulation and face-up placement,
DeleteUntilCount result tracking, DeleteBudget scaling, `ModifyDP` durations,
`PlayFromZone` relative-to-leaving cost matching, and loose hand candidate
resolution.

BT19-100 required two direct/runtime corrections. The
`allYoursMatchFilter` evaluator now treats a filter with
`kind: ["Digimon", "Tamer"]` as the quantified domain, requires at least one
such battle-area permanent, and ignores unrelated battle-area Options. This
implements KB Q3176-Q3178: the condition is not true with no Digimon/Tamer in
the battle area, and a non-D-Reaper Digimon/Tamer blocks it. The evaluator
still leaves its legacy no-filter branch unchanged.

The Security effect does not use `triggerPlayCostAtMostStackCount`: a hand
candidate has no `ctx.trigger.playedPlayCost` before the player chooses it, so
that condition cannot gate the pre-choice pool. Instead, the direct target
filter carries `playCostLte: 0` and `playCostLteScaling` over exact Mother
D-Reaper permanents. The loose-candidate seam materializes that cap before
selection, so only D-Reaper trait cards whose printed play cost is at most the
number of digivolution cards are offered, and the action still plays exactly
one card rather than multiplying its count.

The repository's `matchNameOrTrait` implementation distinguishes broad
`match: "name"` substring matching from `match: "nameExact"` normalized-name
equality. The direct BT19-100 attack scale and Security ceiling both use
`nameExact` for bracketed `[Mother D-Reaper]`; this agrees with the existing
P-158 `Mother D-Reaper` peer and prevents a differently suffixed name from
being treated as the named card.

For the printed “1 of your [Mother D-Reaper]'s digivolution cards” bound,
`scaleFactor`'s `digivolutionCardsOfFiltered` path enumerates the matching
live permanents and takes the largest `Permanent.stack.length`. The schema
defines `Permanent.stack` as the digivolution cards below the live top card,
so `stack.length` is the printed digivolution-card count (not a top-card-plus-
stack count). Taking the largest is the runtime's deterministic resolution of
choosing one matching Mother D-Reaper; the target-level ceiling then applies
that selected maximum to all eligible hand candidates. The old pre-choice
condition and action-level scaling were removed because they either saw no
played-card cost or multiplied “play 1” into multiple plays.
