## Registration, generated IR, and runtime trace

All ten direct modules use exactly one exclusive
`registerIrCard("BT19-NNN", compiled)` registration and no `registerCard`
registration. Every direct module reports `coverage: "full"` and
`residual: []`. The protected generated files
`packages/shared/src/effects/effects.json` and `BT19-STATIC-AUDIT.md` were not
modified.

The generated snapshot is not uniformly identical to the direct executable
modules. This is recorded as read-only evidence rather than changed because
the dispatch prohibited editing it:

- BT19-041's snapshot uses a broad mine-controller cost filter and an
  `ifThisEffectActed` keyword condition; the direct module expresses the
  exact top-security cost and abort-on-decline sequence.
- BT19-042's snapshot omits the stack condition on the follow-up DP action;
  the direct module now carries that condition on both trigger copies.
- BT19-043's snapshot is `coverage: "partial"`, has a raw fallback for the
  recovery/delete branch, and models both-security trash as a single generic
  trash; the direct module is full and uses the atomic
  `trashBothSecurityTop`, `Recover`, and conditional `Delete` actions.
- BT19-044's snapshot uses substring `match: "name"`; the direct module now
  uses exact-name matching.
- BT19-046's snapshot uses a legacy `trait: ["Data"]` shorthand; the direct
  module uses the equivalent typed trait matcher.
- BT19-047's snapshot leaves Save as a keyword marker and omits the explicit
  `PlaceUnder`; the direct module carries the executable placement.
- BT19-048's snapshot lacks the effect-only leave boundary, `affectsAll`, and
  face-up-bottom placement shape; the direct module carries those semantics.
- BT19-049's snapshot uses substring Henry Wong matching; the direct module
  uses exact-name matching.
- BT19-050's snapshot omits the unsuspended filter on the first target; the
  direct module includes it.

The shared runtime paths inspected included action condition gating,
abort-on-decline sequencing, exact versus substring name matching,
`trashBothSecurityTop`, security placement, replacement `leaveReason`,
`affectsAll`, static security effects, inherited timing, Save placement,
digivolution requirements, and natural public intents. In particular,
`runAction` returns without aborting when a per-action condition is false;
this is why BT19-042 needs the stack condition repeated on its later
`ModifyDP` action.
