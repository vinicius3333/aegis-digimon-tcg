## BT19-101 — ZeedMillenniummon

The catalog effect has three trigger points—On Play, When Digivolving, and
When Attacking—with the same “By returning” sequence. Each direct Return
action now targets one opponent Digimon in the battle area, while its optional
cost returns one opponent Digimon from trash to the top of that opponent’s
deck. Under comprehensive rules 15-7-1 and 15-7-2, the processing condition is
represented as `optional: true` with `abortOnDecline: true`, so a decline or an
unavailable cost prevents the dependent bottom-deck return.

The all-turn no-stack restriction and opponent-effect immunity are guarded by
the live `selfHasNoDigivolutionCards` condition. The source tests exercise the
accepted optional On Play, When Digivolving, and When Attacking returns through
public intents, plus natural optional-decline and no-return-target boundaries.
The no-stack immunity case uses a natural opponent play and observes both the
suspension restriction and the immunity seam. The source-proof names were
cleaned to say “accepted optional ... return”; source prose consistently
describes the processing as optional.

The alternate evolution route is `[MoonMillenniummon]`, so both the direct IR
and shared override use `namesExact: ["MoonMillenniummon"]`. A paired near-name
structural rejection prevents `MoonMillenniummon (Variant)` from satisfying
that route. The existing Overclock marker and its rules/engine seams were
reviewed; natural return and immunity coverage is strong, but the central
natural full-turn Overclock loop remains unproven because the existing
comprehensive source records that harness as hanging. This limits Behavioral
proof to 1/2 and the card to 7/10 provisional.

## BT19-102 — Luminamon (Nene Version)

The two On Play/When Digivolving Delete actions now model their
“By playing ...” costs as optional (`optional: true`, `abortOnDecline: true`).
The `playFromDigivolutionCards` cost selects the host and records it in
`lastResolvedPermanentIds`; `sameTarget: true` then deletes that same chosen
host after the source card is played. This preserves the intended cost-then-
dependent-action relationship under comprehensive rules 15-7-1 and 15-7-2.

The natural source proof explicitly sets `autoAcceptOptional: true` for the
On Play positive, and it retains a natural decline/no-payment boundary that
checks the optional decision, zero additional memory payment, and an intact
host stack. A second natural boundary covers an accepted condition with no
eligible source card and verifies that deletion does not proceed. The natural
On Deletion battle path proves the cost-5-or-less under-Tamer play. Existing
natural DigiXros and alternate-evolution positives remain, while near-name
negative cases reject lookalike Luminamon and Nene references.

The bracketed alternate-evolution references `[Luminamon]` and `[Nene Amano]`
use `namesExact` in direct IR, shared overrides, and shared-requirement
expectations. The `[Shademon]` stack requirement remains
`minNameStackNames`, whose repository matcher is exact by schema. DigiXros
plain material `names` are also exact slot names in the runtime material
matcher; substring behavior is available only through an explicit
`nameOrTrait` slot, so no unsupported `namesExact` field was added to those
slots. The source has near-name natural negatives for both alternate routes
and both DigiXros slots; the immutable catalog has no distinct near-name
Shademon variant to add as a further natural case. The natural exact
`[Luminamon]` positive now uses catalog BT19-076 as the base, so BT19-102 keeps
full Behavioral proof and 8/10 provisional.
