## Rules and shared mechanism evidence

The applicable rules in `data/kb/rules/comprehensive.md` are:

- §3-4-7 (`:540-580`) excludes breeding-area cards from effect influence,
  effect triggering/activation, target selection, trigger conditions, and
  information references unless an effect explicitly specifies breeding.
  This is decisive for the explicit battle-area filters in BT10-019 and
  BT10-020 and the new BT10-020 breeding boundary proofs.
- §7-2 (`:1202-1325`) defines DigiXros as placing specified cards from hand or
  battle area, reducing play cost per placed card, allowing at most one of
  each specified card up to the requirement count, and making DigiXros
  optional. This supports the exact two-material BT10-012/015 requirements
  and all five distinct BT10-013 slots.
- §15-3 through §15-8 cover inherited effect source identity, once-per-turn
  activation identity, optional processing, target counts, and durations.
  They support BT10-011's single activation for simultaneous Tamer
  suspension, BT10-016's one-time condition the integration branch and until-opponent-end
  lifetime, and the source-bound inherited effects.
- §16-16 (`:2965-2981`) defines Blitz's opponent-memory-at-least-one gate and
  its optional attack declaration; §16-19 defines Armor Purge; §16-20 defines
  optional Save; and §16-21 (`:3021-3050`) defines Material Save's specified
  source count, all-when-possible behavior, player-selected order, and bottom
  placement under a Tamer.

The relevant runtime seams were traced as follows:

- `apps/api/src/engine/effects/interpreter/effect.ts` maps `YourTurn` and
  `AllTurns` into the continuous/static timing window, while
  `builders.ts`'s `staticModifier` installs continuous modifiers and
  sub-triggers. This is why BT10-011's outer Your Turn record correctly arms a
  `whenSuspended` watcher; the stale comment claiming that trigger was
  unreachable was removed from `BT10-011.test.ts`.
- `actions/subTrigger.ts:785-803,1037-1056` binds event subjects, applies
  owner-turn and once-per-turn gates, and narrows a simultaneous subject set
  through the source filter. `primitives.ts:973-992` publishes one
  `whenPlayed` event for an effect that plays multiple Digimon, with both a
  first `subjectPermanentId` and the complete `subjectPermanentIds` array.
- `targeting/permanents.ts:356-403` resolves `sourceRef: "triggerSubject"`.
  For multiple event subjects, `count: 1` selects one; `count: "all"` returns
  all matching subjects. BT10-016 therefore now uses `count: "all"` for both
  later-play actions, matching the printed “all of your Digimon” clause and
  multi-play event provenance.
- `targeting/loose.ts` distinguishes hand, digivolution-card, and under-Tamer
  candidates. The host filter on BT10-012 restricts its mixed source list to a
  friendly Tamer, while BT10-015's `underTamers` source is already correctly
  scoped.
- `combat/keywords.ts` matches DigiXros material requirements exactly, while
  Material Save uses those requirements rather than treating a DigiXros host
  as its own named material. This supports the four BT10-013 KB negatives and
  the exact Shoutmon/Beelzemon source boundaries.
- `modal.ts` filters BT10-019's recovery option by both friendly Kiriha and a
  MetalGreymon in trash; `actions/reveal.ts` adds as many eligible cards as
  available and bottoms the remainder, supporting Q1946/Q1947.
- `scaling.ts:22-95,200-210` explicitly scans battle area when
  `filter.zone` is `battleArea` and otherwise includes breeding. The two
  BT10-020 filters now carry `zone: "battleArea"`, so both the On Play draw
  multiplier and inherited DP threshold follow the printed “in play” clause
  without counting an opposing breeding-area Digimon.
