## Rules and shared mechanism evidence

The applicable sections in `data/kb/rules/comprehensive.md` are:

- §3-4-7 and the battle-area rules define where cards are in play and keep
  breeding-area cards out of ordinary “in play” effect conditions. The range
  uses explicit battle-area filters for the Xros Heart condition on BT10-034;
  security-zone conditions on BT10-031 and BT10-040 are explicit as well.
- §4-1-3 defines an opponent-memory-at-least-one condition for Blitz, and
  §4-3-7 defines Blocker. The static Blocker on BT10-031 is therefore a
  live opponent-turn keyword window.
- §7-2 defines DigiXros material selection, cost reduction, optional
  declaration, source placement, and distinct named requirements. It is
  relevant to the adjacent Xros Heart peer checks and the legal BT10-034
  evolution/source stack.
- §15-6 through §15-10 define processing conditions, separate conditional
  clauses, optional versus mandatory processing, target cardinality, and
  effect duration. In particular, they support the independent Achillesmon
  branches at exactly 3 security, Kyubimon's mandatory trash after choosing
  its second modal option, and one-target restrictions on the yellow
  Security Attack -1 effects.
- §16-4 defines Security Attack modification, §16-5 defines Blocker, §16-6
  defines Recovery from the specified area, §16-8 defines mandatory Draw,
  §16-19 defines Armor Purge, and §16-20 defines optional Save.

The relevant runtime seams were traced as follows:

- `apps/api/src/engine/effects/interpreter/effect.ts` maps turn triggers to
  static/trigger timing, and the builder's static modifier path installs
  continuous Aura effects and sub-triggers. `registration/module.ts`
  normalizes the direct `CompiledCard`, stores it in the executable registry,
  and makes `registerIrCard` the runtime registration seam.
- `apps/api/src/engine/effects/interpreter/actions/statics.ts` re-evaluates
  Aura `while` conditions live and applies keyword, DP, and Security DP
  modifiers. This supports BT10-031's changing security count and BT10-034's
  global Security Digimon DP effect.
- `apps/api/src/engine/effects/interpreter/conditions.ts` implements
  `zoneCount`, `securityAtLeast`, and `triggerOptionCostAtLeast`. The latter
  reads the card-use cost carried by `ctx.trigger.usedOptionCost`, preserving
  the KB distinction between card-level cost changes, payment-only changes,
  and effect-driven free use.
- `apps/api/src/engine/effects/interpreter/scaling.ts` and target resolution
  enforce explicit zones, controller/seat, kind, count, name, and trait
  filters. Thus one opposing Digimon is selected for BT10-034/035/038/040,
  while BT10-034's inherited Security DP Aura applies to all opposing
  Security Digimon as an overall seat-scoped modifier.
- `actions/reveal.ts` reveals the requested four cards, resolves each add
  bucket from that revealed set, and places the remainder at the bottom in
  player order. This covers BT10-032's two different add requirements and
  remainder behavior.
- `actions/borrowed.ts` enumerates UseOptionWithoutCost candidates from the
  hand, skips payment and color requirements when requested, and publishes
  the original used Option cost through `primitives.ts` to the
  `whenOptionUsed` sub-trigger. This supports both BT10-032 and BT10-039.
- `actions/security.ts` applies Security DP ledger entries with their
  duration and implements deck-top Recovery through the security stack. This
  supports BT10-034 and BT10-040 without treating a security condition as a
  battle-area condition.
