## Method and shared evidence

- Catalog authority: `packages/shared/src/cards/data/cards.json`, using the
  exact printed metadata and effect text for BT10-101 through BT10-110.
- Rules authority: `node tools/kb/query.mjs card <CARD-ID>` plus the relevant
  local comprehensive rules and glossary entries. BT10-101 returned the name
  errata and Q2035–Q2036 (exactly three security cards satisfy both branches;
  cards revealed during a security check do not count in the stack). BT10-103
  returned Q2037 (the bottom-deck target may differ from the Digimon just
  suspended). BT10-107 returned its 2022 errata (the Security target is
  `[Yuu Amano]`, not any black Tamer). BT10-108 returned Q2038 (the return-to-
  hand trigger requires direct trashing from the deck, not revealing or
  searching). BT10-110 returned Q2039 (Venusmon can suppress the borrowed
  Jesmon GX effect, while Seiken Meppa still unsuspends it). BT10-102,
  BT10-104–BT10-106, and BT10-109 have no card-specific KB entries.
- Direct authority: every module in `apps/api/src/cards/BT10/BT10-101.ts`
  through `BT10-110.ts` registers executable behavior exclusively through
  `registerIrCard`; no duplicate `registerCard` registration remains. Each
  direct record has `coverage: "full"` and `residual: []`.
- Shared mechanics traced: color waivers; exact top-card versus
  digivolution-stack matching; security-count conditions and security
  manipulation; cost-reduction replacement scaling; suspend/return ordering;
  trash/reveal zone movement; DigiXros recipe matching and material movement;
  optional play and bound result identity; Blocker/Reboot and deletion
  restrictions with opponent-turn duration; exact trait/name matching;
  direct deck-trash subtriggers; security play/add-to-hand; and borrowed
  When Digivolving activation with bound selections and disabled timing.
- The direct registration path in `packages/shared/src/effects/data.ts` and
  `apps/api/src/engine/effects/interpreter/registration/module.ts` normalizes
  direct compiled records into the runtime module. The shared matching,
  conditions, replacement, play, security, subtrigger, binding, and borrowed-
  effect interpreters were inspected without executing them. The local rules
  covering color requirements, security checks, “X or more” counts, bottom
  decking, DigiXros, Blocker, Reboot, and effect suppression were consulted
  where applicable.
- A concrete reusable gap was found in the `PlayFromZone` DigiXros-material
  prompt: unlike normal hand-play DigiXros, it offered every card from the
  requested loose zone and only validated the selected set after prompting.
  The shared seam now filters candidates through the selected recipe and uses
  the recipe’s material cap before prompting, preventing invalid trash cards
  from being consumed by an automatic selection and silently turning the play
  into a non-DigiXros play. BT10-104’s positive test now includes an invalid
  trash card to prove it remains in trash while both legal materials are used.

### BT10-101 — LxF3nkhē Adistakto — provisional 8/10

- Catalog contract: 2/2. Yellow Option, cost 8, the Pulsemon color waiver, the
  three-security `-12000 DP` branch, the three-or-fewer security face-down
  top-placement branch, and `[Security] Activate Main` match `cards.json`.
- Direct IR: 2/2. The static waiver has two distinct branches: a Digimon whose
  top name contains `[Pulsemon]`, or a Digimon whose underlying stack contains
  the exact `[Pulsemon]` name. Main uses `securityAtLeast 3` for the DP branch
  and `zoneCount security lte 3` for the placement branch; Security activates
  Main. The stack branch was corrected from a global `digivolutionCards` zone
  scan to `battleArea` Digimon plus `digivolutionStackNameOrTrait`.
- Shared mechanism and rules: 2/2. `youHave` delegates to the normal permanent
  matcher, so a loose `digivolutionCards` filter would inspect all stacks and
  non-Digimon hosts; the stack predicate instead inspects cards under each
  battle-area Digimon. Q2035 confirms that exactly three security cards satisfy
  both Main branches, and Q2036 confirms that security-check reveals are not
  counted as security cards during the Security timing.
- Proof/peers/stacks: 2/2. The colocated test covers exactly three cards,
  four-card DP-only, two-card placement-only, Pulsemon under a Digimon, and a
  negative Pulsemon-under-Tamer case. BT9 stack-card peers use the same
  `digivolutionStackNameOrTrait` seam; the mixed host case proves that the
  direct condition does not treat a Tamer stack as a Digimon source.
- Execution gates: 0/2. Focused behavior and mechanism/collection commands were
  intentionally deferred.
- Correction: `apps/api/src/cards/BT10/BT10-101.ts` and its colocated test now
  use and prove host-constrained stack matching.
