# BT11-011–020 Card Audit

## Scope and audit posture

This report covers BT11-011 through BT11-020 in strict ascending order. The
printed contract was read from `packages/shared/src/cards/data/cards.json`, the
local rules and Q&A knowledge base was queried with
`node tools/kb/query.mjs card <CARD-ID>`, the direct TypeScript card module was
traced through `registerIrCard(cardId, compiled)`, and the committed generated
record in `packages/shared/src/effects/effects.json` was inspected as
read-only evidence.

The existing `BT11-AUDIT.md` and `BT11-STATIC-AUDIT.md` were preserved. No
generated effects record was edited. The colocated tests were read as
behavioral proof, including their evolution/DigiXros stacks, target boundaries,
negative paths, optional decisions, and once-per-turn cases, but this dispatch
explicitly forbade running tests, typecheck, lint, format, browser/UI checks,
and `git diff --check`. Consequently the execution gate is intentionally 0/2
for every card and every otherwise complete card remains provisional at 8/10.

All ten card modules register executable behavior exactly once through
`registerIrCard`; no second `registerCard` registration is present. The only
implementation correction made during this audit is the BT11-018 universal
name-alias representation, delivered atomically with its regression proof in
commit `5a3405662`.

#### Contract and KB

combat redirect seam, inherited-source deletion collection, optional decision

### BT11-018 — Shoutmon DX — 8/10 provisional

#### Contract and KB

The catalog defines a red/blue level-6 Digimon costing 13 with 12000 DP,
red-level-5 evolution for 4 or blue-level-6 evolution for 3, Mega/Data/
Composite/Xros Heart/Blue Flare metadata, and DigiXros -3 with distinct

Digimon from attacking until the end of its turn; and End of Attack, optionally

The KB query returned Q2063 and Q3062. Q2063 makes both aliases unconditional

#### Implementation and snapshot comparison

The generated snapshot has the corrected two-slot DigiXros -3 recipe and all
ordinary action clauses, but it has no executable name-grant record for Q2063.
Before this audit, the direct module represented the unconditional aliases in
a `Static` effect. The shared interpreter's
`universalNameAliasesFor` registry intentionally consumes every-zone aliases
from `Rule` effects; `Static` aliases are field-resident and therefore did not
reliably make a loose BT11-018 in hand satisfy a later DigiXros slot.

The correction in commit `5a3405662` changes only that direct effect trigger
from `Static` to `Rule`, preserving the live name grant while making the
aliases available to the universal loose-card DigiXros path. It also adds a
focused regression to `BT11-018.test.ts`: BT11-018 in hand is used as an
OmniShoutmon alias material for a BT11-019 DigiXros alongside ZeigGreymon,
with the reduced cost and retained sources asserted. The direct module still
has full coverage, empty residual, and only `registerIrCard`. The generated
snapshot remains unchanged as required.

#### Seam, peer, and stack proof

This card crosses the Rule/static-name alias registry, DigiXros distinct-slot
matching, Material Save, live-DP deletion, duration-scoped attack restriction,
and optional End of Attack cost handling. BT11-015 is the relevant contrast:
its Shoutmon alias is explicitly DigiXros-only and must not leak into ordinary
name checks, whereas BT11-018's aliases are universal. BT11-019 provides the
six-slot consumer used by the new loose-material regression.

`apps/api/src/cards/BT11/BT11-018.test.ts` checks catalog/IR and the exact
two-slot -3 recipe, the new loose-hand alias path, full DigiXros cost/source
transition, both live aliases and Material Save 2, the inclusive 8000-DP
