## Shared interpreter, mechanism, and snapshot evidence

The direct module is the executable authority once imported through the
`registerIrCard` registry. The generated snapshot remains a comparison
artifact only and was not edited.

The shared seams relevant to this range were traced as follows:

- `candidateLooseInstances` and the loose-cost path distinguish a source's
  own digivolution stack from all stack cards. A `hostFilter: { isSelfRef:
  true }` is required when the cost is worded as “this Digimon's
  digivolution cards”; this drove the BT11-081 correction.
- `resolvePermanentTargets` handles `sourceRef: "triggerSubject"` for
  SubTrigger bodies. `GainTriggeredEffect` resolves its granted effect target
  at installation, so BT11-087 must bind the granted effect to the Digimon
  that moved from breeding rather than scan the opponent's board.
- `definitionMatches` supports `excludeNameOrTrait`; the exclusion is applied
  after the positive trait union. BT11-089 now carries the explicit
  other-than-`Sea Animal` gate from Q2115.
- `playLevelThree` in BT11-085 uses one shared level-3 filter for both blue and
  purple cards and a host filter for both colors, while the source is restricted
  to the host's digivolution cards. The added reverse-direction stack fixture
  proves the two-color union structurally.
- `runPlaceUnder`'s `targetIsPermanent` branch delegates target legality and
  effect immunity to `resolvePermanentTargets`, then relocates the selected
  permanent with its stack. This is the shared implementation used by
  BT11-088's opponent-Digimon placement; Q5207 does not require a card-local
  immunity branch.
- `SubTrigger`'s `byEffect`, once-per-turn, controller, and source-filter gates
  provide the event provenance for BT11-084, BT11-085, BT11-087, BT11-089, and
  BT11-090. No card-local duplicate trigger machinery was needed.

Snapshot comparison, kept read-only, found these differences:

- BT11-081's generated cost record has only `zone: "digivolutionCards"` and
  omits the source-host binding. The direct record is corrected with
  `hostFilter: { isSelfRef: true }`; the stale snapshot was intentionally left
  unchanged.
- BT11-082, BT11-083, BT11-084, BT11-085, and BT11-086 match their direct
  executable clauses and full/empty residual status.
- BT11-087's snapshot retains older On Play aliases (`location`, `trait`, and
  `cardType`) and an inherited Opponent-Turn `RawUnparsed` residual, while the
  direct record has normalized filters and a fully executable inherited
  `GainTriggeredEffect`; the snapshot was not regenerated.
- BT11-088's snapshot uses the older On Play `Trash` + `SelectBind` +
  `PlaceUnder` shape, while the direct module uses the current
  `targetIsPermanent` relocation shape. Its When Digivolving and All Turns
  records are otherwise equivalent for the audited clauses.
- BT11-089's snapshot predates the direct module's explicit
  `excludeNameOrTrait: Sea Animal` correction. It remains unchanged as
  required.
- BT11-090 matches the direct record for its Start Main, event watcher, and
  Security clauses.
