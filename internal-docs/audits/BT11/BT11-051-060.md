## Shared interpreter and generated-snapshot evidence

registerIrCard places the direct compiled record in the runtime registry, where
it is the executable authority when the card module is imported. The generated
effects.json record is a comparison artifact only and was kept unchanged.

The snapshot comparison found these material differences:

- BT11-051, BT11-052, BT11-053, BT11-056, and BT11-060 match the direct records
  for their executable clauses and full/empty residual status.
- BT11-054's snapshot still marks the alias as a Static effect. The direct
  module now uses Rule: universalNameAliasesFor intentionally scans
  self-targeted name grants on Rule effects when resolving loose-card name
  references. Both effects still use the same GrantStatic name token Leomon for
  live static-name observation.
- BT11-055's snapshot omits the direct inherited watcher
  sourceFilter: { isSelfRef: true }. The direct correction is required so only
  the inherited host's own battle deletion trashes Security.
- BT11-057's snapshot stores the Suspend branch condition as raw
  { kind: "raw", raw: "you do" }; the direct module now uses the executable
  { kind: "ifThisEffectActed", raw: "you do" } predicate. The subsequent
  GainMemory action remains intentionally unconditional and counts all currently
  suspended opposing Digimon.
- BT11-058's snapshot still matches X Antibody as a name. The direct correction
  matches it as a trait, as required by the catalog's types
  ["Insectoid", "X Antibody"] record and the printed stack clause.
- BT11-059's snapshot uses a name RustTyrannomon family filter. The direct
  correction uses an exact cardId: "BT11-059" predicate because the catalog also
  has BT2-051, P-113, and P-173 with the same display name but different card
  behavior.

The shared seams traced for this range were:

- compiledCards.ts's universalNameAliasesFor Rule-only alias scan and the
  GrantStatic static-name builder, which drove BT11-054's Rule correction.
- subTrigger.ts's whenDeletesInBattle self gate, which is installed only when
  sourceFilter.isSelfRef is true and compares the event attacker to the
  anchored permanent, which drove BT11-055's correction.
- trigger.ts's byEffect provenance filter, confirming BT11-054's inherited
  watcher excludes ordinary hand plays; the direct module already carried the
  correct byEffect: true and excludeSelf: true fields.
- conditions.ts and action sequencing for ifThisEffectActed; this is the
  executable form of BT11-057's “If you do” clause and reads the preceding
  optional Trash result.
- reveal.ts's totalPlayCostBudget subset selection and scaling count. A
  dual-color Tamer is one permanent/card candidate, not two, and a legal subset
  may intentionally total less than ten, matching Q2089/Q2090.
- permanent.ts and conditions.ts selfHasInDigivolutionCards, which delegates
  name/trait references to the shared definition matcher and now handles
  BT11-058's X Antibody trait branch correctly.
- definition.ts's exact cardId definition predicate, added for BT11-059's
  “into this card” gate. This also makes existing exact-card IR such as BT8-112's
  into: { cardId: "BT8-112" } executable at the common matcher seam.
- restrictions.ts's beReturned mapping and byOpponentEffectsOnly gate, which
  cover both hand and deck returns for BT11-060.
