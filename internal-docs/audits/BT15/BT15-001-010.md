# BT15 static card-by-card audit: BT15-001 through BT15-010

## Audit frame

This report audits exactly BT15-001 through BT15-010 in strict ascending card-ID
order. The immutable catalog source is Git blob
`efbecc002fb9000789123e2f91f201466e1e5b0a`; the protected
`BT15-STATIC-AUDIT.md` and `packages/shared/src/effects/effects.json` were read
but not changed. Every card received a separate local KB query, followed by a
direct TypeScript module, shared IR/runtime seam, behavior-source, peer, and
evolution/stack review.

The current queue snapshot is preserved as requested: BT15-001-010,
BT15-011-020, and BT15-021-030 are Luna-assigned/active; BT15-031-102 are
unassigned; no BT15 range is integrated. This report does not claim
collection completion and the Orca worktree was not marked completed.

## Scoring and execution boundary

Each card receives five exact two-point components: Catalog/rules, IR trace,
Behavioral proof, Peer/stack proof, and Executed gates. The gates component is
fixed at 0/2: focused tests, mechanism tests, collection tests, typecheck, lint,
formatters, browser checks, collection/mechanism gates, and `git diff --check`
were prohibited and unexecuted for this campaign. No gate is listed as pending
worker work; all source assertions below are unexecuted evidence only, so the
maximum result is 8/10.

Structural assertions and direct production testkit seams are identified
explicitly. Where a natural public play, evolution, attack, deletion, turn, or
Security origin was feasible, source proof now uses it; a direct seam is retained
only for focused negative or boundary probes.

## Shared IR and runtime trace

- All ten direct modules are compiled IR with `coverage: "full"` and
  `residual: []`. Each has exactly one `registerIrCard(cardId, compiled)` and
  no `registerCard` duplicate.
- `registration/module.ts` and the effect wrapper apply inherited-stack,
  turn-scope, and once-per-turn limits. The `SubTrigger` event map in
  `apps/api/src/engine/effects/interpreter/actions/subTrigger.ts` routes the
  unsuspend, hand-add, attack, and Security-removal events used here.
- Canonical `permanentMatchesFilter` and `seatsForController` perform live
  controller, kind, color, DP, trait, zone, and stack matching. The corrected
  BT15-005 filter has `kind: ["Digimon"]` without a mine controller default,
  so either player's Digimon can satisfy the printed “a Digimon” clause.
- The `whenEffectAddsToHand` gate requires the host owner's hand to be changed
  by an own Digimon effect; the `triggerByYourDigimonEffect` condition preserves
  the effect-source distinction used by BT15-002.
- The Security-removal gate interprets `sourceFilter.controller: "opponent"`
  as the opponent's Security stack. Security extraction and effect-driven
  Security trash publish the affected seat through that shared event payload.
- The security-trash cost path detects BT15-003's raw “top or bottom” wording,
  prompts for the end, and calls `trashFromSecurity` with the selected end.
  The shared primitive defines index 0 as top and the default end as bottom.
- `RevealAdd`, `Return`, `Draw`, `GainMemory`, `Delete`, and `Attack` resolve
  through the production action/primitives path. Attack declarations publish
  player-target and Digimon-target facts; deletion publishes the full deleted
  permanent and stack context; durations clear at the shared turn boundary.
