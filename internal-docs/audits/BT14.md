## BT14-001 — Koromon — 10/10

### Printed contract and knowledge base

- Catalog record: red level 2 Digi-Egg, In-Training/Lesser, no evolution requirements, inherited effect `[Your Turn][Once Per Turn] When a card is removed from your opponent's security stack, ＜Draw 1＞.`
- `node tools/kb/query.mjs card BT14-001`: no card-specific Q&A, errata, restriction, or ruling. The comprehensive security-check timing is represented by the engine security pipeline, which publishes `whenSecurityRemoved` after the checked card leaves security.

### Direct IR and shared primitive trace

- `apps/api/src/cards/BT14/BT14-001.ts` contains one inherited `YourTurn` effect, frequency `OncePerTurn`, with a `whenSecurityRemoved` `SubTrigger`, `sourceFilter.controller: "opponent"`, and `Draw` 1 for `mine`. Coverage is `full`, residual is empty, and executable registration is exclusively `registerIrCard("BT14-001", compiled)`.
- `registration/module.ts` applies `withSubTriggerTurnScope` and `withSubTriggerFrequency`; these produce the `yourTurn` gate and an instance-scoped once-per-turn watcher key.
- `actions/subTrigger.ts` resolves `removedFromSecuritySeat` relative to the source owner. The explicit `opponent` direction rejects the controller's own security and accepts only the opposing stack.
- `security/securityCheck.ts` removes the revealed security instance and then publishes `whenSecurityRemoved` with the defending seat. `GameEngine.ts` preserves this as a pending trigger when removal occurs during another effect window.
- `actions/resources.ts` resolves `Draw` against the source owner's seat and moves the requested card through the engine draw primitive.

### Peer, trait, and evolution-stack reasoning

- BT13-003 is the inverse-direction peer: it watches the controller's own security removal. Its tests confirm the same watcher seam, direction discrimination, and inherited once-per-turn behavior; BT14-001 intentionally uses `opponent` instead of that peer's `mine` gate.
- Koromon's Lesser trait is not referenced by this effect, so mixed-trait targeting is not applicable. The relevant evolution peer is BT14-007 Agumon, whose catalog and IR permit red level 2 evolution for cost 0 and the alternate `[Koromon]` route.
- The focused proof legally evolves BT14-007 over BT14-001 in breeding, verifies Agumon as the top card and Koromon as its inherited source, moves the stack to battle through the public intent, and performs a real player attack. The security removal draws exactly one card from Koromon's inherited effect.

### Observable proof

- Positive/stack path: legal Koromon → BT14-007 evolution, breeding-to-battle transition, real opposing security removal, and one inherited draw.
- Boundaries: removing the controller's own security does not draw; the first opposing removal draws; a second opposing removal in the same turn does not draw again.
- Isolated command: `pnpm --filter @aegis/api exec vitest run src/cards/BT14/BT14-001.test.ts` — 1 file passed, 3 tests passed.

## BT14-002 — Bukamon — 10/10

### Printed contract and knowledge base

- Catalog record: blue level 2 Digi-Egg, In-Training/Lesser, inherited `[Your Turn]` Jamming condition based on opposing digivolution-card counts.
- The 2023-12-15 erratum replaces “more” with “as many or more.” The effective contract is therefore: this Digimon gains Jamming only while the opponent has no Digimon whose digivolution-card count is greater than or equal to this Digimon's.
- Q6004 confirms the condition is met when the opponent has no Digimon. The card is restricted to one copy from 2024-03-01; that deck-construction restriction does not alter runtime effect behavior.

### Direct IR and shared primitive trace

- `apps/api/src/cards/BT14/BT14-002.ts` is a hand-authored errata override with inherited `YourTurn` `GainKeyword(Jamming)`, a self target, and `opponentHasNone` over opposing Digimon whose `digivolutionCardsCompareToSource` is `gte`. Coverage is full, residual is empty, and registration is only `registerIrCard`.
- `conditions.ts` implements `opponentHasNone` by counting matching opposing permanents and requiring zero.
- `matching/permanent.ts` resolves the live source permanent's stack length and implements `gte` inclusively, so an equal opposing stack correctly suppresses Jamming.
- `actions/board.ts` resolves the self target and records Jamming in the continuous keyword ledger. `security/securityCheck.ts` consumes that keyword to prevent deletion after losing a Security Digimon battle.
- The `YourTurn` registration guard limits the continuous grant to Bukamon's controller's turn; inherited registration anchors the effect to the evolved host rather than the Digi-Egg as a standalone permanent.

### Peer, trait, and evolution-stack reasoning

- BT14-029 Plesiomon and BT14-091 Wave of Reliability use the same errata-sensitive “as many or more” comparison vocabulary. Their `opponentHasNone`/comparison encodings agree with Bukamon's inclusive boundary.
- The Lesser trait is not used as a filter. Mixed board proof instead covers the material boundary: no opposing Digimon, a fewer-source opposing Digimon, and an equal-source opposing Digimon.
- The legal stack proof evolves blue level 3 BT14-019 Otamamon over BT14-002 for cost 0, verifies Bukamon remains the inherited source, moves it from breeding to battle, and pits its 1000 DP host against 12000 DP BT14-101 in security. With the opponent's only battle-area Digimon having fewer sources, Jamming is live and the host survives the otherwise losing security battle.

### Observable proof

- Positive boundaries: no opposing Digimon satisfies Q6004; an opponent with fewer sources also permits Jamming.
- Negative errata boundary: an opposing Digimon with an equal source count suppresses Jamming, proving `gte` rather than the superseded strict-greater wording.
- Keyword consumption: the legally evolved low-DP host remains in battle after losing to a high-DP Security Digimon.
- Isolated command: `pnpm --filter @aegis/api exec vitest run src/cards/BT14/BT14-002.test.ts` — 1 file passed, 4 tests passed.
