## Card findings

### BT25-101 Divine Arms Version Ω

The catalog defines a Black, cost-3 TS Option. Its Main cost trashes one TS card from hand, then draws two and may link this card or one Link-capable TS card from trash to one own Digimon without paying the Link cost. Its security face activates the same Main. The linked Vulcanusmon effect grants Security Attack +1 and Reboot, and replaces that Vulcanusmon's departure by trashing one of its Link cards.

The direct IR at `apps/api/src/cards/BT25/BT25-101.ts:4-116` preserves the TS waiver, now restricted to an own battle-area `Digimon` or `Tamer`, plus the hand-TS payment with `optional: true`/`abortOnDecline: true`, Draw 2, and the optional zero-cost Link from trash. The Link target requires a Link-capable TS card, permits an own battle-area or breeding-area Digimon recipient, and does not pay the Link cost. The linked static grants are permanent while linked and the replacement is scoped to an own Vulcanusmon and exactly one linked card. Security is an `ActivateMain` entry at line 110. Runtime registration is exclusively `registerIrCard("BT25-101", compiled)` at line 116.

Source behavior evidence in `BT25-101.test.ts` covers the paid hand cost, refusal, Draw 2, Link-capable versus non-Linkable TS trash, breeding recipient, no-cost Link path, Security activation, linked keywords, tied-battle departure prevention, and the non-Vulcanusmon negative. The new natural negative proves a TS Option placed in the battle area does not satisfy the Use Req. kind boundary. The real attack/security test supplies the natural origin for the Security clause; the structural keyword and replacement assertions supplement it. The Link interpreter seam accepts the off-field Option source, `from: ["trash"]`, `payCost: false`, Link requirement, and breeding recipient.

Peers BT25-075, BT25-084, and adjacent TS/Link cards establish the same source-zone, recipient, and linked-replacement vocabulary. The realistic stack proof uses a Vulcanusmon host and checks both the linked keyword bundle and the leave-prevention payment. Peer review found one local semantic gap: the Use Req. filter previously matched any TS card in `battleArea`, so a TS Option placed there could incorrectly satisfy the requirement. The correction added `kind: ["Digimon", "Tamer"]` to the `battleArea` filter, and the accompanying natural negative proof rejects a TS Option as a color source. No shared/runtime correction was required.
