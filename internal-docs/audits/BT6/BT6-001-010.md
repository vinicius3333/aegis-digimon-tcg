Audit date: 2026-08-27
Scope: BT6-001 through BT6-010, exact ascending order
Audit mode: static-only, per dispatch
Executed gates: none (explicitly deferred)

## Result

All ten cards have complete direct IR (`coverage: "full"`, empty residuals) and register behavior through exactly one `registerIrCard(cardId, compiled)` call. Two direct behavior gaps were proven and corrected: BT6-003 now checks the owner’s security count for exactly three cards, and BT6-005 now restricts its reveal-to-hand candidate to black Digimon cards. Focused fixtures were also strengthened with legal evolution stacks and boundary negatives; no tests, typecheck, lint, formatting, browser/UI checks, or `git diff --check` were run as required.

The generated snapshot at `packages/shared/src/effects/effects.json` was not edited. Direct registered modules are treated as executable authority; stale snapshot records are documented below.

## Shared interpreter trace

The following shared paths were traced as part of every applicable card review:

- `apps/api/src/engine/effects/interpreter/registration/module.ts:44-95` builds the IR effect module, applies trigger timing, and carries `OncePerTurn` through `withSubTriggerFrequency` and turn scope through `withSubTriggerTurnScope` (`apps/api/src/engine/effects/interpreter/effect.ts:384-403`).
- `apps/api/src/engine/effects/interpreter/conditions.ts:53-69` distinguishes player attacks from attacks against the originally declared opponent Digimon, even after Blocker redirection. `:204-210` shows that `youHave` counts matching permanents, while `:262-265` reads the security stack; this is the reason BT6-003 required correction. `:438-464` confirms live top-card trait and exact-name boundaries.
- `apps/api/src/engine/effects/interpreter/actions/subTrigger.ts:582-595` enforces effect-controller ownership for `bySourceController`; `:690-713` enforces owner/self/name handling for hand-trash events; `:921-924` handles top-card digivolution-trash gates. `apps/api/src/engine/effects/primitives.ts:2184-2261` emits effect-caused digivolution-card trash events, while the bounce path does not emit the same event, supporting BT6-002/Q1399.
- `apps/api/src/engine/effects/interpreter/actions/reveal.ts:108-121`, `:202-220`, and `:277-309` reveal cards, match each definition, enforce bounded/optional selection, and return unselected cards. `:290-296` makes BT6-009’s `optional: true` a 0–2 choice. Matching is delegated to `apps/api/src/engine/effects/interpreter/matching/definition.ts:68-88`, including kind/color and name-or-trait unions.
- `apps/api/src/engine/effects/interpreter/actions/statics.ts` resolves self-targeted live Aura effects and keyword ledgers, so BT6-007 and BT6-010 reevaluate current top-card name/trait state rather than blindly reading an under-card.

Static behavior proof: `BT6-001.test.ts` covers a player attack, a Digimon attack negative, a different attacker negative, and Q1398 Blocker redirection. Fixtures now use the legal egg → red level 3 BT6-007 stack rather than placing the egg directly under a level 5 card. `conditions.ts:53-69` reads the declared target before redirection, matching comprehensive rules 11-2-7-6 and Q1398.

Peer/legal-stack proof: BT2-012 uses the same player-target condition; BT3-004 covers the opposite opponent-Digimon boundary. The corrected focused stack is legal under the catalog’s red level-2-to-level-3 evolution route.

Snapshot: `effects.json` retains an older extra `SubTrigger` wrapper and omits the direct `attackTargetsPlayer` condition. The snapshot is stale and was intentionally left untouched.

Score: 8/10 provisional (2/2 catalog/rules, 2/2 direct IR, 2/2 static behavior evidence, 2/2 peer/legal-stack evidence, 0/2 executed gates).

### BT6-003 Bibimon

Catalog: Yellow Digi-Egg, level 2, Lesser. Inherited text is `[When Attacking][Once Per Turn] If you have 3 security cards, gain 1 memory.`

Proven correction: the original direct IR used `youHave` with only a controller filter. `conditions.ts:204-210` makes that condition count matching permanents (battle area/breeding by default), not security cards, and the default threshold is at least one. It could therefore produce a false positive whenever the player had a matching permanent. The module now uses `allOf(securityAtLeast 3, securityAtMost 3)` at `BT6-003.ts:16-23`, matching the established exact-three implementation in BT6-033.

Static behavior proof: `BT6-003.test.ts` now uses a legal egg → yellow level 3 BT6-033 stack, retains the exactly-three positive, and adds two and four security negatives. The security conditions resolve through `conditions.ts:262-265` and the security-count path rather than permanent enumeration.

Peer/legal-stack proof: BT6-033 is the direct same-mechanism peer and uses the same exact-three `allOf` shape; its focused tests cover four versus three security. Comprehensive rules 13-1 and the security-count interpreter path were checked.

Snapshot: `effects.json` still contains the former `youHave` condition. This is a documented direct-vs-generated snapshot drift; the snapshot was not edited and the direct module is authoritative.

Score: 8/10 provisional (2/2, 2/2 after correction, 2/2 static behavior evidence, 2/2 peer/legal-stack evidence, 0/2 executed gates).
