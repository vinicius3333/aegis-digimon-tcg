## Shared interpreter, primitive, and peer evidence

- Live DP target predicates use `permanent.currentDP`, not printed DP (`apps/api/src/engine/effects/interpreter/matching/permanent.ts:292-322`). This is the load-bearing path for BT6-051's 5,000 threshold.
- `forms` is a definition-level exact form predicate (`apps/api/src/engine/effects/interpreter/matching/definition.ts:63-70`), while `nameOrTrait` intentionally matches the form/attribute/type trait union. BT6-054 therefore uses `forms: ["Hybrid"]` for the wording “Hybrid in its form,” avoiding an accidental attribute/type match.
- Entmon's self-scoped `whenDeletesInBattle` watcher is gated to the anchored attacker by `apps/api/src/engine/effects/interpreter/actions/subTrigger.ts:1213-1225`; the combat controller publishes the event only when the attacking Digimon survives and deletes the battled opponent (`apps/api/src/engine/combat/controller.ts:1451-1476`). This supplies both sides of BT6-052's printed condition, and its Once Per Turn frequency is carried by `registration/module.ts:274-295`.
- `dpImmune` is the consumed restriction for “can't have DP reduced”: `apps/api/src/engine/effects/primitives.ts:625-655` blocks negative DP changes, and `EffectContext.ts:50` exposes the restriction. The snapshot's `haveDPReducedByEffects` spelling is stale; the direct registered module's `dpImmune` is executable authority.
- Security effects activate face-up in the security stack (`data/kb/rules/comprehensive.md:2546-2549`). `securityCheck.ts:253-260` resolves that effect before the Security battle, removes the revealed card, and `:291-313` battles it, trashes it if still loose, then fires `whenSecurityBattleEnded` before the next security check. `subTrigger.ts:414-421` gates that event to the exact checked `securityInstanceId`, so the delayed BT6-056/058 bodies cannot cross-fire between security cards.
- Same-mechanism delayed Security peers inspected were BT3-024, BT3-036, BT3-049, BT3-065, BT3-082, BT5-065, BT6-111, BT14-034, BT23-007, BT23-010, and P-070. They encode “at the end of the battle” as a Security effect containing `SubTrigger(event: "whenSecurityBattleEnded", once: true)`, with self-play peers taking the card from trash. BT6-056 and BT6-058 now follow this canonical shape.
- The RevealAdd path records the full revealed set and then consumes category-specific selections (`apps/api/src/engine/effects/interpreter/actions/reveal.ts:108-121,202-220`); remaining revealed cards are trashed by the same effect (`:511-518`). This supports BT6-060's two independent category slots and Q1453's one-category-only result.
- The Digivolve action resolves hand sources, target self, cost override, and requirement-ignore flags (`apps/api/src/engine/effects/interpreter/actions/digivolve.ts:203-335`). BT6-060's `costOverride: 6`, `from: ["hand"]`, and `ignoreRequirements: true` use that seam; the repository's activation preflight recognizes Digivolve actions (`apps/api/src/engine/effects/interpreter/effect.ts:659-710`).
- Decoy is an immediate opponent-effect replacement per comprehensive §16-18. The parser reads the holder's printed Decoy spec (`apps/api/src/engine/combat/keywords.ts:135-180`), and the deletion primitive enforces the opponent-effect cause, black target matching, optional holder deletion, and prevention (`apps/api/src/engine/effects/primitives.ts:2800-2885`). The direct BT6-059 keyword marker therefore relies on the same shared Decoy engine semantics and its erratum text.
- All return-to-deck cleanup uses `collectForReturn`: a returned top card takes its entire permanent, puts the top card at deck bottom, and trashes attached cards (`apps/api/src/engine/effects/primitives.ts:3678-3757,5547-5587`). This is distinct from explicit `TrashDigivolution`, and no such source-trash event should be inferred for this range.
