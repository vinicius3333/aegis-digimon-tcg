## Shared interpreter, primitive, and peer evidence

- `RestrictMemoryGain` records a seat-level policy, and `ContinuousEffectLedger.canGainMemoryFromEffect` rejects non-Tamer sources while permitting Tamer sources (`apps/api/src/engine/effects/continuous.ts:739-759`). The public observer and the BT3-046 same-mechanism test exercise the same policy boundary (`apps/api/src/engine/testkit/observe.ts:163-165`, `apps/api/src/engine/cards/irKindTier1Cluster.test.ts:666-700`).
- Trait conditions use the live top card, not arbitrary sources in the stack: `selfHasTrait` delegates to `selfTopMatchesTrait` (`apps/api/src/engine/effects/interpreter/conditions.ts:438-449`), and `matchNameOrTrait` checks the form/attribute/type union (`apps/api/src/engine/effects/interpreter/matching/permanent.ts:29-42`). This is the relevant boundary for BT6-022's Hybrid/Ten Warriors wording.
- `opponentHasNone` is a zero-count query over opponent-controlled matching permanents (`apps/api/src/engine/effects/interpreter/conditions.ts:242-244`). Its `digivolutionCards: "hasAny"` filter therefore excludes only opponents with at least one source and also passes when the opponent's battle area is empty, as Q1417 and Q1418 require.
- `OncePerTurn` is carried into registered effects as `maxPerTurn: 1` for both regular and continuous-window effects (`apps/api/src/engine/effects/interpreter/registration/module.ts:240-243,274-295`). Inherited effects are collected from the live stack, so BT6-022, BT6-025, and BT6-027 retain the correct source identity while their hosts attack.
- `TrashDigivolution` takes the requested source direction and amount from a target permanent (`apps/api/src/engine/effects/interpreter/actions/placeUnder.ts:517-542`); this supports BT6-024 bottom trash, BT6-027 top trash, and BT6-029 bottom trash across all opponent Digimon. `scaleFactor` counts matching cards/permanents at resolution (`apps/api/src/engine/effects/interpreter/scaling.ts:152-209`), supporting BT6-029's memory and Security Attack scaling.
- `cantBeBlocked` is a consumed restriction on the attacking permanent: combat legality rejects every block when that restriction is present (`apps/api/src/engine/combat/legality.ts:347-366`). The same-mechanism combat test explicitly identifies BT6-028 and confirms that the old dead-store `attackTargetChange` shape would leave blocks legal (`apps/api/src/engine/cards/combatRestrictCluster.test.ts:157-212`).
- Returning a permanent through `returnToHand` or `returnToDeck` uses `collectForReturn`, which removes the whole top-plus-stack permanent (`apps/api/src/engine/effects/primitives.ts:3523-3600,3678-3757,5547-5587`). For deck return, the top card goes face-down to the requested deck endpoint and attached cards go face-up to their owners' trash (`:3739-3757`); unlike the dedicated `trashDigivolutionCards` path, this rules cleanup does not fire `whenDigivolutionTrashed`. The BT6-002 focused Q1399 negative and engine subtrigger controls establish this distinction (`apps/api/src/cards/BT6/BT6-002.test.ts:66-83`, `apps/api/src/engine/subTriggerSeams.test.ts:310-335`).
- A `Return` action with `fromSelectionRef` resolves the already bound permanent and dispatches to the canonical return primitive (`apps/api/src/engine/effects/interpreter/actions/removal.ts:574-689`). The optional `returnDigivolutionCardsFirst` path would instead put sources into the deck before return (`:531-537`), so BT6-030 correctly leaves that option unset.

Same-mechanism peers inspected include BT3-046's memory-gain lock and focused policy test, BT6-020's `opponentHasNone`/Jamming shape, BT6-022 and BT6-027's inherited Once Per Turn attack watchers, BT6-024's bottom-source operation, BT6-029's dynamic Security Attack grant, BT5-050's inherited stack watcher, and the combat `cantBeBlocked` cluster. These peers confirm the target controller, live-stack source identity, direction of source removal, duration, scaling, and exclusive registration shapes used by the direct range modules.
