## Card-by-card audit

### BT6-041 Manticoremon

The catalog record (`cards.json:58745-58767`) is Yellow, Lv.5, 7000 DP, with a Yellow Lv.4 evolution for 3 and the printed text “You may trash the top card of your security stack to have 1 of your opponent's Digimon get -5000 DP for the turn.” The direct module (`apps/api/src/cards/BT6/BT6-041.ts:8-45`) models a `WhenAttacking` optional `ModifyDP` against one opposing Digimon, `-5000` for the turn, with a cost targeting exactly one card in the controller’s security zone at `position: "top"`. This matches Q1427: the cost is unavailable at zero security and cannot be bypassed.

The focused test was mislabeled “Mistymon”; it now names Manticoremon. Its existing positive path proves that the top security card is trashed and one opposing Digimon loses 5000 DP. A new negative path attacks a suspended opposing Digimon while the source has no security; the source loses the battle, but the opposing Digimon remains and no security card enters trash, proving the optional effect cannot fire without its cost. The target filter and DP modifier were compared with the inherited security-removal peer BT6-040 and the generic attack/ModifyDP primitives.

The generated snapshot record (`effects.json:110713-110735`) omits the direct cost filter’s `zone: "security"` and `position: "top"`, leaving only `controller: "mine"`. This is documented snapshot drift; the direct registered module is executable authority and was not weakened to match the stale snapshot.

## Shared primitive and boundary findings

The important shared seams were inspected directly:

- `apps/api/src/engine/effects/interpreter/actions/digivolve.ts:203-207` treats Static `Digivolve` actions carrying `onto` and `asLevel` without a runtime target as registration metadata, not an effect to execute repeatedly.
- `apps/api/src/engine/cards/cardData.ts:330-344,538-556` rejects gateless alternate requirements and derives Tamer-onto legality from the registered IR’s `asLevel`, shared card color, and the matching evo-cost row. This is why the stale BT6-049 snapshot requirement does not make every-color Tamer legal.
- `apps/api/src/engine/cards/tamerOntoDigivolve.ts:15-22` stores the `asLevel` side registry used by the alternate requirement matcher.
- `apps/api/src/engine/effects/interpreter/actions/statics.ts:17-90` implements conditional Auras and keyword/static capability projection; `board.ts:260-315` and `GameEngine.ts:3008-3030` provide the GainKeyword and keyword projection seams used by BT6-043 and BT6-050.
- `apps/api/src/engine/effects/interpreter/actions/reveal.ts:242-300` implements bounded and up-to reveal selections, while `runRevealAdd` independently processes the two BT6-047 named slots and preserves the revealed remainder.
- `apps/api/src/engine/effects/interpreter/costs.ts:1370-1380` enforces the all-or-nothing `trashSecurityTop` cost used by Dynasmon; the generic security-aware trash fallback is also used by BT6-041’s direct cost.
- `apps/api/src/engine/GameEngine.ts:2248-2260` queues security-removal triggers while a parent effect is active, so Dynasmon completes its six-card reveal before Recovery.
- `apps/api/src/engine/combat/controller.ts:1482-1489` and `GameEngine.ts:752-760` consume intrinsic or granted Piercing at the battle-to-security seam.

Trait and name boundaries were checked explicitly: Rosemon is a name filter, Eosmon is a name filter plus Digimon kind, Bakomon’s opponent count is restricted to suspended Digimon, Dynasmon’s reveal is restricted to Digimon level 6 or lower, and both Hybrid cards’ alternate paths require an actual own Green Tamer rather than a same-color arbitrary permanent. Ordinary legal stacks were checked against each catalog level/color/evo-cost row; BT6-045’s test fixture was corrected to a Green Lv.4 over Green Lv.3 stack.
