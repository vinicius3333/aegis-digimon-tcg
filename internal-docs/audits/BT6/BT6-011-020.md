Audit date: 2026-08-27
Scope: BT6-011 through BT6-020, reviewed in exact ascending order
Audit mode: static evidence only; no execution gates were run

## Scope and canonical score

This audit treats the committed card catalog as the printed contract. For each
card, I inspected the complete catalog record, ran exactly one local KB card
query, read the applicable comprehensive rules and restriction/errata data,
traced the direct TypeScript module and generated effects snapshot, followed
the shared interpreter primitives, read the colocated focused test, compared
same-mechanism peers, checked name/trait boundaries, and checked a legal
evolution/source stack where the card's behavior depends on one.

Every executable module in this range registers only through
`registerIrCard(cardId, compiled)`. No duplicate `registerCard` path is
present. The direct registered module is the executable authority when the
generated snapshot differs; `packages/shared/src/effects/effects.json` was
not edited.

The five canonical 2-point components are catalog and rules, IR trace,
behavioral proof, peer and stack proof, and executed gates. The first four are
static `2/2` findings for every card after the correction below. The executed
gates are `0/2` because the task explicitly prohibited tests, typecheck, lint,
formatting, browser/UI checks, and `git diff --check`; consequently every
score is provisional `8/10`, and this report makes no 10/10 or collection
completion claim.

### Comprehensive rules

The rules pass covered the applicable sections of
`data/kb/rules/comprehensive.md`:

- `3-4-7` (`:542-581`) prevents effects, triggers, choices, or card
  information in breeding from being used unless explicitly specified. This
  is decisive for BT6-013's Q1408 boundary.
- `4-3`/`4-6` (`:654-681`, `:717-778`) define a Digimon, digivolution cards,
  stack order, and inherited effects. `8` (`:1392-1470`) defines legal
  color/level evolution, alternate requirements, cost payment, and
  When Digivolving timing.
- `11`/`12` (`:1691-1832`) define attack and block timing. `15-3`
  (`:1925-1936`) establishes that an inherited effect is activated by its
  host while a reference to “this card” remains the source card in the
  stack. `15-4`/`15-5` and `15-6` (`:1970-2170`) define trigger timing,
  once-per-turn activation identity, optional processing, and processing
  conditions.
- `15-8`/`15-15` (`:2170-2635`) cover target selection, “one” versus “all,”
  DP and duration, effect-source binding, and activation of another effect.
  These rules support BT6-011's fixed count, BT6-016's self source, and
  BT6-017's optional branch.
- `9-1` (`:1616-1661`) defines using an Option as activating its Main effect
  and trashing it after resolution, which is why BT6-017 uses the dedicated
  option-use interpreter action rather than a Digimon play action.
- `16-4`, `16-7`, and `16-16` (`:2797-2861`, `:2965-2976`) define Security
  Attack, Piercing, and Blitz. In particular, Blitz requires opponent memory
  of at least 1 when activated; Piercing is a battle-triggered security check;
  and Security Attack modifies the number of checks.

The generated snapshot range is
`packages/shared/src/effects/effects.json:109966-110275`. It agrees with the
direct behavior for BT6-011, BT6-012, BT6-014, BT6-015, BT6-018, BT6-019, and
BT6-020. Two generated records retain drift that was documented rather than
silently used as runtime authority:

- BT6-013's snapshot uses `GrantStatic` with `grant: "trait"` and lowercase
  `black`, while the direct registered module uses `grant: "color"` and
  canonical token `Black`, which is the printed color/evolution behavior.
- BT6-017's snapshot renders the optional branch as `PlayWithoutCost` with an
  Option target and a raw “you don't” condition. The direct module uses
  `UseOptionWithoutCost`, restricts the hand candidate to printed play cost 7,
  and gates the fallback with structured `ifThisEffectUsed`; this preserves
  the printed “use the Option's Main effect” semantics and Q1410.

BT6-016's pre-correction direct record had also drifted from its snapshot: it
narrowed the watcher with a one-shot `once`, used a `global:` once-per-turn
key, and targeted all own Digimon whose names contain Jesmon. The direct
module now matches the intended self-targeted, frequency-bound shape in the
snapshot; the snapshot itself was not edited.

The runtime authority and primitive trace were checked in these seams:

- `apps/api/src/engine/effects/interpreter/registration/module.ts:274-290`
  applies turn scope and `OncePerTurn` frequency to registered effects, and
  `effect.ts:394-402` supplies the watcher key when the card does not provide
  an explicit one.
- `apps/api/src/engine/effects/interpreter/actions/subTrigger.ts:788-803`
  binds event subjects and `:1029-1034` namespaces non-global once-per-turn
  keys by source instance. The removed `global:` key was therefore a real
  per-copy identity bug, not cosmetic serialization.
- `apps/api/src/engine/effects/interpreter/targeting/permanents.ts` resolves
  `{ filter: { isSelfRef: true }, count: 1, isSelf: true }` to the triggering
  source permanent. `matching/definition.ts:324-330` distinguishes partial
  `name` matching, exact names, and exact traits. This supports `[Sistermon]`
  and `[Matt Ishida]` name containment without changing them into exact-name
  filters.
- `conditions.ts:204-243` implements own-board `youHave` and opponent-board
  `opponentHasNone`; the latter counts matching permanents and therefore
  returns true both for an empty opponent board and for an opponent board with
  only source-less Digimon. `targeting/permanents.ts` rejects a source-less
  Digimon from the `digivolutionCards: "hasAny"` filter.
- `actions/borrowed.ts:333-451,469-543` enumerates eligible Options by
  printed play cost and `runUseOptionWithoutCost` runs the selected Option's
  Main effect, owns payment/lifecycle, and sets `lastOptionUsed` only when an
  Option was actually used. This validates BT6-017's direct action and
  fallback.
- `actions/board.ts:130-220` resolves DP target IDs and durations,
  `GainKeyword` uses the same target binding, and the security/resource
  primitives preserve the BT6-018 deletion-to-security watcher semantics.
