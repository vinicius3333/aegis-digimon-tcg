### The declinable-cost shape, and why it is `optional` on the ACTION

The brief prescribes `cost.optional: true` with `abortOnDecline: true`. Reading
`interpreter/actions/runAction.ts` shows those two knobs are not interchangeable, and the house
shape is the action-level one:

| Shape | Runtime |
| --- | --- |
| cost present, no `optional` anywhere | Cost auto-paid, no prompt. If unpayable the action does nothing, and the effect aborts only when `abortOnDecline` is set. |
| `action.optional: true` (+ `abortOnDecline`) | One prompt (`runAction.ts:474-496`, gated on `actionCost?.optional !== true`); on accept the cost is paid silently. Decline → `runAction` returns `true` → `effect.ts:619-623` breaks the action loop. |
| `cost.optional: true` (+ `abortOnDecline`) | **Two** prompts: `"Pay cost: …?"` (`runAction.ts:714-717`) and then the payload prompt (`runAction.ts:745-751`). |

Every peer in the set encodes a printed "By …" with `optional: true` on the action —
`EX10-060` (both `PlayWithoutCost` clauses, with an explicit CR 15-7-4 comment), `EX10-062`,
`EX10-063`, `EX10-052`. This batch follows that shape; using `cost.optional` would open a second,
unprinted prompt. Flagged here because the brief's wording, read literally, would have introduced
that regression.

**IR trace.**

  `WaiveColorRequirement` from the "you may" prompt, so this stays a legality permission and does

- Clause 2 → `EndOfYourTurn` + `isFromTrash: true` (routed to the `inTrash` builder,

  `withoutSuspending: true`.
  - Q5186: `trashSecurityTop` as an ACTION is a silent no-op on an empty security stack —
    `security.ts:630-641` guards on `security.length > 0` and returns `false` either way — so the
    attack still resolves. That matches the ruling exactly.
  - Q5187: `combat/legality.ts:176` reads `if (attacker.isSuspended && !withoutSuspending) return
    "illegal-target"`, and `combat/controller.ts:544` skips the suspend when `withoutTap` is set. A

- Clause 4 → `Security` + `isSecurity` → `PlayWithoutCost` `from: ["trash"]`, `payCost: false`,
  `optional: true`.

**Defect corrected — the "By …" condition was not declinable (CR 15-7-4).**

*Before:* the `trashSecurityTop` action carried `cost` + `abortOnDecline: true` but no `optional`.
`runAction.ts:723-741` takes the mandatory-cost branch there: the return is paid with no prompt.
The card therefore bottom-decked itself at every end of turn in which a Lucemon was on the field,
with the controller given no choice — and `abortOnDecline` was inert on that path, because it is
only reached when the cost is UNPAYABLE.

*After:* `optional: true` added beside `abortOnDecline: true`. One prompt is raised
(`runAction.ts:474-496`); accepting pays the return and runs both results, declining returns `true`
and `effect.ts:623` breaks the loop so neither the security trash nor the attack happens. Same shape
as EX10-060, EX10-062 and EX10-063.

**Defect corrected — the Lucemon gate did not cover the whole clause.**

*Before:* the condition sat only on the leading `trashSecurityTop` action. A false action-level
condition returns `false` from `runAction` (`runAction.ts:189-196`) and does NOT break the action
loop, so the trailing `Attack` had no gate of its own. In practice the clause was still blocked,
but only through `canActivateEffect`'s leading-`abortOnDecline` branch (`effect.ts:770-778`), which
happens to read that action's condition at declaration time — a load-bearing coincidence, not the
printed structure.

*After:* the condition is also declared as `CardEffect.condition`, which `runEffect`
(`effect.ts:518-519`) checks before ANY action runs, and which `canActivateEffect`
(`effect.ts:672-676`) checks at collection. It is deliberately kept on the leading action too,
because the leading-`abortOnDecline` branch reads that copy. The condition kind is `youHave`, not
`raw` and not `trigger*`-prefixed, so hoisting adds no `canTrigger` gate and cannot make the clause
inert. `isFromTrash` residency gating is composed separately in `builders.ts:109` and is untouched.

### 6.1 `observe().keywordAmount` disagrees with `securityStrikeCount` on a missing amount

`apps/api/src/engine/testkit/observe.ts:48-53` sums `grant.amount ?? 0`, while
`apps/api/src/engine/GameEngine.ts:230-236` reads `g.amount ?? 1`. A card that grants
`SecurityAttack` with no explicit amount therefore performs 2 security checks in play but reads as
`0` through the only test affordance for it — which is how EX10-073's missing `amount` stayed
invisible.

Proposed diff (`observe.ts`):

```diff
     keywordAmount(permanent: Permanent | string, keyword: string): number {
       return internals.continuous
         .grantedKeywords(idOf(permanent))
         .filter((grant) => grant.keyword === keyword)
-        .reduce((sum, grant) => sum + (grant.amount ?? 0), 0);
+        // Match the consume site: a parameterized keyword granted with no amount means 1
+        // (`securityStrikeCount`, `grantLinkMax`), not 0.
+        .reduce((sum, grant) => sum + (grant.amount ?? 1), 0);
     },
```

Failing test it needs: a fixture granting `SecurityAttack` with no `amount`, asserting
`keywordAmount === 1` and that the attacker performs 2 security checks. Today the first assertion
reads 0 while the second passes, so the two contradict each other.

### 6.2 `DelayedDeletePlayed`'s fallback deletes the SOURCE when the play was declined

`apps/api/src/engine/effects/interpreter/actions/removal.ts:855-872`: when
`ctx.lastPlayedPermanentIds` is empty, the action falls back to `ctx.source.permanent()` and arms a
delayed delete on the effect's own source. For EX10-072 this is inert — the ＜Delay＞ branch already
trashed the source before the payload runs, so `ctx.source.permanent()` is `undefined` — but any
future card pairing an optional `PlayWithoutCost` with `DelayedDeletePlayed` outside a ＜Delay＞
window would delete ITSELF when the controller declines the play.

Proposed diff (`removal.ts`):

```diff
     case "DelayedDeletePlayed": {
       const playedIds = ctx.lastPlayedPermanentIds ?? [];
-      if (playedIds.length > 0) {
-        for (const permanentId of playedIds) ctx.fx.delayedDeletePlayed?.(permanentId, timing);
-      } else {
-        const self = ctx.source.permanent();
-        if (self !== undefined) ctx.fx.delayedDeletePlayed?.(self.permanentId, timing);
-      }
+      // "the Digimon this effect played": with nothing played there is no subject. Falling back
+      // to the source turned a declined optional play into a self-delete.
+      for (const permanentId of playedIds) ctx.fx.delayedDeletePlayed?.(permanentId, timing);
       return false;
     }
```

Failing test it needs: an effect whose optional `PlayWithoutCost` is declined, followed by
