## 4. Per-card findings

### EX10-041 Wizardmon (Purple/Yellow, Lv.4, [Wizard]/[Witchelny], 5/5000)

**Clauses.** `[Digivolve] Lv.3 w/[Evil] trait: Cost 2` (alternate) · "When effects trash this card
from the deck or security stack, give 1 of your opponent's Digimon ＜Security A. -1＞ until their
turn ends" · `[On Play] [When Digivolving]` "By trashing your top security card, trash the top 2
cards of your deck and all of your opponent's Digimon get -3000 DP **for the turn**" · inherited
＜Barrier＞.

**IR trace.** The trash trigger is split into two executable seams, which is right: the deck half is
an `AllTurns` `SubTrigger` on `whenTrashedFromDeck` gated by `sourceFilter.isSelfRef` (matched by
card ID in `whenTrashedFromDeckGate`), the security half is a top-level `OnDiscardSecurity` effect.
Both are effect-only without any extra gate — `fireWhenTrashedFromDeck` has exactly one caller
(`TrashTopDeck`) and `fireDiscardedFromSecurity` is the effect-driven security-trash seam — which is
the executable reading of Q5122. The `[On Play]`/`[When Digivolving]` pair is one `CostGatedBlock`
whose `cost.target` is `{ zone: "security", position: "top" }` (honoured by `targeting/loose.ts:366`),
`optional: true` + `abortOnDecline: true` per CR 15-7-4, wrapping `TrashTopDeck ×2` and a
`count: "all"` `ModifyDP`.

**Defect corrected.** The -3000 DP carried `duration: "untilOpponentTurnEnd"`. Printed text is
"**for the turn**". `durations.ts` documents `forTheTurn` as UntilEachTurnEnd and
`untilOpponentTurnEnd` as a strictly longer window, so the debuff survived into and through the
opponent's turn — a materially stronger card, and inconsistent with EX10-049's own "for the turn"
clause in the same range.

- before: `{ kind: "ModifyDP", …, amount: -3000, duration: "untilOpponentTurnEnd" }` (×2)
- after: `{ kind: "ModifyDP", …, amount: -3000, duration: "forTheTurn" }` (×2)

**Type error resolved.** `byEffect: true` on the SubTrigger — see §3. It was dead: no gate reads it,
and its plausible substitute `requireByEffect` would have disabled the clause.

**Tests added.**
- `declining the security cost aborts the mill and leaves every opposing DP untouched` — the optional
  refusal path (`autoDeclineOptional`), asserting security kept, deck untouched, trash empty, DP
  unchanged.
- `the -3000 DP lasts only "for the turn" …` — resolves the clause, asserts 9000 → 6000, then
  `advance(s.engine).runTurn(0)` and asserts 9000 again.
- IR assertions updated to `forTheTurn` and to `not.toHaveProperty("byEffect"/"requireByEffect")`.

**Mutation checks.** Duration → the `runTurn(0)` assertion (`untilOpponentTurnEnd` keeps 6000).
`count: "all"` → the two-Digimon On Play case (`first` 6000 **and** `second` 4000). `position: "top"`
→ the security-length assertion is weak on its own; the top-card restriction is the one field in this
card with no discriminating fixture (single-card security), recorded as residual risk below.
`optional`/`abortOnDecline` → the new decline test. `whenTrashedFromDeck` `isSelfRef` → the Q5122
test mills a deck holding the card plus one other card and asserts only one grant. `OnDiscardSecurity`
→ the security-trash test. Inherited ＜Barrier＞ → the host-vs-standalone pair.

**Open ambiguity.** None on the text. Residual proof gap: `position: "top"` is not distinguished from
"any security card" by any fixture, because the security stack in these tests holds one card.

### EX10-042 GulusGammamon (Purple/Red, Lv.4, [Dragonkin], 5/5000)

**Clauses.** `[Digivolve] [Gammamon]: Cost 2` · `[On Play] [When Digivolving]` mill 2, then you may
place 1 Digimon card with `[Gammamon]` in its name from trash as this Digimon's **bottom**
digivolution card · `[Your Turn] [Once Per Turn]` when effects add to this Digimon's digivolution
cards, it may digivolve into `[Regulusmon]` in hand or trash with the cost reduced by 1 · inherited
＜Raid＞.

**IR trace.** `TrashTopDeck ×2` then `PlaceUnder { position: "bottom", optional: true }` sourced
`from: ["trash"]` with a name filter — correct on the "you may", the zone, and the stack position.
The `[Your Turn]` clause is a `YourTurn` effect (so `turnScope` is stamped `yourTurn` at
registration) with `frequency: "OncePerTurn"`, wrapping an `onAddDigivolutionCards` SubTrigger with
`sourceFilter.isSelfRef` (the card's own stack) whose body is `Digivolve` on self with
`payCost: true, reduceCost: 1, from: ["hand","trash"], optional: true`. No defect found; the module
is already the corrected form of the stale JSON.

**Baseline failure diagnosed and fixed (test-side).** On the untouched branch,
`EX10-042.test.ts > mills 2, places only a Gammamon-name trash card at stack bottom, and triggers
the reduced Regulusmon evolution` fails. **Cause: an unanswered evolution-route `chooseOption`.**
The base is GulusGammamon (Purple/Red, Lv.4, "Gammamon" in name) and the destination EX10-053
Regulusmon carries **both** a matching printed evoCost (Purple Lv.4 cost 5 and Red Lv.4 cost 5)
**and** a matching alternate requirement (`[Digivolve] Lv.4 w/[Gammamon] in name: Cost 5`). In
`interpreter/actions/digivolve.ts:430-441`, when `printed !== undefined && alternate !== undefined
&& pays`, the interpreter opens `ctx.ask.chooseOption(["Printed …", "Alternate …"])`. The harness
was created with `autoAcceptOptional` + `autoSelectCards` + `preferInstanceIds` but **no**
`chooseOption` responder, so the decision was never answered, the digivolution never completed, and
`settle(() => s.perm("gulus").topCard?.cardId === "EX10-053")` timed out. This is the same class the
brief names, not a fixture-keyword prompt (the fixtures BT1-009/BT1-010/LM-016/EX10-040 carry no
＜Evade＞ or other prompt-opening keyword). The module is correct; the evidence points at the test.

- before: `{ autoAcceptOptional: true, autoSelectCards: true, preferInstanceIds: preferred }`
- after: `{ autoAcceptOptional: true, autoSelectCards: true, autoChooseOption: true, preferInstanceIds: preferred }`

Option index 0 is the printed route; both routes cost 5, so the existing `expect(s.state.memory).toBe(0)`
assertion (memory 4, cost 5 − reduceCost 1) is unchanged and still pins `payCost` and `reduceCost`.

**Mutation checks.** `payCost: true` and `reduceCost: 1` → the memory 4 → 0 assertion (free would
leave 4; unreduced would be illegal at 4 memory). `position: "bottom"` → the exact stack-order
assertion `[gammamon, existing, gulus]`. The `Gammamon` name filter → `EX10-040` DemiDevimon stays in
the trash. `onAddDigivolutionCards` + `isSelfRef` → the evolution only happens after the placement in
the same resolution. Inherited ＜Raid＞ → the host-vs-standalone pair.

**Open ambiguity.** None.

Two observations to pass on rather than seam requests:

1. `packages/shared/src/effects/effects.json` is stale for eight of these ten cards, and for
   EX10-041, EX10-045 and EX10-047 it encodes a materially different card (see §3). Any tool that
   rehydrates modules from it would regress them.
2. `SubTriggerAction.requireByEffect` is a trap for the `whenTrashedFromDeck` event: its gate reads
   `trigger.byEffectSeat`/`byEffectCardId`, which that event's payload never sets, so the flag
   silently disables the watcher instead of narrowing it. It already has an event-specific analogue
   (`excludeSelfEffect`). If the shared types are ever revisited, documenting the incompatibility on
   `requireByEffect` — the way `deleteCauseGate` documents its own carve-out — would stop the next
   author reaching for it.
