### EX10-056 Bagramon — **4 defects corrected**

**Clauses.** Lv.6 / 13000 / play 13 / Purple / Mega / Virus / [Demon Lord][Bagra Army]; EvoCost
Purple Lv.5 for 5; `[DigiXros -2] 2 Digimon cards w/[Bagra Army] trait`. (1) `[On Play]
[When Digivolving] You may place 1 of your opponent's Digimon as any of their other Digimon's
bottom digivolution card or under any of their Tamers.` (2) `[All Turns][Once Per Turn] When any
of your opponent's Digimon or Tamers digivolve or effects place cards under them, by trashing any
2 of this Digimon's digivolution cards, trash your opponent's top security card.`

**IR trace.** (1) `PlaceUnder{targetIsPermanent:true, position:"bottom"}` with
`underFilter{controller:"opponent", kind:["Digimon","Tamer"]}` — `placeUnder.ts` routes
`targetIsPermanent` through `relocateByEffect`, and `position !== "bottom"` maps to `belowTop`, so
`"bottom"` gives the true-bottom placement Q5143 requires. Q5145 (the relocated permanent leaves
the battle area, its own sources trashed) is the relocation primitive's own behavior. (2) two
`SubTrigger`s — `whenOneOfYoursDigivolves` and `onAddDigivolutionCards`, both filtered to
`controller:"opponent"` — each paying `cost{isSelfRef, digivolutionCards, count:2}` for a
`trashSecurityTop{controller:"opponent"}`. Q5148 (linking does not trigger) holds because neither
event is `whenLinked`.

**Defects corrected.**

1. **Type-level (TS2322 ×3, `EX10-056.ts:22,47,54`) — widened literals.** The two play-time
   effects were produced by `["OnPlay","WhenDigivolving"].map(trigger => ({trigger, …}))` and the
   watcher body lived in a bare `const watcherActions = [...]`. Both lost their literal types
   (`trigger: string`, `kind: string`), so neither was assignable to `CardEffect` / `Action[]`.
   *Before:* `.map()` + hoisted const. *After:* both effects and both watcher bodies written
   inline inside the `CompiledCard` literal, so contextual typing applies. This was a typing
   defect only — the runtime IR was already correct — but it is what kept the file under
   `@ts-nocheck`.
2. **`digivolutionRequirement: [{level:5, colors:["Purple"], cost:5}]` (TS2741, missing
   `isAlternate`) — an unprinted alternate route.** This card prints no `[Digivolve]` header; the
   row is the ordinary EvoCost already in `cards.json`. Since
   `matchingAlternateDigivolutionRequirement` treats every entry as an alternate route,
   restating it registered a second, unprinted route. *After:* the field is removed entirely.
3. **`underFilter.excludeSelf: true` was a no-op.** `matching/permanent.ts` compares `excludeSelf`
   against `ctx.source` — Bagramon — which can never be one of the opponent's permanents, so it
   never excluded anything. The printed "any of their **other** Digimon" is already enforced by
   `placeUnder.ts`'s `destIds.filter(id => !sourceIds.includes(id))`. *After:* the misleading
   field is dropped and the reason recorded in a comment.
4. **The "by trashing 2" watcher payload was not declinable.** CR 15-7-4 makes a "by" processing
   condition optional. *After:* `optional: true` on the `trashSecurityTop` action.

Also: the module exported only a default. It now exports both the named `compiled` and the
default, so the collection audit's `registerIrCard(…, compiled)` regex and the colocated test's
default import both hold.

**Tests.** The existing suite already covers the relocation with true-bottom ordering, the exact
2-source payment, the shared `oncePerTurnKey`, and the "does not react to its controller's own
placement" negative; it passes unchanged against the corrected module.

**Test added.** `Q5144 cannot place an opposing Digimon under a host that isn't affected by
effects` — the only legal host is given a `beAffected` restriction scoped to Digimon-sourced
effects through the testkit's continuous ledger
(`advance(s.engine).ledgers.continuous.addRestriction(..., EffectDuration.Permanent,
{ fromSourceKind: ["Digimon"] })`, the seam EX12-016's Q6740 tests use). The opposing Digimon stays
in the battle area and the host's stack is unchanged. Deleting the `addRestriction` call makes the
relocation happen, so the assertion is not vacuous.

**Mutation check.** `position:"bottom"` → the relocation test's exact `[material, existing]` stack
order fails. `underFilter.controller:"opponent"` → the same test's `players[1].battleArea` length
fails. `targetIsPermanent` → the relocation would not happen at all and both assertions fail.
`cost.count: 2` → the Q5142 test's `stack).toHaveLength(2)` fails. Shared `oncePerTurnKey` → the
second `fireSubTrigger` in that test would trash a second security card and the
`security).toHaveLength(2)` assertion fails. `sourceFilter.controller:"opponent"` → the
own-placement negative fails. Q5144 → deleting the `addRestriction` call in the new test makes the

## 6. Seam requests

### S-1 — `GrantStatic` trigger-restricted stack conferral — **LANDED**

Requested during this batch and landed as `copyTrigger?: string` on
`GrantStaticAction`, passed to `conferStackEffects` as `trigger` from the structured
`grant: "effects"` path (commit `d7db03755`). Before it, the printed restriction "gains all
**[All Turns]** effects" was inexpressible in typed IR: the object-shaped
`copyEffectsFromDigivolution` form supported a `trigger` field but is not assignable to
`GrantStaticAction.grant`, and the typed path passed no trigger at all. EX10-059 now sets
`copyTrigger: "AllTurns"`. The failing-before test is
`EX10-059.test.ts` → `confers only the stack card's [All Turns] effects, never its [On Play]`.

Follow-up worth considering outside this batch: `BT16-062` and `BT22-078` still use the untyped
object form under `@ts-nocheck` and would migrate to `grant: "effects"` + `filter` + `copyTrigger`
the same way. `BT22-078`'s form already carries `trigger: "Main"`, so its behavior is preserved.

### S-2 — hidden selection for "without looking"

**Need.** EX10-059 prints "Choose 1 card in your opponent's hand **without looking**". `Cost`
already has `selectionHidden?: boolean` and `ownerInspectsSelection?: boolean`
(`ir/predicates/costs.ts`), but `Target` has no equivalent, so an ACTION that selects from a
hidden zone cannot request a blind pick. Today the chooser is offered the opponent's hand with
full card identity.

**Proposed diff** (`packages/shared/src/effects/ir/filters/filter.ts`, on `Target`):

```ts
/** Do not reveal the candidate definitions to the player making this selection
 *  ("choose 1 card in your opponent's hand without looking" — EX10-059). */
selectionHidden?: boolean;
```

plus the consuming branch in the loose-card target resolver, mirroring the existing cost-side
handling.

**Failing test it needs.** In `EX10-059.test.ts`, with two distinguishable cards in the opponent's
hand, assert the `selectCards` decision request the engine publishes carries no card identity for
the candidates (`s.decisions` entry has no `visibleCards` / definitions). That assertion fails
today because the request is fully revealed.

**Scope note.** No `GameState` outcome changes; this is an information-leak fidelity gap, which is
why EX10-059 is scored 7/10 rather than blocked.
