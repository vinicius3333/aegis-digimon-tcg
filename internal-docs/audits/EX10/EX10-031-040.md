## 4. Per-card findings

### EX10-031 DarkKnightmon — 2 defects corrected, 4 type errors resolved

Clauses: `[Digivolve] Lv.4 w/[Knightmon] in text: Cost 4`; `[On Play][When Digivolving]` protection
+ `+3000 DP` until the opponent's turn ends; `[All Turns][Once Per Turn]` leave-replacement free
play from its own digivolution cards; `[DigiXros -1] [SkullKnightmon] x [DeadlyAxemon]`; inherited
`[Opponent's Turn][Once Per Turn]` attack redirect.

**Defect 1 — the protection and the DP buff were two independent selections.**
Before:

```ts
{ kind: "GrantStatic", target: { filter: { controller: "mine", kind: ["Digimon"] }, count: 1 },
  selectionRef: "protected",
  grant: { kind: "Protection", protections: ["deDigivolve"], from: "opponent" }, … },
{ kind: "ModifyDP", target: { filter: { controller: "mine", kind: ["Digimon"] }, count: 1 },
  fromSelectionRef: "protected", amount: 3000, … },
```

`GrantStaticAction` has no `selectionRef` (grep of `grantStatic.ts` returns zero hits) and
`fromSelectionRef` lives on `Target`, not on `ModifyDPAction`. Both keys are inert, so the
`ModifyDP` ran a second `resolvePermanentTargets` pass over "your Digimon" and could buff a
different Digimon from the one protected. After (the shape EX10-029 in the same set already
proves):

```ts
{ kind: "SelectBind", target: { filter: { controller: "mine", kind: ["Digimon"] }, count: 1, bindAs: "protected" } },
{ kind: "Restrict", target: { filter: {}, count: 1, fromSelectionRef: "protected" },
  restriction: "cantBeDeDigivolved", byOpponentEffectsOnly: true, duration: "untilOpponentTurnEnd" },
{ kind: "ModifyDP", target: { filter: {}, count: 1, fromSelectionRef: "protected" },
  amount: 3000, duration: "untilOpponentTurnEnd" },
```

`byOpponentEffectsOnly: true` records the printed "**their** ＜De-Digivolve＞ effects" (see the
seam request in §6 — the enforcement site currently ignores the scope).

**Defect 2 — the leave-replacement play reached other Digimon's stacks.** The printed clause is
"play 1 … card from **its** digivolution cards". `targeting/loose.ts` only self-scopes a
`digivolutionCards` pool on an explicit `hostFilter`/`source: "thisDigimon"`, so every controlled
Digimon's stack was eligible. Added `hostFilter: { isSelfRef: true }` (the brief's preferred shape).

Type errors resolved (TYPE-ERRORS lines 14–17): `GrantStaticAction.grant` is a string union, and
`ModifyDPAction` has no `fromSelectionRef`. Both errors named exactly the two dead keys above —
not a typing chore. (The object `grant` form IS read by `grantStatic.ts` via `PROTECTION_TOKEN_MAP`,
so the protection itself worked; the binding did not.)

Tests: the contract assertion now names SelectBind/Restrict/ModifyDP; the behavioral test asserts
`other`'s DP is unchanged and that **exactly one** `chooseTargets`/`selectCards` decision is raised
for the whole clause (the pre-fix shape raises two); the leave test gained a second Digimon holding
an equally cheap source and asserts that card stays in its own stack.

Mutation check: flip `fromSelectionRef` back to a fresh filter → the single-decision assertion
fails. Drop `hostFilter` → the `elsewhere` assertions fail. Change `count: 1` on the DigiXros
requirement → the `memory === 2` assertion fails (7 − (7 − 2)). Change `texts: ["Knightmon"]` →
the `digivolutionRequirement` toEqual fails.

Ambiguity: none.

**Ambiguity, now pinned by a test.** "By trashing any 1 [Mineral] or [Rock] trait card from your
Digimon's digivolution cards, 1 of your **such** Digimon gains …" has two plausible antecedents
for "such":

- **(A, authored)** the Digimon itself carries the [Mineral] or [Rock] trait;

The KB does not settle it: Q5091–Q5093 cover the digivolve cost, the timing exclusion, and the fact

### EX10-033 Pyramidimon — 0 behavioral defects, 1 misleading field corrected

Every Q&A maps: `upTo: true` + `minimum: 1` is Q5096/Q5099 ("you may decline the effect, but once
activated you must place/trash at least 1"); no `kind` on the placement filter admits Digi-Eggs

### EX10-034 Blastmon — 4 defects corrected, 6 type errors resolved

**Defect 1 — the gained attack was a no-op.** `gainedActions: [{ kind: "Attack" }]`.
`runCombatAction` computes `attacker ?? subject ?? target` and `return`s immediately when it is
undefined, so the granted "[Start of Your Main Phase] This Digimon attacks" subscribed, fired, and
did nothing. Restored the persisted record's subject:
`{ kind: "Attack", target: { filter: { isSelfRef: true }, count: 1, isSelf: true } }`.

**Defect 2 — wrong duration.** `"untilOwnerTurnEnd"` is not an `EffectDurationRef`;
`toDuration`'s `default` returns `EffectDuration.UntilEachTurnEnd`. Because this is an
`[All Turns]` watcher that fires on either player's attack (Q5103), a buff taken on the OPPONENT's
turn expired at the end of that turn instead of at the end of the controller's own turn. The
printed "until your turn ends" is `"untilYourTurnEnd"` (→ `UntilOwnerTurnEnd`). Both the
`GainKeyword` and the `ModifyDP` were fixed.

**Defect 3 — the "by" condition was mandatory.** CR 15-7-4 makes a processing condition
declinable. Added `optional: true` + `abortOnDecline: true`. Q5102 (no partial payment) stays
enforced by the exact `count: 2` with no `upTo`.

**Defect 4 — the DigiXros recipe was uncapped.** `DigiXrosRequirement.count` is the PER-MATERIAL
discount, not a material count, and `costReduction` is read only for a `count: "∞"` recipe, so it
was inert. With a single material slot and no `maxMaterials`, both play paths set
`materialCap = materialCandidates.length` — any number of [Bagra Army] cards could be placed at
−2 each. The printed header is "[DigiXros -2] **2** Digimon cards w/[Bagra Army] trait", so:
`{ materials: [{ traits: ["Bagra Army"] }], count: 2, maxMaterials: 2 }` (the EX3-014 / EX12-015
convention).

`digivolutionRequirement` gained `isAlternate: false`: both rows are the printed EvoCost rows
(catalog `evoCosts` Black/Purple Lv.5 cost 5), not bracketed `[Digivolve]` alternates. A wrong
`true` here would offer them as alternate routes that skip the ordinary colour/level gate.

Type errors resolved (lines 25–30): the two `[On Play]`/`[When Digivolving]` windows were built by
`.map` over a `string[]`, which widened `trigger` to `string` and suppressed `CardEffect` checking
for their entire body — that is how the subject-less `Attack` survived. Both windows are now
written out literally. The two `untilOwnerTurnEnd` errors and the two missing `isAlternate` are
the semantic defects above.

Tests added: the gained-attack test now fires `startOfYourMainPhase` on the granted Digimon's own
turn and asserts it actually suspends and checks the granter's security; a CR 15-7-4 refusal case
(`autoDeclineOptional`: nothing trashed, no DP, no ＜Security A.＞); a duration case that sweeps the
opponent's turn end (buff survives) then the controller's (buff expires); a DigiXros case that
rejects a third [Bagra Army] material. The contract assertions now pin the gained subject, the
duration, `optional`/`abortOnDecline`, `isAlternate`, and `maxMaterials`.

**Test defect found by running the suite.** The extended Q5101 case timed out at 15s. Two causes,
both fixture/harness, neither in the card:
1. The opponent fixture was `BT5-082` Tactimon, whose own `[When Attacking]` opens a chain of
   `chooseOption` prompts — not a neutral fixture. Replaced with vanilla `BT1-019`.
2. Blastmon has ＜Blocker＞, so the forced attack offers it the block; the setup now passes
   `autoDeclineOptional` and `autoChooseOption`.
Even neutral, the forced attack does not settle to completion under the harness: instrumentation
showed the attack IS declared (defender suspended, `isAttacking()` true, the attack-target
`selectCards` for `"player"` raised and answered) but the battle continuation never resolves
outside a real turn flow. The test therefore asserts the **declaration**, which is exactly where
the defect lived — a subject-less `Attack` returns from `runCombatAction` before `forceAttack`, so
nothing suspends and no attack-target decision is ever raised. The fire promise is deliberately not
awaited (`.catch(() => undefined)` + `void`), with the reason written into the test.

Mutation check: remove the gained `target` → the suspension, `isAttacking`, and attack-target
decision assertions all fail. Revert the duration → the "survives the opponent's turn end"
assertion fails. Drop `optional` → the refusal test fails. Drop `maxMaterials` → the
three-material rejection fails. Drop `isAlternate` → the catalog toEqual fails.

Ambiguity: Q5101's "the gained effect won't trigger if the Digimon isn't affected by effects at
the trigger timing" is handled by `runGainTriggeredEffect`'s `immunityAtTriggerGate`, not by this
module.

### 6.1 `deDigivolve` ignores `byOpponentEffectsOnly`

`apps/api/src/engine/effects/primitives.ts:1514` reads the restriction with no scope:

```ts
if (isRestricted(permanentId, "cantBeDeDigivolved")) return [];
```

`ContinuousLedger.hasRestriction` documents that an entry with `byOpponentEffectsOnly: true`
blocks anyway when `opts.byOpponentEffect` is undefined (deliberate over-blocking). EX10-031's
printed text is "**their** ＜De-Digivolve＞ effects don't affect …", so the controller's own
＜De-Digivolve＞ should still work on the protected Digimon. Proposed minimal diff:

```ts
-    if (isRestricted(permanentId, "cantBeDeDigivolved")) return [];
+    if (
+      isRestricted(permanentId, "cantBeDeDigivolved", undefined, {
+        byOpponentEffect:
+          opts?.byEffectSeat === undefined ? undefined : opts.byEffectSeat !== permanent.controllerSeat,
+      })
+    )
+      return [];
```

Failing test it needs (would live in `EX10-031.test.ts` once the seam exists): protect one of your
Digimon with EX10-031, then run your OWN ＜De-Digivolve＞ on it and assert its stack shrinks, while
the opponent's ＜De-Digivolve＞ on the same permanent leaves the stack untouched. The test cannot be
written today because the testkit exposes no `deDigivolve` verb (`advance().verb` has trash,
delete, modifyDP, suspend/unsuspend, draw, return, play, digivolve — no de-digivolve), which is
the second half of this request.

### 6.2 `DigiXrosMaterial` cannot express "Digimon cards"

EX10-034's printed recipe is "2 **Digimon cards** w/[Bagra Army] trait" and EX10-015 hit the same
wall (TYPE-ERRORS line 6: `'kind' does not exist in type 'DigiXrosMaterial'`). Today a Tamer or
Option carrying the trait would satisfy the slot. Proposed minimal diff in
`packages/shared/src/effects/ir/requirements/xrosLink.ts`:

```ts
 export interface DigiXrosMaterial {
   names?: string[];
   traits?: string[];
+  /** Printed card kinds a material may have ("2 Digimon cards w/[Bagra Army] trait"). */
+  kind?: ("Digimon" | "Tamer" | "Option" | "DigiEgg")[];
```

plus the matching `definitionMatches`-style guard in `materialsSatisfyRecipe`. Failing test it
needs: build EX10-034 in hand with one [Bagra Army] Digimon and one [Bagra Army] **Tamer**, and
assert the play intent with that pair is rejected. It passes today, wrongly.
