## BT18-101 — Lucemon: Satan Mode

### Catalog and rules

The immutable catalog specifies Purple level 7, play cost 16, 16,000 DP,
digivolution from `Lucemon: Chaos Mode` for 6, and the following behavior:

* When Digivolving, optionally play one `Lucemon: Larva` from trash into an
  empty breeding area without paying its cost, then delete one opposing
  Digimon or Tamer only if that processing condition is executed successfully.
* At End of All Turns, once per turn, trash the opponent's top security card;
  if that effect did not trash a card, delete one opposing Digimon and one
  opposing Tamer.

The bracketed `Lucemon: Larva` processing-condition reference and the
`Lucemon: Chaos Mode` alternate-evolution source are exact card-name
references, not name substrings.

The local QA entry `Q3053` in `data/kb/qa.json:12970-12977` confirms that the
security trash is mandatory when the opponent has a top security card; the
player cannot choose the fallback instead. The comprehensive rules at
`data/kb/rules/comprehensive.md:2542-2549` define the relevant Breeding,
Trash, and Security effect locations, and
`data/kb/rules/comprehensive.md:2524-2527` covers once-per-turn use counting
even when processing cannot execute. Rules 15-7-1 through 15-7-4 at
`data/kb/rules/comprehensive.md:2082-2120` define text such as “by X” as an
optional processing condition, prohibit the following processing when X is
not executed, and preserve the player's choice to decline it.

### Implementation correction

The original generated trace represented the Larva play as a generic delete
cost string and did not provide the executable source-zone and empty-breeding
constraints. `apps/api/src/cards/BT18/BT18-101.ts:12-50` now explicitly uses
`PlayWithoutCost` from `trash`, matches `Lucemon: Larva` with
`nameExact`, requires an empty breeding area, and marks the “by playing”
processing condition `optional: true` with `abortOnDecline: true`. The
alternate requirement at lines `104-109` uses `namesExact` for `Lucemon: Chaos
Mode`; the shared legality/highlighting override at
`packages/shared/src/effects/data.ts:462-465` keeps that exact field aligned
without modifying generated `effects.json`. The delete follows only when the
play actually acted, so declining the condition or encountering an occupied
breeding area does not delete an opposing card.

The End-of-All-Turns implementation at
`apps/api/src/cards/BT18/BT18-101.ts:52-100` explicitly trashes from Security,
binds the result, and runs the Digimon-plus-Tamer fallback only when no
security card was trashed. It remains once per turn; the security-trash
processing itself is mandatory when possible, as confirmed by Q3053.

### Behavior-driving proof

`apps/api/src/cards/BT18/BT18-101.test.ts:24-48` asserts the exact
`Lucemon: Larva` source field and `apps/api/src/cards/BT18/BT18-101.test.ts:48-76`
drives a natural legal
digivolution from the registered `BT18-082` Chaos Mode, verifies Larva enters
the breeding area and the opposing target is deleted, and verifies the
occupied-breeding negative case at lines `107-135`. Lines `78-105` drive the same natural
digivolution with `autoDeclineOptional`, proving the controller can decline

the engine's end-of-turn timing, proving both the security-trash path and the
no-security Digimon/Tamer fallback. These are source-level behavioral tests;
they were not executed because the task explicitly prohibited test and gate

## BT18-102 — Susanoomon

### Catalog and rules

The immutable catalog specifies White level 7, play cost 9, 16,000 DP, all
seven level-6 color digivolution costs of 6, Mega/Hybrid forms, Vaccine,
Shaman, `isAce`, and overflow memory 5. It also specifies:

* Digivolve from `Takuya Kanbara` or `Koji Minamoto` with 10 Hybrid trait cards
  under it for 6.
* Hand Counter Blast Digivolve.
* When Digivolving/When Attacking, delete one opposing Digimon at or below a
  DP ceiling that starts at 10,000 and rises by 2,000 for each color in this
  Digimon's digivolution cards.
* When Attacking, place up to five of this Digimon's Tamer digivolution cards
  as bottom security cards, then trash the opponent's top security card for
  each card placed.
* Rule Trait: Hybrid.

Local QA entries `Q3054` and `Q3057` in `data/kb/qa.json:12979-13006` confirm
that the player may choose the order of multiple Tamer security cards.
`Q3055` confirms that more than 10 Hybrid cards still satisfies the alternate
digivolution requirement, while `Q3056` confirms that requirement cannot be
used for Blast Digivolve. `Q6665-Q6670` at
`data/kb/qa.json:13009-13048` establish the Tamer-origin digivolution and
stack semantics. The comprehensive rules at
`data/kb/rules/comprehensive.md:717-764` define stacked and digivolution
cards, and lines `962-967` establish that a “with/have X cards” requirement
is fulfilled at X or more.

### Implementation correction

The generated trace had three behaviorally material gaps: its DP scaling was
not sourced from this Digimon's digivolution stack, its security source was
not restricted to Tamers, and its custom security-trash operation did not
provide a supported scaling path. `apps/api/src/cards/BT18/BT18-102.ts:29-76`
now attaches `dpCeilingScaling` directly to each Delete action, with distinct
colors counted from the source Digimon's `digivolutionCards` stack. Attaching
the scaling to Delete is necessary because a later cost-modifier action cannot
retroactively change a deletion already resolved by the runtime.

The second When Attacking effect at
`apps/api/src/cards/BT18/BT18-102.ts:79-109` uses the supported
`SecurityManipulation` `addBottom` path with a Tamer-only
digivolution-card source, `hostFilter.isSelfRef` binding to this Digimon's
host stack, bottom placement, an up-to-five limit, and an actual placed-card
count for the subsequent opponent security trash. This avoids the
`placeAsSecurity` field-permanent branch, which cannot source hosted loose
cards. The shared runtime correction at
`apps/api/src/engine/effects/interpreter/actions/security.ts:565-586` records
the number of selected cards that actually arrived in security, including
zero on no move, and exposes it to the follow-up action for this supported
digivolution-stack path.

The alternate digivolution metadata at
`apps/api/src/cards/BT18/BT18-102.ts:129-138` requires at least 10 Hybrid
trait cards, uses `namesExact` for `Takuya Kanbara` and `Koji Minamoto`, and
marks the requirement incompatible with Blast Digivolve. The shared
legality/highlighting override at `packages/shared/src/effects/data.ts:578-590`
uses the same exact-name fields. The module retains the Hand Counter Blast
Digivolve marker and the Rule Hybrid trait, and registers only through
`registerIrCard`.

### Exact-name fixture boundary

The catalog contains no distinct longer-name variant of `Lucemon: Larva` or
`Lucemon: Chaos Mode`; the available entries are the exact `BT18-086` and
`BT18-082` names (with other printings of Chaos Mode retaining the same exact
name). No synthetic longer-name fixture was introduced. Exactness for those
references is evidenced by the direct and shared `namesExact` fields, the
runtime equality matcher at `apps/api/src/engine/cards/cardData.ts:481-484`,
and exact-name peer implementations such as `BT19-091`. For BT18-102, the
catalog does provide the longer printed `BT18-088` name
`Takuya Kanbara & Koji Minamoto`; its effective Rule-name aliases remain
covered by `packages/shared/src/cards/effectiveNames.ts:8-12` and the natural
assertion at `apps/api/src/cards/BT18/BT18-102.test.ts:162-164`.
