Status: static audit complete in strict ascending order. Every card is capped at
the canonical provisional score of 8/10 because the 2-point executed-gates
component was intentionally not run. Focused tests, interpreter mechanism

## Method and shared evidence

The audit compared each card in order against the committed catalog, local KB
and rules, direct TypeScript module, generated effects snapshot, shared
interpreter primitives, colocated focused tests, traits and same-mechanism
peers, and rules-legal source/target stacks. The primary references are:

- Catalog: `packages/shared/src/cards/data/cards.json:31500–31658` contains
  BT2-101 through BT2-110. All ten are Option cards; the entries provide each
  color, name, use cost, printed Main text, and Security text. Options have no
  Digimon level, DP, evolution requirement, or trait field to verify. The
  tested Main fixtures satisfy the color requirement with a same-color
  Digimon in the battle area; Security fixtures correctly need no color source.
- Card-specific KB: `node tools/kb/query.mjs card <CARD-ID>` was run for every
  card in ascending order. BT2-101–BT2-104, BT2-106–BT2-108, and BT2-110
  returned no card-specific entries. BT2-105 returned Q3247 at
  `data/kb/qa.json:15013–15020`, ruling that a Spider Shooter revealed in
  security cannot activate a later End of Attack effect after De-Digivolve
  trashes it. BT2-109 returned Q1041 at `data/kb/qa.json:15022–15027`, ruling
  that Heat Viper cannot delete a Digimon in the breeding area. No matching
  errata or banlist entry was found for this range.
- Generated snapshot: `packages/shared/src/effects/effects.json:58441–58673`
  contains full records and empty residual arrays for all ten cards. The
  direct modules are authoritative at runtime per `docs/ARCHITECTURE.md:38–51`.
- Shared interpreter: `targeting/permanents.ts:15–124` resolves explicit
  controller, battle-area, suspension, DP, level, and keyword filters; an
  omitted area defaults to the battle area under
  `data/kb/rules/comprehensive.md:1900–1907`. `actions/board.ts:50–184`
  dispatches Suspend, Unsuspend, and ModifyDP with exact counts and durations;
  `primitives.ts:3288–3417` applies real orientation transitions and fires
  unsuspend/suspend timing. `actions/removal.ts:51–120,574–810` dispatches
  Delete and Return, while `primitives.ts:1454–1510` implements the level-3
  De-Digivolve floor and `primitives.ts:3674–3795` returns a selected
  permanent to its owner's deck while trashing its attachments. `actions/play.ts:148–300`
  and `primitives.ts:821–956` implement free plays from trash and atomic
  On Play suppression. `actions/resources.ts:42–100` implements GainMemory and
  deck processing; `actions/meta.ts:15–25` dispatches ActivateMain; and
  `actions/board.ts:423–428` returns a Security Option to its owner's hand.
- Rules: `data/kb/rules/comprehensive.md:904–915` defines Option color
  requirements and their Security exception; `1618–1645` defines Main use,
  pending Option processing, and automatic Security activation; `1900–1907`
  defines default battle-area scope; `1920–1924` classifies Option effects;
  `2911–2945` defines De-Digivolve's mandatory top-card processing and level-3
  floor; and `461–500` covers simultaneous movement, ownership, and deck
  placement. `data/kb/rules/glossary.md:110–119,133–147,295–301` supplies the
  Security, Main, and De-Digivolve definitions used by the trace.

Every direct module registers executable behavior exactly once through
`registerIrCard(cardId, compiled)`; no `registerCard` registration is present
in BT2-101 through BT2-110. Every direct record declares
`coverage: "full"` and `residual: []`; these claims still await the deferred
execution gates.

The snapshot has two semantic-shape discrepancies relative to the authoritative
direct modules. BT2-102's snapshot adds a broad `Trash` action after Return,
which would target all of the controller's Digimon rather than only the
selected permanent's evolution cards; the direct module intentionally relies
on the shared Return primitive to trash only that permanent's attachments.
BT2-108's snapshot models On Play suppression as a separate
`DisableTimingEffect`, while the direct module uses the atomic
`suppressOnPlayEffects: true` option on PlayWithoutCost. Both direct forms are
supported by the inspected runtime seams and focused tests; snapshot
regeneration was not run or claimed.
