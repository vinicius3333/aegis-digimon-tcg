## Rules, rulings, errata, and restrictions

The applicable reference material was read from the committed KB: Official Rule Manual web ver. 6.0 (`data/kb/rules/manual.md`) and Comprehensive Rules ver. 4.2, updated 2026-08-18 (`data/kb/rules/comprehensive.md`). The relevant clauses were:

- Comprehensive §§2-3 define card names, substring name references, individual traits, and multi-trait matching. These govern the Knightmon/Bagramon substring boundaries, `DeadlyAxemon` exact-name selection, and the Hybrid, Insectoid, Ten Warriors, X Antibody, and Black-color filters.
- Comprehensive §§4-8 cover card areas, Tamers, digivolution cards, suspension, deletion/trashing, ordinary digivolution, and alternate Tamer evolution. In particular, §4-8 distinguishes a source card from a card on the field, §8-1-2-7 says ordinary digivolution is not adding a card to a stack, and §8-1-3 fixes the ordinary reveal/pay/place/draw sequence.
- Comprehensive §§11-2 and 14 cover attack timing and battle survival. A `whenDeletesInBattle` event is evaluated after the attacker survives; this supports AncientBeetlemon's lack of a redundant survival field.
- Comprehensive §§15-1, 15-3, 15-4, 15-7, 15-8, and 15-9 cover ordered effect processing, inherited effects, triggering, optional processing, trigger/immediate timing, and mandatory versus optional processing. This supports RhinoKabuterimon's optional `[When Attacking]` digivolution and the inherited Dorumon, SkullKnightmon, and DeadlyAxemon effects.
- Comprehensive §§15-10 and 15-11 distinguish individual targets from overall/all processing and prohibit selecting the same card multiple times. This supports Dinorexmon's same-target restriction and Ebonwumon's overall `all` restriction.
- The Manual's turn, attack, digivolution, stack, and inherited-effect sections were cross-checked against those clauses for implementation terminology.

`data/kb/errata.json` has no BT7-051–BT7-060 entry, and `data/kb/banlist.json` has no assigned-card restriction. No assigned-card ruling or erratum changes the catalog text. The only restrictions relevant to the audited behavior are the card-text restrictions encoded in the effects themselves (unsuspend restriction, optional processing, and alternate evolution requirement).

## Shared interpreter and registration evidence

The following shared primitives were inspected as read-only implementation evidence:

- `turnOwnerGuard` in `apps/api/src/engine/effects/interpreter/effect.ts` gates `OpponentsTurn`; `Static` has no equivalent turn gate. This is the direct proof that Ebonwumon's second effect cannot remain `Static`.
- Permanent target resolution in `apps/api/src/engine/effects/interpreter/targeting/permanents.ts` reuses `ctx.lastResolvedPermanentIds` only when `sameTarget: true`. Dinorexmon therefore needs that explicit marker for its second action.
- Combat dispatch in `apps/api/src/engine/combat/controller.ts` fires `whenDeletesInBattle` only after the winning attacker survives, so AncientBeetlemon's event already carries the printed “and survives” condition.
- Reveal processing in `apps/api/src/engine/effects/interpreter/actions/reveal.ts` uses a `taken` set, preventing one revealed card instance from satisfying two add clauses. This supports Dorumon's two categories and Monitamon's OR category without duplicate selection.
- Placement cost processing in `apps/api/src/engine/effects/interpreter/costs.ts` supports a permanent target, moving all of its sources, placing the target at the bottom of the host stack, and trashing its own sources. This matches SkullKnightmon's DeadlyAxemon cost shape.
- Tamer evolution support in `apps/api/src/engine/cards/tamerOntoDigivolve.ts` and `apps/api/src/engine/cards/cardData.ts` derives the level/color/evolution-cost path from `onto`/`asLevel`; the stale `cost: 0` alternate-requirement marker is not used as the actual payment cost.
- `collectWouldDigivolveSelfReducers` in `apps/api/src/engine/effects/interpreter/registration/reducers.ts` is allowlist-gated. BT7-051 was added to the verified self-reducer allowlist alongside BT7-025, and its direct module now supplies the explicit replacement that the collector consumes.

All ten audited direct modules use exactly one `registerIrCard(cardId, compiled)` call and no `registerCard` call. `apps/api/src/cards/BT7/index.ts` imports BT7-051 through BT7-060 in ascending order.
