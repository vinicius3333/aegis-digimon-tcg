## Scoring and registration policy

Each card is scored against five canonical components at two points each:

| Component | Maximum | Evidence expected |
| --- | ---: | --- |
| Catalog and rules contract | 2 | Printed fields, clause boundaries, rulings, errata, restrictions. |
| Direct IR and registration | 2 | Direct executable mapping and one exclusive `registerIrCard` registration. |
| Shared interpreter trace | 2 | Timing, target, controller, count, cost, zone, duration, and result semantics. |
| Static behavioral, peer, and stack proof | 2 | Focused tests plus comparative, boundary, and legal-stack evidence. |
| Executed gates | 2 | Focused, mechanism, and collection execution gates. |

The executed-gate component is fixed at 0/2 because execution was forbidden. Thus 8/10 is the
provisional static ceiling; no card is claimed as 10/10.

Every direct module in this range has `coverage: "full"`, `residual: []`, exactly one
`registerIrCard("<cardId>", compiled)` call, and no card-local `registerCard` call. The generated
`packages/shared/src/effects/effects.json` file was inspected only as evidence and was not edited.
