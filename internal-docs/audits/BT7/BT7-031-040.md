## Shared interpreter evidence

- `apps/api/src/engine/effects/primitives.ts:2189–2273` implements stack-card
  trashing. The `isDigiBurst` path emits one batch
  `onDigiBurstCardDiscarded` event with all selected source IDs before the
  per-card events, preserving Q1551/Q1567 ordering and self-source identity.
- `apps/api/src/engine/effects/interpreter/actions/subTrigger.ts:715–755`
  checks that a discarded inherited source was among the event's trashed
  instance IDs and that a host filter matches the receiving permanent;
  `:984–1007` preserves a discarded source as the watcher source rather than
  incorrectly rebinding it to the surviving host.
- `apps/api/src/engine/effects/interpreter/costs.ts:779–871` pays fixed and
  up-to Digi-Burst costs from the host stack, records paid count, and routes
  Digi-Burst costs through the primitive with effect provenance.
- `apps/api/src/engine/effects/interpreter/actions/runAction.ts:469–529`
  handles action costs and correctly aborts a Digi-Burst payload when its
  fixed cost cannot be paid; `:559–601` uses the paid up-to count as the
  scaling multiplier.
- `apps/api/src/engine/effects/interpreter/actions/security.ts:632–640`
  writes `ModifySecurityDP` to the Security-DP ledger and preserves its
  duration, while the rules' Security Digimon definitions govern what the
  ledger affects.
- `apps/api/src/engine/effects/interpreter/actions/digivolve.ts:203–207`
  treats a Static Digivolve action with `onto`/`asLevel` as alternate-path
  metadata, not as an effect to execute; `apps/api/src/engine/effects/interpreter/registration/keywords.ts:280–291`
  registers the Tamer-onto level. `apps/api/src/engine/cards/cardData.ts:520–570`
  derives the legal shared-color Tamer requirement, while the committed
  `BT7-036` override in `packages/shared/src/effects/data.ts:552` supplies its
  cost-2, yellow-Tamer alternate path.
- `apps/api/src/engine/effects/interpreter/actions/resources.ts:353–416`
  installs hand-resident digivolution-cost modifiers only while their source
  card is in hand, checks the owner's seat, and matches the destination card
  when `into` is present. This is the relevant BT7-038 peer/mechanism seam.
- `apps/api/src/engine/effects/interpreter/actions/placeUnder.ts:517–610`
  provides the dedicated stack placement/trashing semantics used by BT7-039
  and the stack source transitions used in the focused fixtures.
- Trait/name matching was compared against
  `apps/api/src/engine/effects/interpreter/matching/definition.ts` and
  `matching/permanent.ts`. `match: "nameExact"` is required for a bracket-only
  identity, while `match: "name"` remains correct for text that says “in
  their names.”
