## 4. Per-card findings

### EX12-071 Saneiketsu Invitation (Option, 3, Black/Blue/Red, [Shambala]/[SW])

Clauses: ＜Use Req. ([SW] trait)＞; [Main] "By trashing 1 [SW] trait card from your hand,
＜Draw 2＞ After, place this card in the battle area."; [All Turns] "When any of your [SW] trait
Digimon are played, ＜Delay＞ ・1 of your [SW] trait Digimon may digivolve into a [Saneiketsu]
trait Digimon card in the hand without paying the cost."; [Security] Activate this card's [Main].

IR trace: `WaiveColorRequirement` + `youHave` → `colorWaiverStatic` (`builders.ts`) and
`countMatching` (`interpreter/scaling.ts`, battle-area permanents by default). `Draw` with a
`trash` cost, `optional` + `abortOnDecline` → `runAction`'s decline-abort path, which is what
Q6886 requires. The [All Turns] + ＜Delay＞ + `SubTrigger` shape is the supported reactive-Delay
route: `withIntrinsicDelayGate` (`interpreter/effect.ts:372`) stamps `delayArmedIntrinsic` on the
watcher, so the trash cost and the "not the turn it entered play" gate ride the fire, not the
registration. `Security` → `ActivateMain`.

Defect corrected — ＜Use Req.＞ scope (shared by all five Options in this batch):

- Before: `condition.filter = { controllerDefault: "mine", nameOrTrait: [{tokens:["SW"], match:"trait"}] }`.
- After: the same plus `kind: ["Digimon", "Tamer"]`.
- Why: CR 16-42-3 says ＜Use Req.＞ ignores the color requirement "with specific **Digimon and/or
  Tamers** on the field". `youHave` counts battle-area permanents of any kind, and EX12 is the
  set that puts **Options in the battle area** (this very card does it). Without the gate, one
  resident trait-carrying Option satisfies the next one's ＜Use Req.＞. Reachable inside the set,
  not a theoretical case.

Tests added: "is not enabled by a resident Option carrying the Use Req. trait" — a resident
EX12-074 (White [Shambala]/[SW]/[TB] Option, so its colors can never satisfy this card's
Black/Blue/Red requirement by themselves) must not let EX12-071 be played.

Mutation check: delete `kind: ["Digimon", "Tamer"]` and that test's expected
`{ ok: false, reason: "color-requirement-unmet" }` becomes `{ ok: true }`. Q6886 is guarded by the
existing decline test; `abortOnDecline` removal makes the "places itself" assertion fire on a
declined payment.

Open ambiguity: none. Note that `countMatching` has no zone gate here, so a breeding-area Digimon
counts — EX12-073's suite asserts that explicitly, and CR 16-42-3's "on the field" does not
exclude the raising area, so this is left as the set-wide reading.

### EX12-072 Metal Empire (Option, 2, Black, [ME])

Clauses: ＜Use Req. ([ME] trait)＞; {Security}[All Turns] "All of your [ME] trait Digimon gain
＜Guard＞"; [Main] bottom-security exchange, placing itself **face up** as the bottom security
card; [Security] "You may play 1 play cost 5 or lower [ME] trait card from your hand or trash
without paying the cost."

**Type error resolved (the module's only one), and it was a real defect.** `GainKeyword` takes a
`KeywordRef`, whose `keyword` is the closed `Keyword` union in
`packages/shared/src/effects/ir/keywords.ts`. `"Guard"` is absent from that union. Chasing why it
was absent showed the clause was also dead code: `runBoardAction`
(`interpreter/actions/board.ts:361-400`) records continuous keywords in the continuous ledger and
performs the verb for action-type keywords, but **nothing in the leave-prevention consult reads a
"Guard" grant**. EX12-056, the card that prints ＜Guard＞, does not rely on the keyword either —
it writes the ability out as a `Replacement`. So the persisted node was a flag no rule consumed.

- Before: `GainKeyword` to all my [ME] Digimon, `keyword: {keyword: "Guard"}`, `duration: "permanent"`.
- After: a `Replacement` `wouldLeavePlay` / `mode: "prevent"` / `leaveCause: "byOpponentEffect"` /
  `affectsAll: true`, protecting `{controller: "mine", kind: ["Digimon"]}`, with
  `cost: {kind: "deleteOwn", target: my [ME] Digimon, count: 1}` — i.e. ＜Guard＞'s printed
  reminder text (quoted verbatim on EX12-056) with the keyword holder as the payable pool.
- Host: `builderForTrigger` routes `isSecurity` + `AllTurns` to `securityStatic`, whose base guard
  is `inFaceUpSecurity`, so the protection lives exactly while the card is face up in security
  (Q6888-Q6891). `runReplacement` tolerates an off-field source (`sourcePermanentId: self?.permanentId`)
  and `subscribeReplacement` dedups on `activationIdentity`, so the continuous recompute does not
  install duplicates.

Also fixed: the ＜Use Req.＞ kind gate (see EX12-071).

Tests: the two `hasKeyword(..., "Guard")` assertions were removed — they proved a flag, not a
rule — and replaced with four behavioral cases against `primitives.deletePermanent(ids, "byEffect")`
with `turnSeat` set, following EX12-056's proven pattern:

1. face-up security + an [ME] Digimon: an opponent-effect deletion of a different Digimon is
   prevented and the [ME] Digimon is trashed instead;
2. face-down security: no protection;
3. face-up security but no [ME] Digimon: the cost is unpayable and the deletion resolves;
4. own-turn (controller's own effect): `leaveCause: "byOpponentEffect"` refuses to fire.

Plus the resident-Option ＜Use Req.＞ guard and an IR assertion that no `GainKeyword` survives.

Mutation checks: change `leaveCause` to `"any"` → case 4 fails. Drop `affectsAll` or the
`controller: "mine"` protect filter → case 1 fails. Drop the `nameOrTrait` on the cost → case 3
fails. Drop the kind gate on ＜Use Req.＞ → the resident-Option test fails.

Residual nuance, documented in the module header rather than modeled: printed ＜Guard＞ protects a
Digimon's **other** Digimon, so a lone [ME] Digimon cannot save itself. Here the protected pool
and the payable pool overlap, but paying with the leaving Digimon deletes it anyway, so the
observable outcome is identical. The visible keyword itself cannot be restored without the shared
seam in §6.

### EX12-076 Susanoomon (Digimon, Lv.7, 16/16000, Yellow/White/Red, SEC)

Clauses: `[Digivolve] Lv.6 w/[Hybrid]/[Shambala]/[TS] trait: Cost 5`; `[Assembly -9] 8
[Hybrid]/[Shambala] trait cards w/different names`; ＜Rush＞ ＜Raid＞ ＜Blocker＞; [On Play]
[When Digivolving] -3000 DP to all opponent Digimon for the turn per color in this Digimon's
digivolution cards; [When Attacking][Once Per Turn] place 1 opponent Digimon as their top security
card, then if this Digimon has 4+ colors in its digivolution cards, trash their top security card
and ＜Recovery +1＞; [Rule] Trait: Has [Hybrid] Form.

**Type error resolved.** `GainKeywordAction.duration` is a REQUIRED field
(`packages/shared/src/effects/ir/actions/board.ts:132`) and the inline ＜Recovery +1＞ node omitted
it. Reading `runBoardAction` shows ＜Recovery＞ is an ACTION-type keyword: the interpreter calls
`ctx.fx.recoverToSecurity(...)` and returns **before** the grant is recorded anywhere, so the
duration value is inert. `duration: "permanent"` was added, matching every other inline
＜Recovery +N＞ in this set (EX12-042, EX12-045). Semantics unchanged; the module now conforms.

note answered: **the reported Digi-Egg scaling pattern does not apply here.** The
`kind: ["Digimon"]` in the [On Play]/[When Digivolving] node is on the ModifyDP **target** (the
opponent's Digimon), which is correct. The scaling is `unit: "digivolutionCardColors"`, and
`interpreter/scaling.ts:311` counts distinct colors across the **whole** stack without consulting
`filter` at all, so Digi-Eggs already count.

Q7194 is satisfied without a change: both halves of the "Then, ..." clause carry
`condition: {kind: "selfDigivolutionStackDistinctColorCount", op: "gte", value: 4}`, whose
interpreter case returns `false` when the source permanent is gone.

Tests: the IR assertion for the ＜Recovery＞ node now asserts `duration: "permanent"` and explains
why the value is inert. The existing suite already proves the 3-colour vs 4-colour boundary, the
once-per-turn limit, the keyword set and the [Rule] Hybrid trait.

Mutation check: removing `duration` is a compile error, which is the assertion; changing
`value: 4` to `3` fails the existing `THREE_COLOR_STACK` case; changing the `-3000` or the scaling
unit fails the DP cases.

### EX12-077 Proximamon (Digimon, Lv.7, 15/15000, White/Red/Purple, SEC)

Clauses: `[Digivolve] Lv.6 w/[Gammamon] in text or w/[VB] trait: Cost 5`; `[DNA Digivolve]
Red/Blue Lv.6 + Black/Purple Lv.6: Cost 0` (expanded to all four colour pairs); ＜Security A. +1＞;
＜Blocker＞; [On Play][When Digivolving] "By placing 2 cards with [Gammamon] in their texts or the
[VB] trait from your hand or trash as 1 of your Digimon's top or bottom digivolution cards, delete
1 of your opponent's Digimon or Tamers."; [On Play][When Digivolving][When Attacking][Counter]
[Once Per Turn] "You may play or use 1 play or use cost 10 or lower card with [Gammamon] in its
text or the [VB] trait from any of your Digimon's digivolution cards without paying the cost."

Two defects corrected.

1. **The placement cost was gated to Digimon cards.**
   - Before: `cost.target.filter = { controller: "mine", kind: ["Digimon"], nameOrTrait: [...] }`.
   - After: the `kind` is gone.
   - Why: the printed text says "2 **cards**", not "2 Digimon cards". The host restriction is
     separate and already correct (`underFilter: {controller: "mine", kind: ["Digimon"]}` —
     "as 1 of your **Digimon's** ... digivolution cards"). EX12-073 Giant Meat is an Option
     carrying [VB] and was silently unpayable; so was every [VB] Tamer.
   - Test added: "pays the placement cost with a non-Digimon card carrying the VB trait" —
     EX12-073 from hand plus EX12-007 from trash, asserting the host stack ends up holding both.

2. **The digivolution-card pool spanned zones the text never reaches.**
   - Before: `from: ["digivolutionCards"]` with no `hostFilter`.
   - After: `hostFilter: { kind: ["Digimon"], zone: "battleArea" }` on all four windows.
   - Why: `looseCardsInZone(ctx, seat, "digivolutionCards")`
     (`interpreter/targeting/loose.ts:67`) yields the stack of **every permanent the seat
     controls, plus the breeding-area permanent** — cards under Tamers and cards under the
     breeding Digimon included. Neither is "your Digimon".
   - Test added: "does not reach a qualifying card stacked under one of your Tamers"

regression test was added for the positive cross-stack case ("plays a qualifying card out of
another of your Digimon's stack") and an IR assertion pins
`hostFilter.isSelfRef` to `undefined` so a future "fix" toward `isSelfRef` fails loudly.

Pre-existing drift re-confirmed as module-wins: `kind: ["Digimon", "Tamer", "Option"]` on the

could never reach an Option, and this clause explicitly says "play **or use**". `playCostLte: 10`
is likewise required by the printed "cost 10 or lower".

Mutation checks: restore `kind: ["Digimon"]` on the cost → the new Option-payment test fails;
drop `hostFilter` → the Tamer-stack test fails; set `hostFilter.isSelfRef` → both the IR assertion
and the cross-stack test fail; drop `playCostLte: 10` → the existing EX12-035 (cost 12) exclusion

## 6. Seam requests

### 6.1 Add `"Guard"` to the shared `Keyword` union (required by EX12-072, EX12-056, EX12-057)

`packages/shared/src/effects/ir/keywords.ts`:

```diff
   | "Execute"
   | "Progress"
+  /**
+   * ＜Guard＞ (EX12): "When any of your other Digimon would leave the battle area by your
+   * opponent's effects, by deleting this Digimon, they don't leave." The ability itself is
+   * executed as a `wouldLeavePlay` prevention (EX12-056, EX12-072); this entry exists so a
+   * card that GRANTS the keyword can also expose it on the keyword ledger.
+   */
+  | "Guard"
   | "IceClad"
```

Failing test it needs (once the union carries it, on top of the executable prevention EX12-072
already installs):

```ts
it("shows Guard on the granted ME Digimon while Metal Empire is face-up in security", async () => {
  const s = setupEngine({
    0: {
      battleArea: [
        { card: "EX12-008", as: "me" },
        { card: "EX12-005", as: "other" },
      ],
      security: [{ card: "EX12-072", as: "metal", faceUp: true }],
    },
  });
  await s.ready();

  expect(observe(s.engine).hasKeyword(s.perm("me"), "Guard")).toBe(true);
  expect(observe(s.engine).hasKeyword(s.perm("other"), "Guard")).toBe(false);
});
```

Today that test cannot even be written without a cast, because the grant node does not typecheck.
Note that the union entry alone only restores **visibility** — it does not make the leave-prevention
consult read the keyword, which is why EX12-072 executes the ability explicitly instead.

### 6.3 Note, not a request: `youHave` has no field-zone gate

`countMatching` defaults to battle-area permanents but never distinguishes the breeding area from
the battle area for a filter with no `zone`. EX12-073's suite asserts that an [ME] Digimon in
breeding satisfies ＜Use Req.＞, and CR 16-42-3's "on the field" does not exclude the raising area,
so the current behavior is kept set-wide. Flagged in case a later ruling narrows it.
