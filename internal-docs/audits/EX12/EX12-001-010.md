### EX12-002 Mococomon (DigiEgg, Yellow, Lv.2, [Smoke]/[Shambala]/[SW])

- **Clauses.** Inherited only: "[Your Turn] [Once Per Turn] When any of your other [SW] trait
  Digimon are played, this Digimon may digivolve into an [SW] trait Digimon card in the hand with
  the cost reduced by 2."
- **IR trace.** `YourTurn` + `frequency: "OncePerTurn"` + `isInherited` → `SubTrigger`
  (`event: "whenPlayed"`, `sourceFilter: {controller: mine, excludeSelf: true, kind: Digimon,
  trait [SW]}`) → `Digivolve` (target: self; `into`: [SW] Digimon; `from: ["hand"]`;
  `payCost: true`; `reduceCost: 2`; `optional: true`). `digivolve.ts` enforces the printed
  digivolution requirement of the `into` card unless the effect explicitly waives it, which is the
  correct reading — nothing in this text waives requirements. Q6723's ordering is engine behavior
  and is covered by the existing event-order assertion.
- **Defects corrected.** None. `payCost: true` is the only drift and the module is right.
- **Tests added.** "does not digivolve into an SW card whose digivolution requirements the host
  cannot meet" — host `EX12-006` (Lv.3) with only `EX12-045` Sanzomon (Lv.4 requirement on both its
  printed and alternate routes) in hand.
- **Mutation check.** Remove `payCost` → the existing positive case fails on `memory === -1` (this
  is the drift). Change `reduceCost` to any other value → the same assertion fails. Remove
  `excludeSelf` → "does not react when the played event names the inherited source itself" fails.
  Drop `OncePerTurn` → "does not trigger a second time in the same turn" fails. Drop the [SW] trait
  on `into` → "does not offer a legal Shambala card that lacks the SW trait" fails. Waive
  requirements → the new Sanzomon case fails.
- **Open ambiguity.** None.

### EX12-003 Kapurimon (DigiEgg, Black, Lv.2, [Lesser]/[ME])

- **Clauses.** Inherited only: "[All Turns] When any of your [ME] trait Digimon would leave the
  battle area other than by your effects, 1 of them and any of your other Digimon may DNA digivolve
  into an [ME] trait Digimon card in the hand."
- **IR trace.** `AllTurns` + `isInherited` → `Replacement` (`event: "wouldLeavePlay"`,
  `leaveCause: "otherThanYourEffect"`, `sourceFilter: {controller: mine, kind: Digimon, trait
  [ME]}`) → `DnaDigivolve` (`materials {count: 2, includeRef: "triggerSubject"}`, `into` [ME]
  Digimon in hand, `payCost`, `optional`). `dna.ts` pins the trigger subject and asks for
  `count - 1` partners from a candidate pool with the pinned id removed, which is exactly Q6726.
  `canDnaDigivolve` still gates the destination, which is Q6724/Q6725.
- **Defects corrected.** None; the JSON is missing both the cause gate and the pinned material.
- **Tests added.** "still replaces a leave caused by the opponent's effect" — with `turnSeat = 1`
  the leave-prevention seat resolves to the opponent (`primitives.ts` uses
  `effectSeatStack.at(-1) ?? engine.controllerSeat()`, and `controllerSeat()` is `state.turnSeat`),
  so `otherThanYourEffect` must still fire. This distinguishes `otherThanYourEffect` from a plain
  "not by effect" reading, which the existing suite could not.
- **Mutation check.** Change `leaveCause` to `"any"` → "does not replace a leave caused by its
  controller's own effect" fails. Change it to `"byEffect"` or `"byBattle"` → the `byRule` positive
  case fails. Change it to `"byOpponentEffect"` → the `byRule` positive case fails while the new
  opponent-effect case still passes, so the pair pins the value exactly. Drop `includeRef` → the
  Q6726 case fails because the leaving Digimon would not be in the merged stack. Drop the [ME]
  filter → "does not react when a non-ME Digimon would leave" fails. Change `controller` → "does
  not react when an opponent's ME Digimon would leave" fails.
- **Open ambiguity.** Whether a second [ME] Digimon leaving in the *same* simultaneous batch may be
  chosen as the "other Digimon" is not addressed by the KB and is not asserted here.

### EX12-004 Onibimon (DigiEgg, Purple, Lv.2, [Ghost]/[Shambala]/[TB])

- **Clauses.** Inherited only: "[Your Turn] This Digimon with the [TB] trait gains ＜Execute＞".

  top card only, which is the correct rules reading for "this Digimon with the [X] trait".
- **Defects corrected.** None. The JSON drops the trait gate entirely.
- **Tests added.** None; the existing suite already covers the positive grant, the non-[TB] host,
  the opponent's turn, and both Q6728 orderings.

  trait" fails (this is the drift). Change the trigger to `AllTurns` → "does not grant Execute
  during the opponent's turn" fails. Change the keyword → the positive grant assertion fails.
  Switch to `selfDigivolutionStackHasTrait` → the non-[TB]-host case would start passing Execute to
  `EX12-006`, because Onibimon itself carries [TB] in the stack; the existing negative case is what
  pins the live-top-card reading.
- **Open ambiguity.** None.

### EX12-007 Gammamon (Red/Yellow, Lv.3, [Ceratopsian]/[VB], 3/2000)

- **Clauses.** `[Digivolve] [Gurimon]/Lv.2 w/[VB] trait: Cost 0`; `[On Play] Reveal the top 3 cards
