### EX12-047 — Amaterasumon (Yellow/Red, Lv.6, 12000 DP, cost 12, [Shambala]/[TB])

**Clauses.** `[Digivolve] Lv.5 w/[Shambala]: Cost 3`; ＜Piercing＞, ＜Security A. +1＞,
＜Ascension＞; `[On Play] [When Digivolving] Delete 1 of your opponent's lowest DP Digimon.
Then, by returning 2 cards from their trash to the bottom of the deck, for the turn, this
Digimon gets +6000 DP and, to 1 of their Digimon, give −5000 DP for each of those returned
cards' colors`; `[On Deletion] You may return 1 [TB] trait card from your trash to the hand.
Then, you may play 1 level 5 or lower [TB] trait Digimon card from your hand without paying the
cost`.

**IR trace.** `Delete{superlative:"lowestDP"}`. The "by returning" clause is an activation
`cost{kind:"return", target:{filter:{zone:"trash", controller:"opponent"}, count:2},
trackColors:"returnedCardColors"}` hung on the +6000 `ModifyDP`. In `costs.ts` the fixed-count
trash-return branch (≈line 1436) requires exactly 2 candidates (Q6818's all-or-nothing), lets
the activating player select and order them (Q6816), routes them to the deck bottom because the
raw text does not say "to the top", and calls `recordTrackedColors`, which writes the count of
*distinct colours across the chosen cards* into `ctx.namedCounts` (Q6820: red+blue and
blue+yellow → 3). The −5000 action reads that through
`scaling:{per:1, unit:"namedCount", countSource:"returnedCardColors"}`; `scaling.ts:340` yields
0 when the name is absent, and `runAction.ts:824-832` makes a scale of 0 a no-op, so an unpaid
cost correctly suppresses the whole "Then" payload.

**Type error resolved — and what it meant.** `EX12-047.ts:93` and `:151` carried
`raw: "for each of those returned cards' colors"` inside `scaling`. `Scaling`
(`packages/shared/src/effects/ir/predicates/scaling.ts`) has no `raw` field, which is why the
typecheck failed once `@ts-nocheck` was removed. I traced what the interpreter actually needs
from that node: `scaleFactor` reads only `per`, `unit`, `countSource` and (optionally) `floor`,
and the `namedCount` branch is driven entirely by `countSource` matching the cost's
`trackColors`. Removing `raw` therefore changes no behaviour — the key was documentation the
type does not model. **Before:** `{per:1, countSource:"returnedCardColors", unit:"namedCount",
raw:"…"}`. **After:** the same node without `raw`. The prose survives on the cost, whose `Cost`
type *does* declare `raw`.

**Tests changed.** The blanket `expect(compiledEffects["EX12-047"]).toEqual(compiled)` would
now fail against the still-stale persisted record, so it was replaced with an assertion that
re-adds exactly the two inert `raw` keys before comparing. That keeps the check strong (any
*other* drift still fails) while documenting the one known divergence.

## 6. Seam requests

### S-1 — `[Rule] Name:` aliases are never parsed (shared package, 13 cards)

`packages/shared/src/cards/effectiveNames.ts` matches only the parenthesised form
`(Rule) Name: …`. Thirteen catalog cards print the bracketed form `[Rule] Name: …`, including
EX12-041 ("Also treated as having [Mamemon]"). None of them get a universal alias today.
EX12-041's in-play alias still works — the module's `GrantStatic{grant:"name"}` covers the
battle-area case — but the alias is missing everywhere else the rules apply it (KB Q759: "in
every zone"), so a name-gated search or requirement reading a card in hand, deck, or trash does
not see it.

Affected cards: BT15-012, BT15-035, BT17-091, BT18-088, EX11-053, EX12-041, EX5-030, EX5-046,
EX5-070, LM-026, P-141, P-147, P-152.

Proposed minimal diff (not made — outside my batch):

```diff
-    ...(text.match(/\(Rule\)\s*Name:\s*(?:Also\s+)?treated as(?:\s+having)?[^.。]*/gi) ?? []),
+    ...(text.match(/[[(]Rule[\])]\s*Name:\s*(?:Also\s+)?[Tt]reated as(?:\s+having)?[^.。]*/gi) ?? []),
```

Failing test it needs (in `packages/shared`, or as an EX12-041 case once the seam lands):

```ts
expect(effectiveStaticNames(getCardDefinition("EX12-041")!)).toEqual(
  expect.arrayContaining(["Thundermon", "Mamemon"]),
);
```

That assertion fails today. Note the widened regex must keep `EX5-030`/`EX5-046`/`P-141`, whose
text reads "Treated as having …" without "Also", which is why the `Also` group stays optional.

### S-2 — activation-cost optionality (CR 15-7-4), corpus-wide convention

`runAction.ts:709-742` already implements both halves: `cost.optional === true` prompts the
player, and a refusal skips the payload. No in-catalog `kind:"return"` trash cost sets it, so
every "by returning …" clause is forced whenever it is payable. CR 15-7-4 says the player
chooses. For EX12-047 the choice is meaningful — returning two cards to a nearly-empty
opponent deck can rescue them from a deck-out.

Proposed minimal diff for the card (not made — it would make EX12-047 the only card of 176 with
this shape to behave differently, which is a corpus decision, not a batch decision):

```diff
           cost: {
             kind: "return",
+            optional: true,
             target: {
```

Failing test it needs:

```ts
it("CR 15-7-4 lets the controller decline the trash return and keep the base DP", async () => {
  const s = setupEngine(
    {
      0: { battleArea: [{ card: "EX12-047", as: "source" }] },
      1: {
        battleArea: [{ card: "BT1-009", as: "lowest", dp: 1000 }, { card: "BT1-021", as: "target", dp: 15000 }],
        trash: ["BT1-010", "BT1-027"],
      },
    },
    { autoAcceptOptional: false, autoSelectCards: true },
  );
  const firing = advance(s.engine).fire(EffectTiming.OnPlay, s.perm("source"));
  await settle(() => s.state.pendingDecision?.kind === "optional");
  // decline the "Pay cost: by returning 2 cards…" prompt
  ...
  await firing;
  expect(s.perm("source").currentDP).toBe(12000);
  expect(s.perm("target").currentDP).toBe(15000);
  expect(s.state.players[1]!.trash).toHaveLength(3);
});
```

Today that test cannot even reach the prompt: the cost is paid without asking. Whoever owns the
convention should decide whether to flip all 176 or none.
