### EX12-021 Gabumon — 2 defects corrected

**Clauses.** Blue Lv.3 Rookie, Data, `[Reptile][VB]`, play 3, DP 2000, evo Blue Lv.3 cost 0 (catalog `evoCosts`).
Alternate digivolve: `[Tsunomon]` (no level) **or** Lv.2 with `[VB]`, cost 0 — matching the peer reading used by

Main: `[Start of Your Main Phase] By trashing 1 card with [Garurumon] in its name or the [VB] trait from your hand, ＜Draw 1＞ and gain 1 memory.`
Inherited: `[When Attacking][Once Per Turn] If your hand has 7 or fewer cards, ＜Draw 1＞`.

**IR trace.** One `StartOfYourMainPhase` effect: `Draw{amount:1, optional, abortOnDecline, cost:{kind:"trash", count:1, nameOrTrait:[Garurumon/name, VB/trait]}}` then `GainMemory{amount:1}`.
`effect.ts:609-623` breaks the action loop as soon as `runAction` returns `true`, and `runAction` returns
`action.abortOnDecline === true` on every decline/unpayable path — so the abort flag alone is the correct
gate for the trailing memory gain. The inherited effect is `Draw` under `handAtMost: 7`
(`conditions.ts:298-301`), `isInherited`, `OncePerTurn`.

**Defect 1 — memory gain was gated on the draw succeeding, not on the cost being paid.**
Before: `GainMemory` carried `condition: { kind: "ifThisEffectActed" }`.
`actions/resources.ts:27-40` sets `ctx.lastEffectActed = drewAny`, i.e. *did a card actually reach the hand*.
The printed text pays one cost for a two-part result; nothing ties the memory to the draw resolving.
With an empty deck the cost was still paid, the card was still trashed, and the memory was silently skipped.
After: the condition is removed; `abortOnDecline` on the `Draw` supplies the only gate the text asks for.

**Defect 2 — the hand cost relied on a regex over prose.**
Before: the cost target filter had no `zone`. `costs.ts:1120` reaches the hand branch through
`cost.target.filter.zone === "hand" || /(?:from|in) (?:your|their) hand/i.test(cost.raw ?? "")`.
The module only matched via the `raw` string, so any later edit to that prose would silently reroute the cost
to the generic permanent-target fallback at the end of `case "trash"`.
After: `zone: "hand"` is explicit (this is the one field where persisted was already correct).

**Tests added.**
- *"still gains the memory after paying the cost when the deck is empty and nothing is drawn"* — the exact case
  defect 1 broke: cost trashed, hand empty, `memory === 1`. Fails on the pre-fix module.
- *"cannot pay the trash cost with a matching card that is not in the hand"* — a matching `EX12-007` sitting in
  the trash must not pay; guards the zone scoping behaviorally.
- The IR assertion now requires `zone: "hand"` and asserts the `GainMemory` action has **no** `condition` property.

**Mutation check.** `amount: 1` on `Draw` → the deck/hand-count assertions in the first two tests.
`amount: 1` on `GainMemory` → `expect(s.state.memory).toBe(1)` in three tests. `nameOrTrait` name branch →
the `BT1-036` (Garurumon, non-VB) test. Trait branch → the `EX12-007` test. `optional`+`abortOnDecline` →
the decline test (`memory === 0`, card still in hand). `zone: "hand"` → the new trash-zone test plus the IR
assertion. `handAtMost: 7` → the 7-card draw test and the 8-card no-draw test. `OncePerTurn` → the second
`OnUseAttack` fire in the 7-card test. Every card-specific field has a named assertion.

**Open ambiguity.** None.

### EX12-026 Shellmon — 2 defects corrected, 4 type errors resolved

**Clauses.** Blue Lv.4 Champion, Data, `[Mollusk][Shambala][TB]`, play 5, DP 5000. Alternate digivolve: Lv.3 with `[Shambala]`, cost 2.
`＜Blocker＞`;
`[On Play][When Digivolving] Trash the bottom 2 digivolution cards of 1 of your opponent's Digimon. Then, 1 of their Digimon with 1 or fewer digivolution cards can't attack or block until their turn ends.`;
`[Rule] Trait: Has [Aquatic] Type.`
Inherited: `[When Attacking][Once Per Turn]` draw at 7 or fewer.

**Type errors and what they meant.** Lines 58, 67, 105, 114 reported
`Property 'count' is missing in type '{ fromSelectionRef: string; filter: {}; }' but required in type 'Target'`.
`targeting/permanents.ts:29-38` short-circuits on `fromSelectionRef` and never reads `count`, so adding `count: 1`
would have silenced the compiler without changing behavior. That would have been the typing-chore fix. Treating it
as the brief instructs — as a signal that the IR shape is not what the interpreter expects — surfaced the real
problem: the four-action `SelectBind → Restrict(attack) → Restrict(block)` chain was hand-built to solve a problem
the interpreter already solves natively, and in doing so it dropped a printed filter on one side and carried an
untyped target on the other. Every reference to `fromSelectionRef` in the repo's own IR tests
(`interpreter.test.ts:2433, 3444, 4914`) carries `count: 1`, confirming the shape was written outside the type.

**Defect 1 — the trash clause could be aimed at a Digimon with nothing to trash.**
Before: `TrashDigivolution.target.filter` was `{controller: "opponent", kind: ["Digimon"]}`.
After: `digivolutionCards: "hasAny"` added, matching `matching/permanent.ts:505` and the set convention in
`EX12-033.ts:204` and `EX12-035.ts:72`. Persisted already had this field.
Crucially, the two actions remain independent (no `abortOnDecline`), so when the opponent has **no** stacked
Digimon at all the trash clause finds nothing and the restriction clause still resolves — the printed reading.

**Defect 2 — the restriction target lost its printed `1 or fewer digivolution cards` filter in the persisted
form, and used a non-typechecking encoding in the module form.**
Before (module): `SelectBind{filter:{…, digivolutionCardsAtMost:1}, bindAs:"restrictTarget"}` followed by two
`Restrict` actions targeting `{fromSelectionRef:"restrictTarget", filter:{}}` — no `count`, hence the type errors.
Before (persisted): a single `Restrict{restriction:"attackOrBlock"}` with the `digivolutionCardsAtMost` filter
**missing**, which would let Shellmon silence a fully stacked Digimon.
After: one `Restrict` with `restriction: "attackOrBlock"`, `count: 1`, and
`filter: {controller:"opponent", kind:["Digimon"], digivolutionCardsAtMost: 1}`.
`actions/restrictions.ts:107-113` resolves the target set once and records **both** the `attack` and the `block`
prohibition on each resolved id, which is exactly the "1 of their Digimon … can't attack or block" identity the
`SelectBind` chain was emulating — with one selection prompt instead of two and no untyped target.
`matching/permanent.ts:607` supplies `digivolutionCardsAtMost`. The action count per trigger drops from 4 to 2.

**Q6753 conformance.** The ruling states the prohibition is applied to a Digimon that has ≤1 digivolution cards
*at that moment* and "remains on the Digimon even if its digivolution cards increase". The corrected `Restrict`
carries neither `while` nor `whileMatchesTargetFilter`, so `actions/restrictions.ts:53-56` leaves `continuous`
undefined and the recorded restriction is a one-shot ledger entry, not a re-evaluated one. This is asserted
directly in the test file now.

**Tests added / updated.**
- *"restricts nothing when every opposing Digimon still has two or more sources after the trash"* — a 4-source
  Digimon drops to 2 and must **not** be restricted. This is the assertion the persisted encoding fails.
- *"still restricts a source-less Digimon when no opposing Digimon has sources to trash"* — proves `hasAny`
  narrowed only the trash clause and did not swallow the restriction clause.
- The IR assertion now expects the two-action shape with `attackOrBlock`, requires the `hasAny` and
  `digivolutionCardsAtMost: 1` filters, asserts `actions` has length 2, and asserts the `Restrict` has neither
  `while` nor `whileMatchesTargetFilter` (Q6753).
- The pre-existing test that adds a digivolution card after the restriction and re-asserts both prohibitions
  already proves the Q6753 persistence behaviorally; it is unaffected by the encoding change.

**Mutation check.** `amount: 2` + `fromTop: false` → the `["BT1-011"]` / `["BT1-011","BT1-012"]` remaining-stack
assertions. `digivolutionCards: "hasAny"` → the source-less test (`players[1].trash` stays empty) plus the IR
assertion. `digivolutionCardsAtMost: 1` → the new 4-source negative test. `restriction: "attackOrBlock"` → the
paired `isRestricted(…, "attack")` / `isRestricted(…, "block")` assertions on the **same** permanent, and the
"restrict a different eligible Digimon" test which proves the two prohibitions never split across two Digimon.
`duration: "untilOpponentTurnEnd"` → the post-`placeUnder` re-assertion. `Rule` trait grant → the
`hasEffectiveTrait(…, "Aquatic")` assertion. `Blocker` not inherited → the `plainHost` assertion.
`handAtMost: 7` → the 7/8-card pair.

**Open ambiguity.** None. The one judgement call is whether "Trash the bottom 2 digivolution cards of 1 of your
opponent's Digimon" may legally be aimed at a Digimon with 0 sources; the set convention (EX12-033, EX12-035) and
the persisted record both say no, and it is recorded here as convention rather than as a quoted rule.

**Why the module beats persisted.** Persisted flattens the modal into two sequential actions. Because

**Rulings.** Q6755 (no stacking of two copies' reductions for one play) holds structurally: the reduction lives on
the resolving action, not on a board-wide cost modifier, so a second copy's `[Main]` cannot contribute to the first
copy's resolution. Q6756 (Solarmon) and Q6757 (Pomumon) are engine-level interactions with the play pipeline and are
both covered by existing tests.

**Defects.** None.

test and the full IR assertion. `reduceCostBy: 2` → the memory assertions in the play test (`memory 1 → 0` for a
3-cost card) and the Option test. `match: "text"` → the Q6754 `BT13-028` test. `frequency: "OncePerTurn"` → the
second-activation `illegal-target` test. Inherited `handAtLeast: 7` → the draw-then-trash / draw-only pair.

### EX12-028 Gusokumon — 1 defect corrected (follow-up)

**Clauses.** Blue/Black Lv.5 Ultimate, Vaccine, `[Crustacean][DS]`, play 8, DP 8000.
`[Digivolve] Lv.4 w/[DS]: Cost 3`; `[DNA Digivolve] Blue/Purple Lv.4 + Black/Yellow Lv.4: Cost 0`;
`＜Blocker＞`; `＜Decode (Lv.4 or lower w/[DS] trait)＞`;
`[All Turns][Once Per Turn] When a Digimon attacks, by placing 1 [DS] trait Digimon card from your hand as this Digimon's bottom digivolution card, ＜De-Digivolve 1＞ 1 of your opponent's Digimon. After, if you have 0 or less memory, gain 1 memory.`
Inherited: `[Opponent's Turn][Once Per Turn] When one of your opponent's Digimon attacks, you may change the attack target to 1 of your [DS] trait Digimon.`

**IR trace.** The DNA line's `(Blue or Purple) + (Black or Yellow)` is correctly expanded into all four ordered
material pairs. Decode is a `Replacement{event:"wouldLeavePlay", leaveCause:"otherThanBattle"}` wrapping a
`PlayWithoutCost{from:["digivolutionCards"], playedByDecode:true, optional:true}` under a
`hostFilter: {isSelfRef: true}` + `lte 4` + `[DS]` filter.
The `[All Turns]` clause is a `SubTrigger{event:"whenAttacking", sourceFilter:{kind:["Digimon"]}}` — deliberately
uncontrolled, so it fires for either player's attack as the printed "When a Digimon attacks" requires — carrying
`DeDigivolve{amount:1, optional, abortOnDecline, cost:{kind:"place", destination:"digivolutionStack", position:"bottom", host:"self"}}`
then `GainMemory{1, condition: memoryAtMost 0}`.

**Ruling conformance.** Q6758 (the "After" clause requires the placement) is exactly `abortOnDecline: true` on the
`DeDigivolve`, which `effect.ts:609-623` turns into "stop the action loop". Q6759 ("0 or less memory" = the 0
position and to its right) is `memoryAtMost: 0`, and `conditions.ts:275-283` normalizes the gauge to the effect
controller's perspective before comparing — the non-obvious part, verified rather than assumed.

**Defect — Decode could play a card out of a *neighbouring* Digimon's stack.**

## 6. Seam requests

**None.** No card in this batch needed an engine or shared change. Both EX12-026 defects were fixable inside the
card module because `actions/restrictions.ts` already implements `attackOrBlock` and `matching/permanent.ts`
already implements `digivolutionCardsAtMost` and `digivolutionCards: "hasAny"`; the EX12-028 Decode defect was
fixable because `targeting/loose.ts` already implements `hostFilter.isSelfRef`.

Three observations are recorded for the engine owners as latent risks rather than as blocking seam requests, since
neither breaks a card in this batch:

1. **Prose-dependent cost routing.** `interpreter/costs.ts:1120` decides whether a `trash` cost reads the hand via
   `cost.target.filter.zone === "hand" || /(?:from|in) (?:your|their) hand/i.test(cost.raw ?? "")`. A card whose IR
   omits `zone` is one prose edit away from silently falling through to the generic permanent-target branch at the
   end of `case "trash"`, which would look for a *battle-area permanent* instead. EX12-021 was in that state before
   this pass. A cheap hardening would be to warn (or `unsupported()`) when a `trash` cost resolves through the raw
   regex with no `zone` set. *Failing test it would need:* an IR record with a hand-shaped cost whose `raw` says
   "from your discard" must not silently pay from the hand.
2. **A missing `hostFilter` silently widens a hosted-zone pool instead of failing.**
   `targeting/loose.ts:277-284` treats an absent `hostFilter` as "any host matches", so an IR record that means
   "this Digimon's digivolution cards" but omits `hostFilter` reads every stack the controller owns, with no error
   and no `unsupported()` call. Both EX12 Decode cards (EX12-014, EX12-028) shipped with that omission, which
   suggests the default is the wrong way round for `from: ["digivolutionCards"]`. *Failing test it would need:*
   a `PlayWithoutCost{from:["digivolutionCards"]}` inside a `wouldLeavePlay` replacement with no `hostFilter` must
   not offer a card from a second permanent's stack.
3. **`Target.fromSelectionRef` requires `count` it never reads.** `targeting/permanents.ts:29-38` returns the bound
   permanents and ignores `count` entirely, yet the `Target` type makes `count` mandatory, so every author writes a
   meaningless `count: 1`. Making `count` optional when `fromSelectionRef` is present would remove a class of
   type errors that currently masquerade as semantic ones. *Failing test it would need:* a compile-level assertion
   (or an IR fixture) that a `fromSelectionRef` target without `count` typechecks and resolves to the bound ids.
