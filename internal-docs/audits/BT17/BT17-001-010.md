## Scope and audit boundary

This report audits exactly BT17-001 through BT17-010 in strict ascending
card-ID order. The catalog was read from immutable Git blob
`efbecc002fb9000789123e2f91f201466e1e5b0a`; the working-tree catalog hash
was independently confirmed to be the same. BT16 static coverage and
chronological integration are recorded; BT16 remains open only for deferred
gates and recorded limitations. This BT17 range is eligible
review/integration. This worker makes no collection or worktree-completion
claim and did not mark the Orca worktree completed.

Each card was checked against its catalog record, the local card KB, direct
TypeScript module, compiled IR/shared runtime, useful peers, legal evolution
or stack arrangements, and source-level behavioral proof. Every direct module
has `coverage: "full"`, `residual: []`, and one executable registration through
`registerIrCard(cardId, compiled)`; no duplicate `registerCard` registration was
added or preserved. `packages/shared/src/effects/effects.json` was read only
and was not modified.

The five score components are fixed at two points each: Catalog/rules, IR
trace, Behavioral proof, Peer and stack proof, and Executed delivery gates.
The last component is deliberately `0/2` for every card in this dispatch.
Tests, typecheck, lint, formatters, browser checks, focused/mechanism/
collection gates, and `git diff --check` were not run, as required. The scores
below are therefore provisional and none is a 10/10 delivery result.

## Shared runtime and peer evidence

The shared interpreter paths inspected for this range include:

- `conditions.ts`, target matching, and the deletion resolver for ownership,
  DP, traits, names, and `ifThisEffectDidNotDelete`.
- SubTrigger registration and event payloads for natural play,
  digivolution-card placement, deletion, and battle deletion, including
  inherited-stack source ownership and once-per-turn frequency state.
- Continuous statics and deletion-max-DP ledgers for conditional Blocker,
  inherited DP ceilings, and live memory checks.
- Play, digivolve, DNA-digivolve, RevealAdd, Return, hand-trash, and
  PlayWithoutCost actions, including target legality, optional decisions, and
  printed DNA requirements.

The source tests use public play, digivolution, attack, battle deletion, and
full-turn drivers wherever a natural origin exists. Legal stacks retain actual
catalog-compatible colors and levels; the tests do not use manually fired
timings or event-bus injection as a substitute for a natural origin.

## Card-by-card findings

### BT17-001 — Gigimon

The catalog describes a red Level-2 Digi-Egg whose inherited effect pays one
memory when attacking to delete one opposing Digimon at 3000 DP or less. The
KB query returned no card-specific entry. `BT17-001.ts` compiles an inherited
`WhenAttacking` Delete with the opponent-Digimon/DP filter, `opponentHas`
precondition, and `payMemory: 1`; it is full/residual-empty and exclusively
registered through `registerIrCard`.

The source proof now imports the compiled contract and exercises a natural
attack with the legal BT17-007 red Rookie stack, deleting a 3000-DP target,
paying memory, and leaving a higher-DP target. A no-legal-target attack proves
that the cost and deletion do not occur. The attack/delete/cost path was
cross-checked against the shared deletion and memory primitives and the
nearby inherited Digi-Egg peers.

Correction: source proof only; no production IR correction. Commit:
`04068ae99` (`Audit BT17-001 Gigimon contract`). Unresolved seam: execution
gates remain deferred, so the source proof is not a green test claim.

BT17-010 into BT17-013 at memory 0 so the inherited 2000 ceiling raises
BT17-013's later numeric deletion threshold. BT17-008, BT17-016, and BT17-048
were inspected as DP-ceiling and fallback peers.

ceiling proof; no production IR correction. Commit: `024ea314d` (`Audit
BT17-010 deletion effects`). Snapshot drift was observed: the read-only
snapshot retains a raw fallback condition and GrantStatic/DeleteCap shape
