# BT1-051–BT1-060 range audit

Archival notice: final executed evidence and 10/10 scores are recorded in `docs/audits/BT1-STATIC-AUDIT.md`.

Date: 2026-08-27

## Scope and score policy

This range was audited in ascending card-ID order. Each card was checked against the committed catalog, the card-specific local KB query, the direct TypeScript module, the generated compiled-IR aggregate, interpreter and shared-effect primitives, its colocated tests, relevant peers and traits, and at least one realistic evolution-stack scenario.

All scores in this report are provisional. No focused card tests, mechanism tests, typecheck, lint, formatting check, or `git diff --check` was run, as explicitly required by the dispatch. The 2-point execution-gate component is entirely unrun, so every card in this report is capped at 8.0/10; no card is claimed as 10/10.

The direct modules use the required `registerIrCard(cardId, compiled)` entry point and no audited module contains a second explicit `registerCard` registration. The `registerCard` call internal to `registerIrCard` in `apps/api/src/engine/effects/interpreter/registration/module.ts` is the expected registry seam, not a duplicate card-module registration.

Follow-up correction (2026-09-02): BT1-056's bracketed `[Tinkermon]`
reference is now `nameExact`, with focused and aggregate proof that a longer
near-name is rejected while the printed hand/trash choice and controller scope
remain unchanged.

- Status: no implementation fidelity gap found. Structural and behavioral gates remain deferred, so the score is provisional.

### BT1-053 Darcmon — provisional 8.0/10

- Catalog clauses: Yellow level 4 Champion, Vaccine, Angel; play cost 4; DP 4000; evolves from Yellow level 3 for 2. `[Your Turn] When you play a level 3 yellow Digimon, if this Digimon is suspended, trigger <Draw 1>.`
- Direct IR: `apps/api/src/cards/BT1/BT1-053.ts:1-25` uses a `YourTurn` `SubTrigger` for `whenPlayed`, restricts the source to controller-owned Yellow level-3 Digimon, and draws one for the Darcmon controller only when the source Darcmon is suspended.
- Proof: `apps/api/src/cards/BT1/BT1-053.test.ts:1-168` covers the suspended positive, unsuspended negative, wrong-level/color negatives, multiple Darcmon, movement from the breeding area (Q912), and effect-played level 3 (Q911). The added evolution case proves evolving onto a suspended Yellow level 3 is not a new play event and does not draw.
- Rules/peer interpretation: the `whenPlayed` watcher in `interpreter/actions/subTrigger.ts` observes play events, not digivolution or breeding-area movement. The `BT11-050` inherited watcher peer confirms the source/controller filtering pattern.
- Aggregate ambiguity: `packages/shared/src/effects/effects.json:2890-2913` uses `controllerDefault: "mine"` and an equivalent suspended-source condition. The direct module's explicit controller and normalized condition are clearer executable evidence; no runtime fix is needed.
- Status: no implementation fidelity gap found. All execution gates are deferred.

Q914 confirms that reducing memory after activation does not revert the already-created for-the-turn modifier.
- Aggregate ambiguity: `packages/shared/src/effects/effects.json:2914-2931` is present for this effect; direct IR and tests are the inspected executable source.

### BT1-056 Petermon — provisional 8.0/10

- Catalog clauses: Yellow level 4 Champion, Data, Fairy; play cost 5; DP 5000; evolves from Yellow level 3 for 2. `[On Play] You may play 1 [Tinkermon] from your hand or recycle bin without paying its memory cost.`
- Direct IR: `apps/api/src/cards/BT1/BT1-056.ts:1-26` uses an optional `OnPlay` effect and optional `PlayWithoutCost` from `hand` or `trash`, selecting one controller-owned Digimon whose name exactly matches `Tinkermon`; the bracketed card-name reference must not match longer names.
- Fidelity correction: the prior target filter omitted `controller: "mine"`. Because `interpreter/targeting/matching/permanent.ts:110-130` treats an unspecified controller as both seats, that omission could admit an opponent's Tinkermon during candidate selection. Commit `b8e6f9673` adds the controller-owned scope; the generated aggregate already had the narrower scope. No duplicate `registerCard` was introduced.
- Proof: `apps/api/src/cards/BT1/BT1-056.test.ts:1-169` covers the exact-name matcher (including rejection of `Tinkermon: X Antibody`), playing Tinkermon from trash/hand, optional decline, Q915's one-card limit across hand and trash, Q916's effect-played Tinkermon attack restriction, the added opponent-zone negative, and the added evolution negative proving On Play does not trigger when Petermon is digivolved. `BT1-051-060.audit.test.ts` mirrors the exact matcher contract.
- Rules/primitive interpretation: `interpreter/actions/play.ts:90-680` resolves loose candidates from the declared zones and performs an owner-aware effect play; the explicit controller filter is required at the target boundary. The optional action and one-card count preserve “1” and “may.”
- Aggregate ambiguity: `packages/shared/src/effects/effects.json:2949-2969` still contains the legacy substring `match:"name"`; the direct module is authoritative and now uses `nameExact`. The generated snapshot must be refreshed by set-sync workflow, not edited here.
- Status: implementation gap fixed and covered by tests, but static/mechanism/focused gates remain unrun; provisional score remains 8.0/10.

### BT1-060 MagnaAngemon — provisional 8.0/10

- Catalog clauses: Yellow level 5 Ultimate, Vaccine, Archangel; play cost 7; DP 6000; evolves from Yellow level 4 for 3. `[On Play] Trigger <Recovery +1 (Deck)>.` Inherited: `[Your Turn] This Digimon gets +1000 DP for every 3 security cards you have.`

- Status: no direct implementation fidelity gap found. The stale aggregate representation must be reconciled through the generation workflow if required, and all execution gates are deferred; provisional score remains 8.0/10.
