# BT1-011–BT1-020 range audit

Archival notice: final executed evidence and 10/10 scores are recorded in `docs/audits/BT1-STATIC-AUDIT.md`.

Date: 2026-08-27

## Scope and evidence policy

This range was audited in ascending card-ID order. For every card, the catalog record, local rules/QA knowledge base, direct TypeScript module, compiled IR, shared aggregate snapshot, interpreter/primitives, colocated test, relevant peer implementations, traits, and an applicable evolution-stack scenario were inspected.

The executable card modules were already on the declarative `registerIrCard(cardId, compiled)` path. No duplicate `registerCard` registration was found in BT1-011 through BT1-020. The only code changes in this range are proof improvements: focused evolution/stack tests, a collection IR-coverage test expansion, and a default export for BT1-016 so the structural audit can inspect it.

No tests, typecheck, lint, format, or `git diff --check` were run, per the dispatch instruction. The 2-point execution-gate component is therefore entirely unrun, capping every provisional score at 8/10; none is a 10/10 claim.

## Per-card findings

### BT1-011 Agumon Expert — provisional 8.0/10

- Catalog clause: Red level 3 Rookie/Vaccine/Dinosaur, play cost 3, DP 1000, evolves from a Red level 2 for 0. `[On Play] Return 1 Digimon card with [Agumon] in its name from your recycle bin to your hand.`
- IR clause: `apps/api/src/cards/BT1/BT1-011.ts:4-28` is full IR with `OnPlay` and one target from the controller's trash, kind `Digimon`, name token `Agumon`, returned to hand. The name matcher intentionally accepts longer names, as required by Q874; it does not broaden to non-Digimon cards or the opponent's trash.
- Proof: `BT1-011.test.ts:7-70` covers an Agumon, a longer Agumon-containing name, and a non-Digimon negative. The added `BT1-011.test.ts:72-96` proves the effect does not fire when the card is digivolved onto a Red level 2 Digi-Egg and that the trash card remains in trash.
- Status: No implementation fidelity gap found. Structural IR and behavioral gates remain unexecuted, so the score is provisional.

### BT1-012 Biyomon — provisional 8.0/10

- Catalog clause: Red level 3 Rookie/Vaccine/Bird, play cost 3, DP 2000, evolves from a Red level 2 for 0. Inherited `[Your Turn] When this Digimon is blocked, it gets +2000 DP.`
- IR clause: `apps/api/src/cards/BT1/BT1-012.ts:4-19` marks the effect inherited, uses `WhenBlocked`, guards with `isYourTurn`, modifies self by +2000 for the turn, and binds the modifier to the source instance. This matches Q875's duration and Q876's source-stack lifetime.
- Proof: `BT1-012.test.ts:8-74` covers no boost before a block, boost after a real block, and removal when Biyomon is trashed from the stack. The added `BT1-012.test.ts:76-111` proves the inherited trigger works after Biyomon is evolved onto a Red level 2 and then blocked; the BT1-022 peer supplies the direct-attack negative/timing comparison.
- Status: No implementation fidelity gap found. The declared module is correct and runtime primitives support the source-bound duration. Structural, mechanism, and focused gates remain unexecuted.
