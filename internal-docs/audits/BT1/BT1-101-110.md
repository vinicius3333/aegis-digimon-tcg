Status: provisional; execution gates were explicitly deferred

## Scope and score policy

Each card was checked against the committed catalog at
`packages/shared/src/cards/data/cards.json`, card-specific local knowledge-base
queries under `data/kb/`, the direct module and colocated test under
`apps/api/src/cards/BT1/`, the generated effect snapshot at
`packages/shared/src/effects/effects.json`, the shared interpreter primitives,
peer implementations, and realistic source-stack/evolution interactions where
the card's behavior depends on them. The ten direct modules each register one
executable record through `registerIrCard(cardId, compiled)`; no duplicate
`registerCard` registration was added or retained.

The canonical provisional score is 2/2 catalog+rules, 2/2 IR, 2/2 behavior,
2/2 peer+stack, and 0/2 execution gates. The user explicitly deferred
execution, so no focused tests, mechanism tests, collection tests, typecheck,
lint, formatting, or `git diff --check` were run. No card is claimed as 10/10;
BT1-109 is intentionally lowered to 7/10 because its catalog contains an OCR
typo and the generated snapshot uses a less-specific condition shape than the
direct module, even though the intended ruling is clear.

## Per-card findings

### BT1-101 — Howling Crusher — provisional 8/10

**Catalog contract.** `cards.json` defines a blue Option with play cost 7 and
no evolution or DP fields. Its Main clause is “Trash all digivolution cards
under all of your opponent's Digimon”; its Security clause activates that Main
effect.

**KB and generated snapshot.** `node tools/kb/query.mjs card BT1-101` returns
Q1311: removing the attacker's sources during a Security check does not end an
already-declared attack. `packages/shared/src/effects/effects.json` contains
Main `TrashDigivolution` with generated `amount: 99` and Security `ActivateMain`.

**Direct IR and primitives.** `apps/api/src/cards/BT1/BT1-101.ts` improves the
generated form to one Main/Security action whose target is all opposing
Digimon with `digivolutionCards: "hasAny"`, with `amount: "all"`; the module
registers only `registerIrCard("BT1-101", compiled)`. The dedicated
`runTrashDigivolution` path in
`apps/api/src/engine/effects/interpreter/actions/placeUnder.ts` traverses each
matching host stack, while `securityCheck.ts` keeps a declared attack alive
after a security effect changes the attacker.

**Proof and peers.** `apps/api/src/cards/BT1/BT1-101.test.ts` covers all sources
under multiple opposing Digimon, the Security path, and Q1311 with a
Security-Attack stack. `apps/api/src/cards/BT1/BT1-099.ts` is the closest
single-target stack-trash peer; `BT1-094.ts` and `BT1-110.ts` provide opposing
Digimon target/security peers. This Option has no trait or evolution
requirement, so no additional card evolution stack is applicable beyond the
realistic attacker source stack in Q1311.

**Status.** The direct IR deliberately tightens the generated amount/filter
shorthand and every printed clause has observable proof. No ambiguity remains;
execution gates are deferred.

**Status.** The per-two multiplier and no-effect boundary are explicit in IR

**Proof and peers.** `apps/api/src/cards/BT1/BT1-103.test.ts` now covers catalog

**Status.** The malformed punctuation does not create a rules ambiguity; both
printed clauses now have runtime proof. Execution gates are deferred.

`registerIrCard`.

**Proof and peers.** `apps/api/src/cards/BT1/BT1-104.test.ts` covers metadata,

event-subject and continuous watcher seams. No trait/evolution requirement is
printed; the later-entry/effect-driven digivolution fixtures are the relevant

**Status.** Timing, player scope, dynamic entrants, and independent copies are
mapped and proven. No ambiguity remains; execution gates are deferred.

### BT1-109 — Smashed Potatoes — provisional 7/10 (explicitly lowered)

**KB and generated snapshot.** Q978 confirms a reduction cannot make a cost

the peer+stack component is conservatively 1/2 despite strong focused proof.

**Direct IR and primitives.** `apps/api/src/cards/BT1/BT1-109.ts` refines the
snapshot to a battle-area mine Digimon green level-5 base filter and a hand
green Digimon level-6 destination filter, with `duration: "forTheTurn"` and
`once: true`; it registers only through `registerIrCard`. In
`actions/resources.ts`, CostModifier creates a digivolution predicate consumed
by `continuous.ts`/`primitives.ts`; `actions/digivolution.ts` and the effect
driven paths query the same ledger and floor adjusted costs at zero. The
explicit `zone: "battleArea"` gate excludes breeding and the `into` filter
enforces level 6/color on the destination.

**Proof and peers.** `apps/api/src/cards/BT1/BT1-109.test.ts` covers Q978's
free-not-negative boundary, Q979 breeding exclusion while preserving a
battle-area reduction, Q980 effect-driven X Antibody digivolution, Q1736

Security effect. Cost peers include `BT2-088.ts`/its CAP-C-10 predicate tests,
`BT1-075.ts`, and the shared `apps/api/src/engine/effects/capabilities.test.ts`
CostModifier coverage. The realistic stack suite covers battle-area green
Lv.5→Lv.6, breeding Lv.5, and an effect-driven digivolution. Because the
catalog typo and generated/direct representation mismatch remain visible,
this card is explicitly held at 7/10 pending gates and any future snapshot
normalization decision.

**Status.** The direct runtime predicate is the more faithful implementation;
the remaining ambiguity is documentary/representation-level rather than an
identified runtime gap. Execution gates are deferred.
