## Evidence and findings

### BT20-051 — Raptordramon — 8/10 provisional

- Catalog/rules: The catalog’s black/yellow Lv.4 card text is represented with the Dorumon/Chronicle Lv.3 alternate route, the optional Kota Domoto hand play at one or fewer own Tamers, and the inherited +2000 DP during the opponent’s turn. The card-specific knowledge-base query returned no additional ruling entry.
- IR trace: `BT20-051.ts` uses one `registerIrCard("BT20-051", compiled)` registration. The direct IR uses an exact numeric `permanentCount` condition (`Tamer` `lte 1`) and an exact Kota target; the inherited modifier is scoped to the host and opponent turn. No residual gap was found.
- Behavioral proof: `BT20-051.test.ts` uses natural play/evolution intents across both alternate routes, zero/one/two Tamer states, optional decline, and inherited turn recomputation. This is source-level evidence only because execution was prohibited.
- Peer and stack proof: The alternate Dorumon and Chronicle routes match the catalog’s legal stack paths, and the inherited effect is tested on a host carrying Raptordramon. No implementation correction was required.

### BT20-052 — Oblivimon — 7/10 provisional

- Catalog/rules: The catalog text requires Security play at the end of the opponent’s turn, flipping the next face-down opposing security card, placing this Digimon’s top card face-up at the bottom after a face-up check, and inherited attack-target locking. KB entries Q4375–Q4381 cover skipping face-up cards, face-up checks, end-of-attack behavior, and the zero-security case; Q4720 covers a revealed Tamer changing the attacking Digimon’s presence.
- IR trace: The direct IR has the security timing, next-face-down flip, native `whenCheckedFaceUpSecurity` watcher, and `detachPermanentTop` source operation. The latter is important: it moves Oblivimon itself while promoting its former evolution stack top, rather than taking the card beneath it. The module has exclusive `registerIrCard` registration and no residual gap.
- Behavioral proof: The source tests naturally cover alternate evolution, face-up checking, and inherited turn scope; security-entry timing is invoked directly with `fireForInstance`, so this column remains partial under the audit rule that manual timing injection cannot replace a feasible natural-origin test. Tests were not executed.
- Peer and stack proof: The security interpreter distinguishes `detachPermanentTop` from `fromDigivolutionTop`, and the direct implementation uses the former. This is consistent with the analogous Invisimon implementation and with the face-up security KB entries.

### BT20-053 — Grademon — 7/10 provisional

- Catalog/rules: The catalog requires optional Dorumon/Ryudamon breeding-area play on both entry timings, then one own Digimon during an attack to become unaffected by opponent Digimon effects and gain +5000 DP through the opponent’s turn, plus inherited once-per-turn attack redirection. KB Q4721 confirms that an effect-driven evolution during an active attack satisfies the attack condition.
- IR trace: The direct IR has both entry triggers, an empty-breeding-area requirement, attack-gated +5000 DP/immunity, and the inherited once-per-turn redirect. The initial audit correction added `sameTarget: true` to the On Play immunity target; review then identified that When Digivolving still selected independently, so follow-up commit `d6dbed6a9` adds the same binding there. Both triggers now reuse the Digimon selected for the +5000 DP action so both clauses apply to one Digimon as printed, and the module remains exclusively registered through `registerIrCard`.
- Behavioral proof: Natural play/evolution tests cover breeding placement and inherited redirection. The attack-gated entry is exercised by manually firing `WhenDigivolving` while an attack is live, which is useful supplemental evidence but not full natural-origin proof; the new same-target binding is locked structurally and was not executed.
- Peer and stack proof: The shared target resolver defines `sameTarget` as reuse of the immediately preceding selected permanent, and `GrantImmunity` consumes that resolver. Peer BT26-042 uses the same pattern when two clauses must affect one chosen Digimon; the alternate Raptordramon/Chronicle stack route is represented by the neighboring BT20 tests.

### BT20-054 — Bulbmon — 7/10 provisional

- Catalog/rules: The catalog requires Blocker, an opponent-turn leave replacement, and optional free play of a play-cost-4-or-lower Digimon from this Digimon’s evolution cards; inherited text redirects one opposing attack once per opponent turn. No additional card-specific KB entry was returned.
- IR trace: The direct IR has Blocker, a battle-area-only self replacement source, the cost filter, and the inherited redirect. A semantic defect was corrected: the replacement now uses `fromOwnDigivolutionStack: true` instead of generic `from: ["digivolutionCards"]`. The generic form scans all stacks controlled by the player, while the card text limits the source to Bulbmon’s own stack. Registration remains exclusive `registerIrCard`.
- Behavioral proof: The source test naturally invokes deletion and checks the cost-4 boundary, optional decline, turn scope, and inherited redirect. Because the replacement origin is invoked through a direct delete verb rather than a naturally generated opponent event, the evidence is partial and no test was run.
- Peer and stack proof: The play IR contract documents `fromOwnDigivolutionStack` as the source permanent’s own stack and makes it mutually exclusive with generic `from`. The loose-card resolver confirms generic `digivolutionCards` would collect every permanent stack, which directly supports this correction.

### BT20-055 — Invisimon — 7/10 provisional

- Catalog/rules: The catalog requires Security play at the end of the opponent’s turn; on play/When Digivolving, De-Digivolve 2, flip the next face-down opposing security, then delete an opposing Digimon with at most one evolution card; and the same face-up-check security-bottom clause as Oblivimon. KB Q4382–Q4388, Q4722, and Q4723 cover face-down skipping, ordering, zero security, and top-card removal exposing a Tamer or removing the attacker.
- IR trace: The direct IR preserves action order, the at-most-one-stack target, and native face-up security watcher. `detachPermanentTop` correctly moves Invisimon itself to security bottom while promoting its stack. The module has only `registerIrCard` and no unresolved residual.
- Behavioral proof: Natural play/evolution tests cover De-Digivolve, security flip, the one-stack deletion boundary, and attack-time face-up checking. Security entry is manually fired in the source test, so proof is partial under the dispatch rule; tests were not executed.
- Peer and stack proof: The security interpreter and the Oblivimon peer establish the same detach-versus-under-card distinction, and the KB ordering agrees with the direct action sequence. The source-stack promotion is also observed by the existing HoverEspimon follow-on assertion.

### BT20-056 — Alphamon — 7/10 provisional

- Behavioral proof: Natural play tests cover Recovery and ordinary turn gating; attack-gated breeding evolution, security removal, and leave prevention are invoked through manual effect/event helpers. Those checks are partial under the natural-origin rule and no test was executed.
- Peer and stack proof: The breeding-target digivolve interpreter has a dedicated `targetBreeding` path and explicitly suppresses the evolved card’s entry effect. The inherited stack condition and top-security cost match the catalog’s Alphamon: Ouryuken stack scenario.
