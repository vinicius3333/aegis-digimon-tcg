- Permanent target selection records scalar attributes and bound IDs; `relativeTo.attr: "digivolutionCount"` compares the selected stack count, while restriction records persist on the selected IDs.
- `Search` exposes security cards to the same effect chain, `Digivolve` can consume an earlier security search result, and the production Security-check path activates `[Security]` effects.
- Modal option selection, optional costs, deletion budgets, security placement, deck-top recovery, and public attack intents are all routed through the shared interpreter.

- Effect-driven hand trash emits `whenTrashedFromHand`; BT14-072 provides the natural public origin used for BT14-100 proof.

### BT14-091 — Wave of Reliability

Catalog/rules: Blue Option, cost 2. Main trashes any two opposing digivolution cards as one pooled amount, then chooses one own Digimon and unsuspends it only when no opposing Digimon has as many or more digivolution cards. The 2023-12-22 erratum changes the comparison from “more” to “as many or more”; Security activates Main, then adds itself to hand.

IR/runtime: `BT14-091.ts` uses one across-Digimon `TrashDigivolution` amount 2, a Joe-gated own `SelectBind`, and an inclusive opponent-count comparison before `Unsuspend`; Security is `ActivateMain` plus `AddToHandSelf`. The shared pool and condition seams match the printed order.

Proof: `BT14-091.test.ts` now covers natural pooled trashing across two opposing Digimon, the equal-count erratum boundary leaving the chosen Digimon suspended, and a public attack that reveals the card in Security and runs Main before returning it to hand. Legal stacks use BT14-005/BT14-055 for Lv4 two-source stacks and single Lv3 sources BT14-055/BT14-056.

### BT14-092 — Marching Fishes

Catalog/rules: Blue Option, cost 3. Main chooses one own Digimon and, until the opponent's turn ends, restricts three opposing Digimon with as many or fewer digivolution cards from attacking or blocking. Security restricts one opposing Digimon from attacking this turn, then adds itself to hand. KB Q2467 confirms the chosen count is the activation snapshot.

IR/runtime: The module binds the chosen Digimon, uses `relativeTo`/`digivolutionCount` with `lte`, caps the restriction at three, and maps `attackOrBlock` to both restrictions. The Security branch is an attack-only restriction plus self return.

Proof: `BT14-092.test.ts` naturally proves a two-source chosen Digimon, three eligible opposing targets, exclusion of a three-source target, and public Security activation. Stack peers are legal Lv4 stacks (BT14-005 + BT14-055) and a legal Lv5 three-source stack (BT14-005 + BT14-055 + BT14-058).

IR/runtime: Search, `amongPreviousSearch` Digivolve from security, shuffle, post-cost T.K. Recovery+1, and optional Security Patamon play are represented in the printed order. The natural tests intentionally accept the evolution and Patamon branch, while the pre-existing test retains the decline case.

Proof: `BT14-093.test.ts` covers natural Main search/evolution/recovery and a public Security check that plays Patamon and returns Emissary to hand, in addition to the existing no-Patamon decline proof. The legal evolution peer is BT14-033 Patamon into BT14-035 Unimon (yellow Vaccine Lv4).
