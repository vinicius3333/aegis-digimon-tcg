## Method, evidence, and gate status

Each immutable catalog record was reread for color, kind, level, play cost, DP, evolution requirements, form, attribute, traits, effect text, inherited text, rarity, deck limit, and ACE/Overflow metadata. Every card was queried in the local KB. Each direct module, colocated behavior source, relevant peers and realistic evolution stack, current shared runtime, and registration path was inspected. `internal-docs/audits/BT14.md` was treated as prior evidence only; it was not edited or used as a substitute for the immutable catalog and current source.

The audit intentionally did not run tests, typecheck, lint, formatters, browser checks, collection gates, mechanism gates, or `git diff --check`, as required by the dispatch. Executed gates are therefore fixed at `0/2` for every card and the maximum score is provisional `8/10`. The behavior component below is awarded only where the source contains a natural-origin engine fixture or existing natural-origin proof; structural assertions, direct event injection, and keyword observation alone are not treated as full behavior proof.

Coverage is `full` with an empty residual, and the module has exactly one `registerIrCard("BT14-041", compiled)` with no `registerCard`.

`apps/api/src/cards/BT14/BT14-041.test.ts` naturally evolves a BT1-057 base into Seraphimon, recovers from the deck, observes -7000 DP, and observes the second security check. Its natural Q2414 fixture plays BT1-087 T.K.; T.K. removes a selected security card and his actual effect recovers one from the deck, leaving the count unchanged while the target still receives -7000. Existing direction/frequency assertions use a direct event seam only as supplementary evidence and are not the basis for the behavior score.

### Corrections, limitations, and score
