## Scope and scoring

This is a provisional card-by-card audit of BT24-081 through BT24-090 in strict ascending
card-ID order. The immutable catalog source was the committed catalog blob
`efbecc002fb9000789123e2f91f201466e1e5b0a` (SHA-256
`d9c3892e26c3bee5f800557f6619eb413d39cdc1e7460fa70c291af5ac135ca8`). The generated IR
snapshot `packages/shared/src/effects/effects.json` was inspected read-only (SHA-256
`fb2f278d4a77b940be0bda05141b308a07a3787dfcd54abdc53d00340bf661cf`). The static ledger
`BT24-STATIC-AUDIT.md` and `packages/shared/src/effects/effects.json` were not edited.

Each card is scored on exactly five two-point dimensions:

1. Catalog/rules — immutable catalog fidelity and applicable rules-KB interpretation.
2. IR trace — direct executable trigger/action/requirement trace and registration.
3. Behavioral proof — behavior-driving source proof from observable state changes. Structural
   assertions alone and manually injected timing, subtrigger, or primitive events where a
   natural origin is feasible do not receive 2/2.
4. Peer and stack proof — comparable implementations, source-zone behavior, target binding,
   and legal stack/requirement coverage.
5. Executed delivery gates — tests and delivery gates executed for this dispatch. This is fixed
   at 0/2 because the task explicitly prohibited all test, typecheck, lint, formatter,
   browser/UI, focused/mechanism/collection-gate, and `git diff --check` commands.

Every total is therefore provisional and capped at 8/10. No collection-completion or
completed-worktree claim is made.

## Runtime and registration trace

`apps/api/src/engine/effects/interpreter/compiledCards.ts` resolves a registered direct module
before falling back to the generated shared snapshot, so the direct TypeScript modules are the
runtime authority. `registration/module.ts` maps phase, security, inherited, and subtrigger
entries; `runAction.ts` enforces optional costs and `abortOnDecline`; `subTrigger.ts` enforces
controller/source and security-removal gates; the targeting modules resolve exact names,
trait/text unions, superlatives, source references, and own stacks. The inspected action seams
also included the play, digivolve/App Fusion, Mind Link, borrowed Option, security, scaling,
condition, combat, and continuous-aura interpreters.

All ten direct modules report `coverage: "full"` with `residual: []`, and each registers
executable behavior exactly once through `registerIrCard("BT24-<id>", compiled)`. No audited
module contains a `registerCard` registration. `apps/api/src/cards/BT24/index.ts:82-91`
imports BT24-081 through BT24-090 in ascending order.

The generated snapshot has material drift in this range and was intentionally left untouched:
BT24-081 collapses the exact Titamon and level-limited Titan alternatives; BT24-082 separates
the suspension-dependent DP/Attack tail incorrectly; BT24-083 collapses the Tamer/Digimon
target alternatives; BT24-084 omits the removed-security-seat gate; BT24-085 is partial and
omits the TS Option-use primitive; BT24-086 models inherited keyword grants as broad target
grants; BT24-087 is partial and omits App Fusion; BT24-089 lacks the direct Delay-arm gate and
separate Delay Main payload; and BT24-090 omits Alliance and the precise bottom-security and
integrated cost-reduction semantics. BT24-088’s snapshot uses `match: "text"`, while the
direct module uses `match: "any"`; the inspected matcher defines both as the full
name/trait/effect/inherited-text union, so this is behaviorally equivalent to the catalog’s
“in its text” clause.
